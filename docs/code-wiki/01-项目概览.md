# 01 · 项目概览

## 1. 项目定位

Tioka 是一套**企业级 Agent 套件 + 运行中台 + 治理平台**（自研 Runtime + Orch + Chat/KB/Flow + Connector + HCI + Foundation + Model Hub + 资产控制面）。

产品能力对标并集（能力齐、实现自研）：

| 对标产品 | 映射到 Tioka |
|---|---|
| LibreChat | Chat + HCI + Runtime Skills/MCP |
| Langflow | Flow 可视化编排 + Runtime Agent 节点 |
| WeKnora | Knowledge 工程 + 数据源 + 知识台 |
| agent-autoloop / superagent | Orchestration 事件驱动 + IM |
| Codex / DeepSeek harness | Runtime 执行内核 |
| HiRoute | Model Hub 模型目录与智能路由 |
| AgentCore | Foundation + 资产治理 |

硬边界（架构约束）：自研全部运行时与产品面；跨模块只依赖 `-api`；`*-biz` 互不依赖；出网只经 connector/foundation。

## 2. 能力地图（域 → 职责）

| 层/域 | 职责 | 落地模块 |
|---|---|---|
| HCI | 全交互面与 Generative UI（工作台/审批/观测/Studio/知识台） | `tioka-ui` |
| Chat | 对话、会话、卡片、记忆 | `chat` |
| Flow | 可视化编排、节点库、发布（API/Tool/MCP/Webhook） | `flow` |
| Knowledge | 知识入库、混合检索、引用、Wiki、数据源 | `knowledge` |
| Orchestration | 事件驱动、规则灰度、工单/Run、人审、定时 | `orchestration` |
| Runtime | 模型↔工具循环、沙箱、审批、子 Agent、撤销补偿 | `runtime` |
| Model Hub | 模型目录、智能路由、故障接力、成本观测 | `model` |
| Connector | MCP/IM/业务/数据源连接器（官方实现） | `connector`、`mcp` |
| Foundation | 身份联邦、组织同步、RBAC、SPI、私有化 | `system`、`infra` |
| 资产控制面 | Agent/MCP/Skill 资产目录与发布 | `agent`、`mcp`、`skill` |
| Governance | 策略引擎（Cedar）、配置版本、授权书、自治、审计 | `governance` |
| 业务本体 | 领域包、Schema 注册、文档层、实例折叠 | `ontology`、`tioka-pack-lease` |
| 评测 | 批次评测、数据集、反馈、召回评测、轨迹导出 | `eval` |

## 4. 工程规模与结构总览

顶层 Maven 聚合模块（[pom.xml](file:///f:/AI时代/Tioka/pom.xml)）：

```
Tioka (com.tioka, 0.1.0-SNAPSHOT)
├── tioka-dependencies     # BOM：统一版本锁定
├── tioka-framework        # 通用内核：安全上下文/错误码/持久基类/消息/追踪/加密
├── tioka-modules          # 15 个业务模块（每个再分 -api / -biz）
│   ├── tioka-module-system          # Foundation：RBAC/SSO/审计/配额/密钥/出网
│   ├── tioka-module-infra           # 消息/outbox/死信/通知/追踪
│   ├── tioka-module-runtime         # Agent 执行内核
│   ├── tioka-module-orchestration   # 事件编排引擎
│   ├── tioka-module-chat            # 对话会话
│   ├── tioka-module-knowledge       # 知识库
│   ├── tioka-module-flow            # 工作流编排
│   ├── tioka-module-connector       # IM/业务/数据源连接器
│   ├── tioka-module-model           # 模型 Hub 与路由
│   ├── tioka-module-agent           # Agent 资产
│   ├── tioka-module-mcp             # MCP 管理
│   ├── tioka-module-skill           # Skill 资产
│   ├── tioka-module-ontology        # 业务本体
│   ├── tioka-module-governance      # 策略/配置版本/授权书/自治
│   └── tioka-module-eval            # 评测
├── tioka-pack-lease       # 租赁领域包（DomainPack SPI 纯计算）
├── tioka-testkit          # 测试工具（Fake LLM/ERP 等）
├── tioka-server           # Spring Boot 启动层 + Flyway + ops/catalog/MCP 出站
└── (tioka-ui)             # Vue 3 前端（不在 Maven 聚合内）
```

每个业务模块统一为 `-api`（契约/SPI/MQ 常量，可被其他模块依赖）+ `-biz`（实现，只被 `tioka-server` 聚合）。

## 5. 术语表（跨系统统一语言，节选）

> 完整释义见 [47-GL-统一名词释义](file:///f:/AI时代/Tioka/docs/architecture/enterprise/47-GL-统一名词释义.md)。

| 术语 | 归属 | 定义 |
|---|---|---|
| Thread / Turn / Item / Step | Runtime | 执行上下文；表 `runtime_thread`；Turn 一次模型↔工具循环 |
| SubAgent / Grant / Mandate | Runtime/Orch | 子 Agent 委派；委派授予；授权书 |
| Event / Rule / WorkItem / Run | Orch | 事件 → 规则 → 工单 → 运行实例 |
| Attention | Orch + HCI | 人机闸门（挂起待人处理） |
| Conversation / Part / Memory | Chat | 对话容器；消息片段；会话记忆 |
| KnowledgeBase / Document / Chunk / Citation | Knowledge | 知识资产 |
| Flow / FlowDraft / FlowRun / FlowPublication | Flow | 工作流与发布物 |
| ProviderConnection / LogicalModel / RoutingPlan / ModelBinding | Model | 模型供应商/逻辑模型/路由计划/绑定 |
| Agent / McpServer / SkillPackage | 资产控制面 | 可发布智能体与工具资产 |
| Workspace / Role / ExternalIdentity | Foundation | 空间/角色/外部身份 |

**Part 类型（全局统一）**：`text | markdown | thinking | reasoning_summary | tool_call | tool_result | citation | artifact | code_interpreter | interactive_card | approval_card | form_wizard | status | error | image | audio | file_ref | agent_handoff`

## 6. 生命周期（系统级主链路）

```
刺激（用户/事件/定时/IM/数据源）
 → Chat 或 Orch 或 Flow 触发
 → Runtime Session（可 SubAgent）
 → Tools：KB / Flow / MCP / 沙箱 / 业务
 → 人机：Part 卡片 或 Attention 挂起
 → 写回 Chat / IM / 业务 / 知识 / Wiki
```

## 7. 快速开始（一屏）

```bash
# 1) 中间件
docker compose -f deploy/compose.yml up -d

# 2) 后端（默认 profile=local，模型/MCP 走 mock）
mvn -q -DskipTests compile
mvn -q -pl tioka-server -am spring-boot:run

# 3) 前端
cd tioka-ui
npm install
npm run dev    # http://localhost:5173

# 4) 关 mock（真实 OpenAI 兼容 LLM）
#   tioka.model.mock=false + SPRING_PROFILES_ACTIVE=ext，并配置 provider baseUrl 与 API Key
```

详细步骤、环境变量与 profile 说明见 [06-运行与部署.md](./06-运行与部署.md)。
