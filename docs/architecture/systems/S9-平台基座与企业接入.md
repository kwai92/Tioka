# S9 — 平台基座与企业接入（Foundation）

> **2026-11-06 修订**：Foundation 改为独立部署的基础平台，供 Tioka 与业务系统共用，完整设计见 [S15 Foundation 基础平台系统](S15-Foundation基础平台系统.md) 与 ADR-051〜053（ADR-029 第 69 条）。本文的能力地图仍有效，模块划分、数据模型与波次以 S15 为准。

> 模块建议：`tioka-module-system`（身份/RBAC/组织）+ `tioka-module-foundation`（企业适配 SPI）+ 部分能力落在 `connector` 的「客户侧适配器」  
> 场景：**私有化部署**——客户自有用户体系、组织、IM、业务系统、审计/通知通道必须可打通，而不是只内置一套飞书/本地账号。  
> 对标：企业 IAM 联邦、SCIM、RuoYi/若依权限模型、AgentCore Workspace、iPaaS 式适配器

---

## 1. 定位与边界

### 1.1 定位

Tioka 的 **Enterprise Foundation**：解决「谁可以登录、组织是谁、能访问什么资源、客户侧系统如何标准化接入」。

私有化交付时，Tioka **不取代**客户主数据（用户/组织/IM/核心业务），而是：

| 模式 | 说明 |
| --- | --- |
| **联邦优先** | 登录与组织以客户 IdP/主数据为准，Tioka 存映射与授权缓存 |
| **内置兜底** | 无 IdP 时可用本地账号（演示/小团队）；生产默认关闭或只作应急 |
| **适配器接入** | 客户 IM/业务系统通过 Foundation SPI / Connector Adapter 接入，而非改内核 |

### 1.2 边界内

- 身份认证与会话（SSO/OIDC/SAML/CAS/LDAP…）  
- 用户/组织/岗位同步与映射  
- RBAC（+ 可选 ABAC/数据权限）  
- 租户/Workspace/环境  
- 企业适配器注册：IdP、Org、IM、Biz、Audit、Notify  
- 服务账号、OpenAPI 密钥、权限委派  
- 私有化部署形态（专有云、隔离网络、客户自备中间件）

### 1.3 边界外

- 不实现客户的 HR/ERP 业务本身  
- 不强制客户改用 Tioka 自建 IM  
- 具体飞书/钉钉协议实现仍在 S6，但 **「客户自有 IM」走同一 IM Adapter SPI**

### 2.4 租户 / 空间 / 环境（私有化）

| 能力 | 说明 | 波次 |
| --- | --- | --- |
| 单租户专有部署 | 默认形态：一套 Tioka = 一个客户 | W0 |
| 多 Workspace | 客户内多业务线隔离 | W1 |
| 逻辑多租户 | 集团多子公司（可选打开） | W3 |

| 功能开关 | 按空间开通 Chat/KB/Flow 等 | W2 |

### 2.5 企业 Foundation 适配器（核心）

统一 SPI，客户侧系统「插拔接入」：

| Adapter 类型 | 职责 | 示例 |
| --- | --- | --- |
| **IdentityProviderAdapter** | 认证跳转、回调、用户声明解析 | OIDC、SAML、客户 OAuth |
| **OrgDirectoryAdapter** | 拉用户/部门/变更事件 | SCIM、LDAP、客户 HR API |
| **ImChannelAdapter** | 发卡片/收消息/验签/用户映射 | 飞书、钉钉、**客户自研 IM** |
| **BizSystemAdapter** | 事件入站映射、出站回写、主数据查询工具 | ERP/ITSM/工单/客户业务中台 |
| **AuditSinkAdapter** | 审计日志外送 | 客户 SIEM/日志平台 |
| **NotifyAdapter** | 邮件/短信/站内信 | 客户通知中心 |
| **SecretStoreAdapter** | 密钥读取 | Vault、客户 KMS、本地加密文件 |
| **ObjectStorageAdapter** | 对象交换与产物（预签/读写） | MinIO、客户 OSS；**不作** Agent 会话工作盘（ADR-014） |
| **WorkspaceFs**（Runtime 协作） | Session POSIX 工作盘 | 本地目录 / PVC / 客户 NFS；逻辑路径 uploads/skills/scratch/artifacts |
| **MiddlewareBinding** | 使用客户已有 PG/Redis/MQ | 连接串与隔离前缀 |

**原则**：内置飞书/钉钉 = 官方 Adapter 实现；客户自有系统 = 实现同一 SPI（可由我方交付或客户二开），**内核零分支**。

### 2.6 业务系统与 IM 打通（私有化必达）

| 场景 | Foundation + 域协作 |
| --- | --- |
| 员工用公司账号登录 Tioka | IdentityProviderAdapter → 会话 → RBAC |
| 组织变更自动同步权限范围 | OrgDirectoryAdapter → 角色/数据权限重算 |
| 客户自有 IM 审批 Agent 操作 | ImChannelAdapter ↔ Orch Attention（同 S2 语义） |
| 业务系统抛事件驱动 Agent | BizSystemAdapter → OrchEventApi.emit |
| Agent 回写业务单状态 | BizSystemAdapter egress + 审计 |
| 审计进客户安全平台 | AuditSinkAdapter |
| 客户禁止公网 | 离线许可、无电话回家、全适配器内网 |

## 4. 组件与包结构

```
tioka-module-system-biz          # 用户、角色、菜单、权限（RuoYi 对齐并扩展）
tioka-module-foundation-api      # SPI 接口、DTO、事件
tioka-module-foundation-biz
├── identity/     SsoService, TokenService, LocalAuth
├── orgsync/      ScimController, LdapSyncJob, OrgMapper
├── rbac/         PermissionEvaluator, DataScopeInterceptor
├── workspace/    WorkspaceService
├── adapter/      AdapterRegistry, health
├── audit/        AuditService → AuditSinkAdapter
└── license/     （私有化许可，可选）

tioka-module-connector-biz
├── adapters/im/feishu|dingtalk|wecom|custom-spi
├── adapters/biz/generic-http|custom-spi
└── …（官方实现；客户自定义可独立 jar 热加载）
```

热加载：客户 Adapter 以 SPI jar / Spring 插件包部署到指定目录，**不改 Tioka 主版本**。

## 5. 状态机与生命周期

### 登录

`未认证 → IdP 跳转 → 回调验签 → 映射/建档 → 发会话 → RBAC 加载`

### 组织同步

`调度/Webhook → 拉取变更 → 幂等合并 → 失效权限缓存 → 审计`

### Adapter

`REGISTERED → ENABLED ↔ DISABLED → DEREGISTERED`；健康检查失败可熔断告警但不删配置。

## 9. 安全与多租户

- 私有化默认：**数据不出客户网络**。  
- 适配器密钥进 SecretStoreAdapter。  
- 管理员操作全审计；模拟登录强制原因码。  
- 跨 Workspace 默认拒绝；显式共享策略另配。  
- IM/业务回调验签失败直接拒，防伪造审批。

## 11. 失败、重试与幂等

- 同步任务按外部 ID 幂等；冲突策略：外部为准。  
- IdP 短暂失败：已发会话可用至过期；新登录排队重试。  
- Adapter 超时熔断；人工可切备用 Adapter（同类型多实现）。  
- 权限变更：缓存失效失败则降级「拒绝」而非「放行」。
