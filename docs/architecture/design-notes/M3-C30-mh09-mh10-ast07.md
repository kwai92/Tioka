## MH-09 供给侧配额与预算

- **只读端口**：`SupplyQuotaPort`（`system-api`）定义两个作用域常量（`provider` / `alias`）与两个指标常量（`tokens_month` / `cost_month`），方法 `Long monthlyLimit(scopeType, scopeId, metric)`——**未配置或不认识的作用对象返回 `null`**（约束 F13：读不到即「不限」）。
- **实现**：`GovQuotaSupplyPort` 先校验 `scopeType ∈ QuotaMetrics.SUPPLY_SCOPES`，再经 `GovQuotaRepository.find(...)` 取 `limitValue`。
- **卡点**：`ModelBudgetGuard.check` 分两维——`checkBinding` 读 V218 已落列 `budget_token_month` / `budget_cost_month`；`checkProvider` 经 `SupplyQuotaPort.monthlyLimit(SCOPE_PROVIDER, providerId, METRIC_*)` 取上限，已用量按 `usages.sumTokensByProvider` / `sumCostByProvider`（月初起算，系统时区）。超限抛 `MODEL_BUDGET_EXHAUSTED`。
- **兼容**：`ModelBudgetGuard` 保留 1 参构造，另加 `@Autowired` 2 参构造 `(ModelUsageRepository, ObjectProvider<SupplyQuotaPort>)`——旧装配与旧离线单测零改动，`SupplyQuotaPort` 缺席时 provider 维度按「不限」降级。
- **预警**：`gov_quota.warn_ratio`（V152，缺省 80）供 `QuotaWarnNotifier` 判定越阈值并发 `QuotaThresholdExceededEvent`。
- **迁移口径**：`scope_type`/`metric` 均为既有 VARCHAR，`provider`/`alias` 容量内，metric 允许集已在 V218 扩展（含 `cost_month`），故 MH-09 **只需补 `warn_ratio` 一列**，与 L540 登记的「V218 与 MH-09 主题重叠须先核对」结论一致：**复用 V218 已落结构，不另建表**。

## MH-10 内置运行状态与健康

- **六态与优先级**（`ModelHealthEvaluator`，纯函数）：`DISABLED → BUDGET_EXHAUSTED → COOLDOWN → DOWN → DEGRADED → UP`。
  - `DOWN`：供应商探测连续失败 ≥ 3（`DOWN_PROBE_FAILURES=3`）或 5 分钟错误率 > 50% 且调用数 ≥ 10；
  - `DEGRADED`：P95 延迟 > 24h 基线 2 倍（`DEGRADED_LATENCY_FACTOR=2.0`）或 429 占比 > 10%（`DEGRADED_429_RATIO=0.10`）。
- **信号**（`ModelHealthSignals`）：禁用 / 预算耗尽 / 冷却 / 探测连续失败 / 5 分钟调用与错误数与 429 数 / P95 与基线 P95；由 `ModelCallStatsWindow`（含 `WindowStats`、`ModelCallSample`）聚合。
- **聚合服务**（`ModelHealthService`）：`snapshot(dim,id)` 组装 60 分钟窗口统计 + 熔断状态 + 配额已用比例（经 `SupplyQuotaPort` 的 tokens/cost 指标）+ 最近错误样本；`refreshProvider` 仅在与库中值不同才写 `model_provider.health`；`refreshAllProviders` 由探测调度收尾调用。**任一底层数据源缺席按「无信号」降级，不抛异常。**
- **主动探测**（`ModelHealthProbe`）：`@Scheduled(fixedDelayString = "${tioka.model.probe.interval-ms:60000}")`，Redis `setIfAbsent` 多实例互斥（Redis 缺席退化为单实例），`tioka.model.mock=true` 跳过；经 `egress.send(GET {baseUrl}/models)` 探测，结果落 `ModelProbeStore`（连续失败计数 / 最近结果，均 24h TTL）。
- **指标**（`ModelMetrics`，ADR-041 §5.2 / GOV-08）：既有指标名不改；新增 `tioka_quota_usage_ratio`（`setQuotaUsageRatio`，标签 `scope_type`/`scope_id`/`metric`）与 `tioka_prompt_render_errors_total`（`recordPromptRenderError`，标签 `template`）。**无 `MeterRegistry` 时全部空操作降级**（只保留内存引用），保证离线单测与无指标环境零破坏。
- **管理面**：`ModelAdminController` 增 `GET /health/providers`（全部供应商快照）与 `GET /health/{dim}/{id}`（指定 provider / binding / alias 快照）。

## AST-07 Prompt 模板资产

- **归属与版本化**：`prm_template` 只存**身份与作用域**（`name`/`scope`/`scope_ref` + 当前版本指针），内容（分段正文 / 变量定义 / 用途 / 输出格式 / Schema 引用 / 建议别名 / 样例变量）作发布型对象进 GOV-12（`objectType=prm_template`），复用 `/api/model/configs/prm_template/{id}/publish|rollback|current` 与草稿流（`ModelConfigVersionService`）。
- **校验扩展点**：新增 `ConfigSpecValidator` SPI（`governance-api`），`DefaultConfigVersionService.validate` 在基线（草稿存在、spec 为对象或数组）之后，遍历 `ObjectProvider<ConfigSpecValidator>` 追加专属检查；`PromptTemplateSpecValidator`（model-biz）注册 `prm_template`，把 `PromptTemplateValidator` 的字段 / 占位符-变量双向一致 / 样例渲染自检映射为 `ValidationIssue`。**未注册实现时既有行为不变。**
- **渲染**（`PromptRenderEngine`，纯函数）：`{{name}}` 变量替换、`{{#name}}…{{/name}}` 条件段（真值才渲染，支持 `^` 取反）、列表展开（每项重复段体，项内 `{{.}}` 取当前项）；**不执行任何表达式**。缺必填变量或结构损坏抛 `PromptRenderException` → `PROMPT_RENDER_ERROR`（HTTP 422，`isGovernanceFailure()` 收录），并计数 `tioka_prompt_render_errors_total`。
- **内置集合**（`BuiltinPromptTemplates`）：`sys.decider` / `sys.competence` / `sys.summarize` / `sys.memory.extract` / `sys.compaction`，固定 ID `prmtpl_sys_<名>`。
- **试运行**（`PromptTemplateService.testRun`）：渲染后经 `ModelGateway` 调用，用途 `ModelPurpose.PROMPT_TEST`；别名须指向路由计划（否则 `BAD_REQUEST`），沿用统一治理卡点（不在请求线程之外自行实现模型调用）。
- **管理面**（`ModelAdminController`）：`GET /prompt-templates`、`GET /prompt-templates/{id}`、`POST /prompt-templates`（`model.prompt.create`）、`POST /prompt-templates/{id}/draft`、`POST /prompt-templates/{id}/render`、`POST /prompt-templates/{id}/test-run`（`model.prompt.test_run`）。
- **架构安全**：`ModelAdminController` 只依赖 `PromptTemplateService`，**不 import `ModelGateway`**，故 ArchUnit `noModelCallOnRequestThread`（直接依赖检查）保持绿；类级 `@RequirePermission(Model Admin)` 满足 `controllersDeclarePermission`。

## 登记偏差与观察

1. **AST-07 落点与 M3-00 施工对照口径不一致**——M3-00 L410 写「AST-07、AST-08 施工对照 = `agent-biz` 的 prompt 子域」，实际实现落 **`model-biz`**（与 ADR-041 §1「内容进 `cfg_*`、身份表只存名称与作用域」及 `prm_template` 归 Model Hub 域一致，且复用 `ModelConfigVersionService` 与 `ModelAdminController`）。回写时须说明；`agent-biz` 侧仅留 AST-08（Prompt 接入 AgentSpec / Flow / 领域包）时不冲突。
2. **AST-07 迁移号 V154 作废**——ADR-041 §9 预登记 V154 已被 GOV-13 等占用，身份表 DDL 取 **V237**、内置种子取 **V238**（Java 迁移）；`prm_template` 进 ScopeLine 豁免白名单（无 `workspace_id`）。
3. **审计动作登记为本批补登**——`ModelAdminController` 的 `model.prompt.create` / `model.prompt.test_run` 属 ADR-072 §2「先登记再使用」，本批补入 `actions.yaml`（category=CONFIG，module=tioka-module-model），否则 `AuditedActionCatalogTest.everyAuditedActionIsRegistered` 失败。
4. **`ModelConfigVersionService.buildSpecFromRow` 对 `prm_template` 返回 null**——身份表只存名称与作用域，无「由投影行重建 spec」的入口；发布 / 回滚复用草稿→发布流（`PromptTemplateService.saveDraft` + `publishDraft`），符合「内容在 `cfg_*`、身份行不承载内容」的口径。
5. **试运行用途 `PROMPT_TEST` 与配额归集**——ADR-041 §4 要求「试运行不计入业务配额归集口径」，本批以独立 `ModelPurpose` 值表达，未改归集统计维度（MH-11 统计接入时按 purpose 过滤）。
6. **MH-10 健康状态为「投影」而非权威源**——`model_provider.health` 仅由 `ModelHealthService.refreshProvider` 在值变化时写入；实时快照以内存窗口 + Redis 探测结果为准，DB 列供管理面列表与告警信号源读取。
7. **主动探测依赖 `egress`**——探测经出口守卫调用供应商 `/models`，无 `egress` / 无网络时探测失败按信号计入（不阻断其它逻辑）；`tioka.model.mock=true` 时跳过探测（离线与桩环境）。
8. **探测调度与 GOV-13 的衔接**——`ModelHealthProbe` 调度收尾调 `refreshAllProviders`，`AlertSignalProvider`（GOV-13，另批）可直接读健康状态投影；两批解耦，互不改对方结构。
9. **`ModelMetrics` 无注册表降级**——所有 `record*` 在 `MeterRegistry` 缺席时只更新内存引用 / 直接返回，保证离线单测与未启用指标环境零破坏；指标名以 ADR-041 §5.2 为契约，**禁止改名**（GOV-08 / 约束 F20）。
10. **`SupplyQuotaPort` 与 P2-L5 的关系**——V218 已落 binding 预算与 provider 分摊结构；MH-09 在 provider 维度**复用**该结构（`gov_quota` + `SupplyQuotaPort`），仅补 `warn_ratio` 一列，不新建表（与 L540「须先核对」的结论一致）。
11. **渲染引擎不支持表达式**——ADR-041 §4 明确「无逻辑模板」；本批只做变量 / 条件段 / 列表三种，不做算术或函数调用（复杂逻辑留 AgentSpec / Flow 节点承载）。
