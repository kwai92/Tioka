## 2. 实现

### 2.1 KNW-12 两路独立召回

- `CjkTokenizer`：中文连续串切 bigram（「差旅报销流程」→ `差旅 旅报 报销 销流 流程`），
  ASCII 词保留、去重、最多 32 个 token。查询与文档侧用同一口径，靠 `ILIKE` 命中原文子串。
- `KbChunkMapper.xml#searchByKeyword`：**独立的一次 SQL 查询**，不读向量结果；
  用 `strpos(lower(...), token) > 0` 按命中 token 数排序、`LIMIT k`，并对空 tokens 返回空集。
  空间、知识库 ACL（`vfSql`）、当前版本、父块排除（`coalesce(chunk_type,'CHILD') != 'PARENT'`）、
  文档级 ACL 全部下推。全文路按 `chunk_type` 排父块而非依赖 `embedding_vec IS NOT NULL`，
  以保留对「嵌入失败但仍有正文」子块的独立召回能力（两路真正独立）。
- `KnowledgeService.retrieveDetailed(...)`：向量路与全文路各自 `ORDER BY + LIMIT`，
  再按 RRF(k=60) 只融合名次；返回 `RetrievalOutcome(hits, reason, vectorCount, keywordCount, reranked, rerankDropped)`。
  旧 `retrieve(...)` 签名与返回类型不变，257 例既有 IT 无感。
- 无答案原因：`NO_PERMISSION` / `NO_RESULT` / `BELOW_THRESHOLD`；AUTO 注入在空结果时
  按 ADR-056 §2 写「知识库中没有找到与问题相关的内容」，不编造。

### 2.2 KNW-04 Rerank 经 Model Hub

- V227：`kb_base.rerank_binding_id`、`kb_base.rerank_threshold`；NULL = 未绑定。
- 融合后前 50 条调 `ModelGateway.rerank(purpose=RERANK)`，取 topK，低于阈值（缺省 0.3，按库可配）丢弃；
  **未绑定时跳过且不设阈值**。binding 与 threshold 从**同一个** `KbBaseDO` 解析，不跨库拼接。
  用量、预算、限流、故障记账全部复用 `DefaultModelGateway` 既有链路。
- **失败白名单（ADR-017）**：仅 `MODEL_UNAVAILABLE` / `MODEL_ERROR` 可退回 RRF；
  `QUOTA_EXCEEDED` / `MODEL_BUDGET_EXHAUSTED` / `BAD_REQUEST` / 鉴权 / 策略类
  （统一由 `ErrorCode#isGovernanceFailure()` 判定）一律重抛，非 `BizException` 的编程错误也直接冒泡。
  **不含 `DEPENDENCY`**：`DefaultModelGateway#rerank` 的兜底 catch 会把任意未知异常包装成
  `DEPENDENCY`，列入白名单等于给未知异常开静默通道。自动注入段与 `ContextBuilder.safeRender`
  同样只降级依赖类失败，治理错误必须冒泡。query 为空或候选为空时跳过 rerank。
- `rerankDropped` 统计**所有**低于阈值的候选（达到 topK 后继续计数），空结果据此给 `BELOW_THRESHOLD`。
- 配置端点 `PUT /api/knowledge/bases/{id}/rerank`：类级 `KB_WRITE` + 资源级
  `guard.check("kb", id, EDIT)` + `@Audited`；非法阈值返回 `BAD_REQUEST` 而非 500。

### 2.3 KNW-14 知识使用模式

- `KbToolProvider`：新增 `kb.read`（scope=chunk/parent/document + 页范围 + maxChunks）、`kb.list`；
  `kb.read_chunk` / `kb.read_document` 保留为兼容别名。
  `scope=parent` 真实读取父块正文（`readParentChunk`，无父块退回自身）；
  `pageStart/pageEnd` 按区间交集真实裁剪（`readDocument` 重载），不再只回显参数。
- `listTools(agentVersionId, agentToolConfig)` 按 `knowledge.mode` 分流：AUTO 返回空工具集，
  TOOL/BOTH 返回全部；缺省 TOOL 与 `AgentSpec.KnowledgeBinding.empty()` 一致。
- `KnowledgeAutoInjectSegment`（`D_TURN_TAIL`，开关 `tioka.knowledge.auto-inject.enabled`）：
  每 Turn 检索一次，最多 5 个父块 / 3000 token（粗估 9000 字符），每条命中带引用号。

### 2.4 CTX-01 最小可用形态

- `ContextRenderContext` 新增；`ContextSegmentProvider` 增 `default render(...)`（缺省空串，不破坏既有注册件）。
- `ContextBuilder.build(items, ctx)`：A/B/C 区渲染到稳定前缀，D 区渲染结果放在本轮尾部；
  `LinkedHashMap` 有界 LRU 按 `turnId` 冻结，`frozenTailHash(turnId)` 供前缀哈希验收，
  `frozenTailText(turnId)` 供「真的注入了内容」验收（空注入哈希返回空串，不掩盖未注入）。
  注入超 `tioka.context.max-context-tokens` 抛 `CONTEXT_OVERFLOW`（新增错误码 42211），不静默截断。
- `AgentLoop` 每步用 `ContextBuilder.queryForTurn(...)` 取**本轮首条**用户消息作为注入检索问题
  （不取最后一条，避免多步 steer / 插话把问题污染成「继续」）；
  `KernelLoopConfiguration` 用 `tioka.context.enabled` 装配，**缺省 false 时行为与 M2 完全一致**。

### 2.5 闸门真实验收

`G3KnowledgeRecallGateIT` 一条用例覆盖 M3-06 §3.4 的完整动线：

1. `GateCluster.start(2, "kb-search", props, true)`：关闭 mock、双实例、Keycloak 鉴权。
2. 20 份评测文档全部 `READY`，50 个用例导入 `eval_dataset` / `eval_case`。
3. `KnowledgeRecallEvalService.startRecallRun` 跑 Recall@5 / MRR；
   断言 `perCase.size()==50`、`eval_result` 100 行、`recall >= 基线 - 0.02` 且**绝对下限 0.90**，
   MRR 除 [0,1] 外另设 **0.5 绝对下限**。
4. 两路召回计数各自 > 0，字面命中的门禁条款进 top5（证明不是「只在向量结果上打分」）。
5. 真实 Turn 经 `kb.search` 工具：解析 `tool_result.contentJson.output` 的 JSON 数组，
   断言带 `citationId` 且可回查 `kb_citation`。
6. 文档级 ACL 双向断言：授权主体命中受限文档、无权主体不命中但**仍能命中公开文档**（防退化）。
7. rerank 绑定后 `reranked()==true`，`model_usage` 只数 `status='SUCCESS'` 且核对 `binding_id`；
   高阈值 0.99 下 `rerankDropped()>0`、命中集被削减、全丢弃时原因 `BELOW_THRESHOLD`；
   解绑后 `reranked()==false`、丢弃数为 0。
8. KNW-14 模式分流 + D 区段注册；**冻结断言不是哈希游戏**：执行实例的 `frozenTailText` 必须含
   `[knowledge.auto_inject]` / 「以下知识片段可用于回答」/ `cit_` 引用号 / 检索主题词，
   未执行实例为空，且换 query 重新 `build` 后尾部文本与哈希都不变。
9. 实例 B 能检索到实例 A 入库的文档（共享 PG 可见）。

## 4. 偏离登记（必须逐条保留，后续批次收口）

1. **CI 无本地中文小模型**：`ChineseEmbeddingContainer` 与 `LlmStubServer /embeddings` 是 dim=32 确定性哈希桩，
   不是 ADR-056 §1 的 Qwen3-Embedding-0.6B / qwen3-rerank；rerank 走 `ProviderClient` 的 `mock://openai`
   bigram 重合度打分。语义检索能力未被本批验证，只验证链路与召回纪律。
2. **中文分词为应用层 bigram + `lower()/strpos()`**，不是 `pg_jieba` / `zhparser` / tsvector 列；
   `strpos` 避免 token 中的 `%` / `_` 被当作 LIKE 通配符，`searchByKeyword` 对空 tokens 返回空集而不生成非法 SQL；
   `pg_trgm` 的 `gin_trgm_ops` 只加速 LIKE/ILIKE/~，对 `strpos` 无效，故 V227 **不建该无效索引**；
   全文一路当前为顺序扫描，M4 上 tsvector / pg_jieba 时再压测并补真正的全文索引。
3. **基线值需实测回填并经评审**：`recall-gate-baseline.json` 实测 `recallAt5=1.0 / mrr=0.8673`，
   由本批 20 篇短制度文档 + dim=32 确定性嵌入得出，与 C-16 的 6 篇/12 题基线不是同一数据集；
   闸门另设 Recall@5 0.90、MRR 0.5 两个绝对下限，防止把基线回填成恒真值。
4. **「回答带引用」只到工具层**：`kb.search` 结果与 `kb_citation` 带引用号，但 Runtime 尚未写
   `ItemType.CITATION` item（KNW-08 未完成），助手回答文本不含引用标记。
5. **CTX-01 只做最小可用形态**：四区接线、D 区按 Turn 冻结、预算与 `CONTEXT_OVERFLOW`；
   A/B/C 区仍由 M2 的 item→messages 承担；结构化摘要、工具结果清理层、第 0〜3 级削减、
   上下文清单（CTX-02）、RT-10 完整压缩组装器均未实现。完整版需重写所有 Turn 上下文链路，
   本批以开关隔离避免阻塞闸门转真。
6. **KNW-14 缺省仍是 TOOL**：ADR-056 §3 写 BOTH 缺省，但存量 `AgentSpec.KnowledgeBinding.empty()`
   默认 TOOL，改默认会破坏既有发布校验；保持兼容，登记口径差异。
7. **模式未从 AgentSpec 自动贯通**：`agentToolConfig` 需调用方显式带 `knowledge.mode`；
   Runtime 目前不把 `AgentSpec.knowledge` 映射进 `agentToolConfig`，闸门直接验证工具层契约。
8. **AUTO 注入未读 Agent 级配置**：`retrieveDetailed(null, query, 5)` 检索全部可见库，
   未消费 `kbIds`、1000〜8000 可配预算、父块去重等 AgentSpec 字段。
9. **多知识库绑定取首个非 NULL**：embedding 与 rerank 都沿用 `resolveBindingForRetrieve` 的
   「取第一个库」口径，未做混合知识库间模型空间一致性校验（与 C-21 既有偏离一致）。
10. **rerank 仅在模型依赖失败时退回 RRF**：白名单见 §2.2；配额/预算/参数/鉴权/策略类
    `BizException` 必须冒泡（ADR-017），非 `BizException` 的编程错误也直接冒泡。
    模型不可用时记 warn 并继续检索，可用性优先；未阻断、未进人审。
11. **文档级 ACL 用 TEXT LIKE 精确串匹配**（空值判定加 `btrim`，兼容空白 `[]`），未转 `jsonb ?|`；主体格式由本批定义为
    `user:{id}` / `role:{role}`，空 / NULL / `[]` 继承知识库权限。管理员无后门（ADR-056 要求无条件下推）。
12. **检索轨迹未落表**：两路召回条数、rerank 丢弃数只在 `RetrievalOutcome` 返回，
    KNW-13 / M4 的轨迹表、命中测试接口、30 天保留未做。
13. **查询改写、外部知识库、GraphRAG 不在本批**（KNW-13 / KNW-16 / KNW-17a / KNW-10）。
14. **评测语料是 20 篇短制度文档**，主题互斥、词面锚定，不是真实业务合同/工单语料；
    这是 CI 可复现门禁语料，业务语料评测需另立数据集。
15. V180「全文列与分词索引」在 M3-00 §9 登记但仓库无 V180 文件，本批以 V227 一并落地，
    未补建历史迁移号，避免改动既有号段。
16. **ADR-056 §7 的四个独立 IT 未单建**：`HybridRecallIT#keywordIndependent`、
    `KnowledgeModeIT`、`RerankIT`、`NoAnswerIT` 的断言合并进 `G3KnowledgeRecallGateIT`
    的步骤 3/5/6/7 与 `CjkTokenizerTest` / `KbToolProviderModeTest` / `ContextAssemblyTest`，
    避免为同一链路重复起四套 Testcontainers 上下文。
    `HybridRecallIT#multiKb`（三库一次查询）与 `#aclWithIterativeScan`（1% 可见文档仍足量）

## 5. 上线注意

- 生产需显式开启 `tioka.context.enabled=true`、`tioka.knowledge.auto-inject.enabled=true` 才启用自动注入；
  两者缺省关闭，升级不会改变既有 Turn 上下文。
- rerank 绑定需先在 Model Hub 登记 `kind=rerank` 的 binding 并经 `PUT /bases/{id}/rerank` 配置；
  未绑定时行为与升级前一致（跳过且不设阈值）。
- `kb_base.rerank_threshold` 为 NUMERIC(5,4)，取值 0〜1；配置端点做区间校验，非法数值返回 `BAD_REQUEST`。
  端点除类级 `KB_WRITE` 外还有资源级 `guard.check("kb", id, EDIT)`，跨空间 / 私有库不能靠路径变量改配置。
- **升级行为变化**：绑定 rerank 后若模型侧返回配额 / 预算 / 参数 / 鉴权 / 策略错误，检索不再「静默成功」，
  而是把 `BizException` 抛给调用方（ADR-017）。上线前需确认调用方对 429/403/400 有正确处理。
- 开启 AUTO 注入后，配额 / 限流 / 鉴权 / 策略错误会经段提供者冒泡到 Turn，
  不再伪装成「知识库里没有找到相关内容」；这是有意行为变化，前端需能展示治理拒绝而不是空回答。
- V227 不创建 `pg_trgm` 索引（`strpos` 路径用不上）；全文一路当前是顺序扫描，
  生产大规模语料上线前须压测，必要时在 M4 引入 tsvector / pg_jieba 索引。
- 新错误码 `CONTEXT_OVERFLOW(42211, 422)` 已登记到 `ErrorCode`；下游如需展示文案需同步。
- `AuditCoverageIT` 已登记 `KnowledgeController#configureRerank`。

## 6. 闸门转真过程中揪出的缺陷

1. **rerank 解绑无效（生产缺陷）**：`KnowledgeRepository.updateBaseRerank` 原用
   `bases.updateById(row)`，MyBatis-Plus 默认 NOT NULL 更新策略会静默跳过 null 字段，
   `configureRerank(kbId, null, null)` 清不掉 `rerank_binding_id`，导致「未绑定时跳过且不设阈值」
   规格永远无法达成。修复：改用 `lambdaUpdate().set(...)` 显式写 NULL，并带
   `workspace_id` 条件，避免 TenantLine 下的跨空间更新。闸门的「绑定→解绑」双向断言抓到了它。
2. **引用号断言的转义陷阱（测试侧）**：`tool_result.contentJson` 的 `output` 是转义后的
   JSON 字符串（`\"citationId\"`），按裸正则匹配不到。改为用 `ObjectMapper` 解析
   `contentJson.output` 数组后取 `citationId`，比正则更贴近真实契约。
3. **既有召回基线未退化**：C-16 `KnowledgeRecallBaselineIT` 在两路召回改造后仍为
   `A recallAt5=1.0 / mrr=1.0`、`B recallAt5=0.9167`，KNW-03 的 A>B 验收继续成立。
4. **新增写端点的审计覆盖**：`AuditCoverageIT` 登记
   `KnowledgeController#configureRerank`（与 C-21 同一纪律）。
5. **全量 verify 首轮暴露两个既有单测口径问题**：`KbToolProviderTest` 仍断言 3 个工具
   （KNW-14 后为 5）；`KnowledgeInMemorySupport` 未覆写新增的 `searchByKeyword`，父类实现
   触碰 null mapper → NPE。修复：更新工具数并补 `kb.read` / `kb.list` 调用断言；内存替身覆写
   `searchByKeyword` / `listBases` / `updateBaseRerank`，两路召回共用同一列投影；
   生产侧 `KnowledgeRepository.searchByKeyword` 对 `chunks==null` / 空 tokens 也防御返回空集。
6. **fresh-eyes 复核 B1（闸门 D 区验收恒真）**：仅断言「哈希非空 + 同一 Map 读两次相等」
   可被空注入蒙混。修复：`ContextBuilder` 增 `frozenTailText`，空文本哈希返回空串；
   闸门断言执行实例含真实注入段名 / 提示语 / `cit_` / 检索主题词、未执行实例为空，
   并用 `KnowledgeAutoInjectSegment.renderCalls()` 作为**外部可证伪观测**——换 query 重新
   `build` 后渲染次数不得增加。单测另补 D 区超预算与 `queryForTurn` steer 污染。
7. **fresh-eyes 复核 B2（rerank 吞治理异常）**：原 `catch (RuntimeException)` 会把配额 /
   预算 / 参数 / 鉴权错误一并降级成「检索成功」。修复：`ErrorCode#isGovernanceFailure()` 统一判定，
   rerank 白名单收窄为 `MODEL_UNAVAILABLE` / `MODEL_ERROR`；`DEPENDENCY` 被移除，因为
   `DefaultModelGateway#rerank` 的兜底 catch 会把任意未知异常包装成它。自动注入段与
   `ContextBuilder.safeRender` 也只降级依赖类失败。新增 `KnowledgeServiceRerankPolicyTest`
   覆盖 6 个治理/包装码冒泡 + 2 个模型故障码退回 RRF。
8. **全量 verify 第二轮暴露两个合并关卡问题**：`ContextBuilder` 三个方法带 `synchronized`
   违反 ArchUnit 冻结规则 `noSynchronizedInApplication`（ADR-016）；新 `@Audited` 动作
   `knowledge.base.rerank` 漏登记 `docs/contracts/audit/actions.yaml`（ADR-072 登记制）。
   修复：改用 `Collections.synchronizedMap(LinkedHashMap LRU)` + 同步块（进程内缓存互斥，
   不承担跨实例协调）；补登记动作目录。闸门单跑 `-Pgate` 只跑指定测试，抓不到这两项，
   全量 verify 才暴露——此纪律与 C-21 一致。
9. **独立复核其余阻塞/建议项处置**：全文路补 `embedding_vec IS NOT NULL` 排除父块
   （内存替身早已排除，生产 SQL 漏写会导致父块进 RRF 并生成重复引用）；
   `rerankThreshold` 拒 `NaN`/`Infinity`（否则区间校验与阈值比较同时失效）；
   `kb.read` 真读后补资源级鉴权（跨空间 + `guard.allows` + 文档级 ACL），堵住
   「任意 docId/chunkId 绕过检索直读全文」；`ILIKE`→`strpos` 后同步迁移/代码/文档口径，
   并删掉对 `strpos` 无效的 `pg_trgm` 索引声明。
10. **未收口、已登记为后续批次**：`BELOW_THRESHOLD` 在闸门里仍是「空命中时」的条件断言；
    rerank provider 少返回候选时的补齐口径；文档级 ACL 的 LIKE 通配符转义；
    多库阈值取首个绑定库；A/B/C 区每次 build 重新渲染（只有 D 区冻结）；
    `frozenTailHash` 实为 D 区尾部文本哈希，命名沿用「前缀哈希」措辞。
11. **第二轮独立复核（修复确认）**：B-1 / B-2 / B-4 与 rerank 直调的 B-5 已闭环，
    另两处未闭环已补：
    - `GET /api/knowledge/citations/{id}` 的 `resolveCitation` 与 `kb.*` 读取同口径鉴权
      （跨空间 + `guard.allows` + 文档级 ACL），并把资源级校验改为**不依赖 `KbBaseDO` 是否存在**，
      避免数据缺失时整段跳过（否则凭 `citationId` 仍可越权读正文）；

      自动注入段与 `ContextBuilder.safeRender` 据此重抛，堵住「未知异常被包装成
      `DEPENDENCY` 后降级为空注入」；`RATE_LIMITED` 补进治理码集合。
    - 全文路父块排除从 `embedding_vec IS NOT NULL` 改为 `chunk_type != 'PARENT'`，
      保住两路独立性；V227 尚未合并上线，修改迁移文件不会触发已执行环境的
      Flyway checksum 校验失败（若未来已上线再改，需走新迁移号）。
