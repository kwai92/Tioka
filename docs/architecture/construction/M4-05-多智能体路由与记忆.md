## 0. 共用安排

### 0.1 AgentSpec 段：M4 第 0 波一次加齐

M3 的 P3-00b 给 AgentSpec 加了 `output`、`charter`、`prompt`、`context`、`memory`、`execution` 六段。M4 还要三段：`guardrails`（GRD-01，W59）、`router`（RTE-01，W64）、`team`（MAS-04，W65），另有 `profile.type` 增加 `ROUTER`、`TEAM`。三个工作项分在两人、相隔 6 周，各自持 K9 会让 AgentSpec 被改三次。

## 3. RTE-03 受控交接、粘滞、入口、路由评测（1 人天，W65）

| chat-biz/memory | 后台抽取 | 消费 `turn_finished`；`purpose = memory`，系统 Prompt `sys.memory.extract`；输入只取用户本人消息与本轮最终回答（ADR-050 第 3.2 节第 1 条）；四种操作（`ADD`、`UPDATE`、`INVALIDATE`、`NOOP`），后台不删除；限流每 Turn 3 条、每用户每天 20 条；抽取前后经 `pii.detect` 的 `REDACT`（GRD-04 合入前用 DAT-02 正则）、`secret.detect` 命中不抽取；`SECRET` 标签 Turn 不抽取 |

| chat-biz/memory | 可移植与标签 | 第 2.3 节规则；标签高于当前 Turn 可用路由许可密级的条目不注入并记入清单 |
| chat-biz/memory | 保留与删除 | 休眠、失效后 180 天删除、用户删除后 30 天物理删除（`mem_event` 只留哈希）、删会话时询问、空间删除；定时任务数据库锁互斥 |

| agent-biz | `memory` 段 | 放开配置；ROUTER 与任务型 Agent 缺省 `NONE` |

### 9.2 M4 范围的收窄

MEM-02（空间记忆审核、置顶、`memory.search`、异常检测）在 M4 之后，所以 M4 内：

- 后台抽取**不产生 SPACE 候选**（抽取 Prompt 只要求 USER 条目），避免产生无人审核的 `PROPOSED` 堆积；
- 显式保存只支持 USER 作用域；
- 异常检测（含指令性表述的条目转本人确认）随 MEM-02，M4 内由 `secret.detect` 与输入限制兜底。

### 9.3 V220 的破坏性迁移

现有代码有 `chat_memory_item`（`ChatMemoryDO`、`ChatMemoryRepository`，带 `tenant_id`）。处理：

1. 在脱敏的现网副本上统计行数并演练；
2. 若有数据，迁为 `mem_item` 的 USER 作用域、类别 `CONTEXT`、状态 `DORMANT`、来源 `MANUAL`（不自动注入，用户在记忆管理页可恢复），写 `mem_event`；
3. 删除旧表与旧代码；PR 描述附演练结果。

备选：直接丢弃旧数据。旧数据没有类别与来源、可信度低，但用户可能依赖它；保守做法是休眠保留。
