## 1. 结论

1. **Foundation 是独立仓库**，与 Tioka 仓库并行开发。Tioka 侧只改 BAS-20、BAS-26 及相关前端挂接（BAS-FE-12）；其余 BAS 包全部在 Foundation 仓库。
2. **迁移**：Foundation 库自 V1 起；Tioka 侧 BAS-20/26 用 **V270 起**（F-00 第 5 节约定 1）。两边互不共用 Flyway 历史表。
3. **热点隔离**：Foundation 的 pom / 配置 / 路由不占用 Tioka 的 K1〜K11。Tioka 侧 BAS-20/26 持有 Tioka 的 K3（依赖切换）、K5（ArchUnit 规则迁移）、必要时 K7（管理页跳转）。
4. **按 F-00 第 3〜4 节三人分工拆约 35 个包**（交叠 3、后端约 22、前端约 10）。关键路径是权限链（BAS-04→05→06→07→08→20），零余量，主管优先保证该链。
5. **并发度**：Foundation 仓库每名后端仍最多 2 会话；与 Tioka 开着的 PR 合计建议 ≤ 12（其中 Tioka ≤ 4，仅 BAS-20/26 与联调）。

## 5. 合入顺序与跨人交接

严格遵守 F-00 第 4 节五处交接：

1. W80 BAS-05 不依赖组织的部分可先合；组织/岗位授权等 BAS-02。
2. W84 BAS-14 等 BAS-07 事件契约（先合契约小 PR）。
3. W84 BAS-20 前半可先行；换 PrincipalLoader 等 BAS-08。
4. W86 BAS-28 等 BAS-08、BAS-27（同人）。
5. W87 BAS-22 等 BAS-20。

GF 12 条用例转绿周次见 F-00 第 6.1 节，由对应包去掉 `@Disabled`。

## 6. 实现硬约束（摘自 F-00 第 5 节）

1. Foundation / Tioka 迁移号段分离。
2. BAS-26 后 Tioka ArchUnit 冻结库保持为空。
3. BAS-20 保留本地模式开关；两模式 G1 都要通过。
4. FND-09/10 的 Tioka 实现删除，不留两套。
5. BAS-10 只汇聚不改审计格式（F46）。
6. 离线镜像清单登记 Foundation 与 Keycloak（F43）。

## 7. Cursor 提示词

### 7.1 主管指令

```text
你是 Tioka / Foundation F 阶段主管。排期权威 F-00；包表 F-01；设计 S15 与 ADR-051〜054。
先确认仓库：foundation 包不得改 Tioka 业务代码；tioka 包（BAS-20/26、BAS-FE-12）不得改 Foundation 中台实现。
优先保障权限链；P2（BAS-17/18/13）按 F-00 第 7 节让路。
每天状态表 → 派活 → 冲突预检 → worktree → 专家模板 → 验收；不合并。
R6/R7 未满足时 BAS-28 / BAS-12 标「等前置」。
```

### 7.2 专家指令模板

```text
你是专家 Agent，只完成【包号 BAS-ID】，仓库【foundation|tioka】。
1. 在对应仓库 rebase 最新 main；读该仓库的规则与 S15 相关节。
2. 只改本包可改范围；迁移号：foundation 用 V1 段、tioka 用 V270+；禁止 tenant_id。
3. 跨仓库依赖只经已发布的 starter / OpenAPI / 事件契约，不直接依赖对方 -biz。
4. 先写验收 / 闸门用例至红再实现；提交前跑本包测试。
5. PR 标题 [BAS-ID]；描述五项 + 仓库名 + 实际人天；只开 PR 不合并。
```
