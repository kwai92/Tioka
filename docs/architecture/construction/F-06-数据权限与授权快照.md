本文覆盖 Foundation 权限中台的**数据权限定义**（BAS-06）与**授权快照与变更事件**（BAS-07）。两者是同一链路的上下游：BAS-05 先算出「有效角色」，BAS-06 把角色与人员的**数据范围**（部门五档 + 自定义维度）定义清楚，BAS-07 把「有效角色 + 权限码 + 菜单 + 数据范围 + 人员属性」汇总成**一个人员在一个应用里一份快照**并广播变更。数据范围的**执行**在应用内，由 BAS-08 的 starter 承载；本文只定义契约与产物形态。

## BAS-06 数据权限（P0，6 人天）

### 目标与边界

- 用**部门五档**表达组织树能覆盖的范围（沿用若依）。
- 用**自定义数据维度**表达组织树表达不了的范围（如合同场景的区域 `region`、门店 `store`）。
- 支持两种授予路径：**角色**（随角色生效）与**人员**（「某人额外负责华东区」这类不走角色的授予）。
- 只在 Foundation 定义与计算，**不执行**；执行见本文第 3 节（starter）与 S15 第 11.4 节。

### 数据模型

四张建议表加一张辅助表。部门范围是角色级的单值（五档之一），维度取值集合是角色级的**多值**，因此按「头 + 行」拆成 `fdn_role_data_scope`（头）与 `fdn_role_dimension_value`（行）。

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_data_dimension` | 一个数据维度 | 应用（可空 = 全局）、编码、名称、值来源、是否层级 |
| `fdn_dimension_value` | 维度下的一个值 | 维度、值编码、名称、上级 |
| `fdn_role_data_scope` | 一个角色的部门范围 | 角色、部门档位、自定义部门单元 |
| `fdn_role_dimension_value` | 角色在某维度的一个取值 | 角色、维度、值编码、是否「全部」 |
| `fdn_person_dimension` | 人员在某维度的一个取值 | 人员、维度、值编码、是否「全部」、来源 |

字段细则：

- **数据维度** `fdn_data_dimension`：`app_code` 可空表示**全局维度**；`code` 形如 `region`、`store`；`value_source` 取 `DICT`（字典，取自 BAS-09）/`ORG_TREE`（组织树，直接引用 BAS-02 的组织单元）/`APP_REPORTED`（应用上报的值列表）；`hierarchical` 表示是否层级。
- **维度值** `fdn_dimension_value`：层级维度用 `parent_id` 指向上级值；应用上报的值列表**经接口增量维护**（见「接口」）。
- **角色数据范围** `fdn_role_data_scope`：`dept_scope` 取 `ALL`（全部）/`CUSTOM`（自定义部门）/`DEPT`（本部门）/`DEPT_AND_SUB`（本部门及以下）/`SELF`（本人）；`CUSTOM` 时 `dept_units` 存组织单元 id 数组。一个角色可**同时**限定部门范围与多个维度。
- **角色维度取值** `fdn_role_dimension_value`：`all_values = true` 表示该维度「全部」，此时 `value_code` 为空。
- **人员维度授予** `fdn_person_dimension`：`source` 取 `MANUAL`/`RULE`/`SYNC`；`RULE` 与 `SYNC` 产生的授予不覆盖 `MANUAL`（延续 ADR-026）。

### 迁移 SQL 示意

```sql
-- BAS-06 数据权限（Foundation 库，Flyway 自 V1 起；示意 V12〜V14）

-- 数据维度：app_code 为空表示全局维度
CREATE TABLE fdn_data_dimension (
    id            VARCHAR(32)  PRIMARY KEY,              -- ULID，前缀 fdd_
    app_code      VARCHAR(64),                           -- 空 = 全局维度
    code          VARCHAR(64)  NOT NULL,                 -- 如 region、store
    name          VARCHAR(255) NOT NULL,
    value_source  VARCHAR(16)  NOT NULL,                 -- DICT / ORG_TREE / APP_REPORTED
    hierarchical  BOOLEAN      NOT NULL DEFAULT FALSE,
    create_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    create_by     VARCHAR(64)  NOT NULL DEFAULT 'system',
    update_by     VARCHAR(64)  NOT NULL DEFAULT 'system'
);
CREATE UNIQUE INDEX uk_dimension_app_code ON fdn_data_dimension (COALESCE(app_code, ''), code);

-- 维度值：应用上报的值列表经接口增量维护
CREATE TABLE fdn_dimension_value (
    id            VARCHAR(32)  PRIMARY KEY,              -- ULID，前缀 fdv_
    dimension_id  VARCHAR(32)  NOT NULL REFERENCES fdn_data_dimension (id),
    code          VARCHAR(64)  NOT NULL,
    name          VARCHAR(255) NOT NULL,
    parent_id     VARCHAR(32),                           -- 层级维度的上级值
    create_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (dimension_id, code)
);

-- 角色数据范围：一行一个角色，含部门五档
CREATE TABLE fdn_role_data_scope (
    id            VARCHAR(32)  PRIMARY KEY,              -- ULID，前缀 frs_
    role_code     VARCHAR(64)  NOT NULL,
    dept_scope    VARCHAR(16)  NOT NULL,                 -- ALL/CUSTOM/DEPT/DEPT_AND_SUB/SELF
    dept_units    JSONB        NOT NULL DEFAULT '[]',    -- dept_scope=CUSTOM 时的组织单元 id 数组
    create_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (role_code)
);

-- 角色维度取值：all_values=true 表示该维度「全部」（value_code 置空）
CREATE TABLE fdn_role_dimension_value (
    id            VARCHAR(32)  PRIMARY KEY,              -- ULID，前缀 frv_
    role_code     VARCHAR(64)  NOT NULL,
    dimension_id  VARCHAR(32)  NOT NULL REFERENCES fdn_data_dimension (id),
    value_code    VARCHAR(64),
    all_values    BOOLEAN      NOT NULL DEFAULT FALSE,
    create_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_role_dim ON fdn_role_dimension_value (role_code, dimension_id, COALESCE(value_code, ''));

-- 人员维度授予：某人额外负责华东区这类不走角色的授予
CREATE TABLE fdn_person_dimension (
    id            VARCHAR(32)  PRIMARY KEY,              -- ULID，前缀 fpd_
    person_id     VARCHAR(32)  NOT NULL,
    dimension_id  VARCHAR(32)  NOT NULL REFERENCES fdn_data_dimension (id),
    value_code    VARCHAR(64),
    all_values    BOOLEAN      NOT NULL DEFAULT FALSE,
    source        VARCHAR(16)  NOT NULL DEFAULT 'MANUAL', -- MANUAL / RULE / SYNC
    create_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_person_dim ON fdn_person_dimension (person_id, dimension_id, COALESCE(value_code, ''));
```

### 部门五档与多角色合并规则

**部门五档**（`dept_scope`）：

| 档位 | 编码 | 含义 | 展开 |
| --- | --- | --- | --- |
| 全部 | `ALL` | 不限部门 | 部门集合 = 「全部」 |
| 自定义部门 | `CUSTOM` | 指定若干组织单元 | 展开为 `dept_units` 给出的组织单元编码集合 |
| 本部门 | `DEPT` | 人员主组织单元 | 展开为 1 个编码 |
| 本部门及以下 | `DEPT_AND_SUB` | 主组织单元及其下级 | 展开为主组织单元子树编码集合 |
| 本人 | `SELF` | 仅本人 | 部门集合 = 空（按 `owner/经办人` 判本人） |

**合并规则**（写进 BAS-07 的快照计算）：

1. **多个角色之间取并集**：一个人员经多个角色获得的范围，按「任一角色成立即可见」（OR）合并。部门范围合并为编码集合的并集；每个维度合并为取值集合的并集。
2. **同一角色内，部门范围与各维度之间取交集**：一个角色内同时限定部门范围与维度时，是「部门 ∈ 范围 **AND** dimension ∈ 取值」（AND）。不同维度之间同为 AND。
3. 快照对外给出的是**去重后的结果**：部门范围给「展开后的组织单元编码集合」或「全部」；每个维度给「最终取值集合」或「全部」。应用按维度、部门分别过滤时，等价于「跨角色 OR」的近似（同角色内的 AND 由角色内条件块表达）。

**示例**——区域负责人：

- 角色 `region_manager`：部门范围 `CUSTOM`（`dept_units = [HD_SALES]`），维度 `region ∈ {华东}`。
- 人员「张一」额外授予：`region ∈ {华东, 华南}`（`source = MANUAL`）。
- 结果：部门范围 = `HD_SALES` 子树相关编码；`region` 取值集合 = `{华东, 华南}`。

基础路径 `/api/fdn`；所有写接口要求 `Idempotency-Key`（S15 第 14.1 节），随 OpenAPI 发布。

| 方法与路径 | 权限 | 说明 |

## BAS-07 授权快照与变更事件（P0，3 人天）

### 粒度与内容

**一个人员在一个应用里一份快照**（S15 第 11.3 节）。内容：

| 字段 | 说明 |
| --- | --- |
| 有效角色 | 经 BAS-05 计算（直接/组织单元/岗位授予 ∪，去过期与互斥） |
| 权限码集合 | 有效角色展开后的 `资源:动作` 集合 |
| 可见菜单树 | 按权限过滤后的菜单（目录/菜单/按钮） |
| 部门范围 | 展开后的组织单元编码集合，或「全部」（来自 BAS-06） |
| 各维度取值集合 | 每个自定义维度的最终取值集合，或「全部」（来自 BAS-06） |
| 人员属性 | 主组织单元、岗位、职级（同时作为 GOV-07 Cedar、ADR-040 CEL 的属性来源） |
| 快照版本号 | 单调递增的整数 |

快照 JSON 形态（示意）：

```json
{
  "personId": "per_01J...",
  "appCode": "tioka",
  "version": 43,
  "roles": ["region_manager", "auditor"],
  "permissions": ["contract:read", "audit:read"],
  "menus": [{ "code": "contract", "type": "MENU", "children": [] }],
  "deptScope": { "all": false, "units": ["D01", "D0101"] },
  "dimensions": {
    "region": { "all": false, "values": ["HD", "HN"] },
    "store":  { "all": true,  "values": [] }
  },
  "person": { "primaryOrgUnit": "D0101", "positions": ["sales"], "grade": "P6" },
  "computedAt": "2026-11-13T03:00:00Z"
}
```

### 快照计算

- **增量重算**：下列任一变化时，重算**受影响人员**（只重算这些人）。
  - 授权变化（BAS-05）：授予对象为人员 → 该人员；为组织单元 → 该单元（及下级）下所有任职人员；为岗位 → 该岗位所有任职人员。
  - 任职变化（BAS-02）：该人员。
  - 组织树变化（BAS-02）：该单元（及下级）下的任职人员。
  - 角色定义变化（BAS-05）：该角色授予对象覆盖的全部人员。
  - 清单变化（BAS-05）：该应用的全部已登记人员。
- **全量兜底**：每日对账任务全量重算所有（人员 × 应用），修复事件丢失或漏算。
- **版本递增**：重算后 `version = version + 1`（按 `(person_id, app_code)` 单调），写入 `fdn_authz_snapshot` 并发事件。

### 获取

- 应用以**服务账号**调用快照接口取快照。
- starter 在本地 Redis 缓存，**缓存键含版本号**（如 `fdn:snap:{appCode}:{personId}:{version}`），避免版本漂移。
- Foundation **不在请求热路径**：应用靠 starter 的本地缓存运行。

### 失效与事件

- 快照变化时 Foundation 发 `fdn.authz.changed`（含**人员**、**应用**与**新版本号**）。
- starter 收到后删除本地缓存；下一次请求按新版本号重新拉取。
- **事件丢失兜底**：缓存 TTL 默认 **5 分钟**，TTL 到期即强制回源。

### 故障降级（拒绝）

- Foundation 不可用：starter 使用**未过期**缓存。
- 缓存**已过期且无法获取**：**拒绝**（返回 403），**不放行**——延续 S9 第 11 节「降级拒绝」。

### `fdn.authz.changed` 事件

- 经 **outbox → RocketMQ 主题 `fdn-events`**（Foundation 自己的 outbox，示意表 `fdn_outbox`，与 Tioka 的 `sys_outbox` 相互独立）；可同时投 Webhook。
- 事件体**只带 ID、版本与变化类型**，不带敏感字段（订阅方需要详情时回查接口）。
- 要求：授权变更后 **5 秒内**发出；`snapshotVersion` **单调递增**（同一人员与应用不回退）。

```json
{
  "eventId": "evt_01J...",
  "type": "fdn.authz.changed",
  "personId": "per_01J...",
  "appCode": "tioka",
  "snapshotVersion": 43,
  "changeType": "AUTHZ_RECOMPUTED",
  "occurredAt": "2026-11-13T03:00:01Z"
}
```

### 数据模型（快照版本）

```sql
-- BAS-07 授权快照（示意 V15〜V16）
CREATE TABLE fdn_authz_snapshot (
    id           VARCHAR(32)  PRIMARY KEY,               -- ULID，前缀 fsn_
    person_id    VARCHAR(32)  NOT NULL,
    app_code     VARCHAR(64)  NOT NULL,
    version      BIGINT       NOT NULL,
    body         JSONB,                                  -- 快照内容；为空时按需重算回填
    computed_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
    create_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (person_id, app_code)
);
CREATE INDEX idx_snapshot_app_changed ON fdn_authz_snapshot (app_code, update_at);
```

### 接口

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/fdn/apps/{appCode}/persons/{personId}/snapshot` | 应用服务账号 | 取单人快照；`If-None-Match`/版本号命中则不重算 |
| `POST /api/fdn/apps/{appCode}/snapshots:batch` | 应用服务账号 | 批量取（`personIds[]`），供启动预热或对账 |

| `GET /api/fdn/apps/{appCode}/persons/{personId}/snapshot/version` | 应用服务账号 | 只取版本号，供 starter 判缓存是否过期 |

## 3. 数据权限执行（starter，契约由本文定义、实现归 BAS-08）

执行**在应用里**，starter 提供两种用法（S15 第 11.4 节）；BAS-08 实现，本文锁定契约。

### 用法一：数据范围注解 + 持久层条件生成

应用在查询方法上声明「本查询的部门字段、维度字段对应哪一列」，starter 按当前快照生成过滤条件拼进 MyBatis-Plus 查询。

```java
// 注解：声明本查询涉及的部门和维度列（SQL 片段）
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface DataScope {
    /** 部门/组织单元列，如 "c.dept_code"；留空表示本查询不按部门过滤 */
    String deptColumn() default "";

    /** 维度编码，与 dimensionColumns 一一对应，如 {"region", "store"} */
    String[] dimensionCodes() default {};

    /** 维度取值列，如 {"c.region_code", "c.store_code"} */
    String[] dimensionColumns() default {};
}

// 条件生成：由 starter 按快照拼出可直接塞进 Wrapper 的条件
public interface DataScopeFilter {
    /** 生成过滤条件；all=true 表示部门与各维度均「全部」，调用方可跳过拼接 */
    ScopeCondition build(DataScope spec);

    /** 当前请求是否对全部数据可见（用于短路） */
    boolean isAll(DataScope spec);
}

public record ScopeCondition(boolean all, String sql, Map<String, Object> params) {}
```

生成的 SQL 片段（示意）：

```sql
-- deptColumn=c.dept_code，dimensionCodes={"region"}，dimensionColumns={"c.region_code"}
(
  (:deptAll = TRUE OR c.dept_code IN (:deptUnits))
  AND
  (:regionAll = TRUE OR c.region_code IN (:regionValues))
)
```

### 用法二：直接读取快照取值集合

适合复杂业务规则（跨表、编号规则判断等）：应用自己读快照并判断。

```java
AuthzSnapshot snapshot = CurrentUser.snapshot();        // starter 从缓存/接口取，含版本号

Long version   = snapshot.version();
boolean deptAll = snapshot.deptScope().all();            // 部门范围是否「全部」
Set<String> deptUnits = snapshot.deptScope().units();    // 展开后的组织单元编码集合

boolean regionAll     = snapshot.dimension("region").all();
Set<String> regions   = snapshot.dimension("region").values();  // 最终取值集合
```

### 与既有设计的关系（并存、互不替代）

- **与 Tioka FND-03 空间行级过滤并存**：FND-03 在 Tioka 持久层按 `workspace_id` + `owner_id` 过滤，SqlParser/拦截器不变。本项的数据范围条件与之**同时生效**（AND），互不替代。
- **与 GOV-07（Cedar）/ ADR-040（CEL）**：快照的人员属性（组织单元、岗位、职级）与维度取值作为 principal/主体属性**多一个来源**，执行位置不变；M3-03 的 `acl_principals` 直接写 Foundation 的维度值编码，口径一致。
- **硬约束**：执行在应用内、读本地缓存，Foundation 不进入请求热路径。

## 硬约束

- **禁止 `tenant_id` / `sys_tenant`**（ADR-029 第 60 条）：Foundation 按单企业部署，隔离靠应用编码与组织/维度范围，不引入租户列或租户拦截器。
- **ULID 主键**：26 字符，带前缀（`fdd_`、`fdv_`、`frs_`、`frv_`、`fpd_`、`fsn_`），列宽 `VARCHAR(32)`。
- **时间列 `TIMESTAMPTZ`**；DO 字段 `LocalDateTime`（UTC），API 用 `Instant` 输出 ISO-8601。
- **不把 Foundation 放进请求热路径**：应用靠 starter 快照缓存运行，Foundation 短时不可用不影响已登录用户。
- 所有写接口要求 `Idempotency-Key`；接口经 OpenAPI 发布，应用侧用契约测试校验。
- 事件体不带敏感字段，只带 ID、版本与变化类型。
