# FE-00 — 前端信息架构与页面规格（M3、M4）

- 状态：**设计权威（前端页面）**（2026-11-07，ADR-029 第 78 条）。排期与人天仍以 [M3-00](M3-00-M3实施计划.md) 第 5.2 节、[M4-00](M4-00-M4实施计划.md) 第 5.2 节为准；任务包见 [M3-07](M3-07-并行开发任务包.md) 第 5.6 节
- 上位文档：[ADR-028](../adr/ADR-028-hci-frontend.md)（前端架构、流协议、共享组件）、[S7](../systems/S7-HCI人机交互.md)（能力地图）、各 ADR 的界面小节（ADR-032、034、035、038、041〜044、046、048〜050、056、057、060〜071、075）、M3-02〜M3-06 的前端小节、[S15](../systems/S15-Foundation基础平台系统.md) 第 14、18.2 节（F 阶段前端）
- 用途：回答「页面长什么样、放在哪、谁能看、有哪些状态」。ADR 定义的是后端字段与规则；本文把它们落成页面：路由、区块、字段、操作、状态、权限与验收
- 写法：只用文字和表格，不画像素级视觉稿；需要视觉稿的页面在第 9 节列出，由负责人确认后再做

## 1. 结论

1. **前端只有架构（ADR-028）和工作项清单，没有页面设计。** 本文补四样东西：路由总图（第 3 节）、通用页面模式与状态（第 4、5 节）、Generative UI 组件与视觉规范（第 6 节）、逐页规格（M3 第 7、8 节，M4 第 10 节）。F 阶段的页面由 S15 第 14、18 节与 BAS-FE 包覆盖，本文只定接入位置。
2. **路由从平铺改为四个分区**：`/chat`（对话）、`/studio`（构建）、`/console`（运行与观测）、`/admin`（管理）。这是 ADR-028 原定的结构，M1、M2 为了快先做成了平铺。M3 页面数量翻倍，不分区导航会失控。改动由 M3-07 的前端骨架包 P3-00c 一次完成，旧路径全部重定向。
3. **大部分页面用 5 种通用模式拼出来**（列表、详情、草稿与发布、Schema 生成表单、报告），新页面先选模式再填字段。这样 1 名前端加 Cursor 能撑住 M3 约 25 个、M4 约 31 个页面。
4. **前端产能够用，缺的是评审与确认的节奏。** 按人天，M3 负载约 54%，M4 约 78%。风险在两处：业务系统 5 个页面是法务每天用的，要负责人确认（第 9 节）；前端同时最多 2 个 Cursor 会话，瓶颈在评审。做法是每个页面先合「规格 + fixtures + 组件测试」，再接真接口。
5. **一处现存不一致**：前端与后端的管理员权限码仍是 `tenant:admin`（`Permissions.TENANT_ADMIN`），而第 60 条已取消租户概念、角色已改名 `system_admin`。本文新页面统一用 `system:admin` 作为平台管理员权限码的名字，**改名本身是后端的事**，记为 M3-07 第 0 波后的一个独立小包（后端改常量与种子数据，前端同 PR 改 `adminNav.ts` 与路由 `meta`），合入前新页面先同时认两个码。

## 4. 通用页面模式

新页面先从下表选一种模式；同一模式的页面用同一个布局组件，只填字段。

| 模式 | 布局 | 必备元素 | 用在 |
| --- | --- | --- | --- |
| **A 列表** | 顶部筛选栏 + 表格 + 右上角主操作；行点击进详情或开抽屉 | 关键字搜索、按状态与时间筛选、分页（游标接口用「加载更多」）、空态与无结果态区分、列可配置（记在本地） | 凭证、插件、数据集、知识库文档、Run、待标注、分诊、资产目录 |
| **B 详情** | 头部（名称、状态徽标、主操作）+ 标签页；右侧可放「引用方」或「时间线入口」 | 状态徽标、最后修改人与时间、「查看完整时间线」入口（FE-46 起）、复制 ID | Agent 档案页、知识库详情、Run 详情 |
| **C 草稿与发布** | 编辑区 + 顶栏「保存草稿 / 校验 / 发布」+ 右侧版本面板（FE-07） | 保存状态与 `revision`、校验结果计数、发布对话框（差异、校验、影响范围、说明）、409 冲突处理（服务器版本与本地版本语义差异，选择覆盖或合并）、「某人正在编辑」提示 | 模型中枢各对象、Prompt、Flow、路由计划、护栏策略、解析方案、要点库 |
| **D Schema 生成表单** | 按后端给的 JSON Schema 生成表单 | 字段说明、必填、枚举、密钥字段只写（显示掩码与指纹，不回显）、连通性测试按钮 | 连接器与数据源配置、外部知识库、解析引擎实例、MCP 客户端、节点检查器 |
| **E 报告** | 摘要卡片行 + 图表 + 明细表；右上角导出 | 数据口径说明（悬停）、时间范围、导出（CSV / Excel）、「数字可点到明细」 | 统计、评测结果、上岗报告、经营看板、双跑报告、护栏与解析指标 |

## 5. 状态与反馈规范

所有页面都要处理下表的状态；组件测试按页面逐个覆盖。P3-00c 在 `components/state/` 提供统一组件。

| 状态 | 表现 | 触发 |
| --- | --- | --- |
| 加载 | 骨架屏（表格、卡片），超过 10 秒显示「仍在加载」与重试 | 首次请求 |
| 空 | 插图 + 一句话说明 + 主操作（如「新建知识库」）；无权限新建时不显示主操作 | 列表为空 |
| 无结果 | 「没有符合条件的结果」+ 清除筛选 | 筛选后为空 |
| 错误 | 错误码与人能读的一句话 + 重试 + 「复制请求号」（`X-Tioka-Request-Id`） | 5xx、网络错误 |
| 无权限 | 整页 403 或区块内「你没有查看此内容的权限」；不显示被隐藏的数据数量 | 403；按钮级按权限码隐藏 |
| 版本过期 | 顶部黄条「此对象已被他人更新」+ 查看差异 + 重新加载 | 409 或心跳发现新 `revision` |
| 长任务 | 进度或「后台进行中，已等待 N 分钟」+ 离开页面不中断 + 完成后站内通知 | 入库、批次评测、解析、导出 |
| 数据标签 | 标签徽标（PUBLIC / INTERNAL / CONFIDENTIAL / SECRET），CONFIDENTIAL 以上的正文按 `trajectory:read:content` 决定是否显示 | 对话、轨迹、时间线、知识文档 |
| AI 生成 | 平台内 Chat 与轨迹中 AI 产出固定标出「AI 生成」（ADR-067） | 助手消息、`data` item |

文案：统一走 i18n 资源；错误信息不直接展示后端异常栈；按钮动词在前（「发布版本」而不是「版本发布」）。

## 6. Generative UI 组件与视觉规范

| 组件 | 渲染什么 | 关键交互 | 飞书对应 | 阶段 |

### 6.2 视觉规范

| 项 | 规定 |
| --- | --- |
| 组件库与主题 | Element Plus；颜色、间距、圆角只用 Element Plus CSS 变量与本文的语义令牌，不写死色值。`tioka-ui` 目前固定深色（`main.ts` 给根元素加 `dark`），令牌必须在深浅两套下都可读；浅色切换放 M4 之后。业务系统缺省浅色 |
| 语义令牌 | 状态色：成功、警告、危险、信息、中性五种，映射到 Element Plus 的 success / warning / danger / primary / info；业务语义一律映射到这五种：草稿 = 中性、已发布 = 成功、已弃用 = 中性虚线、失败 = 危险、待复核 = 警告；风险结论「必备不满足」= 危险、「不满足」= 危险浅、「缺失」与「待人工」= 警告、「满足」= 成功、「不适用」= 中性 |
| 标签色 | PUBLIC 中性、INTERNAL 信息、CONFIDENTIAL 警告、SECRET 危险；徽标同时带文字，不只靠颜色 |
| 字体与密度 | 系统字体栈；正文 14px，表格行高紧凑；代码与 JSON 用等宽字体 |
| 图表 | ECharts（与 Element Plus 无冲突，按路由懒加载）；同一页图表颜色取自语义令牌；每张图有数据口径说明 |
| 可访问性 | 键盘可操作；表单与审批达到 WCAG AA 对比度（ADR-028）；状态不只用颜色表达 |
| 性能 | 首屏 JS ≤ 300KB（gzip），Studio、Flow 画布、文档查看器、图表按路由懒加载（ADR-028） |

## 7. M3 页面规格（Tioka 工作台）

每页写：路径、模式、区块与字段、操作、状态与边界、验收。字段名以对应 ADR 与施工设计为准，这里只写页面上要出现哪些。

### 7.1 Flow（FE-12、FE-12b、FE-13a/b、FE-14a/b）

- **路径**：`/studio/flows/{id}`（画布）、`/console/flows/runs`（Run 列表与统计）。模式：C（草稿与发布）+ 画布。
- **区块**：照 ADR-043 第 12 节：顶栏（保存状态与 `revision`、校验结果数、试运行、版本、发布）、左侧节点面板（按类别分组、可搜索、来源标记，弃用节点不显示）、画布（连线时检查端口类型，节点角标显示错误、固定输出、断点、运行状态）、右侧检查器（Schema 生成表单，表达式编辑器带上游输出补全与类型提示）、底部面板（试运行输入、事件流、节点数据、变更单、HumanCard 作答）、版本面板（FE-07）、发布面板（形态、名称与说明、可覆盖参数、同步超时、速率限制、破坏性变更提示）。
- **调试（FE-13a）**：草稿试运行、单节点运行、固定输出；写工具只显示变更单，不提交。**FE-13b**：从此节点重跑、断点、生产 Run 回放。
- **Run（FE-14a/b）**：模式 A + E；列表列为 Run ID、Flow 与版本、状态、开始时间、耗时、成本；详情为节点时间线与每个节点的输入输出；统计页复用 FE-09 的图表组件。
- **状态与边界**：409 冲突按第 4 节 C；Flow 结构化节点未连 `failed` 端口时发布按钮置灰并提示（SCH-09）；模板库四个模板（ADR-043 第 12 节）。
- **验收**：端口类型不符时连线被拒；固定输出后试运行不调用该节点；发布对话框显示破坏性变更。

### 7.2 模型中枢（FE-07、FE-08、FE-11、FE-24、FE-09）

- **路径**：`/admin/models/{providers|models|aliases|routing|credentials|quota|changes}`；状态与统计在 `/console/models`。
- **FE-07 通用版本组件**（所有模式 C 页面共用）：版本历史（标当前版本）、按 Schema 显示字段名的差异、发布对话框（差异、校验结果、影响范围、发布说明）、回滚对话框、引用方面板、变更记录时间线（版本动作与即时改动混排，可按对象类型与操作人筛选）。
- **FE-08**：供应商、模型、别名、配额与预算四个子页，均为模式 C；别名页显示每个别名当前指向与系统别名标记；配额页分供应商级与模型级。
- **FE-11**：凭证列表（状态、掩码、指纹、角色、到期时间、用量）、凭证操作（只写输入框录入或替换、连通性测试、轮换、停用、紧急吊销）、「即将到期」清单、供应商详细配置（模式 D）、模型发现向导、模型参数编辑（默认值、约束、锁定、扩展参数白名单提示、价格与阶梯价）；Agent 编辑器内的参数覆盖面板只列允许覆盖的参数并显示取值范围。
- **FE-24**：路由计划编辑（模式选择、组与候选、类别映射、决策器与兜底组）；会话路由时间线（在轨迹视图内展示每次选模的理由）。
- **FE-09**：健康网格（供应商 × 模型）、迷你趋势、最近错误、告警列表；统计为分组表、趋势图、版本对比（模式 E）。
- **验收**：密钥只写不读（刷新页面后看不到原值）；草稿与发布分开；吊销需二次确认并写审计。

### 7.3 Prompt、MCP（FE-10、FE-25）

- **FE-10** `/studio/prompts`：模式 C。分段编辑（系统、示例、尾部）、变量定义表单、渲染预览（填变量看结果）、试运行（选模型别名）、版本与引用方；Agent 编辑器里加模板选择器（选模板与钉版本）。
- **FE-25** `/studio/mcp`：MCP 服务端的 OAuth 客户端登记（模式 D，显示回调地址与授权提示）；MCP Server 登记时选传输方式（stdio / Streamable HTTP）。

### 7.4 岗位档案页（TRU-01、FE-22）

- **路径**：`/studio/agents/{id}/profile`；模式 B，标签页：身份、授权、自治与撤销、（M4）上线阶段、（M4）表现。
- **身份**：岗位、部门、负责人、名义、状态（ACTIVE / SUSPENDED / HANDOVER）、一句话职责。
- **授权**：动作类别表（工具、额度、范围、四眼、等级上限、当前等级），每行显示「距下一级还差什么」（ADR-034）；命中的策略 `@id` 可点开看「这次为什么被拦」。
- **自治与撤销（FE-22）**：当前等级与升降记录；负责人手动调整等级（不超过上限，需填原因）；降级通知在站内消息中可见。对话页与轨迹视图的「撤销本次」按钮：确认弹窗列出将撤销的动作；结果区显示已撤销、无法撤销清单（转人工）、补偿失败提示。
- **验收**：撤销后按钮消失，变更单徽标为 COMPENSATED；无负责人权限时等级调整按钮不显示。

### 7.5 数据集与去向（FE-21）

- `/admin/data/datasets`：模式 A + C；登记、列密级与掩码、策略编辑（CEL 输入带语法校验，错误定位到行列）、DRYRUN 差异查看（同一查询在 DRYRUN 与 ENFORCE 下的结果差）。
- `/admin/data/sinks`：按去向（模型、渠道、外部知识库、业务系统）配置最高标签与超限处理。
- 对话与轨迹：thread 标题旁 `LabelBadge`；被拒的去向在轨迹中显示原因。

### 7.6 本体确认组件（ONT-08）

- 以 Web Component `@tioka/ontology-confirm` 发布，供业务系统嵌入；属性与数据流照 M3-03 第 13 节。
- **布局**：左侧取值列表、右侧原文面板（M4 换成 `DocViewer`）。
- **默认只列需要人看的取值**：与上一版的差异、空白、待复核、低置信度（< 0.8）、被必备要点依赖的取值；其余折叠为「其余 N 项」。每个取值旁显示原文定位（页、条款、高亮引文），点击滚动原文面板。
- **操作**：确认全部、逐项更正（输入框按 Schema 类型）、标记「原文有误」。确认与更正提交给业务系统后端。
- **验收**：五类筛选各有单测；组件不持有 Tioka 令牌。

### 7.7 知识库（FE-32、FE-33）

- `/studio/knowledge/{kbId}`，模式 B，标签页：文档、切块与解析质量、使用模式、外部知识库、（M4）命中测试与检索轨迹、（M4）数据源。
- **文档**：模式 A；列为名称、版本、入库阶段（解析、切块、向量化、索引）、状态、失败原因、更新时间；失败行可重试。
- **切块与解析质量**：页与块对照预览；低置信与表格块高亮；父子块关系。
- **使用模式**：`AUTO` / `TOOL` / `BOTH` 单选，自动注入预算滑块（ADR-056）。
- **外部知识库（FE-33）**：模式 D 生成表单；选择外部知识库、健康状态、权限方式标注（用户身份 / 应用身份）。

### 7.8 轨迹与运行（FE-23、FE-09 的模型部分）

- 轨迹视图增加：`ChildThreadItem`（展开子 thread、委派链与授予 ID、被拒原因）。渲染快照测试覆盖委派成功、被拒、回收三种。

### 7.9 评测与反馈（FE-26）

- 消息气泡的点赞点踩与意见（写 `eval_feedback`）。
- `/console/eval/datasets`：数据集与用例（模式 A + B）；`/console/eval/runs`：批次评测结果（模式 E，按评估器分列、失败用例可点到轨迹）；知识库召回率报告（Recall@5、MRR，与 CI 基线对比）。

### 7.10 时间线（FE-46）

- `/console/timeline`：入口支持输入 `request_id`、对方单号（经 ADR-074 反查）、trace ID 或主体（如合同号）。
- **布局**：纵向时间线，按类别着色（INBOUND、RUN、MODEL、TOOL、DECISION、APPROVAL、CHANGE、OUTBOUND、NOTIFY、FEEDBACK、CONFIG、SECURITY），每轮审查分组；配置变更作为灰色背景条目插入。条目可展开到轨迹视图、审计详情、外部交互详情、Jaeger。
- 现有入口加「查看完整时间线」：轨迹视图、审批详情、Run 详情、审计记录。
- **验收**：一份合同从推送到通知的全过程在一条时间线；无 `trajectory:read:content` 时 CONFIDENTIAL 条目只显示标题。

## 8. M3 页面规格（合同业务系统）

业务系统是法务每天用的系统，五个页面在开工前请负责人看一遍规格（第 9 节）。角色：`legal`、`legal_lead`、`ops`（M3-04 第 2 节）。按区域授权，拿到别人的深链也看不到不该看的合同。

### 8.1 工作台与深链（BIZ-08）

- **路径**：`/`（工作台）、`/review/{reviewRunId}#finding={findingId}`（深链）。
- **工作台**三个列表：我经办的合同、待确认模型、待处置结论；每条显示合同号、门店、种类、阶段、最近一轮审查状态与时间。「已签署但模型未确认」的合同置顶并标警告。
- **深链**：不带令牌；未登录走 Keycloak 后回到原地址。

### 8.2 合同与提交、模型确认（BIZ-02、BIZ-03）

- **提交**（`ops`、`legal`）：上传文件（Word、PDF、图片，多文件排序）、填门店与合同种类、指定经办法务、关联前序合同；「提交审查」。
- **模型确认**：嵌入 `@tioka/ontology-confirm`；顶部显示模型版本与状态（DRAFT_RECEIVED / CONFIRMED / SUPERSEDED）；确认后生成版本号。确认不阻塞审查，签署后必须确认。

### 8.3 要点库（BIZ-04，`legal_lead`）

- 模式 C：要点按版本编辑（编码、主题、模式 D / H / J、必备、适用条件、前置、检查表达式、空白处理、判断要点说明、参数）；发布前调用 Tioka 规则校验，错误逐条列出；发布生成新的要点集合。
- 子页：阈值（按全局 / 品牌）、修订案例、正反例（增删改，保存后同步到 Tioka 知识库，显示同步状态）。

### 8.4 审查结果与处置（BIZ-05）

- **排序**：必备不满足 → 不满足 → 缺失 → 待人工 → 满足 / 不适用。
- **每条**：结论徽标、理由、建议修改、依据（模型取值 + 原文高亮，复用确认组件的原文面板）、参考的修订案例与正反例；上一轮已处置的标「上一轮已处置」。
- **处置**：接受、修改（改结论或建议）、驳回（必填原因码，ADR-071 第 2 节码表，加自由文本）；「补充问题」入口用于报漏报（EVO-08a）。全部必备项处置完才能「完成审查」。
- **验收**：驳回不填原因码不能提交；完成审查后列表只读。

### 8.5 租约状态（BIZ-06）

- 门店页按时间轴展示费用项分段、减免、押金余额与复核项；只读；每段可跳到来源合同；有异议时引导到对应合同的模型更正。

## 11. 前端测试与 E2E

- 每个页面：组件测试覆盖第 5 节全部状态；关键交互（发布、撤销、处置）写交互测试。
