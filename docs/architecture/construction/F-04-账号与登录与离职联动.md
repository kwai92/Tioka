## BAS-03 账号：开通、停用、锁定、重置与每日对账（P0，5 人天）

S15 第 8.2 节把「人员」与「账号」分开：人员在 Foundation 组织主数据里（BAS-02），账号是「人用来登录的凭证载体」，由 Foundation 推送到 Keycloak。**Foundation 不保存密码**，密码、TOTP 由 Keycloak 保存与校验（S15 第 3.3 节）。一个部署只有一个 Keycloak realm（第 57 条），Foundation 用服务账号调其管理接口。

### 1. 账号实体

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `id` | ULID，`acc_` 前缀 | 主键 |
| `login_name` | 登录名 | 全局唯一；开通时生成或由管理员指定 |
| `person_id` | 关联人员（BAS-02） | 个人账号必填；**应急管理员为空** |
| `keycloak_user_id` | Keycloak 用户 ID | 推送后回写，全局唯一 |
| `status` | `NORMAL` / `LOCKED` / `DISABLED` | 锁定与停用分开：锁定可自动或手动解除，停用需重新开通 |
| `type` | `PERSONAL` / `EMERGENCY_ADMIN` | 见下 |
| `last_login_at` | 最近登录 | 由 BAS-10 的 Keycloak 登录事件采集回填 |

规则：

- **一个人员最多一个个人账号**：以 `type = 'PERSONAL'` 的部分唯一索引约束（`person_id` 唯一）。
- **应急管理员**（S15 第 9.4 节）：`type = 'EMERGENCY_ADMIN'`、不关联人员、**默认停用**；启用需两名系统管理员先后确认（四眼），或在服务器上执行运维命令；启用、每次登录、停用都写审计并通知。生产可关闭（ADR-026「本地账号只保留应急管理员」）。
- Foundation 与 Keycloak 各保留一个应急账号；Foundation 侧只记录账号元数据与启用状态，口令由 Keycloak 侧生成、一次性写入启动日志（S15 第 16 节）。

### 2. 外部身份实体

统一记录「外部身份 → 人员」的关联，**继承 ADR-026 的绑定方式**，在 F 阶段由 Foundation 承担（原 Tioka 的 `sys_external_identity` 迁入并变更所有人）。

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `source` | 来源枚举 | `FEISHU_OPEN_ID`、`FEISHU_UNION_ID`、`DINGTALK_USER_ID`、`WECOM_USER_ID`、`AD_OBJECTGUID`、`SCIM_EXTERNAL_ID` |
| `external_id` | 外部 ID | 与 `source` 联合唯一 |
| `person_id` | 关联人员 | 未关联时为 `NULL`，即一条**待处理关联** |
| `link_mode` | 关联方式 | `AUTO`（按工号或已验证邮箱自动）、`SELF_CONFIRMED`（本人用该来源登录后确认）、`ADMIN`（管理员确认） |
| `linked_at` | 关联时间 | — |

关联规则（ADR-026、ADR-052 第 3 条）：

1. **按工号或已验证邮箱自动关联**（`AUTO`）：同步或首次登录时，外部身份携带的工号 / 邮箱与人员主数据匹配且唯一时自动建立关联。
2. **本人登录后确认**（`SELF_CONFIRMED`）：无法自动关联时，用户在 Keycloak 登录流程停在「请联系管理员」页，同时在 Foundation 生成一条待处理关联；管理员确认后用户重新登录即可（S15 第 9.2 节）。
3. **不允许仅凭姓名匹配**；匹配不唯一或确实无对应人员时**不自动建人**，只留待处理关联。
4. 解除关联后该外部身份回到待处理状态，下次登录重新走确认流程。

### 3. 服务账号实体

面向应用与机器调用（S15 第 8.2、12 节），**只用 `client_credentials` 流程**。

| 字段 | 说明 | 规则 |
| --- | --- | --- |
| `id` | ULID，`svc_` 前缀 | 主键 |
| `name` | 名称 | 同应用内唯一 |
| `app_code` | 所属应用（子系统） | 引用 BAS-04 登记的应用 |
| `keycloak_client_id` | Keycloak 客户端 | 由 BAS-04 开通；密钥轮换也归 BAS-04 |
| `permission_codes` | 可用权限码集合 | 权限码的**子集**，最终权限 = 应用角色权限 ∩ 该集合（空 = 不收窄） |
| `status` | `NORMAL` / `DISABLED` | 停用后 `client_credentials` 取令牌失败 |
| `owner_person_id` | 负责人 | 必填；**负责人离职时进入交接待办**（BAS-14） |
| `expires_at` | 过期时间 | 可空表示不过期 |

> Tioka 的个人与空间 API Key（FND-06）仍留在 Tioka（它绑定空间），其所有人引用 Foundation 账号（S15 第 8.2 节）；本文件不迁移 API Key。

### 4. 迁移 SQL 示意（V30〜V33）

```sql
-- V30：账号。硬约束：不带 tenant_id（ADR-029 第 60 条）；主键 ULID；时间 TIMESTAMPTZ
CREATE TABLE fdn_account (
    id                VARCHAR(32)  PRIMARY KEY,               -- acc_ + ULID
    login_name        VARCHAR(128) NOT NULL,
    person_id         VARCHAR(32),                             -- 应急管理员为 NULL
    keycloak_user_id  VARCHAR(64)  NOT NULL,
    status            VARCHAR(16)  NOT NULL DEFAULT 'NORMAL',  -- NORMAL / LOCKED / DISABLED
    type              VARCHAR(16)  NOT NULL DEFAULT 'PERSONAL',-- PERSONAL / EMERGENCY_ADMIN
    last_login_at     TIMESTAMPTZ,
    create_at         TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at         TIMESTAMPTZ  NOT NULL DEFAULT now(),
    create_by         VARCHAR(64)  NOT NULL DEFAULT 'system',
    update_by         VARCHAR(64)  NOT NULL DEFAULT 'system',
    CONSTRAINT ck_account_emergency_no_person CHECK (type = 'PERSONAL' OR person_id IS NULL));
CREATE UNIQUE INDEX uk_account_login_name   ON fdn_account (login_name);
CREATE UNIQUE INDEX uk_account_keycloak_uid ON fdn_account (keycloak_user_id);
-- 一个人员最多一个个人账号（S15 第 8.2 节）
CREATE UNIQUE INDEX uk_account_person_personal ON fdn_account (person_id)
    WHERE type = 'PERSONAL';

-- V31：外部身份。person_id 为 NULL 即一条待处理关联
CREATE TABLE fdn_external_identity (
    id           VARCHAR(32)  PRIMARY KEY,                     -- xid_ + ULID
    source       VARCHAR(32)  NOT NULL,                        -- FEISHU_OPEN_ID / ... / SCIM_EXTERNAL_ID
    external_id  VARCHAR(255) NOT NULL,
    person_id    VARCHAR(32),
    link_mode    VARCHAR(16),                                  -- AUTO / SELF_CONFIRMED / ADMIN
    linked_at    TIMESTAMPTZ,
    create_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (source, external_id));
CREATE INDEX idx_external_identity_person ON fdn_external_identity (person_id);

-- V32：服务账号
CREATE TABLE fdn_service_account (
    id                 VARCHAR(32)  PRIMARY KEY,               -- svc_ + ULID
    name               VARCHAR(128) NOT NULL,
    app_code           VARCHAR(64)  NOT NULL,
    keycloak_client_id VARCHAR(64)  NOT NULL,
    permission_codes   TEXT         NOT NULL DEFAULT '',        -- 逗号分隔的权限码子集
    status             VARCHAR(16)  NOT NULL DEFAULT 'NORMAL',
    owner_person_id    VARCHAR(32)  NOT NULL,
    expires_at         TIMESTAMPTZ,
    create_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (app_code, name));

-- V33：每日对账记录
CREATE TABLE fdn_account_reconcile (
    id          VARCHAR(32) PRIMARY KEY,
    ran_at      TIMESTAMPTZ NOT NULL,
    total       INT         NOT NULL,
    drifted     INT         NOT NULL,
    fixed       INT         NOT NULL,
    held        BOOLEAN     NOT NULL DEFAULT FALSE,            -- 超阈值暂停修复待确认
    detail_json TEXT);
```

### 5. 开通 / 停用 / 锁定 / 重置到 Keycloak

所有写操作**先落 Foundation 库，再推送 Keycloak**，推送失败进入重试队列（复用 outbox 思路，`fdn_account_push` 待发记录）；对账任务兜底修复。所有写接口要求 `Idempotency-Key`（S15 第 14.1 节）。

| 操作 | Foundation 侧 | Keycloak 侧 |
| --- | --- | --- |
| 开通 | 建 `fdn_account`（凭工号生成 `login_name`），写待发记录 | `POST /admin/realms/{realm}/users` 建用户；按配置设必需动作 `UPDATE_PASSWORD`（发重置邮件）或返回临时密码 |
| 停用 | `status=DISABLED` | `enabled=false`（登录被拒）；再触发会话吊销（BAS-14） |
| 锁定 / 解锁 | `status=LOCKED` / `NORMAL` | 走 Keycloak 暴力破解锁定或临时禁用；锁定原因与操作人入审计 |
| 重置密码 | 只记录操作（**不保存密码**） | 发重置邮件（`UPDATE_PASSWORD`），或生成临时密码**只显示一次**并要求首次登录修改（`mustChange`） |

- **密码策略、失败锁定与过期由 Foundation 管理台设置后下发到 realm**（S15 第 9.1 节），策略键见 BAS-15。
- 临时密码与重置链接不落库、不进日志；重试与补偿只调 Keycloak 管理接口，不回读口令。

### 6. 每日对账（发现并修复人为改动）

- **单实例执行**：`@Scheduled` 任务用 Redis 锁保证同一时间一个实例在跑（S15 第 4 节）。
- **对账维度**：账号存在性与 `enabled` 状态、`username`、必需动作；逐条比对 Foundation 账号列表与 Keycloak realm 用户。
- **以 Foundation 为准修复**：状态不一致（如有人在 Keycloak 控制台手工停用/启用）回正；Keycloak 中多出的、非 Foundation 管理的账号标记并停用。
- **阈值保护**：一次差异超过阈值（默认停用类 > 5% 或 > 50 条）时**暂停修复并告警**，等管理员确认（沿用 ADR-052 第 5 节的差异阈值思路）。
- **记录**：每次对账写 `fdn_account_reconcile`（总数、差异数、修复数、是否暂停、明细），可在管理台查询。

### 7. 接口与权限码

| 方法与路径 | 权限码 | 说明 |
| --- | --- | --- |
| `GET /api/accounts?q&status&type&page&size` | `fdn:account:read` | 账号列表（个人与应急管理员；含在线会话入口） |
| `POST /api/accounts` | `fdn:account:admin` | `{personId, loginName?}` 开通并推送 Keycloak |
| `PUT /api/accounts/{id}/disable` / `enable` | `fdn:account:admin` | 停用 / 重新开通；停用连带会话吊销（BAS-14） |
| `PUT /api/accounts/{id}/lock` / `unlock` | `fdn:account:admin` | 锁定 / 解锁 |
| `PUT /api/accounts/{id}/reset-password` | `fdn:account:admin` | 经 Keycloak 发邮件或临时密码 |
| `GET /api/accounts/{id}/sessions` | `fdn:account:read` | 在线会话（来自 Keycloak） |
| `DELETE /api/accounts/{id}/sessions` | `fdn:account:admin` | 强制下线，发 `fdn.account.sessions_revoked` |
| `GET /api/external-identities?pending=true` | `fdn:identity:admin` | 待处理关联列表 |
| `POST /api/external-identities/{id}/confirm` / `unlink` | `fdn:identity:admin` | 确认 / 解除关联（`link_mode=ADMIN`） |
| `GET /api/service-accounts` / `POST` | `fdn:serviceaccount:admin` | 服务账号列表 / 新建（客户端由 BAS-04 开通） |
| `PUT /api/service-accounts/{id}/disable` / `enable` | `fdn:serviceaccount:admin` | 停用 / 启用 |
| `POST /api/accounts/emergency/{id}/enable-request` | `fdn:account:admin` | 应急管理员启用第一步（发起） |
| `POST /api/accounts/emergency/{id}/enable-confirm` | `fdn:account:admin` | 第二步（另一名系统管理员确认，四眼） |

- 账号相关权限归**系统管理员**；高风险授权（授予带高风险权限码的角色）需**安全管理员**复核（S15 第 15 节、BAS-19）。
- 应急管理员启用、每次登录、停用一律写审计并发通知（S15 第 9.4 节）。

## BAS-15 登录方式：Keycloak 配置化与策略下发（P1，4 人天）

### 1. 范围与选型

**登录协议全部由 Keycloak 实现，Foundation 只做配置与管理**（S15 第 3.3 节、第 9.1 节）。本项**取代 FND-10**：SAML、LDAP 从「编码」变为「配置 + 验收」。

| 登录方式 | 实现（Keycloak） | 优先级 | 本期 |
| --- | --- | --- | --- |
| 账号密码 | 本地凭证；密码策略、失败锁定、过期由 Foundation 下发到 realm | P0 | 是 |
| 企业 IdP（OIDC） | 身份代理到客户 IdP（Entra ID、Okta、客户自建） | P0 | 是（配置） |
| LDAP / AD | 用户联邦，**只做认证**；人员数据由 BAS-02/BAS-12 同步 | P1 | 是 |
| SAML 2.0 | 身份代理 | P1 | 是（配置） |
| 飞书、企微、钉钉扫码 | 身份代理（OAuth 类提供方），首次登录按 BAS-03 第 2 节规则关联人员 | P1 | 是 |
| TOTP 二次验证 | 必需动作；可按角色强制（系统管理员、安全管理员） | P1 | 是 |
| CAS | Keycloak 社区扩展或网关 | — | **不在本期** |

### 2. 管理台封装与下发

- **封装常用配置**：密码策略、会话策略、登录方式开关，在 Foundation 管理台表单里配置，经管理接口**下发到 realm**。
- **复杂配置引导到控制台**：身份代理的开通、SAML 元数据、LDAP 连接细节等复杂项在管理台给出入口与说明，**引导到 Keycloak 控制台**完成（S15 第 3.3 节「管理界面封装常用配置，复杂配置引导到 Keycloak 控制台」）。
- **共用一个 realm**（第 57 条）：所有应用、所有登录方式都在该 realm 内；Tioka、业务系统、Foundation 管理台同为接入应用。

配置下发内容：

| 分组 | 下发项 | 目标 |
| --- | --- | --- |
| 密码策略 | 最少 8 位、三类字符、90 天过期、不得与近 5 次重复、连续失败 5 次锁定 15 分钟（S15 第 15 节默认值） | realm password policy |
| 会话策略 | 空闲 30 分钟、最长 10 小时、同账号并发会话上限（可配） | realm token / SSO session |
| 登录方式 | OIDC / SAML / LDAP / IM 扫码身份代理的启用与排序、TOTP 必需动作 | realm authentication flow / identity providers |

### 3. 登录流程（延续 ADR-051 第 3 条、M1-01 FND-05）

1. 用户访问任一应用，前端包发现未登录 → 跳 Keycloak 授权页（授权码 + PKCE，**由后端完成换码**）。
2. Keycloak 完成认证（本地 / 代理 / 联邦），签发令牌；令牌只带身份：Keycloak 用户 ID、Foundation 账号 ID、人员 ID、工号、姓名、主组织单元编码，**不带角色与权限**。
3. 应用后端用 starter 校验令牌，按「人员 + 应用」取授权快照；Tioka 延续 FND-05，把 OIDC 令牌换成自己的 `tka_` 令牌（第 32 条：访问令牌只在前端内存、刷新令牌放 `HttpOnly; SameSite=Strict; Secure` Cookie、URL 中不出现令牌）。
4. 已登录用户打开另一个应用直接单点登录（共用一个 realm）。

**关联失败**：外部身份无法关联到人员时，Keycloak 首次登录流程停在「请联系管理员」页，Foundation 生成一条待处理关联（BAS-03 第 2 节），**不自动建人员**。

### 4. 接口与权限码

| 方法与路径 | 权限码 | 说明 |
| --- | --- | --- |
| `GET /api/auth/policy` | `fdn:auth:policy:read` | 读取当前密码 / 会话策略 |
| `PUT /api/auth/policy` | `fdn:auth:policy:admin` | 修改策略并下发 realm（**安全管理员**域） |
| `GET /api/auth/login-modes` | `fdn:auth:policy:read` | 登录方式与启用状态 |
| `PUT /api/auth/login-modes` | `fdn:auth:policy:admin` | 启用 / 排序 / 强制 TOTP（简单项下发；复杂项返回控制台引导链接） |
| `POST /api/auth/policy/apply` | `fdn:auth:policy:admin` | 重新下发并返回逐项结果 |

- 密码与会话策略、登录方式属**安全管理员**职责（S15 第 15 节三员分立）；修改写审计。
- 下发失败列出失败项与 Keycloak 返回，不静默成功。

### 5. 验收要点

- 飞书扫码登录后，**按 BAS-03 第 2 节规则关联到正确人员**（工号 / 已验证邮箱），关联不上停在「请联系管理员」并生成待处理关联。
- LDAP / SAML 只做认证，人员主数据仍来自 BAS-02；登录后令牌只带身份，权限来自快照。
- 密码策略、会话策略经管理台修改后，realm 生效（可用一条新策略做验收，如失败次数）。
- TOTP 对系统管理员 / 安全管理员强制时，登录需二次验证。

### 6. 配置（`foundation.auth.*`）

```yaml
foundation:
  auth:
    keycloak:
      base-url: ${FOUNDATION_KC_BASE_URL}          # 例如 http://keycloak:8080
      realm: enterprise                             # 单 realm（第 57 条）
      admin-client-id: foundation-admin
      admin-client-secret: ${FOUNDATION_KC_ADMIN_SECRET}
    policy:
      password: "length(8) and digits(1) and upperCase(1)"
      session-idle-minutes: 30
      session-max-hours: 10
      concurrent-sessions: 0                        # 0 = 不限
    login-modes: [password, oidc, ldap, saml, im-qr] # totp 由必需动作单独配置
    totp-required-roles: [system_admin, security_admin]
```

## BAS-14 停用与离职联动：会话吊销、交接待办、事件（P0，2 人天）

BAS-14 是离职链的下游：BAS-02 → BAS-03（W82）→ **BAS-14（W84，等 BAS-07）** → BAS-20 的离职事件处理 → `GfOffboardingGateIT`（[F-00](F-00-F阶段实施计划.md) 第 4 节关键路径）。契约（事件名与载荷，S15 第 14.2 节）由 BE-C 在 W84 第一天先合，本项第三天接真事件。

### 1. 动作链

停用 / 离职一次触发，按序执行（各步失败重试，单步失败不回滚已生效的会话吊销）：

1. **账号停用**：`fdn_account.status=DISABLED`，并推送 Keycloak `enabled=false`（BAS-03）。
2. **Keycloak 会话吊销**：调 Keycloak 管理接口注销该账号全部会话与令牌；**吊销结果与吊销时间记录**（用于验收 1 分钟口径）。
3. **服务账号与负责事项进入交接待办**：该人员作为 `owner_person_id` 的**服务账号**、以及在门户登记为处理人的**待办**进入交接待办队列（消息中心 BAS-16；服务账号交接待办由本项生成）。
4. **发事件**：`fdn.person.disabled`、`fdn.account.sessions_revoked` 经 outbox 投递到 RocketMQ 主题 `fdn-events`（并可同时投 Webhook）。**事件体只带 ID、版本与变化类型**，不带敏感字段（S15 第 14.2 节）。

| 事件 | 载荷（ID 与变化类型） | 触发时机 |
| --- | --- | --- |
| `fdn.person.disabled` | `personId`、`reason`（离职 / 停用 / 同步删除）、`at` | 人员停用或离职时 |
| `fdn.account.sessions_revoked` | `accountId`、`keycloakUserId`、`at` | 停用、强制下线、单点注销（S15 第 9.3 节） |

强制下线（管理台在线用户页，BAS-03 第 7 节）只发 `fdn.account.sessions_revoked`，不改 `person` 状态。

### 2. 应用侧反应

| 消费方 | 收到事件后 | 依据 |
| --- | --- | --- |
| Tioka | 吊销 `tka_` 令牌与**代用户令牌**（FND-08 `TokenVault.revokeAll`）；取消进行中的 Turn；资产转交空间管理员待处理队列（已发布资产继续可用）；**所负责的数字员工（Agent）暂停**（TRU-03 负责人失效：新 Turn 返回 `AGENT_SUSPENDED`，运行中 Turn 在下一步开始前取消） | S15 第 10.3 节、[M1-01](M1-01-权限与身份联邦.md)、[M3-05](M3-05-策略引擎与可信放权.md) 第 4 节 |
| 业务系统（合同系统等） | 待办转交；吊销本地会话与本地令牌 | S15 第 10.3 节 |
| 各应用 starter | 收到 `fdn.authz.changed` 或人员停用后失效授权快照缓存；`fdn.account.sessions_revoked` 后吊销本地令牌 | ADR-051 第 3 条 |

- 记忆离职清理（MEM-01）改由 `fdn.person.disabled` 触发；Tioka 内的身份生命周期事件仍保留给本地模式（[F-00](F-00-F阶段实施计划.md) 第 5 节约定 7）。
- 消费端**幂等**：按事件 ID 去重；重复事件只处理一次。

### 3. 1 分钟内失效的验收口径

- 从**停用动作提交成功**（`fdn_account.status=DISABLED` 落库）起算，到 Tioka 与业务系统的**已登录会话失效**（旧令牌 401、进行中的 Turn 取消可观测）**不超过 60 秒**。
- 失效三条路径任一成立即算通过：Keycloak 会话吊销即时生效（新请求被拒）；应用收到 `fdn.account.sessions_revoked` 后立即吊销本地令牌（`tka_` 等）；授权快照缓存按事件失效、TTL 兜底（默认 5 分钟，但事件路径满足 60 秒内）。
- 闸门 `GfOffboardingGateIT` 断言：停用后 Tioka 与业务系统的旧令牌在 1 分钟内返回 401；交接待办生成；记忆清理触发（[F-00](F-00-F阶段实施计划.md) 第 6.1 节）。

### 4. 接口与权限码

| 方法与路径 | 权限码 | 说明 |
| --- | --- | --- |
| `POST /api/accounts/{id}/disable` | `fdn:account:admin` | 停用并触发本项动作链（与 BAS-03 同一入口） |
| `POST /api/persons/{id}/offboard` | `fdn:account:admin` | 离职停用（人员状态置离职 + 账号停用 + 动作链） |
| `DELETE /api/accounts/{id}/sessions` | `fdn:account:admin` | 强制下线（只发 `fdn.account.sessions_revoked`） |
| `GET /api/service-accounts/handover` | `fdn:serviceaccount:admin` | 交接待办队列 |
| `POST /api/service-accounts/{id}/handover` | `fdn:serviceaccount:admin` | 指定新负责人 |

### 5. 配置（`foundation.offboarding.*`）

```yaml
foundation:
  offboarding:
    session-revoke-deadline-seconds: 60      # 验收口径
    revoke-on-disable: true
    create-handover-todo: true               # 服务账号与负责事项进交接待办
    notify: [inapp, feishu]                   # 通知渠道（复用 BAS-16）
    event-topic: fdn-events
```

| 类 | 职责 |

## 完成标准

- [ ] 账号开通后可在 Keycloak 登录；停用后 Keycloak 登录失败；锁定 / 重置（邮件或临时密码）可用。
- [ ] 一个人员最多一个个人账号；应急管理员不关联人员、默认停用、启用需双人确认并审计。
- [ ] 外部身份按工号或已验证邮箱自动关联、或本人登录后确认；**无姓名匹配、无自动建人**；待处理关联可确认 / 解除。
- [ ] 服务账号只用 `client_credentials`，权限码为子集，负责人离职进交接待办。
- [ ] 每日对账发现并修复人为改动；超阈值暂停并告警。
- [ ] 登录方式（账号密码、OIDC、LDAP/AD、SAML、IM 扫码、TOTP）经管理台下发 realm；复杂项引导控制台；飞书扫码关联到正确人员（取代 FND-10）。
- [ ] 停用 / 离职动作链完整：账号停用 → Keycloak 会话吊销 → 交接待办 → 发 `fdn.person.disabled` 与 `fdn.account.sessions_revoked`；Tioka 与业务系统 1 分钟内失效。
- [ ] `GfAccountLifecycleGateIT`、`GfOffboardingGateIT` 转绿；相关 `*IT`/`*Test` 通过；CI 全绿。
- [ ] 硬约束守住：无 `tenant_id`；ULID 主键；`TIMESTAMPTZ`；Foundation 不保存密码；令牌只带身份不带权限。
