### 资源级权限规则

`DefaultResourceGuard implements ResourceGuard`（system-biz `application/authz/`）。判定顺序（任一成立即允许）：

1. `Principal` 有 `*` 或 `{type}:admin` → 允许。
2. 资源不在当前空间 → **404**（不暴露存在性）。
3. ACL 中 `subject=user:当前用户`、`group:用户所属任一组`、`workspace:当前空间` 的最高 level ≥ 要求 level。
4. 空间内默认可见性：`resource.visibility = WORKSPACE`（V111 给五类资源加 `visibility VARCHAR(16) NOT NULL DEFAULT 'WORKSPACE'`，取值 `PRIVATE`/`WORKSPACE`）时，空间成员拥有 `USE`（若其角色有 `{type}:read`）；有 `{type}:write` 的角色拥有 `EDIT`。

| AccessLevel | 含义 | 典型操作 |
| --- | --- | --- |
| `VIEW` | 看到配置 | 详情、版本列表 |
| `USE` | 可在会话/Flow 中使用 | 选 Agent 对话、检索知识库 |
| `EDIT` | 改配置、发布 | 保存草稿、发布 |
| `OWNER` | 改 ACL、删除、转让 | 分享、删除 |

level 有序：`VIEW < USE < EDIT < OWNER`。

`visibleIds(type, level)` 返回 SQL 片段而不是集合，避免大集合进内存：

```java
public interface ResourceGuard {
    void check(String resourceType, String resourceId, AccessLevel level);
    boolean allows(String resourceType, String resourceId, AccessLevel level);
    Set<String> visibleIds(String resourceType, AccessLevel level);   // 保留：仅用于小集合（≤ 1000）
    /** 新增：返回可直接拼入 MyBatis-Plus Wrapper 的条件。 */
    VisibilityFilter filter(String resourceType, AccessLevel level);
}
public record VisibilityFilter(boolean all, String sql, Map<String, Object> params) {}
// sql 例：(visibility = 'WORKSPACE' OR id IN (SELECT resource_id FROM sys_resource_acl
//          WHERE resource_type = 'agent' AND level IN ('USE','EDIT','OWNER')
//          AND ((subject_type='user' AND subject_id=#{uid}) OR (subject_type='group' AND subject_id IN (#{gids})))))
```

缓存：用户组 ID 列表放进 `Principal`（新字段不加到 record，放在 `PrincipalLoader` 的 Redis 缓存 `auth:groups:{uid}`，TTL 60s）。

### `@RequirePermission` 落地

- `PermissionAspect`（`@Aspect`，order 早于事务）：方法或类上的注解，多个值为「全部需要」；不满足抛 `FORBIDDEN`，并写审计 `DENIED`（GOV-02）。
- 资源检查不在注解里做，由应用服务第一行调用 `guard.check(...)`。
- ArchUnit `controllersMustDeclarePermission` 冻结库存在本项结束时清零：所有 Controller 方法按下表补注解。

| Controller | 注解 |
| --- | --- |
| `AgentController` | 读 `AGENT_READ`；写 `AGENT_WRITE`；发布 `AGENT_PUBLISH`；分享 `AGENT_SHARE` |
| `FlowController`、`FlowPublicationController` | `FLOW_*`；webhook 端点改 API Key（FND-06） |
| `KnowledgeController` | `KB_*` |
| `McpController`、`SkillController` | `MCP_*`、`SKILL_*` |
| `ChatController`、`ThreadController`、`ThreadEventsController` | `CHAT_USE` |
| `ModelController`、`RoutingPlanController` | 读 `MODEL_READ`；写 `MODEL_ADMIN` |
| `QuotaController` | `QUOTA_READ` / `QUOTA_ADMIN` |
| `OrchController` | `ORCH_*` |
| `OpsFacadeController` | 按各方法所代理的能力 |
| `WorkspaceController` | `WORKSPACE_MANAGE`；`/mine` 仅登录 |
| `AdminUserController`、`RoleController`、`ApiKeyController`、`AuditController`（新） | `TENANT_ADMIN`；审计 `AUDIT_READ` |

### REST（新增）

## GOV-02 审计管道（P0，6 人天）

### 写入点

| 来源 | 机制 | action 命名 |
| --- | --- | --- |
| 应用服务写操作 | `@Audited(action="agent.publish", resourceType="agent", resourceId="#cmd.agentId")`（SpEL） | `{资源}.{动词}` |
| 工具调用 | `ToolGateway`（[M1-04](M1-04-工具网关与其他.md) CON-01） | `tool.invoke` |
| 认证 | 登录成功/失败、刷新、登出、令牌族吊销 | `auth.login` 等 |
| 拒绝 | `PermissionAspect`、`ResourceGuard.check`、`RestAccessDenied`、出网守卫 | 原 action，`outcome=DENIED` |
| 审批 | `decideApproval` | `approval.decide` |

### 实现

```java
// system-biz application/audit/
public class AuditService implements AuditApi {
    /** 与业务同事务写入（Propagation.MANDATORY 时加入；无事务时自开 REQUIRES_NEW）。 */
    public void record(AuditEvent e);
}
@Aspect class AuditedAspect {
    @Around("@annotation(a)")
    Object around(ProceedingJoinPoint pjp, Audited a) {
        try { Object r = pjp.proceed(); audit.record(build(a, pjp, r, SUCCESS, null)); return r; }
        catch (BizException ex) { audit.recordIndependent(build(a, pjp, null, ex.isDenied() ? DENIED : ERROR, ex.getMessage())); throw ex; }
    }
}
```

- 成功记录与业务同一事务：业务回滚则审计也回滚（没发生的事不记）。
- 失败/拒绝记录用 `REQUIRES_NEW` 独立事务（业务回滚了，但「有人试过」要留下）。
- `details_json` 只放参数摘要：字段白名单由 `@Audited(include={"name","version"})` 指定，默认不记请求体；任何名为 `password`、`secret`、`token`、`apiKey` 的字段一律替换为 `***`。
- 转发：`AuditForwarder`（`@Scheduled` 每 5 秒）读 `audit_event` 中 `forwarded=false` 的记录批量写 `AuditSink`（现有 `FileAuditSink` 每行一个 JSON），成功后置 `forwarded=true`。V112：`ALTER TABLE audit_event ADD COLUMN forwarded BOOLEAN NOT NULL DEFAULT FALSE; CREATE INDEX idx_audit_unforwarded ON audit_event (ts) WHERE forwarded = FALSE;`。M2 改走 outbox。
- 保留期：`tioka.audit.retention-days`（默认 365），每日清理已转发且超期的行。

### 查询 API

`GET /api/system/audit?from&to&actorId&action&resourceType&resourceId&outcome&page&size`（`audit:read`，非 tenant_admin 只能查当前空间；`to-from` ≤ 93 天；`size` ≤ 200）；`GET /api/system/audit/export?…` 返回 CSV 流（同条件，最多 100000 行）。

## FND-05 OIDC 登录（Keycloak 验收）（P0，8 人天）

### 流程

采用授权码 + PKCE，后端作为机密客户端完成换码，**登录成功后仍签发 Tioka 自己的不透明令牌**（与本地登录同一套 `TokenService`），前端不接触 IdP 令牌。这样 SSE、API Key、吊销逻辑只有一套。另外提供 JWT 资源服务器路径，供已持有 IdP 访问令牌的系统直接调用 API。

```text
浏览器 → GET /api/system/auth/oidc/{idp}/authorize?redirect=/chat
  后端生成 state、nonce、code_verifier，存 Redis auth:oidc:{state}（TTL 10 分钟），302 到 IdP
IdP → GET /api/system/auth/oidc/{idp}/callback?code&state
  校验 state（一次性，GETDEL）→ 换码（client_secret + code_verifier）→ 校验 id_token（签名、iss、aud、exp、nonce）
  → 用户映射（见下）→ TokenService.issue → 写刷新令牌 Cookie `tioka_rt` → 302 到前端 /login/callback?redirect=/chat
    （URL 中不带任何令牌；前端回调页调 /refresh 取访问令牌，与本地登录后的页面刷新是同一条路径）
```

### 用户与角色映射

| IdP 声明 | 映射 |
| --- | --- |
| `sub` | `auth_user.external_subject`，`idp = oidc:{idp}`；首次登录自动建用户（`auto-provision=true` 时），ID 取序列 |
| `preferred_username` / `email` / `name` | `username`（冲突时加后缀 `_{idp}`）、`display_name` |
| `groups`（可配置声明名） | 同步到 `sys_group(source=oidc:{idp}, external_id=组路径)` 与 `sys_group_member`：每次登录全量覆盖该用户在此来源下的组 |
| 角色映射规则 | 配置 `group-role-mappings`：组 → (空间, 角色)；登录时按规则 upsert `sys_member`，并删除「由映射产生但已不满足」的成员行（V113 给 `sys_member` 加 `source VARCHAR(32) NOT NULL DEFAULT 'manual'`，只删 `source='oidc:{idp}'` 的行） |

### 配置

```yaml
tioka:
  auth:
    oidc:
      providers:
        keycloak:
          issuer-uri: http://localhost:8180/realms/tioka
          client-id: tioka
          client-secret: ${TIOKA_OIDC_SECRET}
          scopes: [openid, profile, email]
          groups-claim: groups
          auto-provision: true
          group-role-mappings:
            - { group: /tioka/admins,   tenant-role: tenant_admin }
            - { group: /tioka/sales,    workspace: ws_sales, role: member }
      resource-server:
        enabled: true             # 接受 Authorization: Bearer <IdP JWT>
        audiences: [tioka-api]
```

使用 `spring-boot-starter-oauth2-client` 只为了复用其 `ClientRegistration`、JWK 获取与校验工具（`NimbusJwtDecoder`），不启用它的 `oauth2Login()` 会话流程（会话有状态，与我们的无状态设计冲突）。

### 认证过滤器扩展

`BearerTokenFilter` 判别令牌：`tka_` 前缀 → Redis；`tk_live_` 前缀 → API Key（FND-06）；三段式且 `resource-server.enabled` → `JwtDecoder` 校验后按上表映射到本地用户（不存在且不允许自动建 → 401）。三条路径最后都走 `PrincipalLoader`，`authMethod` 分别为 `password`/`oidc`、`api_key`、`oidc_jwt`。

### 现有代码

`LocalOidcIdPAdapter`、`IdPAdapter` SPI：删除 `LocalOidcIdPAdapter`（它是本地模拟 IdP）；`IdPAdapter` 改为 `OidcProviderRegistry` 内部接口，M4 的 SAML/LDAP 实现同一接口。

## FND-06 服务账号与 API Key（P1，5 人天）

### 模型

- 服务账号是 `auth_user` 的一行：`type='SERVICE'`（V113 加 `ALTER TABLE auth_user ADD COLUMN type VARCHAR(16) NOT NULL DEFAULT 'USER'`），无密码，不能登录，按普通成员方式加入空间并分配角色。
- API Key 属于服务账号（`sys_api_key.service_user_id`），可选绑定空间（绑定后 `X-Workspace-Id` 被忽略）；`scopes` 为权限点子集，最终权限 = 角色权限 ∩ scopes（空表示不收窄）。
- 明文格式：`tk_live_{8 位前缀}{32 字节 base62}`，前缀明文入库供识别；库中存 `SHA-256`（不是 bcrypt：高熵随机串无需慢哈希，且每次请求都要校验）。明文只在创建时返回一次。
- `last_used_at` 每分钟最多更新一次（Redis `SET NX EX 60` 节流）。

### REST

| 方法与路径 | 权限 | 请求 / 响应 |
| --- | --- | --- |
| `POST /api/system/service-accounts` | `tenant:admin` | `{name, workspaceId, role}` → `{userId}` |
| `POST /api/system/api-keys` | `tenant:admin` 或该空间 `workspace:manage` | `{serviceUserId, name, workspaceId?, scopes?, expiresAt?}` → `{id, key}`（明文仅此一次） |
| `GET /api/system/api-keys` | 同上 | 列表（无明文，有 prefix、lastUsedAt） |
| `DELETE /api/system/api-keys/{id}` | 同上 | 立即失效（删 Redis 缓存 `auth:apikey:{hash}`） |

Flow 发布的 webhook（`/api/flows/publications/webhook/{versionId}`）去掉 `@PublicApi`，改为要求 API Key 且服务账号对该 Flow 有 `USE`。

### 测试

`ApiKeyIT#keyBoundToPermissions`（34 号验收：API Key 调用受同样权限约束）、`#revokedKeyRejectedImmediately`、`#scopesNarrowPermissions`、`#expiredKey401`。
