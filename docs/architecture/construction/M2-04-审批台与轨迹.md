## HCI-06 Runtime 事件对齐 AG-UI（P1，后端 5 人天 + 前端 2 人天）

ADR-028：内部协议不变，在网关层提供 AG-UI 兼容端点，供 CopilotKit 等 AG-UI 客户端直接接入 Tioka 的 Agent。

### 端点

`POST /api/agui/agents/{agentVersionId}/run`，`Accept: text/event-stream`，请求体为 AG-UI `RunAgentInput`：

```json
{"threadId": "…", "runId": "…", "messages": [{"id":"…","role":"user","content":"…"}], "tools": [], "state": {}, "context": [], "forwardedProps": {}}
```

处理：

1. 鉴权同其他 API（登录令牌或 API Key），`chat:use` + Agent `USE`。
2. `threadId` 映射：`runtime_session.metadata_json.aguiThreadId` 查找，不存在则 `createThread(origin=chat, metadata={aguiThreadId})`。
3. 取 `messages` 中最后一条 `role=user` 作为输入，`startTurn(clientMsgId = runId)`；客户端传入的历史消息不覆盖服务端历史（以服务端为准）。
4. 客户端声明的 `tools`（前端工具）M2 不支持：非空时返回 `RUN_ERROR{code:"CLIENT_TOOLS_UNSUPPORTED"}`。
5. 订阅该 thread 的内部事件流并按下表转换后写出，Turn 终态后关闭流。

### 映射表（`AgUiEventMapper`，纯函数，单元测试全覆盖）

| 内部事件 | AG-UI 事件 |
| --- | --- |
| `turn.started` | `RUN_STARTED{threadId, runId}` |
| `item.created`（message/assistant） | `TEXT_MESSAGE_START{messageId=itemId, role:"assistant"}` |
| `item.delta`（message） | `TEXT_MESSAGE_CONTENT{messageId, delta}` |
| `item.completed`（message/assistant，有流式开头） | `TEXT_MESSAGE_END{messageId}` |
| `item.completed`（message/assistant，无流式开头） | START + CONTENT（全文）+ END 三连 |
| `item.created/delta/completed`（reasoning） | `THINKING_TEXT_MESSAGE_START/CONTENT/END` |
| `item.completed`（tool_call） | `TOOL_CALL_START{toolCallId=callId, toolCallName}` + `TOOL_CALL_ARGS{delta=参数 JSON}` + `TOOL_CALL_END` |
| `item.completed`（tool_result） | `TOOL_CALL_RESULT{toolCallId, content=output, messageId=itemId}` |
| `item.discarded` | `CUSTOM{name:"tioka.item_discarded", value:{messageId}}`（AG-UI 无对应事件） |
| `approval.requested` | `CUSTOM{name:"tioka.approval_requested", value: ApprovalView}` |
| `turn.waiting` | `CUSTOM{name:"tioka.turn_waiting", value:{reason}}`；流保持打开直到终态或客户端断开 |
| `turn.completed` | `RUN_FINISHED{threadId, runId}` |
| `turn.failed` / `turn.cancelled` | `RUN_ERROR{message, code}` |
| `citation`、`card`、`status`、`file_ref` 等其他 item | `CUSTOM{name:"tioka.item", value: ItemView}` |

事件字段名与类型以 AG-UI 官方 TypeScript 包 `@ag-ui/core` 的定义为准；后端用 Jackson 输出 camelCase。

### 前端

内部前端不改用 AG-UI（仍用内部协议）。FE 工作量是 `examples/agui-client/`：一个最小 CopilotKit 页面，用于在 CI 中做兼容性验证（Playwright 打开页面、发一句话、断言收到回答）。

### 测试

`AgUiEventMapperTest`（表中每一行）、`AgUiEndpointIT#streamsAndFinishes`、`#clientToolsRejected`、`#threadIdReused`、`AgUiCompatE2E`（Playwright，G2 任务中运行）。

### 后端：轨迹查询

### 前端：`TrajectoryView.vue`

- 入口：对话页每个 Turn 的「查看轨迹」、审批详情、编排 Run 详情、Flow 运行详情（Agent 节点）。

## FLW-03 HumanCard 节点挂起下游（P1，6 人天）

M3 会按 ADR-019 把 Flow 引擎重写为数据库驱动的事件调度器。M2 只做「人工节点可挂起与续跑」，但表结构直接采用 ADR-019 的 `flow_run` / `flow_node_run`，避免 M3 再迁移。

### 迁移（并入 V143）

按 ADR-019 重建 `flow_run`、新建 `flow_node_run`（`TIMESTAMPTZ`、BaseDO 列名，ADR-029 第 17、20 条），另加：

```sql
ALTER TABLE flow_run ADD COLUMN state_json TEXT;   -- M2 专用：挂起时的引擎快照（各边状态、已完成节点输出），M3 删除
ALTER TABLE flow_run ADD COLUMN workspace_id VARCHAR(64);
-- 旧 flow_run 的 trace_json 不迁移（仓库无生产数据）
```

### 引擎改造（基于 FLW-01 修复后的 `runDag`）

1. 每个节点执行前后写 `flow_node_run`（RUNNING → SUCCEEDED / FAILED / SKIPPED / WAITING），`trace_json` 不再整体保存。
2. `HumanCardNodeExecutor` 返回 `NodeOutcome.waiting(cardSpec)`（`NodeExecutor` 返回类型由 `Object` 改为 `NodeOutcome`，其他执行器包装为 `NodeOutcome.done(output)`）。
3. 引擎遇到 WAITING：
   - 事务内：`flow_node_run.status=WAITING`、`wait_key=approvalId`；插入 `runtime_approval(subject_type='flow_node_run', subject_id=nodeRunId, kind='card', card_json=节点配置渲染结果, assignee_json=节点配置, expires_at)`；`flow_run.status=WAITING`、`state_json=EngineSnapshot`。
   - 与 WAITING 节点无依赖关系、已经就绪的其他分支继续执行；全部可执行节点跑完后返回（调用方收到 `status=WAITING` 与 `runId`）。
4. `FlowApprovalHandler implements ApprovalSubjectHandler`（`subjectType="flow_node_run"`）：
   - `APPROVED`/`REJECTED`：节点输出 = `{approved, answer, comment, decidedBy}`；恢复快照，把该节点标记完成，下游按边条件继续（节点配置可设 `rejectEdge`：拒绝时只走标记为 `when: "rejected"` 的出边）。
   - `EXPIRED`：节点配置 `onTimeout: fail | default`；`fail` → `flow_run FAILED`。
   - 执行身份：`flow_run.run_as_json`（不是审批人）。
5. 同步调用方（发布为 API 的 Flow）遇到 WAITING：HTTP 响应 202 `{runId, status:"WAITING", approvalId}`；调用方用 `GET /api/flows/runs/{runId}` 轮询或订阅 `tioka.flow.run_finished.v1`。Flow 作为工具被 Agent 调用时，按 RT-09 的异步工具返回 `PendingJob`，Turn 进入 `WAITING_CHILD`。

```java
public record EngineSnapshot(Map<String, EdgeState> edges, Map<String, Object> outputs,
                             Set<String> completed, Set<String> skipped, Map<String, String> waiting) {}
```

## 完成标准

- 审批台可处理三类来源的审批，批准后 Run / Turn / Flow 续跑。
- AG-UI 客户端可直接对话 Tioka Agent（兼容 E2E 通过）。
- 每个 Turn 可查看按步展开的轨迹，含用量与故障接力。
- HumanCard 节点挂起下游、审批后继续。
