## 2. 全局代码约定

以下约定对 M0〜M2 所有工作项生效，Code Review 按此检查。

### 2.1 包与分层

沿用现有 DDD 分层，每个 `*-biz` 模块固定为：

```text
com.tioka.<domain>
├── api/             # Controller 与请求/响应 record，只做参数校验和权限注解
├── application/     # 应用服务，事务边界在这里（@Transactional）
├── domain/          # 领域对象与纯逻辑（状态机、规则），不依赖 Spring
├── infrastructure/  # *Repository、mapper/、persistence/*DO、外部客户端
└── config/          # *AutoConfiguration、@ConfigurationProperties
```

跨模块只能依赖对方的 `*-api`（ArchUnit 守护，见 ENG-10）。`tioka-server` 只做装配、闸门测试和极少量门面。

### 2.2 标识、时间、JSON

| 项 | 规则 | 实现 |
| --- | --- | --- |
| 主键 | ULID，26 字符，带前缀 `{前缀}_{ulid}` 时列宽 VARCHAR(32)；前缀表见下 | `com.tioka.framework.id.Ids.newId(String prefix)`（ENG-05） |
| 时间 | 列用 `TIMESTAMPTZ`；DO 字段用 `LocalDateTime`（语义为 UTC，JVM 与 JDBC 会话时区固定 UTC），领域对象与 API 用 `Instant`，输出 ISO-8601 UTC | Jackson `WRITE_DATES_AS_TIMESTAMPS=false`；基类与规则见 M0-01 ENG-11「DO 基类与时间类型」 |
| JSON | 只用 Spring 注入的 `ObjectMapper`；禁止 `new ObjectMapper()` | ArchUnit 规则 `noNewObjectMapper` |
| 枚举入库 | 存 `name()` 字符串，不存序号 | — |
| 金额 | `cost_micros BIGINT`（百万分之一元） | — |

ID 前缀：`ws` 空间、`key` API Key、`thr` thread（即 runtime_session，新建）、`turn`、`item`、`apv` 审批、`evt` 编排事件、`dec` 决定、`man` Mandate、`wi` 工单、`run` 编排 Run、`tmr` 定时器、`use` 用量、`aud` 审计。旧数据的 ID 保持不变，外键列宽 VARCHAR(64) 兼容旧格式（ADR-029 第 9 条）。用户 ID 例外：`auth_user.id` 保持 BIGINT（序列 `auth_user_id_seq`），其他表引用时存十进制字符串（ADR-029 第 31 条）。

### 2.3 错误与响应

- 统一抛 `BizException(ErrorCode, message)`；HTTP 状态取 `ErrorCode.httpStatus`（已在 M0 契约落地）。
- 响应体沿用 `ApiResponse{code,message,data,traceId}`。SSE 例外：直接写事件流，错误以 `turn.failed` 事件表达。
- 不吞异常：`catch (Exception e) { return 默认值; }` 一律禁止，至少记录 `log.warn` 并带上下文；解析失败抛 `BAD_REQUEST`。

### 2.4 事务与并发

- 事务只开在 `application` 层的 public 方法上；Controller 和 Repository 不加 `@Transactional`。
- 应用代码禁止 `synchronized` 与 `ReentrantLock` 做业务互斥（ArchUnit 守护），一律用数据库行锁或 Redis 锁。
- 需要「写库后发事件」时：M0〜M1 用 `TransactionSynchronization.afterCommit` 发 Redis；M2 起跨域事件一律走 `sys_outbox`。

### 2.5 配置

所有新配置项放在 `tioka.*` 下，用 `@ConfigurationProperties` 类绑定并带默认值，类名 `<Domain>Properties`，与 `*AutoConfiguration` 同包。本文各节的「配置」小节给出键名与默认值。

### 2.6 测试分层

| 层 | 命名 | 运行方式 | 依赖 |
| --- | --- | --- | --- |
| 单元 | `*Test` | `mvn test` | 无外部依赖；Redis/DB 用接口替身 |
| 集成 | `*IT` | `mvn verify`（failsafe） | Testcontainers：PostgreSQL 16 + pgvector、Redis 7；单例容器，所有 IT 共享 |
| 契约 | `*ContractTest` | `mvn test` | 无 |
| 闸门 | `gate/G{n}*GateIT`，`@Tag("gate")` | CI 独立任务 | 双实例 + 容器 |

集成测试隔离规则（ENG-01）：每个测试用例用 `TestFixtures.newWorkspace()` 新建独立空间和用户，只断言本用例创建的数据；禁止断言列表第一条、禁止依赖执行顺序。

### 2.7 分支、PR 与完成定义

- 分支 `feat/<工作项编号>-<简述>`，PR 标题以工作项编号开头，模板必填对应 ADR（已有 `.github/pull_request_template.md`）。
- 一个工作项一个 PR；超过 800 行改动拆成多个 PR，先合契约和迁移。
- **完成定义**：本文该节「测试」小节全部用例实现并通过；「完成标准」逐条满足；CI 全绿；涉及 API 的，OpenAPI（springdoc 生成）已更新且前端类型已重新生成。
