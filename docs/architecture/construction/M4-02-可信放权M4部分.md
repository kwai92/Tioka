## 1. TRU-11 影子上岗（9 人天，W62–W63）

### 1.1 影子 Run 从哪里来

| 来源 | 改动 |
| --- | --- |
| 编排规则（主要） | `orchestration-biz`：规则版本增加 `shadow`（布尔）与 `actual_mapping`（JSONPath 列表）。`accept_mode = observe` 且 `shadow = true` 时，推断事件在记 `WOULD_ACCEPT` 的同一事务里创建一个影子 Run（`orch_run` 标记 `shadow`，不参与回执生效、不写 `orch_fact`），并派 `origin = shadow` 的 Turn。显式事件照常由人处理 |
| 历史回放 | `eval-biz`：批次评测的被测对象可选「影子模式」，每条用例以 `origin = shadow` 运行（与 `origin = eval` 的区别：工具走真实 `prepare` 而不是桩，用于对照真实预演结果） |
| 候选版本双跑（EVO-11，M4-01 第 11 节） | 同一派发路径，多一个「目标 Agent 版本」参数；本节实现时把它做成参数，EVO-11 不再改派发 |

### 1.2 硬约束的落点

| 约束 | 落点 | 说明 |
| --- | --- | --- |
| 只能 `prepare` 不能 `commit` | `runtime-biz` 的 ToolGateway **commit 入口**：`origin = shadow` 直接拒绝并写审计 | 这是 commit 路径上的一处判断，不在 prepare 管线里；持 **K1b** 一次。READ 工具照常执行 |
| 自治判定 | 管线第 10 步（TRU-09 已有）对 `origin = shadow` 返回 `SHADOW_ONLY` | 已有，回归测试 |
| 不外发 | 回答卡片（M2-03）、`tell` 通知、去向许可步骤（DAT-02）检查 `origin`：影子 Turn 的外发一律丢弃并记一条 `status` item「影子模式不外发」 | 三处各加一个判断，不建新机制 |
| 用量 | 影子 Turn 的模型调用 `purpose = EVALUATION`，计入空间评测预算，不占用户配额 | 在 Turn 创建时由 `origin` 决定 purpose |
| 静态规则 | ArchUnit `shadowNeverCommits`：commit 实现类必须调用影子检查；冻结库不允许有条目 | 与 `ShadowNeverCommitsIT` 双保险 |
| 可见性 | 影子 Turn 只出现在负责人的「影子审阅」列表（权限 `trust:shadow:review`），不出现在用户会话 | `runtime-biz` 查询过滤 |

### 1.3 比对

| 步骤 | 做法 |
| --- | --- |
| 记录 | 影子 Turn 结束时，把它产生的变更单（ADR-033 预演结果）写 `trust_shadow_case.proposed_json` |
| 结构化比对 | 编排跟进订阅（ADR-020 修订第 8 条）收到结案事件时，按规则的 `actual_mapping` 映射出「人实际做了什么」写 `actual_json`，逐关键字段比较，全部一致记 `AGREE` |
| 非结构化比对 | 无映射字段时，用 `shadow-agreement` 评估器判定（`purpose = EVALUATION`）；该评估器未过 EVO-09 校准时，结果只记录不计入一致率，报告标出 |
| 无对照 | 每日任务：结案后 7 天仍无对照数据的用例记 `NO_TRUTH`，不进一致率 |
| 人工耗时 | 结案事件带人工处理耗时的，写 `human_seconds`（TRU-15 在 M4 之后用它生成实测基线） |

### 1.4 上岗报告

- 触发：影子期满（缺省 14 天或 50 个有对照用例，以后到为准）。
- 内容：按动作类别的一致率与 **按材料单元聚类的 Wilson 区间**（ADR-034 评测修订，统计函数用 EVO-07 的）、不一致的典型例子（影子建议与人工处理并排）、人工耗时分布、建议初始等级（下界 ≥ 0.85 建议 L1，≥ 0.95 建议 L2）。
- 影子期产生的人工结论按 ADR-068 第 1 节进入密封集或开发集（调 `eval-api`）。
- 负责人确认后：规则切到 `accept_mode = auto`；各动作类别按确认的等级写 `trust_autonomy`（经 `AutonomyApi` 内部方法，写 `trust_autonomy_event` 与审计）；EVO-10 的上线阶段从 E3 推进到 E4 或 E5（EVO-10 已合入时）。

### 1.5 测试

| 用例 | 断言 |
| --- | --- |
| `ShadowNeverCommitsIT` | 影子 Run 跑完一个含 3 个写工具的工单，ToolGateway 0 次 commit，FakeErp 无变化 |
| `ShadowNoOutboundIT` | 影子 Turn 的回答卡片与 `tell` 都没有发出；轨迹里有「影子模式不外发」 |

| 事件 | 发布方 | 状态 |
| --- | --- | --- |

### 3.2 一条账怎么算

按 ADR-035「记账」一节的算法，本节只写数据从哪来：

| 字段 | 来源 |
| --- | --- |
| `outcome` | 编排 Run 终态与审批记录：无审批无复核 → `AUTO`；有审批或复核 → `ASSISTED`；Run 被转人工处理 → `HANDED_OFF`；失败 → `FAILED`；规则判定无事可做 → `NOTHING` |
| 审批次数、复核次数 | `runtime_approval` 按 `run_id` 关联键（ADR-073）统计 |
| `cost_micros` | `model_usage` 按 `run_id`（编排、Flow）或 `turn_id`（对话任务）求和，含子 Agent 与团队成员的调用；**只算生产用途**，`purpose = EVALUATION` 的线上评估与影子用量不计入（推荐方案，见第 3.4 节） |
| 工具单次成本 | ToolDescriptor 可选声明的单价 × 调用次数 |
| `department_id` | 任务类型的部门，缺省取授权书的部门；纯字符串，与 Foundation 数据维度取值一致（约束 F44） |
| `baseline_id` | 事件发生时刻生效的基线；基线修改不回溯 |
| 端到端时效与等待时长 | 事件到达到任务结束；审批停留单独记，不计入人工 |

### 3.3 冲销

ADR-035 只写了「被撤销时写一条冲销」，没有写一个任务里多个动作先后被撤销、以及撤销早于记账的情况。本文定案如下（推荐方案，ADR-029 第 79 条登记）：

| 情况 | 处理 |
| --- | --- |
| 一个任务的第一个动作被撤销 | 写一条冲销：`subject_kind = ACTION`、`subject_id = actionId`、`outcome = UNDONE`、`reverses_id` 指向原账，`saved_minutes` = 原账的相反数再减撤销人工（缺省 5 分钟） |
| 同一任务的其他动作随后被撤销 | 每个动作再写一条冲销，只扣撤销人工，不再冲原账的节省 |
| 撤销时原账尚未写（Run 还在进行） | 消费者按退避重试（最长 24 小时）；仍找不到原账时进死信并告警 |
| 幂等 | 唯一约束 `(subject_kind, subject_id, outcome)` 不变：`ACTION` 维度按动作唯一 |

备选：A. 冲销按任务唯一，后续撤销不入账。会漏掉撤销人工，不采用。B. 原账改为可更新。违反账本只增，不采用。

### 3.4 评测用量是否计入任务成本

推荐：**不计入**，线上评估与影子用量属于平台质量成本，进入「平台分摊」的月末记录（空间配置的月度固定费用之外，再加当月评测用量），在看板上单列。理由：采样是随机的，计入会让同类任务的单件成本随抽样波动；影子期没有生产任务可挂。备选：按 ADR-035 原文计入被采样任务。需负责人在第 79 条确认，确认前按推荐实现，开关在空间配置。
