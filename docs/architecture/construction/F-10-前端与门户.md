## 2. 全局约定（贯穿全篇，Code Review 必查）

### 2.1 令牌与权限口径（硬约束）

- **令牌只带身份**：访问令牌承载 Keycloak 用户 ID、Foundation 账号 ID、人员 ID、工号、姓名、主组织单元编码，**不带角色与权限**（S15 §9.2）。
- **菜单与按钮可见性来自 starter 权限快照 / 接口**，不来自令牌、也不前端硬编码：
  - 菜单：基座路由由前端包按快照返回的「可见菜单树」生成；无权限项不渲染。
  - 按钮：`v-perm` 指令按快照权限码集合判定；无权限不渲染（直访仍由后端 403 兜底）。
- 管理台自身也是一个接入应用（`kind=ADMIN`），其菜单、权限码同理由权限清单（BAS-05）与快照驱动（F-05、S15 §8.3）。
- **禁止 `tenant_id`**（ADR-029 第 60 条）：前端不得出现任何租户字段、租户切换或 `tenant:*` 权限码。
- 权限码格式 `资源:动作`（S15 §11.1、ADR-052 第 7 条）；Foundation 自身用 `fdn:*` 前缀。

### 2.2 登录（Keycloak / OIDC）

以 S15 §9.2 与 ADR-029 第 32 条为准：**授权码 + PKCE 由后端承载**。

```text
未登录 → 前端包整页跳转  GET /api/fdn/auth/oidc/{idp}/authorize?redirect={path}
       → Keycloak 授权页（授权码 + PKCE）
       → 后端 callback（换码、校验、关联人员）→ 写 HttpOnly 刷新 Cookie
       → 302 回前端 /login/callback（URL 中不带任何令牌）
       → 回调页调 POST /api/fdn/auth/refresh 取访问令牌（只在内存）→ 进入 redirect
```

- 前端**不接触** IdP 令牌；回调 URL **不带**令牌；访问令牌只在前端内存，刷新令牌放 HttpOnly、`SameSite=Strict` Cookie。
- 默认 IdP `keycloak`，可用 `VITE_OIDC_IDP` 覆盖。
- 关联失败：Keycloak 流程停在「请联系管理员」，Foundation 生成待处理关联（BAS-FE-04 的「外部身份关联」页处理）。

### 2.3 状态与数据获取（沿用既有栈，不引入新框架）

| 用途 | 方案 |
| --- | --- |
| 服务端数据（列表、详情、字典、快照） | `@tanstack/vue-query`（ADR-029 第 26 条）包在 Axios 客户端之上 |
| 会话态（当前用户、权限码、菜单树、可见应用） | Pinia `session` store |
| 门户待办计数、消息未读 | Pinia `portal` store + vue-query 轮询/事件刷新 |
| 表单校验 | Element Plus 表单规则 |
| 流式（本文件不涉及） | 沿用 [45-FE](../enterprise/45-FE-前端架构.md) §6，与门户无关 |

约定：查询缓存键含快照版本；收到 `fdn.authz.changed`（或前端包暴露的失效回调）后失效 `session` 与相关查询。

### 2.4 路由生成与守卫

1. 基座启动 → 调 `/me` 类接口取当前用户、可见菜单树、权限码集合 → 写入 `session` store。
2. 前端包按菜单树 `addRoute` 注册动态路由（`component` 由菜单项的组件标识映射到本地组件表）。
3. 全局守卫：未登录 → 走 §2.2；已登录但目标路由不在动态路由中 → 403 页。
4. 菜单渲染与动态路由同源，保证「菜单不显示即路由不存在」。

## 8. 微前端基座挂接（无界 wujie）

基座由 BAS-FE-10 在 M4 交付（子应用注册与加载、路由同步、保活、通信接口、降级页）；本文件只做 **BAS-FE-12 的挂接与验证**，并遵守其约定（S15 §6.3、ADR-054 第 4 条）。

### 8.1 子应用注册

| 项 | 约定 |
| --- | --- |
| 框架 | 无界（wujie）；iframe 承载 JS 沙箱、Web Component 承载 DOM（S15 §6.3） |
| 注册粒度 | 一个子系统通常注册为一个子应用；体量大的模块（如 Tioka 工作流画布）可单独注册 |
| 加载方式 | 菜单项声明：内置路由（门户自身）/ 子应用（入口 + 子路由）/ iframe（第三方）/ 外链（新窗口） |
| 登记来源 | 子应用入口来自应用登记（BAS-04 `accessUrl`）；菜单与加载方式来自权限清单（BAS-05） |

### 8.2 路由与菜单由权限清单驱动

- 门户**不硬编码**子应用路由：可见菜单树来自授权快照，菜单项携带「加载方式 + 子应用入口 + 子路由」。
- 基座路由与子应用路由同步：刷新与深链可直达子应用的具体页面（S15 §6.3）。
- 降级：子应用加载失败显示错误页与「在新窗口打开」按钮，不影响基座与其他子应用。

### 8.3 令牌透传

- **基座完成登录**；子应用通过前端包取令牌，不再各自跳转登录；子应用被单独访问时由前端包自行走单点登录（S15 §6.3）。
- 子应用不直接访问基座全局对象；令牌与用户上下文只经前端包定义的通信接口取得（ADR-054 第 4 条）。
- 收到单点注销 / `fdn.account.sessions_revoked` 后，基座与子应用令牌一并失效。

### 8.4 样式隔离与通信

| 项 | 约定 |
| --- | --- |
| 样式隔离 | wujie 天然隔离 DOM 与全局变量；统一外观由前端包提供主题变量与布局规范，子应用在基座内运行时隐藏自身外层布局 |
| 共享依赖 | 不强制共享 Vue / Element Plus 实例；公共组件（组织人员选择器、字典组件等）以 npm 包发布，各子应用自行引入 |
| 通信 | 只允许经前端包通信接口：基座 → 子应用下发用户、主题、语言；子应用 → 基座发「打开某功能」「更新待办数」「显示通知」等事件；事件名与载荷在前端包内统一定义 |

| 权限 | BAS-FE-05、13 | 角色、授权、数据维度与值、快照查询、谁有这个权限 |
| 公共服务 | BAS-FE-06、08、09 | 字典、参数、消息与待办、公告、文件、工作日历、编号 |
| 日志 | BAS-FE-06 | 审计查询与导出、登录日志查询 |
| 同步 | BAS-FE-07 | 来源配置、手动触发、差异预览与确认、任务记录 |

**契约约定**：

- 所有写接口要求 `Idempotency-Key`（S15 §14.1、总纲 §2.4）；前端 http 客户端统一在写请求注入。
- 401 → 走 §2.2 重新刷新或回登录；403 → 403 页 / 空态（[45-FE](../enterprise/45-FE-前端架构.md) §7）。
- 快照与 `/me` 类接口返回的权限码是菜单与按钮的唯一来源；前端不缓存越权数据。

## 11. 硬约束与完成标准

硬约束（Code Review 必查）：

1. **禁止 `tenant_id`**（ADR-029 第 60 条）：前端无租户字段、无租户切换、无 `tenant:*` 权限码。
2. **菜单 / 按钮不硬编码**：一律来自授权快照 / 前端包接口；本地不得维护菜单或权限码清单。
3. **令牌只带身份**：前端不解析权限，权限来自快照；前端不接触 IdP 令牌（ADR-029 第 32 条）。
4. **不引入新框架**：沿用 Vue 3 + TS + Vite + Pinia + Vue Router + Element Plus + `@tanstack/vue-query`（[45-FE](../enterprise/45-FE-前端架构.md) §2）。
5. 仓库边界：[F-01](F-01-并行开发任务包.md) §7.2——foundation 包不改 Tioka 业务代码；`tioka-ui` 的 BAS-FE-12 只改接入层，不改 Foundation 中台实现。
6. **本文件无数据库迁移**。

完成标准：

- [ ] BAS-FE-03〜09、12、13 各页面 / 改造按第 3 节路由—权限表落地，菜单按快照显隐，直访 403。
- [ ] 前端包被正确消费（登录、菜单路由、按钮指令、字典、选择器、401/403）；无重复实现。
- [ ] 门户启动台只显示有权限的应用；消息与待办可深链回应用。
- [ ] BAS-FE-12：Tioka 与合同业务系统挂入门户，单点、深链、保活、降级、六项自检通过。
- [ ] §10 单测 / 组件测试绿；`npm test` / `npm run typecheck` 绿；端到端冒烟通过。
- [ ] 无 `tenant_id`、无硬编码菜单 / 权限码；无新增数据库迁移。
