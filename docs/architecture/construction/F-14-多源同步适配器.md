## 0. 范围与两个工作项的关系

| 工作项 | 内容 | 来源 | 迁移 | 闸门 |
| --- | --- | --- | --- | --- |
| BAS-32 | 第一批适配器（插件包）：**企业微信、钉钉**（IM 通讯录）、**北森云**（HR）；并把 BAS-12 的**飞书适配器对齐到 SPI**（`SourceCapabilities` 与 `IncrementalMode` 声明补齐） | ADR-078 第 4 条 | 不新增表 | 并入 `GfSyncVendorGateIT`（IM + HR 部分） |
| BAS-33 | 第二批适配器（插件包）：**泛微 OA**、**金蝶**（ERP） | ADR-078 第 4 条 | 不新增表 | `GfSyncVendorGateIT`（OA、ERP 各一源） |

**交付分两批的原因**（ADR-078 第 4 条）：第一批覆盖最常见的「IM 通讯录」与「HR 系统」两种权威来源形态；第二批的 OA / ERP 多为补充外部身份或权威来源备选，客户实际只接 1〜2 个来源，按插件装载、按客户装配（ADR-078 备选节）。

**顺序与「首个权威来源」的依赖**：S15 §21 第 4 条把「首个客户组织数据的权威来源」列为待确认项，**它决定 BAS-32 内部三个来源的先后**。本文件按「企业微信 / 钉钉（IM）→ 北森云（HR）→ 泛微 → 金蝶」给出默认顺序；客户已明确时以客户为准（不改人天）。

### 0.1 硬约束（贯穿全文，Code Review 必查）

- **禁止** `tenant_id` / `sys_tenant`（ADR-029 第 60 条）；隔离边界只有组织单元树与「人员 + 应用」。
- 主键 ULID，带前缀时列宽 `VARCHAR(32)`；时间列一律 `TIMESTAMPTZ`，DO 字段 `LocalDateTime`（UTC 语义），领域对象与 API 用 `Instant`（[00-施工总纲](00-施工总纲.md) §2.2）。
- **单一权威来源**（ADR-052 第 4 条、ADR-078 第 3 条）：一个部署只有一个来源负责组织树与人员主信息；其余来源只补外部身份，**六源全纳不等于六源并列写主信息**。
- 外部身份关联**只按工号或已验证邮箱**，不按姓名匹配、不自动建人（ADR-026、ADR-052 第 3 条）。
- **不引入 iPaaS / 集成平台，不新增中间件**（ADR-078 备选节）；来源访问只经 FND-07 出网通道（`EgressClient`）。
- 适配器插件只依赖 `foundation-starter-sync` 的 SPI 与 `-api` 契约，**不依赖中台 `-biz`**（ADR-078 第 8 条，ArchUnit 守护）。

## 3. 冲突与权威源编排

### 3.1 权威来源的唯一性与切换

- `fdn_sync_source.authority = TRUE` 的部分唯一索引沿用 F-08 §8（`uq_sync_source_authority`），**一个部署至多一个权威来源**（ADR-052 第 4 条）。本文不新增第二套判定。
- **多源并存时的落地范围**（ADR-078 第 3 条、F-08 §4）：

| 来源角色 | 可写对象 | 不可写 | 越界处置 |
| --- | --- | --- | --- |
| 权威来源（`authority = TRUE`） | 组织树、人员主信息、岗位、职级、任职、外部身份 | — | — |
| 非权威来源 | **只写 `fdn_external_identity`** | 人员 / 组织 / 岗位 / 任职主信息 | 引擎落地前校验来源角色；越界记 `AUTHORITY_CONFLICT` 冲突条目 |
| 金蝶特例（权威来源备选且未启用为主源） | `fdn_external_identity` + **字段级补充**（成本归属组织等，见 §9.5） | 人员主信息、主职 | 同上，并记字段级来源标记 |

- **切换权威来源是显式管理动作**（F-08 §5）：停旧来源 → 启新来源 → 跑一次全量对账（`mode = RECONCILE`）→ 确认无漂移后转正式。**不做来源间的自动合并**（ADR-078 备选节否决「多源并列写主信息」）。

### 3.2 优先级配置

来源优先级用**既有登记字段**表达，不新增配置模型：`fdn_sync_source.authority`（唯一权威）+ `fdn_sync_source.status`（启用 / 停用）+ `fdn_sync_source.code`（稳定标识）。管理台（BAS-FE-07 扩展）呈现为「来源角色」列，可选项固定三个：

| 角色 | 落地范围 | 说明 |
| --- | --- | --- |
| 权威来源 | 组织树 + 人员主信息 + 岗位/职级/任职 | 全部署唯一 |
| 外部身份来源 | 只写 `fdn_external_identity` | 默认值；企微 / 钉钉 / 飞书 / LDAP / SCIM 的常规角色 |
| 补充来源 | 外部身份 + 白名单字段级补充 | 仅金蝶（§9.5）与「OA 只补组织联系方式」一类的受限场景；白名单字段在字段映射里显式标记 |

### 3.3 字段级来源标记与本地锁定（继承 F-08 / ADR-078 第 5 条）

- **裁决顺序**（自上而下，逐字段判定）：
  1. **本地锁定字段**（`fdn_person.local_locked_fields` / `fdn_org_unit.local_locked_fields`）——任何来源都不覆盖，跳过的字段记 `LOCKED_FIELD` 冲突（可查、不告警）；
  2. **权威来源**——覆盖本地未锁定字段；
  3. **补充来源的白名单字段**——只在权威来源**未提供该字段**时写入；
  4. **其他来源**——不参与主信息裁决，只写外部身份。
- **字段级来源标记的落点（不新增表）**：落地时对每个被写入的字段写一条 `fdn_sync_log`（`action = UPDATE`），`detail_json` 记 `{internalField, externalField, sourceCode, beforeDigest, afterDigest}`（**只记 SHA-256 摘要，不记原值**，与 ADR-074 §1 的载荷策略一致）。复盘时按「对象 + 来源」查询即可回答「这个字段最后是谁写的」。
- **物化视图属待确认项**：若客户要求「字段 → 最后写入来源」的**在线可查**（而非查日志），需要新增一张映射表（示意 `fdn_sync_field_provenance`，ULID 主键、`TIMESTAMPTZ`），走 §9.6 + S15 §21 的待确认流程，用 F2 号段 **V200 起**。**默认不做**（克制：日志已能回答同一问题，多一张写放大明显的表不划算）。

## 4. 增量与对账：各源差异如何在 SPI 下统一

各源的增量方式差别很大，统一由 **SPI 声明 + 引擎编排**吸收，适配器内部各自实现（ADR-078 第 1、6 条）：

| 来源 | 原生增量方式 | 适配器映射到 SPI | 游标内容（`cursor_json`） |
| --- | --- | --- | --- |
| 企业微信 | 通讯录变更回调（成员 / 部门 增改删） | `EVENT_CALLBACK`：回调 → 触发一次 `INCREMENTAL`；无事件时的变更由定时全量兜底 | 上次全量完成时刻（`TIMESTAMPTZ`，ISO-8601 UTC） |
| 钉钉 | 通讯录事件订阅（`user_add_org` / `user_modify_org` / `user_leave_org` / `org_dept_*`） | 同上 | 同上 |
| 北森云 | `lastModified` 时间戳增量（员工 / 组织 / 岗位 / 任职各一游标） | `TIMESTAMP`：`fetchIncremental` 传 `since`，逐对象类型推进 | `{objectType: lastModified}` 的 JSON（按 `SyncObjectType` 分别记） |
| 泛微 OA | 组织 / 人力资源接口的 `lastmoddate` 时间戳 | `TIMESTAMP` | `{objectType: lastmoddate}` |
| 金蝶 | `FModifyDate` 时间戳 + 分页 | `TIMESTAMP`（`FULL_ONLY` 亦可，按客户是否开放增量接口降级） | `{formId: lastModifyDate}` |

统一规则：

1. **游标推进只由引擎做**：适配器在 `advanceCursor(cursor, page)` 里给出推进点，引擎在**增量成功后**写回 `fdn_sync_task.cursor_json`（F-08 §7）。同一游标重复拉取幂等，`getUpdated` 语义由适配器保证只返回变更集。
2. **幂等键恒为 `SyncKey(来源, 外部ID)`**（F-08 §7）：同一批、重复批次**零重复新增**；事件重复投递（回调重发）不产生第二条记录。
3. **无增量能力的来源**（或客户未开放增量接口）声明 `FULL_ONLY`，走分页全量 + 差异预演（同样是「先算差异再落地」，ADR-078 第 6 条）。
4. **差异预演（dry-run）**：预演与落地共用 `DiffPreviewService`（F-08 §6），口径不分叉；管理台可先预演再确认落地。
5. **每日全量对账**：`RECONCILE` 定时任务（`foundation.sync.schedule.full-reconcile-cron`，默认每日 03:00）对每个启用来源跑一次全量快照与差异比对，修复「增量漏拉 / 人为改动」造成的漂移，同样受删除保护阈值约束（F-08 §7）。
6. **对账修复遵循权威来源**：非权威来源的对账只校验外部身份关联，**不修主数据**；权威来源的对账可修主数据。

## 5. 删除保护与差异预演

**完全沿用 F-08 §6 / ADR-052 第 5 条 / ADR-078 第 7 条**，阈值与行为不变：

| 维度 | 默认阈值 | 行为 |
| --- | --- | --- |
| 一次停用人员 | 超过 **5%** 或超过 **50 人** | 暂停落地剩余停用：`status = PAUSED`、`pause_reason = THRESHOLD`，等管理员确认（`POST /api/sync/tasks/{id}/confirm`）或取消（`/cancel`） |
| 删除（实为停用）组织单元 | 超过 **10 个** | 同上 |

本批次的两点补充，**不改变阈值**：

- **事件型来源（企微 / 钉钉）无法事前预演**：与 SCIM 同理，改为**时间窗口内累计**判定（缺省 10 分钟窗口），复用 `DeleteProtectionPolicy` 的窗口模式（F-08 BAS-13 §4 已实现）。**新增与修改照常落地，只暂停剩余停用**。
- **多源场景下阈值按来源独立计算**，不跨来源合并：一个部署只有一个权威来源，只有它能产生主数据停用；非权威来源的「删除」只影响外部身份关联，不触发人员停用，因此不参与阈值判定（报告中单列「外部身份解绑」计数）。

| 形态 | 每个来源一个**独立 jar**：`foundation-sync-adapter-wecom`、`-dingtalk`、`-beisen`、`-weaver`、`-kingdee`；打包与签名遵循 FND-12 精简插件宿主（哈希写 `fdn_sync_source.plugin_sha256`，F-08 §8） |

| SPI 版本 | 插件声明它编译所依赖的 `foundation-starter-sync` SPI 版本；宿主校验不匹配即拒绝加载并告警（FND-12），避免「主干升级后旧插件静默用错契约」 |

| 二开 | 客户自有来源按 SPI 二开，**不改 Foundation 主干**（ADR-078 第 8 条） |

```yaml
foundation:
  sync:
    adapters: [feishu, ldap, wecom, dingtalk, beisen]   # 第一批（BAS-32）；第二批（BAS-33）追加 weaver, kingdee
    adapters-dir: /opt/foundation/plugins/sync
```

## 7. 出网、凭证与台账

- **出网**：所有来源访问经统一出网通道 `EgressClient`（FND-07 / ADR-021），目标主机 + 路径模板须在**出网白名单**内；白名单外的目标直接拒绝，并按 ADR-072 记审计。**不为本批次新增白名单之外的通路，不引入直连 HTTP 客户端旁路**。
- **凭证**（ADR-042）：来源凭证（企微 `corp_secret`、钉钉 `appsecret`、北森 `app_secret`、泛微与金蝶的 app 凭证 / 签名密钥）**只存引用**——`fdn_sync_source.credential_ref` 指向密钥来源，值由 `CredentialCipher`（AES-256-GCM，AAD = 凭证 ID + 所属对象 ID）加密保存。**配置文件与 `config_json` 中不得出现明文密钥或令牌**；access_token 只存内存（含过期时间），不落库、不写日志。
- **台账**（ADR-074）：每次同步写 `ext_interaction`，方向 `OUT`，`kind` 用既有的 **`http`**（不为目录类来源新增 `kind`，F-08 §9）：
  - `counterparty` = 来源实例（`source_code`）；`endpoint` = 主机 + 路径模板（不含查询串）；`operation` = 如 `sync.person.fetch`、`sync.dept.full`、`sync.employment.incremental`；
  - `auth_mode` = `SERVICE`；`credential_id` = 凭证 ID（不存值）；`request_digest` / `response_digest` = SHA-256；缺省只存哈希与大小（ADR-074 §3）；
  - **入站事件回调**（企微 / 钉钉）按 ADR-074 §2 在**验签后、去重前**写一条 `IN` 台账，`dedupe_key` 去重，重复记 `status = DUPLICATE`。
- **限流与重试**：适配器内部实现分页节流与退避重试，次数与退避基准取 `foundation.sync.rate-limit.*`（默认 `default-qps: 10`、`max-retries: 3`、`backoff-ms: 500`，F-08 §11）；**命中对方限流（如企微 `45009`、钉钉频率限制）必须退避而非立即失败**。
- **告警**：
  - 凭证失效 / 权限不足 / 限流持续失败 → 任务 `FAILED`，发 `fdn.sync.failed`，管理台告警；
  - 单条对象失败 → 记 `fdn_sync_log` ERROR 并跳过，任务记 `PARTIAL`；
  - 能力缺失、字段被本地锁定跳过 → 只记报告与日志，**不告警**（可查即可，避免噪音）；
  - 台账写失败 → 按 ADR-074 与 ADR-072 处置（失败仍记审计），不因台账失败回滚已落地的同步结果。

## 8. 事件：同步变更事件不变

**不新增事件类型**（ADR-078 第 10 条、F-08 §10）。新增来源只增加既有事件中「来源」字段的取值：

| 事件 | 触发 | 本文的影响 |
| --- | --- | --- |
| `fdn.org.changed` | 权威来源同步实际改动了组织单元 | 事件体 `{id, version, changeType}` **不变**；仅新增 `source` 取值 `WECOM` / `DINGTALK` / `BEISEN` / `WEAVER` / `KINGDEE` |
| `fdn.person.created` / `updated` / `disabled` | 权威来源改动了人员 | 同上 |
| `fdn.sync.completed` / `paused` / `failed` | 同步结果 | 复用；`sourceCode` 取新来源，`capabilityMissing` 记 §2 的缺失项 |
| `fdn.account.sessions_revoked` | 停用 / 离职链路（BAS-14） | 由北森 / 金蝶的离职状态经停用链路触发，**不改该事件** |

事件仍经 outbox 投递到 RocketMQ 主题 `fdn-events`，事件体只带 ID、版本与变化类型（S15 §14.2）。

## 9. 逐源设计

通用的包结构与类骨架（每个来源一个 jar，包名 `com.tioka.foundation.sync.adapter.<source>`）：

```text
foundation-sync-adapter-<source>/
├── src/main/java/com/tioka/foundation/sync/adapter/<source>/
│   ├── <Source>SyncAdapter.java          # implements SyncSourceAdapter：能力声明 + fetchFull/fetchIncremental/fetchOne
│   ├── <Source>Client.java               # 经 EgressClient 的 HTTP 调用、签名、分页
│   ├── <Source>AuthProvider.java         # 凭证引用 → access_token（内存缓存，含过期）
│   ├── <Source>RecordMapper.java         # 外部 JSON → ExternalRecord（字段名归一）
│   ├── <Source>FieldConverter.java       # FieldConverter 实现（枚举归一、时间归一、编码前缀等）
│   ├── <Source>Probe.java                # 连通性与能力探测（逐项结果，不抛异常）
│   └── <Source>AdapterConfiguration.java # @ConfigurationProperties("foundation.sync.<source>") + SPI 注册
└── src/main/resources/META-INF/services/com.tioka.foundation.sync.spi.SyncSourceAdapter   # 插件宿主用
```

公共约定（五源一致，下面各节不再重复）：认证走 `credential_ref`；请求经 `EgressClient` + 出网白名单；每次调用写 `ext_interaction`（§7）；分页与限流由适配器内部实现；字段映射经 `fdn_sync_field_mapping` 配置；本地锁定字段不覆盖；**不按姓名匹配**（`MatchBy` 只能是 `EMP_NO` / `VERIFIED_EMAIL`）。

### 9.1 企业微信（WECOM，BAS-32）

| 部分 | 约定 |
| --- | --- |
| 对象 | 部门（组织单元）、成员（人员）、外部身份；**不含职级**；兼岗以「多部门 + 主部门」近似为多条任职，报告标注 |
| 认证 | `corp_id` + `corp_secret`（`credential_ref`）→ `access_token`（约 2 小时，内存缓存）；回调另需 `token` / `encoding_aes_key`（同样只存引用） |
| 全量 | 部门树递归拉取（`fetch_child`）+ 各部门成员列表；每个部门一次请求，`fetchFull` 内实现按部门游标与节流 |
| 增量 | **通讯录变更回调**（成员 / 部门 增改删）→ 触发一次 `INCREMENTAL`；**定时全量兜底**（`full-sync-cron`，默认每日一次）；`fetchOne(deptId/userid)` 供回调与对账修复回查 |
| 分页 / 限流 | 无全局分页，按部门递归；接口 QPS 分档，命中 `45009`（频率超限）退避重试，重试仍失败则 `FAILED` + 告警 |
| 外部身份 | `userid` → `WECOM_USERID`；`openid`（微信插件 / 外部联系人）→ `WECOM_OPENID`。候选关联按**工号或已验证邮箱**；关联不上生成待处理关联，**不自动建人** |
| 字段映射要点 | 部门：`id → external_id`、`name → fdn_org_unit.name`、`parentid → parent_id`（→ `path` / `depth` 重建）、`order → sort_no`、部门负责人 → `leader_person_id`；成员：`userid → fdn_person.external_id`、`name → name`、`mobile → mobile`、`email → email`、`position → 岗位文本`、`department/main_department → fdn_employment`（主部门 → `is_primary = TRUE`）；转换函数 `phone-normalize`（去区号前缀）、`enum-normalize`（状态） |
| 失败与告警 | 凭证失效 / 应用无通讯录权限 → `FAILED` + `fdn.sync.failed`；回调验签失败 → 拒绝并记审计（ADR-074、ADR-072）；单成员失败记 ERROR 跳过，任务 `PARTIAL` |

配置（`foundation.sync.wecom.*`）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 来源级开关（与 `fdn_sync_source.status` 联动） |
| `corp-id` | — | 非密钥标识，可放 `config_json` |
| `credential-ref` | — | 指向 `corp_secret` 的密钥引用（**不落明文**） |
| `callback-token-ref` / `callback-aes-key-ref` | — | 回调验签 / 解密凭证引用 |
| `full-sync-cron` | `0 0 4 * * *` | 定时全量兜底 |
| `qps` | 10 | 覆盖 `foundation.sync.rate-limit.default-qps` |

### 9.2 钉钉（DINGTALK，BAS-32）

| 部分 | 约定 |
| --- | --- |
| 对象 | 部门、用户、外部身份；「角色（角色组）」**不作为独立对象**，只作 `POSITION` 的**可选候选**（映射到岗位文本 / 岗位编码） |
| 认证 | `appkey` + `appsecret`（`credential_ref`）→ `access_token`（内存缓存）；事件订阅另需 `aes_key` / `token`（只存引用） |

| 分页 / 限流 | 分页（offset/size）；按接口频率限制节流退避，超限退避重试 |
| 外部身份 | `userid` → `DINGTALK_USERID`；`unionid` → `DINGTALK_UNIONID`（跨应用稳定，作首选关联键）。关联按**工号或已验证邮箱**；`unionid` 需在应用授权范围内才可读，读不到时标注能力受限 |
| 字段映射要点 | 部门：`dept_id → external_id`、`name → name`、`parent_id → parent_id`、`order → sort_no`；用户：`userid → external_id`、`name → name`、`mobile → mobile`、`email → email`、`title → 岗位文本`、`dept_id_list → fdn_employment`（主部门 → 主职）；角色（角色组 `role_name` / `group_name`）→ `POSITION` 候选（仅当客户启用岗位字典）；转换函数 `enum-normalize`、`role-to-position` |
| 失败与告警 | 与企微一致；另：`unionid` 不可读（未授权）→ 记 WARN「外部身份能力受限」并在报告标注，**不使任务失败**；事件重复投递按台账 `dedupe_key` 去重 |

配置（`foundation.sync.dingtalk.*`）：`enabled`、`app-key`、`credential-ref`、`event-aes-key-ref`、`event-token-ref`、`full-sync-cron`、`qps`、`position-from-role`（布尔，是否用角色组生成岗位候选，默认 `false`）。

### 9.3 北森云（BEISEN，BAS-32）—— HR 权威首选

| 部分 | 约定 |
| --- | --- |
| 对象 | 组织、人员、**岗位**、**任职**、**职级**（本批次唯一提供职级的来源） |
| 认证 | `app_key` + `app_secret`（`credential_ref`）→ `access_token`（OAuth 客户端凭证模式，租户级；内存缓存，含过期） |
| 全量 | 各对象分页（`page` / `size`）拉全量；组织 / 员工 / 岗位 / 职级 / 任职各自一个 `SyncObjectType` 游标 |
| 增量 | **`TIMESTAMP`**：按 `lastModified` 逐对象类型拉增量；员工状态（在职 / 离职）变化 → 人员停用 / 离职（`fdn_person.status = LEFT`，走 BAS-14 的停用离职链路）；每日全量对账（`RECONCILE`）修复漂移 |
| 分页 / 限流 | `page/size` 分页 + 接口 QPS 节流；退避重试 |
| 外部身份 | **工号 → `BEISEN_EMP_NO`**（主关联键）；北森内部 `userId` → `BEISEN_USER_ID`。关联按**工号或已验证邮箱** |
| 字段映射要点 | 部门：`departmentId → external_id`、`departmentName → name`、`parentId → parent_id`、`code → code`、负责人 → `leader_person_id`；员工：`employeeNo → fdn_person.emp_no`（**唯一**）、`name → name`、`mobile/email → mobile/email`、`status → fdn_person.status`；岗位：`positionId → fdn_position.external_id`、`positionName → name`、所属部门 → `org_unit_id`；职级：`jobLevelId → fdn_job_grade.code`、`jobLevelName → name`、序列 → `series`；任职：`employmentRecord → fdn_employment`（`is_primary` 取主职标记）；转换函数 `date-normalize`（`TIMESTAMPTZ`，ISO-8601 UTC）、`enum-normalize`（在职 / 试用 / 离职 / 停薪） |
| 作为人事权威源之一 | 矩阵角色为**权威来源首选**：当它被设为权威来源时，组织树 + 人员主信息 + 岗位 + 任职 + 职级均以它为准；企微 / 钉钉 / 飞书退回「外部身份」角色（§3.1） |
| 失败与告警 | 认证失败 / 授权范围不足 / 接口限流持续失败 → `FAILED` + `fdn.sync.failed`；职级或岗位接口未开通 → 记「能力缺失」标注（不静默跳过）；离职人数超阈值（§5）→ `PAUSED` + `fdn.sync.paused` 告警 |

配置（`foundation.sync.beisen.*`）：`enabled`、`app-key`、`credential-ref`、`tenant-id`（北森租户标识，非 `tenant_id` 列，仅请求参数）、`incremental-cron`（覆盖全局 `0 */15 * * * *`）、`qps`、`objects`（显式声明启用的对象子集，缺省全启用）。

### 9.4 泛微 OA（WEAVER，BAS-33）

| 部分 | 约定 |
| --- | --- |
| 对象 | 组织、人员；**岗位（`POSITION`）为可选能力**——仅当客户启用泛微人力资源模块且岗位字典被采用时声明，否则标注缺失 |

| 增量 | **`TIMESTAMP`**：按组织的 `lastmoddate` 拉增量；无可靠增量接口的版本降级为 `FULL_ONLY` + 差异预演（声明能力，引擎据此编排，ADR-078 第 6 条） |
| 分页 / 限流 | 分页 + 接口 QPS 节流；退避重试 |

| **OA 场景下权威源的选择** | 泛微多数情况下是「流程与人事审批的载体」，组织与人员主数据往往**来源于 HR 系统**。因此：① 客户已有北森 / 其他 HR 系统时，泛微**默认只作外部身份来源**；② 客户**只有泛微一个组织源**（无独立 HR 系统）时，才把它设为权威来源，且切换按 §3.1 的显式动作执行；③ 管理台在把 OA 类来源设为权威来源时**强制二次确认**（提示「组织口径可能与人事口径不一致」）——这只是界面确认，不新增表与配置模型 |
| 字段映射要点 | 部门：`id/deptcode → external_id/code`、`name → name`、`supdepid/parentid → parent_id`、`departmentmark → sort_no`；人员：`workcode/employeeNo → emp_no`、`lastname → name`、`mobile/email → mobile/email`、`status → fdn_person.status`、所属部门 → `fdn_employment`；转换函数 `enum-normalize`、`date-normalize` |
| 失败与告警 | 与北森一致；另：组织口径异常（同一人在多个平级部门、部门树有环）→ 记 `SYNC_DATA_INVALID` 日志并跳过该条，任务 `PARTIAL`，报告标注，不使整批失败 |

配置（`foundation.sync.weaver.*`）：`enabled`、`app-key`、`credential-ref`、`base-url`（客户部署地址，须在出网白名单内）、`incremental-cron`、`qps`、`enable-position`（布尔，默认 `false`）。

### 9.5 金蝶（KINGDEE，BAS-33）—— ERP 口径与冲突处理

| 部分 | 约定 |
| --- | --- |
| 对象 | 组织、岗位、人员、任职（**受口径限制**，见下） |
| 认证 | 金蝶开放平台 app 凭证 + 签名（`credential_ref`）；租户标识（`acctID` / `lcid`）放 `config_json`（非密钥） |
| 全量 | 按业务对象（`FormId`）分页拉取；组织（`BD_Org` 类）、岗位、人员、任职各一游标 |
| 增量 | **`TIMESTAMP`**：按 `FModifyDate` / 最后更新字段增量 + 分页；客户未开放增量查询时降级 `FULL_ONLY` + 差异预演 |
| 分页 / 限流 | `FormId` + 分页 + 接口 QPS 节流；退避重试 |
| 外部身份 | 人员编码 → `KINGDEE_EMP_NO`（工号）；组织编码 → `KINGDEE_ORG_NO`。关联按**工号或已验证邮箱** |
| **财务 / HR 口径与冲突处理** | 金蝶是 ERP，人员与组织是**业务 / 财务口径**（费用承担组织、核算主体、供应商 / 客户联系人），与 HR 口径（人事组织、任职）**不等价**。因此：① **金蝶默认不作人员主信息来源**——客户端已有北森等 HR 源时，金蝶角色为「外部身份来源」或「补充来源」（§3.2）；② 金蝶侧的「组织」若只是核算组织，映射到 `fdn_org_unit` 需**显式字段映射 + 类型限定**（不在映射表中登记的核算组织不建组织单元，只记外部身份）；③ 金蝶的「任职」记录只用于补充**成本归属 / 核算组织**类的白名单字段（字段级来源标记，§3.3），**不覆盖 `fdn_employment` 的主职与 `fdn_person` 的主信息**；④ 与 HR 源同字段冲突时**以 HR 源为准**（权威来源优先），冲突记 `AUTHORITY_CONFLICT`（含字段名与两个来源），可查不告警；⑤ 仅当客户**没有 HR 系统、以金蝶为唯一人事载体**时，才把它设为权威来源（§3.1 显式切换 + 二次确认） |
| 字段映射要点 | 组织：`FNumber → code/external_id`、`FName → name`、`FParentId → parent_id`、类型过滤（只取映射表登记的类型）；岗位：`FNumber → fdn_position.code`、`FName → name`；人员：`FNumber → emp_no/external_id`、`FName → name`、`FEmail/FTel → email/mobile`（有则映射，无则留空不覆盖）；任职：`FOrgId → fdn_employment.org_unit_id`（**仅补充**）、成本归属字段 → 白名单补充字段；转换函数 `org-type-filter`、`enum-normalize`、`date-normalize` |
| 失败与告警 | 与北森一致；另：口径冲突（金蝶非权威却返回人员主信息变更）→ **不落地**，记 `AUTHORITY_CONFLICT` 并计入报告「口径冲突」计数，连续超阈值（缺省同 §5 的 5%）→ 发 `fdn.sync.paused` 提示管理员复核来源角色配置 |

配置（`foundation.sync.kingdee.*`）：`enabled`、`app-key`、`credential-ref`、`acct-id` / `lcid`（标识，非密钥）、`base-url`（出网白名单内）、`incremental-cron`、`qps`、`org-type-filter`（允许建组织单元的 ERP 组织类型白名单）、`supplement-fields`（白名单补充字段，缺省空）。

### 10.3 闸门 `GfSyncVendorGateIT`（`@Tag("gate")`）

口径差异说明（**原文并列，两者都写进闸门**）：ADR-078 后果节定为「**至少两个来源（一个 IM、一个 HR）**完成全量 + 增量 + 差异暂停 + 外部身份关联的端到端用例」；S15 §18.1 BAS-33 验收定为「`GfSyncVendorGateIT` **覆盖 OA 与 ERP 各一源**」。据此编排：

| 阶段 | 用例 | 断言 |
| --- | --- | --- |
| BAS-32（必过） | `VendorGateIT#imSourceE2E` | **企业微信或钉钉**任一个：全量建树建人 → 增量（事件 / 定时）→ 差异暂停 → 外部身份关联（工号 / 已验证邮箱） |
| BAS-32（必过） | `VendorGateIT#hrSourceE2E` | **北森云**：全量 + 增量（`TIMESTAMP`）→ 离职停用 → 差异暂停 → 外部身份关联；岗位 / 职级 / 任职落地 |
| BAS-33（必过） | `VendorGateIT#oaSourceE2E` / `#erpSourceE2E` | **泛微 OA**、**金蝶**各一源：全量 + 增量 → 字段映射与本地锁定 → 权威来源 / 补充来源角色判定 → 台账写入 |
| BAS-32 / 33（必过） | `VendorGateIT#repeatIdempotent`、`#reconcileFixesDrift` | 重复同步幂等；对账修复漂移 |

测试桩：`WireMock` 录制桩（先例见 [F-00](F-00-F阶段实施计划.md) §2 R7、[F-01](F-01-并行开发任务包.md)）；企微 / 钉钉 / 北森优先接官方测试企业或测试租户，泛微 / 金蝶无公开沙箱，**以 WireMock 桩为准**，真实客户环境联调不计入闸门转绿（沿用 F-00 第 7 节风险 3 的处置）。

### 10.4 完成标准

- [ ] 五个适配器插件 jar 可按 `foundation.sync.adapters` 按需装载；SPI 版本与签名校验生效；适配器**不依赖中台 `-biz`**（ArchUnit 通过）
- [ ] 能力矩阵逐源声明与 §2 一致；**能力缺失在同步报告显式标注**，无静默跳过
- [ ] 权威来源唯一（`uq_sync_source_authority` 生效）；非权威来源只写 `fdn_external_identity`；金蝶口径冲突不覆盖人员主信息（记 `AUTHORITY_CONFLICT`）
- [ ] 外部身份按**工号或已验证邮箱**关联；**不按姓名匹配、不自动建人**；无匹配生成待处理关联
- [ ] 增量方式差异（事件回调 / 时间戳 / 分页全量）在 SPI 下统一；游标推进正确；**幂等键 = 来源 + 外部 ID**；重复同步零重复新增
- [ ] 每日全量对账修复漂移；删除保护沿用「停用 > 5% 或 > 50 人、删除组织 > 10 个暂停待确认」；事件型来源用窗口累计判定
- [ ] 字段映射与「本地锁定字段不被覆盖」对五源均生效；字段级来源标记可经日志复盘
- [ ] 凭证**只存引用不落明文**；访问走出网白名单；按 ADR-074 写 `ext_interaction`（OUT 与回调 IN）；限流退避重试与告警可用
- [ ] 同步变更事件**不新增类型**，仅在 `fdn.org.changed` / `fdn.person.*` / `fdn.sync.*` 上增加来源取值
- [ ] 无 `tenant_id`；ULID 主键；`TIMESTAMPTZ`；未引入 iPaaS / 新中间件
- [ ] §10.1〜10.3 用例通过；`GfSyncVendorGateIT` 转绿；OpenAPI 已更新（复用 F-08 的同步接口，通常无新增路径，若有则同步前端类型重新生成）
