## 1. 发布前置步骤：EVO-06、EVO-10、MH-15 与 GOV-06 共用的插入点

### 1.1 为什么要一个注册点

GOV-12 的发布流程是「校验 → 发布」。M4 有四个工作项要在这两步之间插东西：EVO-10（变更分级）、EVO-06（Agent 发布回归门禁）、MH-15（平台配置的受影响 Agent 评测）、GOV-06（资产发布审批，约束 F33）。EVO-06 与 GOV-06 都排在 W59–W60，分属 BE-A 与 BE-C，直接改发布服务必然撞车。所以照 M3-07 第 3.2 节的做法，加第四个注册点。

### 1.2 设计（推荐方案）

| 项 | 定案 |
| --- | --- |
| 位置 | `governance-api` 的「发布前置步骤」接口与固定序号表；`governance-biz/config` 的发布服务按序号依次调用 |
| 序号 | 10 校验（GOV-12 现有）→ 20 变更分级（EVO-10）→ 25 专项闸门（解析方案为 PRS-08，护栏策略为 GRD-08）→ 30 评测门禁（Agent 类资产为 EVO-06；平台配置类资产为 MH-15）→ 40 资产审批（GOV-06）→ 50 发布（GOV-12 现有） |
| 唯一性 | 同一序号、同一资产类型只能注册一个实现；同一序号可以按资产类型各有实现 |
| 步骤结果 | `PASS`（进入下一步）、`BLOCK`（终止，版本回到草稿并写原因）、`NEED_APPROVAL`（写一条通用审批，审批通过后从下一步继续）、`PENDING`（异步执行中，完成后回调继续） |
| 版本状态 | 草稿 → 校验通过 → `GATING`（评测门禁运行中）→ `PENDING_APPROVAL` → 已发布；`GATING` 与 `PENDING_APPROVAL` 期间版本不可被会话使用（ADR-025「执行侧只认已发布」） |
| 异步 | 评测门禁要跑批次评测，分钟级。步骤返回 `PENDING` 后发布请求立即返回；评测结束时由 `eval-biz` 发事件，发布服务消费后继续。超时（缺省 2 小时）按 `BLOCK` 处理 |
| 合并 | 评测门禁的结果 `INCONCLUSIVE`（非劣效无法判定）转为 `NEED_APPROVAL`，并与第 40 步的资产审批**合并成一条审批**，审批卡片同时带门禁报告与最差 5 条用例，避免同一次发布审两次 |
| 适用 | 每个资产类型声明自己走哪些步骤：Agent、Flow 发布走 20、30、40；解析方案、护栏策略走 25、30、40；别名、路由计划、binding、知识库嵌入绑定、`sys.*` Prompt 走 30（MH-15）、40；其他资产只走 40 |

**备选**：A. EVO-06 与 GOV-06 各自在发布服务里加调用（不建注册点）。两人同时改一个类，排期上已确定冲突，不采用。B. 门禁做成发布后的异步检查、失败再回滚。违反「未审批资产无法被会话使用」，不采用。

注册点由 M4 第 0 波后端骨架包建（M4-07 定包号）；本文的 EVO-10、EVO-06、MH-15，M4-03 的 PRS-08，M4-04 的 GRD-08 与 M4-06 的 GOV-06 只新增步骤类。

### 1.3 测试

| 用例 | 断言 |
| --- | --- |
| `PublishPreStepOrderTest` | 步骤按序号执行；同一序号、同一资产类型注册两个实现时启动失败 |
| `PublishGatingInvisibleIT` | `GATING` 与 `PENDING_APPROVAL` 状态的 Agent 版本不能被新会话选用 |
| `GateAndApprovalMergedIT` | 门禁 `INCONCLUSIVE` 且该资产类型要求审批时，只生成一条审批 |
| `GateTimeoutBlocksIT` | 评测超时后版本回到草稿，原因可见 |

## 2. 夜间评测：哨兵与各专项夜间回归合并

ADR-069 第 6 节要求把解析夜间回归（ADR-062）、结构化夜间回归（ADR-066）并入哨兵评测。M4 还有护栏回归（GRD-08）与知识召回（KNW-07 已在 CI，夜间用真实模型再跑一次）。统一做法：

| 项 | 定案 |
| --- | --- |
| 调度 | 一个定时任务 `eval.nightly`，数据库锁互斥（ADR-072 第 9 节），登记进 ENG 基线「必须互斥的任务」清单 |
| 子任务 | 「夜间套件」SPI：每个套件声明名称、要跑的数据集或子集、被测对象的取法、预算份额、告警规则。M4 内的实现：哨兵（EVO-12，本文）、解析回归（PRS-08，M4-03）、结构化回归（SCH-10 已有，迁入）、护栏回归（GRD-08，M4-04）、知识召回（KNW-07 已有，迁入） |
| 预算 | 用量 `purpose = EVALUATION`；空间评测预算之外另设平台级夜间上限（缺省每晚等于一个 R3 Agent 的 50 个材料单元单次成本），按套件份额分配，超出的套件跳过并告警 |
| 被测配置 | 一律用生产配置：别名当时解析到的实际快照、当前已发布的解析方案与护栏策略 |
| 告警 | GOV-13 规则模板 `eval.sentinel.drift`，按套件名与 Agent 切片；结构化失败、证据绑定错误、护栏「有后果攻击」出现时直接告警，不看容差 |
| 结果 | 每个套件一条 `eval_run`（`kind = NIGHTLY`），报告格式按 ADR-068 第 6.1 节；进 ADR-041 统计 |

`eval_run.kind` 增加 `NIGHTLY`、`SHADOW_DUAL`、`SELECTION`、`SENTINEL` 四个取值，随 V237 加。夜间套件 SPI 由 EVO-12 建（W70），PRS-08（W69）比它早一周：PRS-08 先按本节契约实现一个独立定时任务，EVO-12 合入后在同一 PR 里改为套件注册（EVO-12 的可改范围包括 PRS-08 的调度入口）。
