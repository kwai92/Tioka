## BAS-02 组织主数据（P0，7 人天）

### 1. 定位与范围

Foundation 中台的「主数据」第一块：以本项为组织与人员的唯一权威来源，账号（BAS-03）、权限（BAS-05）、同步（BAS-11）、数据权限（BAS-06）都读它。各应用只读本项。

本项做：组织单元、岗位、职级、人员、任职、汇报关系的建模与增删改查；Excel 导入导出；变更历史。本项不做：账号开通与推送 Keycloak（BAS-03）、从外部来源同步（BAS-11/12/13）、角色与授权（BAS-05）、数据范围计算（BAS-06）。

### 2. 领域模型与表

#### 2.1 实体与规则

| 实体 | 关键字段 | 规则 |
| --- | --- | --- |
| 组织单元 | 编码、名称、类型（集团 / 公司 / 部门）、上级、排序、负责人、状态、来源与外部 ID、生效时间 | 编码全局唯一；树深不超过 10 层；停用前要求下级与在岗人员已迁出 |
| 岗位 | 编码、名称、所属组织单元（可空表示全局岗位）、状态 | 可作为角色授予对象（BAS-05 引用） |
| 职级 | 编码、名称、序列、等级 | 只做属性，供数据规则与策略引用 |
| 人员 | 工号、姓名、手机、邮箱、类型（员工 / 外包 / 数字员工）、状态（在职 / 停用 / 离职）、来源与外部 ID | 工号唯一；手机、邮箱加密存储，列表脱敏显示 |
| 任职 | 人员、组织单元、岗位、是否主任职、开始与结束日期 | 一人恰有一个主任职；兼职用多条任职表达 |
| 汇报关系 | 人员、直属上级 | 可由同步来源提供，也可按组织负责人推导 |

补充约定（在实体规则内推导，不新增字段之外的机制）：

- **树深与子树**：组织单元存 `parent_id`、物化路径 `path` 与 `depth`（根 `depth=1`），写入时校验 `depth ≤ 10` 并拒绝成环；`path` 供「本部门及以下」等子树查询（BAS-06）免递归。
- **状态取值**：组织单元、岗位、职级用 `ACTIVE` / `DISABLED`；人员用 `ACTIVE`（在职）/ `DISABLED`（停用）/ `LEFT`（离职）。枚举存 `name()` 字符串（总纲 §2.2）。
- **来源与外部 ID**：`source` 取值 `local`（管理台录入 / Excel 导入）/ `feishu` / `ldap` / `scim` / `tioka:agent`（数字员工）；`(source, external_id)` 唯一，作为同步与导入的幂等键（BAS-11 沿用）。
- **敏感字段**：手机、邮箱存密文（`*_cipher`，AES-256-GCM，主密钥来自 `SecretStoreAdapter`，与 S15 §15、ADR-026 一致）与查重用的 `*_hash`；接口出参先解密再按列表/详情分别脱敏。

#### 2.2 建议表名

| 实体 | 表名 | 主键前缀 |
| --- | --- | --- |
| 组织单元 | `fdn_org_unit` | `org_` |
| 岗位 | `fdn_position` | `pos_` |
| 职级 | `fdn_job_grade` | `grd_` |
| 人员 | `fdn_person` | `per_` |
| 任职 | `fdn_employment` | `emp_` |
| 汇报关系 | `fdn_report_line` | —（复合语义，主键为 `person_id`） |
| 变更历史 | `fdn_org_change_log` | `chg_` |

主键为 ULID，带前缀列宽 `VARCHAR(32)`（总纲 §2.2）；时间列 `TIMESTAMPTZ`，DO 字段 `LocalDateTime`（UTC 语义），领域对象与 API 用 `Instant`；不引入 `tenant_id`（ADR-029 第 60 条）。

### 3. 数字员工

人员类型含「数字员工」（`type = DIGITAL_EMPLOYEE`），对应 Tioka 的已发布 Agent（ADR-032 岗位授权书）。

| 项 | 约定 |
| --- | --- |
| 何时建立 | Tioka 在 Agent **上岗**（发布并启用）时调用本项接口建立数字员工档案；**下岗**（停用 / 撤回）时置为停用 |
| 归属 | `source = 'tioka:agent'`、`external_id = Agent 的 Tioka ID`，`(source, external_id)` 唯一，重复上岗幂等 |
| 组织位置 | 出现在组织树里，通过主任职（`fdn_employment.is_primary`）挂到其服务部门（授权书 `departmentId` 对应的组织单元），可有岗位 |
| 负责人 | **必填**：记为 `fdn_report_line` 的直属上级（对应 Agent 的 `owner_id` 所属人员），`source = 'local'` |
| 登录账号 | **无**：不为其开通账号，不推送到 Keycloak（BAS-03 明确不处理 `DIGITAL_EMPLOYEE`） |
| 待办处理人 | 可被选为待办处理人（BAS-16 的待办登记按人员选择器筛选时可选中数字员工） |
| 权限 | 由 **Tioka** 计算，不由 Foundation 授予：Tioka 按 Agent 的岗位授权书（ADR-032）与负责人权限**求交集**（ADR-039 的 `on_behalf_of` 交集），Foundation 只提供身份与组织位置 |
| 维护方 | 档案由 Tioka 经接口维护；Tioka 用其服务账号调用，写接口带 `Idempotency-Key` |

数字员工的建立 / 停用复用人员接口，另提供一个按 Agent ID 定位的入口（见 §5）：`PUT /api/fdn/persons/by-external/{source}/{externalId}`，避免 Tioka 侧保存 Foundation 的 `per_` ID。上岗 → 建人员 + 主任职 + 汇报关系，并发出 `fdn.person.created`；下岗 → 状态置 `DISABLED`，并发 `fdn.person.disabled`（供 Tioka 与业务系统收敛）。

### 4. 导入导出与变更历史

#### 4.1 Excel 导入（500 人规模）

| 项 | 约定 |
| --- | --- |
| 入口 | `POST /api/fdn/org/import`（multipart，`Idempotency-Key` 必填），模板含四个工作表：组织单元、岗位、人员、任职 |
| 校验 | 逐行校验：编码 / 工号唯一、上下级存在、树深 ≤ 10、主任职唯一、日期区间合法；整表先全量校验，任一行失败则整体拒绝并返回逐行错误（不半量落库） |
| 幂等 | 以业务键 upsert：组织单元按 `code`、岗位按 `code`、人员按 `emp_no`、任职按 `（person_id, org_unit_id, start_date）`；同一文件重复导入**零新增、零更新**；`Idempotency-Key` 相同则直接返回上次结果 |
| 规模 | 500 人按 `foundation.org.import.batch-size` 分批写入同一事务；一次导入一条 `IMPORT` 变更历史 |
| 结果 | 返回 `{taskId, created, updated, skipped, errors[]}`；导出与结果可查询 |

#### 4.2 导出

`GET /api/fdn/org/export`：按筛选条件导出组织 / 人员 / 任职（Excel），单次上限 `foundation.org.export.max-rows`（默认 100000）；导出**仅导出授权的字段，手机与邮箱按脱敏值或明文由开关控制**（默认脱敏）。

#### 4.3 变更历史

- 每次组织 / 岗位 / 职级 / 人员 / 任职 / 汇报关系的写操作，在同一事务内追加一行 `fdn_org_change_log`（含 `before_json` / `after_json` 字段白名单摘要，来源与操作人）。
- 变更历史是**只追加**表，不随业务回滚以外的路径修改；同时管理类操作由 BAS-10 审计管道汇聚（S15 §13）。变更历史用于「某人 / 某组织单元的历次变化」查询，审计用于全局检索，两者并存不替代。

### 5. 接口

均以 Foundation 管理台（管理端）与应用（只读、服务账号）为调用方；写接口一律要求 `Idempotency-Key`（由 `foundation-starter-web` 处理，S15 §14.1、总纲 §2.4）。权限码由管理台应用的权限清单声明（BAS-05 导入）。

| 方法与路径 | 权限码 | 说明 |
| --- | --- | --- |
| `GET /api/fdn/org/tree?rootId&depth&includeDisabled` | `org:read` | 组织树查询（含岗位计数） |
| `GET /api/fdn/org/units?q&type&status&page&size` | `org:read` | 组织单元列表 / 搜索 |
| `POST /api/fdn/org/units` | `org:write` | 新建（`Idempotency-Key`） |
| `PUT /api/fdn/org/units/{id}` | `org:write` | 修改 / 移动（`Idempotency-Key`） |
| `DELETE /api/fdn/org/units/{id}` | `org:write` | 停用（校验下级与在岗人员已迁出，`Idempotency-Key`） |
| `GET /api/fdn/positions`、`POST`、`PUT /{id}`、`DELETE /{id}` | `org:write` | 岗位增删改（写带 `Idempotency-Key`） |
| `GET /api/fdn/job-grades`、`POST`、`PUT /{id}`、`DELETE /{id}` | `org:write` | 职级增删改（写带 `Idempotency-Key`） |
| `GET /api/fdn/persons?q&type&status&orgUnitId&page&size` | `org:person:read` | 人员列表（脱敏） |
| `GET /api/fdn/persons/{id}` | `org:person:read` | 人员详情（按权限决定明文 / 脱敏） |
| `POST /api/fdn/persons` | `org:person:write` | 新建人员（`Idempotency-Key`） |
| `PUT /api/fdn/persons/{id}` | `org:person:write` | 修改人员（`Idempotency-Key`） |
| `DELETE /api/fdn/persons/{id}` | `org:person:write` | 停用人员（`Idempotency-Key`） |
| `PUT /api/fdn/persons/by-external/{source}/{externalId}` | `org:person:write` | 按外部 ID（Tioka Agent ID）维护数字员工档案（`Idempotency-Key`） |
| `GET/POST /api/fdn/persons/{id}/employments`、`PUT/DELETE /{employmentId}` | `org:person:write` | 任职增删改（含改主任职） |
| `PUT /api/fdn/persons/{id}/report-line` | `org:person:write` | 维护直属上级（可由来源提供或按组织负责人推导） |
| `GET /api/fdn/persons/{id}/changes`、`GET /api/fdn/org/units/{id}/changes` | `org:read` | 变更历史查询 |
| `POST /api/fdn/org/import`、`GET /api/fdn/org/import/{taskId}` | `org:import` | Excel 导入与结果（`Idempotency-Key`） |
| `GET /api/fdn/org/export` | `org:export` | Excel 导出 |

`fdn-org-api` 发布 OpenAPI，前端（BAS-FE-03）按生成类型接线；其他模块（BAS-05、BAS-06、`foundation-starter-client` 的组织查询）只依赖 `fdn-org-api` 的 DTO 与接口。

### 6. 事件

经 outbox 投递到 RocketMQ 主题 `fdn-events`（S15 §14.2）；事件体**只带 ID、版本与变化类型**，订阅方需详情时回查接口，避免敏感字段在消息里扩散。

| 事件 | 触发 | 事件体 |
| --- | --- | --- |
| `fdn.org.changed` | 组织单元新增、修改、移动、停用 | `{id, version, changeType}`，`changeType ∈ CREATED / UPDATED / MOVED / DISABLED` |
| `fdn.person.created` | 人员新增（含数字员工上岗） | `{id, version, changeType}` |
| `fdn.person.updated` | 人员修改、调岗（任职变化） | `{id, version, changeType}` |
| `fdn.person.disabled` | 人员停用、离职、数字员工下岗 | `{id, version, changeType}` |

- `version` 取 `fdn_org_unit.version` / `fdn_person.version`（乐观锁行版本，每次写 +1），订阅方据此判重与排序。
- 发布时机：`TransactionSynchronization.afterCommit`（总纲 §2.4）；写库与写 `fdn_outbox` 同事务，中继由 `foundation-starter-mq` 负责。
- 本项只发上述事件；`fdn.authz.changed`、`fdn.account.sessions_revoked` 分别由 BAS-07、BAS-14 发出，此处不重复。

### 7. 配置项、包结构与关键类

#### 7.1 配置项（`foundation.*`）

```yaml
foundation:
  org:
    max-tree-depth: 10              # 组织树最大深度，超限拒绝创建与移动
    import:
      template-version: v1          # 导入模板版本
      batch-size: 200               # 单事务分批写入行数
      max-rows: 20000               # 单文件最大数据行
    export:
      max-rows: 100000              # 单次导出最大行
      include-sensitive: false      # 导出是否含手机/邮箱明文，默认脱敏
    person:
      mask:
        mobile: tail-4              # 手机脱敏：保留后 4 位，其余 *
        email: domain               # 邮箱脱敏：保留首个字符与 @ 后域名
```

配置类 `OrgProperties`（`@ConfigurationProperties(prefix = "foundation.org")`，带默认值），与 `OrgAutoConfiguration` 同包（总纲 §2.5）。

```text
foundation-org-api/                      # 对外契约，其他模块只依赖这里
  com.tioka.foundation.org.api.dto.*      # OrgUnitView、PersonView、EmploymentView、ImportResult
  com.tioka.foundation.org.api.event.*    # OrgChangedEvent、PersonCreatedEvent、PersonUpdatedEvent、PersonDisabledEvent
foundation-org-biz/
  com.tioka.foundation.org
  ├── api/             # Controller 与请求/响应 record，只做参数校验与权限注解
  ├── application/     # 应用服务，事务边界（@Transactional）在这里
  ├── domain/          # 领域对象与纯规则（树、任职、数字员工约束），不依赖 Spring
  ├── infrastructure/  # *Repository、mapper/、persistence/*DO、加密与脱敏
  └── config/          # OrgProperties、OrgAutoConfiguration
```

跨模块只依赖对方 `-api`（ArchUnit 守护，S15 §5.3）；规则集由 `foundation-test` 提供，含「禁止 `tenant_id`」。

#### 7.3 关键类

| 类 | 层 | 职责 |
| --- | --- | --- |
| `OrgUnitController` / `PersonController` / `EmploymentController` / `OrgImportController` | api | REST、权限注解、`Idempotency-Key` 入口 |
| `OrgUnitService` | application | 建 / 改 / 移动 / 停用，维护 `path`、`depth`，写变更历史并入 outbox |
| `PersonService` | application | 人员增删改、数字员工档案（按外部 ID 幂等）、任职与汇报关系维护 |
| `EmploymentService` | application | 主任职与兼职的写入与切换 |
| `OrgImportService` | application | Excel 解析 → 全量校验 → 分批 upsert → 结果与变更历史 |
| `OrgExportService` | application | 按条件导出，脱敏 |
| `OrgTreePolicy` | domain | 树深 ≤ 10、防环、停用前「下级与在岗人员已迁出」校验、负责人推导 |
| `EmploymentRule` | domain | 一人一主任职、任职日期区间、主任职切换的原子性 |
| `DigitalEmployeeRule` | domain | 数字员工约束：无账号、负责人必填、必须挂主任职 |
| `PersonCipher` / `PersonMasker` | infrastructure | 手机 / 邮箱加解密（主密钥来自 `SecretStoreAdapter`）与列表 / 详情脱敏 |
| `OrgUnitRepository` / `PersonRepository` / `EmploymentRepository` / `ReportLineRepository` | infrastructure | MyBatis-Plus 仓储，ORM 只用 MyBatis-Plus |
| `OrgChangeLogWriter` | infrastructure | 追加 `fdn_org_change_log` |
| `OrgEventOutbox` | infrastructure | 写 `fdn_outbox`（只带 id / version / changeType） |

### 8. 测试

| 用例 | 层 | 断言 |
| --- | --- | --- |
| `OrgTreePolicyTest` | 单元 | 第 11 层拒绝；移动成环拒绝；停用仍有下级或在岗人员时拒绝 |
| `EmploymentRuleTest` | 单元 | 第二条主任职拒绝；改为兼职后可新增另一主任职；主任职切换原子 |
| `DigitalEmployeeRuleTest` | 单元 | 数字员工缺负责人拒绝；数字员工不产生账号；下岗置 `DISABLED` |
| `PersonCipherTest` / `PersonMaskerTest` | 单元 | 加解密往返；列表脱敏保留后 4 位 / 域名 |
| `OrgEventPayloadTest` | 单元 | 事件体只含 `id`、`version`、`changeType`，无敏感字段 |
| `OrgUnitIT` | 集成 | 建 — 移 — 停全链路；`path` / `depth` 正确；按 `code` 唯一 |
| `PersonCipherIT` | 集成 | 手机 / 邮箱落库为密文；按 `*_hash` 命中；详情按权限返回明文 |
| `EmploymentIT` | 集成 | 主任职部分唯一索引生效；多人多部门兼职正确 |
| `OrgImportIT#idempotentReimport` | 集成 | 同一文件导入两次：第二次零新增、零更新、`skipped=行数` |
| `GfOrgImportGateIT`（`@Tag("gate")`） | 闸门 | 导入 500 人后树、岗位、兼职、数字员工任职正确；重复导入幂等 |

`GfOrgImportGateIT` 为 [F-00](F-00-F阶段实施计划.md) §6.1 的 GF 闸门用例，W81 转绿；依赖 Testcontainers PostgreSQL 16（`foundation-test` 提供，单例容器）。
