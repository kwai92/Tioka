### CEL 子集与编译

允许：列引用 `row.col`、principal 属性 `principal.attrs.x` / `principal.roles`、字面量、`== != < <= > >=`、`in`、`&& || !`、`startsWith`。其余语法在保存策略时拒绝（`cel-java` 解析后遍历 AST 白名单）。

```java
record PlannedQuery(String whereSql, List<Object> params,      // JDBC：外层 WHERE，参数化
                    Map<String, String> restParams,              // REST：可下推的过滤
                    Predicate<Map<String, Object>> postFilter,   // REST：不可下推部分，插件内执行
                    List<String> selectColumns) {}

PlannedQuery compile(DatasetPolicy p, Principal eff, DelegationGrant g, DatasetQuery q) {
    // 1. rows：when 对 eff 求值为真的规则，取其 predicate 的 OR；一条都不为真 → 返回 FALSE（零行）
    // 2. AND 用户 filter AND grant.scope 中与列同名的键（如 contractId in [...]）
    // 3. principal.* 在编译期代入为常量，只剩 row.* 进入 SQL / REST
    // 4. 列：q.columns ∩ 描述中的列；DROP 列从 select 去掉
}
```

JDBC 执行：`SELECT {cols} FROM ({source.sql}) t WHERE {whereSql} LIMIT ?`。`source.sql` 由管理员在登记数据集时填写并经 `EXPLAIN` 校验只读（拒绝含 `INSERT/UPDATE/DELETE/DDL` 的语句，连接用只读账号）。

### 掩码

| 掩码 | 规则 |
| --- | --- |
| PARTIAL | 字符串保留前 3 后 4，中间 `*`；数字保留量级（`12****`） |
| HASH | `sha256(tenantSalt + value)` 前 16 位，可用于关联但不可还原 |
| NULLIFY | 置为 null |
| DROP | 不返回该列 |

### 去向判定

```text
SinkGuard.check(kind, ref, label, payload):
  rule = gov_label_sink(ws, kind, ref) ?? gov_label_sink(ws, kind, '*') ?? 缺省（见下）
  if label <= rule.max_label: PASS
  switch rule.on_exceed:
    DENY                → DENY
    REDACT_THEN_DENY    → p2 = RegexPiiHook.redact(payload)；p2 已无命中且 label 仅因 PII 超限 → REDACTED(p2)，否则 DENY
    REDACT_THEN_APPROVE → 同上，否则 REQUIRE_APPROVAL（通用审批，subject_type=data_egress）
```

缺省规则（`tioka.governance.label-sink-defaults`）：MODEL_PLAN 允许到 INTERNAL；IM 内部群到 CONFIDENTIAL、外部群到 INTERNAL；MAIL、SMS 到 INTERNAL；MCP 到 INTERNAL。空间管理员按客户合规决定放宽，例如商业租赁合同审查空间已获同意把合同送到百炼、DeepSeek，需在该空间把对应路由计划配置为 CONFIDENTIAL。

## DAT-03 按标签选模（2 人天）

`ModelGateway` 在路由前加一步：

```text
plans = 路由计划候选（ADR-024）
allowed = plans.filter(p → SinkGuard.check(MODEL_PLAN, p.id, thread.label) == PASS)
if allowed 为空 → Turn FAILED(NO_ELIGIBLE_MODEL)，提示「当前对话含 {label} 数据，没有获准的模型」
else 在 allowed 内按原路由模式选模
```

冻结（MH-01）以轮次为单位：标签在轮内上升时，下一次模型调用重新判定，已冻结模型不再获准则按故障接力规则切到获准模型，并在时间线记录「因数据标签切换模型」。

| 用例 | 断言 |
| --- | --- |
| `LabelRoutingIT#switchAfterSecret` | 读到 SECRET 后下一次调用切到私有化计划 |
| `LabelRoutingIT#noEligible` | 无获准计划 → `NO_ELIGIBLE_MODEL` |

错误码：`NO_ELIGIBLE_MODEL` 42210 → 422，`DATA_LABEL_EXCEEDED` 40332 → 403。

## 前端（3 人天）

- 管理后台「数据集」页：登记、列密级与掩码、策略编辑（CEL 输入带语法校验）、DRYRUN 差异查看。
- 空间设置「数据去向」页：按去向配置最高标签与超限处理。
- 对话与轨迹：thread 标题旁显示当前数据标签徽标；被拒的去向在轨迹中显示原因。

## 闸门 G3 追加用例

`gate/G3DataPermissionGateIT`：两位不同区域用户经同一 Agent 查同一数据集，得到不同行与掩码；子 Agent 读到 CONFIDENTIAL 后，结果不能原文发到外部群，下一次模型调用只在获准计划内选模。

## 完成标准

- Agent 访问业务数据只有 `DatasetGateway` 一条路径，ArchUnit 守护。
- 任一 item、thread、黑板产物都能查到数据标签；标签从不自动下降。
- 去向超限时的处理与空间配置一致，并有审计。
