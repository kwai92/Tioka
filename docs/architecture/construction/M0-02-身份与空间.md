## 0. 本节确定的几件事

| 事项 | 结论 |
| --- | --- |
| 认证框架 | Spring Security 6（Boot 3.2 自带），无状态，删除 sa-token（ADR-029 第 28 条） |
| 令牌 | 不透明随机令牌，存 Redis；访问令牌 8 小时，刷新令牌 7 天（ADR-015），刷新即轮换。M1 加 OIDC 时 JWT 走另一条认证路径，不替换本机制 |
| 用户 ID | `auth_user.id` 保持 `BIGINT`，新用户取自序列 `auth_user_id_seq`；在 `Principal.userId`、`owner_id`、`sys_member.user_id` 等处一律用十进制字符串。不使用 `usr_` 前缀（ADR-029 第 31 条，更正总纲 2.2 节） |
| 当前空间 | 请求头 `X-Workspace-Id`；缺省取 `auth_user.default_workspace_id`；必须是 `sys_member` 中的成员 |
| 令牌存放（ADR-028） | 访问令牌只在前端内存；刷新令牌放 HttpOnly Cookie `tioka_rt`（`Path=/api/system/auth; SameSite=Strict; Secure`），JS 读不到。页面刷新后前端先调 `/refresh` 换取访问令牌 |
| SSE 带令牌 | 前端改用 `fetch` 读流（`@microsoft/fetch-event-source`），通过 `Authorization` 头传令牌；**服务端不接受 URL 查询参数里的令牌** |
| 持久层过滤 | MyBatis-Plus 行级插件只按 `workspace_id` 自动追加条件；`owner_id`（私有资源）由应用服务显式过滤；**无 `tenant_id`** |

### 令牌设计

| Redis 键 | 值 | TTL |
| --- | --- | --- |
| `auth:at:{sha256(accessToken)}` | `{"uid":"1001","rt":"<refresh 哈希>","iat":…}` | `tioka.auth.access-ttl`，默认 8h |
| `auth:rt:{sha256(refreshToken)}` | `{"uid":"1001","fam":"<family id>"}` | `tioka.auth.refresh-ttl`，默认 7d |
| `auth:user:{uid}` | Set，成员为该用户所有 at/rt 哈希 | 与最长 rt 相同 |

- 令牌为 32 字节 `SecureRandom` 的 base64url，前缀 `tka_`（访问）、`tkr_`（刷新），便于日志脱敏识别。Redis 中只存 SHA-256。
- 刷新：校验 rt → 删除旧 at、rt → 签发新对。旧 rt 被再次使用（重放）时，按 `fam` 吊销整个令牌族并返回 401。
- 禁用用户、改密码：删除 `auth:user:{uid}` 中所有键。

```java
public interface TokenService {
    TokenPair issue(long userId);
    Optional<TokenClaims> verifyAccess(String accessToken);   // 不存在或过期 → empty
    TokenPair refresh(String refreshToken);                   // 无效 → BizException(UNAUTHORIZED)
    void revoke(String accessToken);
    void revokeAll(long userId);
    record TokenPair(String accessToken, String refreshToken, Instant accessExpiresAt) {}
    record TokenClaims(long userId) {}
}
```

### 初始管理员

`BootstrapAdminRunner implements ApplicationRunner`：当 `auth_user` 中没有 `enabled=true` 且拥有 `tenant_admin` 角色的用户时：

1. 用户名取 `tioka.bootstrap.admin-username`（默认 `admin`）；若与禁用的旧行冲突，旧行改名为 `admin_legacy_1`。
2. 密码取环境变量 `TIOKA_BOOTSTRAP_ADMIN_PASSWORD`；未设置则生成 20 位随机密码，**只打印一次**到日志 `WARN`，并写入 `${tioka.home}/bootstrap-admin.txt`（权限 600）。
3. 写 `sys_member(ws_default, uid, workspace_admin)`，并在 `tenant_admin` 层面写一条 `sys_member(ws_default, uid, tenant_admin)`（M0 用此判断租户管理员；M1 改为 `sys_user_role`）。
4. 设置 `must_change_password=true`（V103 加列 `ALTER TABLE auth_user ADD COLUMN must_change_password BOOLEAN NOT NULL DEFAULT FALSE`）。登录响应带该标志，前端强制跳改密页。

并发：两个实例同时启动时，用 `pg_advisory_xact_lock(hashtext('tioka.bootstrap'))` 保证只创建一次。

### 过滤链

```java
@Bean
SecurityFilterChain api(HttpSecurity http, BearerTokenFilter bearer, PublicApiRegistry pub,
                        RestAuthEntryPoint entry, RestAccessDenied denied) throws Exception {
    return http
        .csrf(c -> c.disable())                                   // 无 Cookie 会话，令牌在头里
        .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
        .cors(Customizer.withDefaults())
        .authorizeHttpRequests(a -> a
            .requestMatchers(pub.matchers()).permitAll()           // @PublicApi 方法
            .requestMatchers("/actuator/health/**", "/v3/api-docs/**").permitAll()
            .requestMatchers("/api/**").authenticated()
            .anyRequest().permitAll())                             // 前端静态资源
        .addFilterBefore(bearer, UsernamePasswordAuthenticationFilter.class)
        .exceptionHandling(e -> e.authenticationEntryPoint(entry).accessDeniedHandler(denied))
        .build();
}
```

`RestAuthEntryPoint` 输出 `ApiResponse{code=40100, message="未登录或令牌已过期"}`，HTTP 401；`RestAccessDenied` 输出 40300，HTTP 403。

### BearerTokenFilter 逻辑

```text
1. 取 Authorization: Bearer <token>；没有 → 放行（交给授权规则决定 401 / permitAll）
2. tokens.verifyAccess(token) 为空 → 401（不再往下走）
3. wsId = header X-Workspace-Id，否则 user.default_workspace_id，否则用户的第一个成员空间
4. principal = loader.load(claims.userId, wsId)
   - 用户不在该空间 → 403 WORKSPACE_FORBIDDEN（新错误码 40302）
   - 用户 disabled → 401 并 revokeAll
5. SecurityContextHolder.getContext().setAuthentication(new TiokaAuthentication(principal))
6. MDC.put("uid", …)、MDC.put("ws", …)；finally 清理 SecurityContext 与 MDC
```

`PrincipalLoader.load`：

```java
Principal load(long userId, String workspaceId) {
    UserRow u = users.require(userId);
    List<MemberRow> ms = members.findByUser(userId);             // sys_member
    MemberRow m = ms.stream().filter(x -> x.workspaceId().equals(workspaceId)).findFirst()
                    .orElseThrow(() -> new BizException(ErrorCode.WORKSPACE_FORBIDDEN, "不是该空间成员"));
    Set<String> roles = ms.stream()
        .filter(x -> x.workspaceId().equals(workspaceId) || x.roleCode().equals("tenant_admin"))
        .map(MemberRow::roleCode).collect(toSet());
    Set<String> perms = rolePermissions.expand(roles);  // sys_role_permission
    return new Principal(String.valueOf(userId), workspaceId, PrincipalType.USER, roles, perms, "password");
}
```

缓存：Redis `auth:principal:{uid}:{ws}`，TTL 60 秒（ADR-029 第 6 条）；`sys_member`、`sys_role_permission` 变更时删除对应键（M0 由 `WorkspaceMemberService` 调用 `PrincipalCache.evictUser(uid)`）。

### 后台任务

`PrincipalHolder.runAs(principal, body)`：保存旧上下文 → 设置新 → 执行 → 恢复。线程池任务必须经 `TiokaExecutors.wrap(executor)` 包装，把提交线程的 Principal 传到执行线程（`DelegatingSecurityContextExecutorService`）。无 Principal 的后台代码（定时清理、迁移）显式调用 `runAs(SystemPrincipals.system(), …)`。

### 白名单（`@PublicApi`）

M0 只有：`login`、`refresh`、`oidc/start`、`oidc/callback`、IM 平台回调（M0 保持现有路径；M2 CON-02 改为 `/api/connector/im/{channel}/{bindingId}/events` 并以平台签名鉴权）、Flow 发布的 webhook（`/api/flows/publications/webhook/{versionId}`，M1 改为 API Key）。其他所有 Controller 方法在 M0 结束时都要么 `@RequirePermission`，要么类级 `@RequirePermission("…")`；M0 期间未标注的方法默认「已登录即可」，由 ArchUnit 冻结库存跟踪。

## FND-07 出网守卫（P0，2 人天）

### 改动

`AirGapService` 重写为 `DefaultEgressGuard implements EgressGuard`（system-biz `application/egress/`），`AirGapService` 删除。所有出站 HTTP（模型、MCP、IM、Embedding、Webhook、知识源）在发请求前调用 `egressGuard.assertAllowed(URI)`；M1 MH-04 后模型调用统一在 Model Hub 里调用一次。

```java
public void assertAllowed(String rawUrl) {
    URI uri = URI.create(rawUrl.trim());                         // 解析失败 → BAD_REQUEST
    String scheme = lower(uri.getScheme());
    if (!Set.of("http", "https").contains(scheme)) deny("scheme", rawUrl);
    String host = IDN.toASCII(lower(uri.getHost()));             // 用户信息、端口、路径都不参与判断
    if (host == null || host.isBlank()) deny("host", rawUrl);
    if (props.mode() == Mode.OPEN) return;
    if (matchesAllowList(host)) { checkResolved(host); return; }
    deny("not-allowed", rawUrl);
}
// matchesAllowList：精确匹配，或以 "*.example.com" 形式的后缀匹配（只匹配子域，不匹配 example.com 本身外的拼接）
// checkResolved：mode=STRICT 时解析 DNS，所有 A/AAAA 落在 deny-cidrs（默认 169.254.0.0/16、云元数据地址）则拒绝；
//               allow-private=false 时私网段同样拒绝
```

### 配置

```yaml
tioka:
  egress:
    mode: OPEN            # OPEN（默认，不限制）/ ALLOW_LIST / STRICT（白名单 + DNS 校验）
    allow-hosts: []       # 例：["api.openai.com", "*.feishu.cn", "localhost"]
    allow-private: true
    deny-cidrs: ["169.254.0.0/16", "100.100.100.200/32"]
```

## GOV-04 核心多步写入加事务（P1，2 人天）

只处理三处，其余随各自重写处理。

| 场景 | 现状 | 改法 |
| --- | --- | --- |
| Agent 发布 | `AgentService.publish` 先写 `agent_version` 再更新 `agent_agent.published_version_id`，无事务 | 方法加 `@Transactional`；`agent_agent` 加 `version INT` 乐观锁（V103 `ADD COLUMN version INT NOT NULL DEFAULT 0`），冲突抛 `STALE_REVISION` |

| Chat 发送 | 先写用户消息，再调 Runtime，再写助手消息 | M0：用户消息与 Turn 创建在同一事务（新内核的 `startTurn` 只写库，不调模型）；助手消息由 Runtime item 表达，不再单独写（CHT-03 在 M1 删除 `chat_message` 写入） |
