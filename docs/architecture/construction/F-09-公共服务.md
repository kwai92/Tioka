## BAS-10 审计与登录日志（P0，4 人天）

### 目标与边界

- **审计日志**：Foundation 自身管理操作全量记录（写一条 `fdn_audit_log`），各应用经 starter 上报的操作日志**集中汇聚存储**，按应用、人员、操作、结果、时间检索与导出（S15 §13、§14.1）。沿用 ADR-053 决定 3：**只汇聚不改格式**（[F-00](F-00-F阶段实施计划.md) §5 约定 5、约束 F46），Tioka 的 GOV-02 审计仍在 Tioka、由它镜像管理类操作，Tioka 哈希链（GOV-09 / OBS-10）原样保留，不在本文改动。
- **登录日志**：从 Keycloak 事件采集登录成功 / 失败、来源 IP、登录方式、客户端与失败原因（S15 §13）。
- **不做**：不做跨应用统一的审计格式改造；不把 Tioka 的工具调用审计集中上来（ADR-053 备选已否决，避免 Foundation 进入热路径）；不自建审计写入链路替代各应用的本地落盘。

### 数据模型

字段沿用 [ADR-072](../adr/ADR-072-audit-event-model-coverage.md) §1 的三组（基本 / 主体 / 上下文 / 内容）。**无 `workspace_id`、无 `tenant_id`**（单企业部署，隔离边界只有应用与人员，ADR-029 第 60 条）。

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_audit_log` | 一条审计事件 | `app_code`、`action`、`resource_type` / `resource_id`、`outcome`、`reason`、主体组、上下文组、`details`、`before_hash` / `after_hash`、`retention_class`、`ts` |
| `fdn_login_log` | 一次登录尝试 | `login_name`、`account_id`、`success`、`auth_method`、`client_id`、`failure_reason`、`client_ip`、`user_agent`、`event_id`、`ts` |
| `fdn_audit_seal` | 审计链封印记录（GOV-09 / ADR-072 §8） | 窗口起止、前序哈希、本批哈希、`sealed_at` |

要点：

- **保留类别** `retention_class` 取 ADR-072 §7 的 `SEC`（400 天在线 / 3 年归档）、`CFG`、`BIZ`、`OPS`，由动作目录（`docs/contracts/audit/actions.yaml` 一类的契约文件）登记；Foundation 自身按 `SEC` 执行，保留下限 180 天（ADR-053 修订）。
- **来源 IP**：仅当请求来自配置的可信代理网段时取 `X-Forwarded-For` 最右侧不可信地址，否则取连接地址；原始头截断后入 `details.xff_raw`（ADR-072 §1）。
- **前后值**：配置类动作不存全量前后值，只存 `before_hash` / `after_hash`（SHA-256），差异到 ADR-041 的变更记录，不在本文。
- **登录日志去重**：按 Keycloak 事件的 `event_id` 幂等入库；采集成功后回填 `fdn_account.last_login_at` 与失败计数（[F-04](F-04-账号与登录与离职联动.md) BAS-03 §1 引用本项回填）。

### 迁移 SQL 示意

```sql
-- BAS-10 审计与登录日志（Foundation 库，Flyway 自 V1 起；示意 V44〜V45）

-- V44 审计日志。硬约束：不带 tenant_id / workspace_id；主键 ULID；时间 TIMESTAMPTZ
CREATE TABLE fdn_audit_log (
    id              VARCHAR(32)  PRIMARY KEY,                 -- ULID，前缀 adl_
    app_code        VARCHAR(64)  NOT NULL,                    -- 上报方应用（子系统编码）
    action          VARCHAR(128) NOT NULL,                    -- {域}.{对象}.{动词}，登记在动作目录
    resource_type   VARCHAR(64),
    resource_id     VARCHAR(64),
    outcome         VARCHAR(16)  NOT NULL,                    -- SUCCESS / DENIED / ERROR
    reason          VARCHAR(512),
    actor_type      VARCHAR(16)  NOT NULL,                    -- USER / SERVICE / AGENT / SYSTEM
    actor_id        VARCHAR(64)  NOT NULL,
    run_as          VARCHAR(64),                              -- 实际权限主体
    root_principal  VARCHAR(64),
    on_behalf_of    VARCHAR(64),                              -- 委派链字段沿用 ADR-039 列名
    chain_json      TEXT,
    grant_id        VARCHAR(64),
    agent_version_id VARCHAR(32),
    client_ip       INET,                                     -- 可信代理网段取 XFF 最右不可信地址
    user_agent      VARCHAR(512),
    origin          VARCHAR(16),                              -- web / im / api / orch / flow / a2a / system
    trace_id        VARCHAR(64),
    request_id      VARCHAR(64)  NOT NULL,                    -- 系统任务用任务运行 ID
    subject         VARCHAR(128),                             -- 业务主体（如合同号）
    data_label      VARCHAR(16),                              -- 该次调用后的数据标签（ADR-040）
    before_hash     VARCHAR(64),
    after_hash      VARCHAR(64),
    details         JSONB,                                    -- 白名单字段；敏感字段打码
    retention_class VARCHAR(8)   NOT NULL,                    -- SEC / CFG / BIZ / OPS
    ts              TIMESTAMPTZ  NOT NULL DEFAULT now()
) PARTITION BY RANGE (ts);                                    -- 按月分区（ADR-072 §7）
CREATE INDEX idx_audit_app_ts  ON fdn_audit_log (app_code, ts DESC);
CREATE INDEX idx_audit_actor   ON fdn_audit_log (actor_id, ts DESC);
CREATE INDEX idx_audit_trace   ON fdn_audit_log (trace_id);
CREATE INDEX idx_audit_subject ON fdn_audit_log (subject) WHERE subject IS NOT NULL;

-- V44 审计链封印（GOV-09 / ADR-072 §8；哈希不写回审计行）
CREATE TABLE fdn_audit_seal (
    id           VARCHAR(32) PRIMARY KEY,
    window_from  TIMESTAMPTZ NOT NULL,
    window_to    TIMESTAMPTZ NOT NULL,
    prev_hash    VARCHAR(64),
    batch_hash   VARCHAR(64) NOT NULL,
    sealed_at    TIMESTAMPTZ NOT NULL DEFAULT now());

-- V45 登录日志（来自 Keycloak 事件）
CREATE TABLE fdn_login_log (
    id               VARCHAR(32) PRIMARY KEY,                 -- ULID，前缀 lgn_
    event_id         VARCHAR(128) NOT NULL,                   -- Keycloak 事件 ID（幂等去重）
    account_id       VARCHAR(32),                             -- fdn_account.id，账号不存在时为空
    login_name       VARCHAR(128),
    person_id        VARCHAR(64),
    keycloak_user_id VARCHAR(64),
    success          BOOLEAN     NOT NULL,
    auth_method      VARCHAR(32) NOT NULL,                    -- password / oidc:keycloak / saml / ldap / im:feishu
    client_id        VARCHAR(64),                             -- Keycloak 客户端（应用）
    failure_reason   VARCHAR(255),
    client_ip        INET,
    user_agent       VARCHAR(512),
    ts               TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (event_id));
CREATE INDEX idx_login_name_ts ON fdn_login_log (login_name, ts DESC);
```

## BAS-16 消息中心（P1，5 人天）

### 目标与边界

- **站内信 / 待办 / 公告**三类统一在一套表上：站内信与待办由各应用投放给「人」，公告由管理侧发布给「范围」（全员 / 组织 / 角色）。各应用登记待办、门户统一展示、点击深链回应用（S15 §13）。
- **渠道**：站内为主，可选邮件 / 飞书；渠道走 ADR-026「通知」类 SPI `NotificationChannel`（ADR-029 第 56 条：第一期只做飞书与邮件，钉钉 / 企微 / 短信按接口后续增加，不改调用方）。
- **不做**：本期不改 Tioka 的 NTF 通知实现（ADR-053 决定 4：Tioka 通知渠道改为调用 Foundation 消息中心放在 M4 之后，不计入本期）；不做审批流（S15 §3.2）。
- **与门户的对接**：门户「个人中心 / 消息与待办」按前端包（S15 §12.3）与微前端通信接口刷新未读（S15 §6.3）；深链只带业务对象 ID、不带令牌（ADR-029 第 57 条）。

### 数据模型

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_message` | 一条待投递消息（站内信 / 待办 / 通知 / 公告展开项） | `app_code`、`kind`、`title`、`body`、`template_code`、`payload`、`link`、`channels`、`dedupe_key`、`data_label` |
| `fdn_message_receiver` | 一个收件人（决定「已读」与「未读」） | `message_id`、`person_id`、`read_at`、`deliver_status` |
| `fdn_message_template` | 一个渠道模板 | `app_code`、`code`、`channel`、`title_tpl`、`body_tpl`、`data_label` |
| `fdn_announcement` | 一条公告头 | `title`、`content`、`scope_type`、`scope_id`、`status`、`publish_at`、`expire_at` |

要点：

- `kind` 取 `INBOX`（站内信）/ `TODO`（待办）/ `NOTICE`（通知）/ `ANNOUNCEMENT`（公告展开项）；公告发布时按范围展开为一条 `kind=ANNOUNCEMENT` 的 `fdn_message` 并生成 `fdn_message_receiver`，**已读复用 `read_at`**，不再单建公告已读表。
- **未读数**：`fdn_message_receiver WHERE person_id=? AND read_at IS NULL` 计数；热点用 Redis 计数（`fdn:msg:unread:{personId}`）按变更失效，键加 `fdn` 前缀（S15 §4）。
- **幂等 / 去重**：`(app_code, dedupe_key)` 唯一；同键重复投放幂等返回原消息。
- **深链**：`link` 只带业务对象 ID（ADR-029 第 57 条）；渠道外发时只带站内跳转地址。
- **数据标签**：`data_label` 缺省 `INTERNAL`；高于渠道去向许可时不外发（ADR-040 §去向要许可），仅保留站内。

## BAS-17 文件服务（P2，3 人天）

### 目标与边界

- **统一上传下载** + **元数据** + **按应用与业务对象归档** + **病毒扫描挂点** + **预签名下载** + **存储抽象**（本地 / 对象存储）（S15 §13）。
- 存储抽象沿用 ADR-026 的 `ObjectStorageAdapter`（后端 MinIO 或客户 OSS）；业务集成两种方式：**经 starter SDK**（走 Foundation REST）或**直连 S3 兼容接口**（用 Foundation 颁发的预签名 URL）。
- **数据标签与密级**遵循 ADR-040：文件带 `data_label`（缺省 `INTERNAL`），下游消费（模型 / IM / 邮件 / 外发）受去向许可约束。
- **不做**：不做在线预览 / 格式转换（由文档层 / 解析引擎承担，S15 §3.2）；不把文件内容写入审计（只记长度与哈希，ADR-072 §1）。

### 数据模型

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_file` | 一个文件对象 | `app_code`、`file_name`、`content_type`、`size_bytes`、`sha256`、`storage_kind`、`storage_key`、`data_label`、`scan_status`、`uploaded_by` |
| `fdn_file_ref` | 一次「业务对象引用文件」 | `file_id`、`app_code`、`biz_type`、`biz_id` |

要点：

- **去重**：同一应用内同 `sha256` + 同大小可复用（可选）；默认按上传生成新对象，`fdn_file` 保留 `sha256` 供校验。
- **分片与大文件**：超过 `foundation.file.multipart.threshold-mb` 走分片上传（S3 `MultipartUpload` / 本地分片目录），完成后合并并校验 `sha256`。
- **病毒扫描占位**：`VirusScanHook` SPI；本期 `foundation.file.virus-scan=placeholder` 只把 `scan_status` 置 `SKIPPED`，预留 `PENDING` / `CLEAN` / `INFECTED`；接入 ClamAV 时替换实现，`INFECTED` 的文件禁止下载。
- **访问鉴权**：下载走**短时签名 URL**（`foundation.file.signed-url-ttl`，默认 10 分钟）；或经 `GET /api/fdn/files/{id}/content` 流式下载（走 starter 权限，`fdn:file:read`）。业务集成侧直连 S3 时用 Foundation 颁发的预签名 URL，不发放长期凭证。
- **应用隔离**：所有查询按 `app_code` 过滤；跨应用访问需显式授权（管理台 / 共享引用），不默认放行。
- **数据标签与密级**：`data_label` 取上传参数或应用缺省；高密级文件的下载 / 预览受 ADR-040 去向许可与去向脱敏约束。
- **删除**：有 `fdn_file_ref` 引用时禁止物理删除，转为逻辑删除并延迟清理对象（对齐 ADR-029 第 13 条删除语义）。

## BAS-18 工作日历与编号规则（P2，3 人天）

> F-00 §3.1 把「工作日历」与「编号规则」放在同一工作项（`PF-A06`）；本节分两小节。

### 18.1 工作日历

#### 目标与边界

- 法定节假日与调休、企业自定义休息日；提供「N 个工作日后」的计算接口，供期限、逾期、SLA 计算（S15 §13）。
- **区域日历**：支持多区域，默认 `CN`（中国）；`foundation.calendar.default-region`（§0.6）。
- 只提供日历与计算，**不做**审批 / 排期引擎（S15 §3.2）。

#### 数据模型

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_calendar` | 一个「区域 + 年度」的日历头 | `region_code`、`year`、`name`、`status`、`source` |
| `fdn_calendar_day` | 日历中的一天 | `calendar_id`、`day_date`、`day_type`、`is_workday`、`name` |

`day_type` 取 `WORKDAY`（普通工作日）/ `RESTDAY`（周末休息）/ `HOLIDAY`（法定节假日）/ `ADJUSTED_WORKDAY`（调休上班）。`is_workday` 冗余存储便于快速判断。`source` 取 `OFFICIAL`（导入的官方日历）/ `CUSTOM`（企业自定义）。

#### 迁移 SQL 示意

```sql
-- BAS-18 工作日历（示意 V42）
CREATE TABLE fdn_calendar (
    id          VARCHAR(32)  PRIMARY KEY,                     -- ULID，前缀 cal_
    region_code VARCHAR(16)  NOT NULL DEFAULT 'CN',
    year        SMALLINT     NOT NULL,
    name        VARCHAR(128) NOT NULL,
    source      VARCHAR(16)  NOT NULL DEFAULT 'CUSTOM',        -- OFFICIAL / CUSTOM
    status      VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',
    create_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (region_code, year));

CREATE TABLE fdn_calendar_day (
    id          VARCHAR(32) PRIMARY KEY,                      -- ULID，前缀 cdd_
    calendar_id VARCHAR(32) NOT NULL REFERENCES fdn_calendar(id),
    day_date    DATE        NOT NULL,
    day_type    VARCHAR(24) NOT NULL,                         -- WORKDAY/RESTDAY/HOLIDAY/ADJUSTED_WORKDAY
    is_workday  BOOLEAN     NOT NULL,
    name        VARCHAR(128),
    UNIQUE (calendar_id, day_date));
```

### 18.2 编号与序列

#### 目标与边界

- 按规则生成业务编号：**业务码值 / 前缀 / 日期 / 流水 / 校验位**，保证**并发唯一**（S15 §13）。
- 支持**重置规则**（不重置 / 按日 / 按月 / 按年）；供各应用生成单据号、合同号等。
- **不做**：不做分布式 Snowflake（流水号需要规则化与可读，非纯 ID）；不自建跨库协调服务（用数据库原子自增，见下）。

#### 数据模型

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_sequence_rule` | 一条编号规则 | `code`、`pattern`、`prefix`、`seq_length`、`step`、`reset_cycle`、`check_digit`、`status` |
| `fdn_sequence` | 某规则在某周期的当前值 | `rule_id`、`period_key`、`current` |

- **并发安全与跨节点唯一**：以数据库为单一权威，用一条原子语句取号（`INSERT … ON CONFLICT … DO UPDATE … RETURNING`），行锁与自增在数据库内完成，多实例天然唯一、无需协调；允许「跳号」（不为回滚补号）。
- **重置规则**：`fdn_sequence` 主键为 `(rule_id, period_key)`，`period_key` 按 `reset_cycle` 取 `-`（不重置）/ `yyyyMMdd` / `yyyyMM` / `yyyy`——周期切换自然落到新行、从 0 起算，**无需定时重置任务**。

取号原语（示意）：

```sql
INSERT INTO fdn_sequence (rule_id, period_key, current)
VALUES (:ruleId, :periodKey, :step)
ON CONFLICT (rule_id, period_key)
DO UPDATE SET current = fdn_sequence.current + :step, update_at = now()
RETURNING current;
```

`pattern` 由 `SequenceGenerator` 渲染，占位符：`{prefix}`、`{date:yyyyMMdd}`、`{seq:N}`（补零到 N 位）、`{check}`（校验位，`check_digit` 取 `NONE` / `MOD10` / `MOD11`）。

#### 迁移 SQL 示意

```sql
-- BAS-18 编号与序列（示意 V43）
CREATE TABLE fdn_sequence_rule (
    id          VARCHAR(32)  PRIMARY KEY,                     -- ULID，前缀 sqr_
    code        VARCHAR(64)  NOT NULL,                        -- 业务码值，全局唯一
    name        VARCHAR(255) NOT NULL,
    pattern     VARCHAR(255) NOT NULL,                        -- 如 {prefix}{date:yyyyMMdd}{seq:4}{check}
    prefix      VARCHAR(32),
    seq_length  SMALLINT     NOT NULL DEFAULT 4,
    step        INT          NOT NULL DEFAULT 1,
    reset_cycle VARCHAR(8)   NOT NULL DEFAULT 'NONE',          -- NONE / DAILY / MONTHLY / YEARLY
    check_digit VARCHAR(8)   NOT NULL DEFAULT 'NONE',          -- NONE / MOD10 / MOD11
    status      VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',
    sample      VARCHAR(64),                                   -- 预览样例
    create_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    update_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    UNIQUE (code));

CREATE TABLE fdn_sequence (
    rule_id    VARCHAR(64) NOT NULL,                           -- fdn_sequence_rule.code
    period_key VARCHAR(16) NOT NULL,                           -- '-' / yyyyMMdd / yyyyMM / yyyy
    current    BIGINT      NOT NULL DEFAULT 0,
    update_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (rule_id, period_key));
```

#### 与字典（BAS-09）的关系

- **业务码值**（`fdn_sequence_rule.code`）与字典项对应：字典类型如 `sequence_biz_code` 登记「合同号 / 单据号 / 工单号」等业务码值，管理台下拉与前端展示取自字典；规则定义时校验 `code` 在字典中已登记。
- **枚举取值**（`reset_cycle`、`check_digit`）登记在字典（如 `sequence_reset_cycle`、`sequence_check_digit`），供管理台渲染。
- **运行时不依赖字典**：取号只读 `fdn_sequence_rule` 与 `fdn_sequence`，不查字典（避免热路径依赖）；字典变更发 `fdn.dict.changed`，编号模块只刷新本模块缓存。

#### 接口（S15 §14.1「公共服务」组）

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/fdn/sequence-rules` | `fdn:sequence:admin` | 规则列表 |
| `POST /api/fdn/sequence-rules` / `PUT /{code}` | `fdn:sequence:admin` | 新建 / 修改规则（含预览样例） |
| `POST /api/fdn/sequences:next` | 应用服务账号 | 取号：`{ruleCode, count?}` → `{values[]}`；按 `Idempotency-Key` 幂等 |
| `GET /api/fdn/sequences/{ruleCode}/current` | `fdn:sequence:admin` | 当前周期已用值（排障） |

#### 关键类与测试

| 类 | 包 | 职责 |
| --- | --- | --- |
| `SequenceService` / `SequenceGenerator` | `com.tioka.foundation.sequence` | 取号、渲染、校验位 |
| `SequenceRuleService` | `…sequence` | 规则管理 |
| `SequenceClient`（`foundation-starter-client`） | `com.foundation.starter.client` | 应用侧取号 |

| 用例 | 断言 |
| --- | --- |
| `SequenceIT#concurrentUnique` | 多线程并发取号无重复；跨实例（双写同一库）也不重复 |
| `SequenceIT#resetByCycle` | `DAILY` / `MONTHLY` / `YEARLY` 在跨周期后从 1 起算 |
| `SequenceIT#patternAndCheckDigit` | `{prefix}{date}{seq:N}{check}` 渲染正确；`MOD10` / `MOD11` 校验通过 |
| `SequenceIT#idempotent` | 同 `Idempotency-Key` 重复取号返回同一批值 |

## BAS-19 三员分立与高风险授权复核（P1，2 人天）

### 目标与边界

- **三员分立**（S15 §15、ADR-053 决定 5）：系统管理员（组织、账号、应用、角色）、安全管理员（密码与会话策略、登录方式、授权审核）、审计管理员（只读日志）三个内置角色**互斥**，同一人不能兼任；部署时可关闭此约束（小团队）。
- **高风险授权复核**：授予带高风险权限码（`fdn_permission_code.risk_level = HIGH`）的角色需安全管理员复核后生效（S15 §15「高风险授权」），复核走 Foundation 内置的简单复核，不依赖 Tioka 审批台。
- **不做**：不重定义三员角色与权限码目录（内置于 [F-05](F-05-应用与权限中心.md) BAS-05 的 V18 种子），本项只做**互斥的执行**与**复核流程**；不改 Tioka 侧权限（ADR-029 第 60 条、S15 §17）。

### 依赖与数据模型

- 复用 [F-05](F-05-应用与权限中心.md) BAS-05 的种子：角色码 `system_admin`（权威码，界面「系统管理员」，**不用历史码 `tenant_admin`**）、`security_admin`、`audit_admin`（ADR-029 第 60 条修订），互斥定义在 `fdn_role_mutex`（V18 已插入三对互斥）。
- 本项新增**高风险授权复核**表：

| 表 | 一行含义 | 关键字段 |
| --- | --- | --- |
| `fdn_high_risk_review` | 一次高风险授权复核 | `grant_id`、`permission_code`、`requested_by`、`status`、`reviewer_id`、`reviewed_at`、`reason` |

`status` 取 `PENDING`（待复核）/ `APPROVED`（已放行，授权生效）/ `REJECTED`（拒绝）。

### 迁移 SQL 示意

```sql
-- BAS-19 三员分立与高风险授权复核（示意 V40；三员角色与 fdn_role_mutex 已在 BAS-05/V18 种子）
CREATE TABLE fdn_high_risk_review (
    id              VARCHAR(32)  PRIMARY KEY,                 -- ULID，前缀 hrr_
    grant_id        VARCHAR(32)  NOT NULL,                    -- fdn_role_grant.id
    permission_code VARCHAR(128) NOT NULL,                    -- 高风险权限码
    requested_by    VARCHAR(64)  NOT NULL,
    status          VARCHAR(16)  NOT NULL DEFAULT 'PENDING',   -- PENDING / APPROVED / REJECTED
    reviewer_id     VARCHAR(64),
    reviewed_at     TIMESTAMPTZ,
    reason          VARCHAR(512),
    create_at       TIMESTAMPTZ  NOT NULL DEFAULT now());
CREATE INDEX idx_hrisk_status ON fdn_high_risk_review (status, create_at);
```

### 规则

- **互斥校验**（`RoleMutexGuard`）：授予 / 修改角色时，若「人员当前有效角色 ∪ 本次授予」命中 `fdn_role_mutex` 的任一互斥对 → 拒绝（`CONFLICT`），并写审计 `authz.role.mutex_denied`；同一人无法同时被授予系统管理员与审计管理员。部署开关可关闭该约束（S15 §15）。
- **高风险复核**：授权若含 `risk_level=HIGH` 的权限码，先把 `fdn_role_grant` 置于待生效、生成一条 `fdn_high_risk_review(PENDING)`；安全管理员复核通过（`APPROVED`）后授权生效，拒绝（`REJECTED`）则授权不生效并写审计。高风险权限码的授予须二次确认并审计（S15 §8.3）。
- **审计**：互斥拒绝、复核提交 / 通过 / 拒绝、部署开关变更均写审计（BAS-10 汇聚）。

### 接口（S15 §14.1「权限」组，与 BAS-05 同域）

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/fdn/high-risk-reviews?status&cursor&size` | `fdn:hrgrant:review` | 待办 / 历史复核列表（**安全管理员**） |
| `POST /api/fdn/high-risk-reviews/{id}/approve` | `fdn:hrgrant:review` | 通过：授权生效 |
| `POST /api/fdn/high-risk-reviews/{id}/reject` | `fdn:hrgrant:review` | 拒绝：授权不生效 |

授予接口的互斥校验并入 BAS-05 的 `POST /api/grants`（[F-05](F-05-应用与权限中心.md)），命中互斥即 409，不新增端点。
