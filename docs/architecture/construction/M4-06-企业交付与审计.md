## 0. 共用安排

### 0.1 数据库账号分离（GOV-09、OBS-10、FND-11 共同的前提）

ADR-072 要求「应用账号对审计、台账、运行清单只有 INSERT 与 SELECT」。PostgreSQL 中**表的属主不受 REVOKE 约束**，而现在 Flyway 由应用在启动时以应用账号执行（ADR-026），应用账号就是表属主。所以必须先分账号，否则 V247 收回权限不起作用。

| 账号 | 用途 | 权限 |
| --- | --- | --- |
| `tioka_owner` | Flyway 迁移；只在安装、升级时使用 | 全部表的属主 |
| `tioka_app` | 运行时 | 业务表增删改查；审计、外部交互台账、运行清单只有 INSERT、SELECT；链表无权限 |
| `tioka_sealer` | 封印任务 | 三张表 SELECT；链表与封印表 INSERT、SELECT |
| `tioka_archiver` | 归档、分区维护、恢复后校验 | 分区的 DETACH、DROP、导出；不参与在线业务 |

- 迁移改为独立执行：Helm 中一个迁移 Job（`tioka_owner`），应用 Deployment 等 Job 完成后再启动；Compose 与开发环境可以只用一个账号，但 G4 环境（ENG-04e）必须是四个账号。
- 封印与归档任务仍在应用镜像里（`scheduler` 角色），以各自账号的连接池运行。
- 这一条写进 ADR-029 第 79 条；ADR-026「启动时由拿到锁的实例执行迁移」改为「由迁移 Job 执行」。

## 2. 审计防篡改与保留归档

### 2.1 GOV-09 哈希链与外部锚点（4 人天，BE-C，W58）

**链放在哪里（推荐方案）**：哈希不写回审计行，而是写进独立的只增链表（表名、记录 ID、链内序号、哈希、批次）。

| 项 | 定案 |
| --- | --- |
| 三条链 | `audit_event`、`ext_interaction`、`run_manifest` 各一条，无租户维度 |
| 封印任务 | 每分钟一批，数据库锁互斥；用 `tioka_sealer` 账号 |
| 待封记录 | 不按 ID 水位线取，而是取「最近 10 分钟窗口内、链表里还没有的记录」，按写入时间与 ID 排序后依次计算 `hash = sha256(prev_hash + 规范化记录)`；这样迟提交的长事务不会被跳过 |
| 迟到记录 | 每日校验发现窗口外仍未封印的记录时告警 `audit.chain.unsealed`，并以「迟到批次」封印 |
| 规范化 | 字段顺序、时间格式、空值写法固定，写进 ops 文档并版本化（约束 F46） |
| 封印表 | 每批末尾哈希写 `gov_audit_seal`；同时推 SIEM；每小时写一份到对象存储（外部锚点） |
| 校验 | 按时间段重算接口；每日自动校验；从备份恢复后自动校验一次；不一致写 `audit.chain.mismatch` 并告警 |
| 转发 | 「已转发到的最大 ID」记进度表，不再逐行更新审计表 |

**备选**：A. 哈希写回审计行（ADR-025 原写法），封印账号对哈希列有列级 UPDATE 权限。审计表不再严格只增、且按 ID 水位线会漏掉迟提交的记录，不采用。B. 写入时同步算哈希。写入串行化，ADR-025 已否决。

- 测试：`AuditTamperDetectIT`（篡改一行后校验发现）；`AuditLateCommitSealedIT`（一个持续 90 秒的事务写入的审计在提交后被封印）；`AppAccountCannotUpdateAuditIT`（`tioka_app` 执行 UPDATE、DELETE 被数据库拒绝）；`ChainVerifyAfterRestoreIT`。
- ArchUnit：`auditTablesInsertOnly`（M4-00 第 7.4 节）。

### 2.2 OBS-10 保留分级、月分区、归档、法律保全、个人信息删除（3 人天，BE-C，W58–W59）

**分区结构**：三张表（审计、外部交互台账、时间线）按月 RANGE 分区，每个月再按保留类别 LIST 子分区（`SEC`、`CFG`、`BIZ`、`OPS`，ADR-072 第 7 节）。这样一个子分区内的记录到期时间一致，可以整块归档。

**V248 的在线迁移方案（推荐）**：

| 步 | 做法 | 锁与停机 |
| --- | --- | --- |
| 1 | 演练：在脱敏现网副本上按以下步骤完整走一遍，记录每步耗时 | — |
| 2 | 为旧表加保留类别列（可空，带缺省值的加列在 PostgreSQL 中不重写表） | 秒级 |
| 3 | 在一个短事务内：旧表改名为 `*_legacy`；以原名建分区表与当前月及之后 3 个月的子分区；把 `*_legacy` 以一个「历史区间」分区挂入（先加 `NOT VALID` 约束、事务外 `VALIDATE`，挂入时不全表扫描） | 秒级的排他锁；写入在这段时间排队 |
| 4 | 后台按月把历史分区的行搬到新的月分区（每批小事务，速率可调），搬完后历史分区为空即卸下删除 | 无停机 |
| 5 | 哈希链引用的是记录 ID，搬迁不改变记录内容，链校验不受影响；搬迁前后各跑一次全量校验 | — |

备选：A. 停机整表复制（简单，停机时长与数据量成正比，现网数据小时可接受）；B. 引入 pg_partman 扩展（离线环境多一个扩展依赖）。若演练显示整表复制在 5 分钟内，可改用 A，PR 描述说明。

**到期处理**：封印确认 → 子分区与对应封印记录导出为压缩文件写对象存储（可选 WORM 桶）→ 回读校验哈希 → DETACH、DROP → 写 `audit.partition.archived`。全部由 `tioka_archiver` 执行，数据库锁互斥。

| 项 | 定案 |
| --- | --- |
| 分区预建 | 每日任务保证未来 3 个月的分区存在 |
| 法律保全 | 可对 `subject`、用户、空间或时间段设置；保全期间，包含被保全记录的子分区不归档删除（整块保留，ADR-072 原文）；设置与解除需双人并写审计 |
| 个人信息删除 | 只在身份映射表把用户 ID 假名化为「已删除用户 #n」，审计行不动 |
| 下限 | 部署可调大保留期，不能低于 180 天（《网络安全法》第二十一条） |
| 归档格式 | 与链规范一起写进 ops 文档并版本化（约束 F46，F 阶段 BAS-10 汇聚审计不改格式） |
| 恢复 | 归档文件可导入独立 schema 查询，导入后校验链 |

- 测试：`PartitionArchiveVerifyIT`（到期子分区归档后可从归档文件校验哈希，在线分区已删除）；`LegalHoldBlocksArchiveIT`；`UserPseudonymizeKeepsChainIT`；`V248OnlineMigrationRehearsal`（演练记录附 PR）。

## 4. RT-11 容器沙箱（10 人天，BE-B，W60–W62）

### 4.1 设计要点

| 项 | 定案 |
| --- | --- |
| 接口 | `SandboxProvider`（ADR-027）放 `runtime-api`；接口通用化：工具桥、资源上限、文件进出都不绑定代码解释器（约束 F47，供 `CODE_ACT` 与外部执行器） |
| 后端 | 生产为 Kubernetes：每个沙箱一个 Pod，放在专用命名空间，RuntimeClass 按 R3 选 gVisor 或 Kata；应用的 ServiceAccount 只有该命名空间内 Pod 的创建、删除、exec 权限。开发与 Compose 用 Docker，**只用于演示**（挂 Docker 套接字等同主机 root，部署手册写明不得用于生产） |
| 资源 | CPU、内存、进程数、临时盘上限；只读根文件系统；非 root 用户；丢弃全部 Linux capabilities |
| 网络 | 缺省无网络；允许联网时只经 Tioka 出口代理，白名单为 Agent 沙箱策略与 Skill 权限的交集；元数据地址与内网地址一律拒绝 |
| 工作盘 | 按 thread 挂载 `/workspace`（uploads、skills、scratch、artifacts），不同 thread 互不可见 |
| 生命周期 | 每 thread 最多一个；首次执行时创建；空闲 15 分钟回收、最长 8 小时；回收后工作盘保留；团队与子 Agent 回收时立即释放（MAS-03） |
| 底线 | 沙箱未启用时，代码执行与脚本类工具不出现在工具列表；任何情况下不在应用进程内执行 |

### 4.2 改动清单

| 模块 | 组件 | 改动 |
| --- | --- | --- |
| runtime-biz/sandbox | 提供者 | Kubernetes 与 Docker 两个实现；会话登记 `runtime_sandbox`（V251） |
| runtime-biz/tools | `code.run` | 取代现在返回 `code.hashCode()` 的假实现；stdout、stderr 各截断 20 KB；写到 `/workspace/artifacts` 的文件变成 `file_ref` item |
| runtime-biz/tools | Skill 脚本 | Skill 中的脚本在沙箱内执行；`shell.exec` 只对沙箱策略为 full 的 Agent 开放 |
| runtime-biz | 后台 Job | 长命令转后台 Job 在沙箱里继续（RT-09 的 Job 模型） |
| deploy | 镜像 | 内置 Python 数据分析镜像与 Node 镜像，登记进离线清单 |
| framework | ArchUnit | `sandboxOnlyViaRuntimeSandboxApi` |

- 前端（2 人天，W63）：代码解释器结果与文件渲染。
- 测试：`SandboxNoEgressIT`（代码在沙箱内运行，访问外网与元数据地址失败）；`SandboxIsolationIT`（读不到其他 thread 的工作盘）；`SandboxLimitsIT`（内存超限被杀、fork 炸弹被进程数限制）；`SandboxDisabledNoToolIT`；`CodeRunArtifactIT`（生成文件可下载）。

| 脚本 | 环境自检（内核、CPU 架构、存储类、RuntimeClass、DNS、时钟）→ 导入镜像到客户仓库 → 安装 → 初始化（建管理员、导入权限清单、冒烟）→ 升级 → 回滚 |

### 5.3 升级与回滚规则

- 迁移只向前；同一里程碑内的迁移遵守「先扩后收」：新版本加列与新表，旧版本代码能在新库上运行；删列、删表、收权限只在里程碑边界做，并要求先备份。
- 回滚 = 应用回到上一版本镜像；跨越破坏性迁移的回滚只能从备份恢复，安装包的升级脚本在执行破坏性迁移前强制备份并提示。

### 5.4 企业适配 SPI 实现

M4 交付的实现：密钥（本地文件、Vault）、对象存储（MinIO、S3 兼容）、审计外送（Syslog、HTTP）、IM（飞书，已有）。其余按 ADR-026 九类 SPI 由交付或客户以插件补。

- 演练：W64 首次离线安装演练（ENG-04e 环境）；W76 全量演练（含升级与回滚），记录写进 `docs/ops/`。
- 测试：`OfflineInstallSmoke`（离线环境一条命令安装并通过冒烟）；`ManifestCompletenessCheck`（CI）；`UpgradeRollbackDrill`（W76 演练记录）。
