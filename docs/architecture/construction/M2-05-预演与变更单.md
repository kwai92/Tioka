### 执行循环（替换 M1-02「执行循环中的处理」中对单个调用的部分）

```text
对每个 tool_call：
  if descriptor.risk == READ:
      out = toolGateway.call(ctx, name, args)              // 与现在相同
  else:
      p = toolGateway.prepare(ctx, name, args)             // 写 change_set item（PROPOSED）
      switch p.gate:
        AUTO_COMMIT      → out = toolGateway.commit(ctx, p.preparedId)
        REQUIRE_APPROVAL → runtime_approval.card_json = {changeSet: p.changeSet, reversibility, estimated}
                           item_id 指向 change_set item；放入待审批集合
        DENIED           → tool_result{ok:false, output:"策略拒绝：…"}
// 续跑（approval.decided = APPROVED）：
  若 answer 带修改后参数 → 重新 prepare，新变更单仍需审批（同一 approval 关闭，新开一条）
  否则 → commit(ctx, preparedId)
```

### `commit` 漂移检测

```java
ToolResult commit(ToolCallContext ctx, String preparedId) {
    TrustActionDO a = store.lockForUpdate(preparedId);
    if (a.status() == APPLIED) return a.cachedResult();                 // 幂等
    if (Instant.now().isAfter(a.validUntil())) return reprepare(ctx, a);
    TransactionalTool t = registry.transactional(a.toolName());          // 非事务型 → 直接 invoke
    try {
        ApplyReceipt r = t.apply(a.invocation(), a.changeSet(), a.itemId());
        store.markApplied(a, r);                                         // 同事务写 change_set item 状态
        return ToolResult.ok(r);
    } catch (StaleChangeSetException e) {                                // 实现方重算指纹不一致
        store.markStale(a);
        return new ToolResult(false, "数据已变化，请重新确认后再执行");
    }
}
```

## TRU-06 变更单卡片（8 人天：后端 3、前端 5）

### 飞书审批卡片（改 M2-03 `ApprovalCardService` 与 `FeishuCardBuilder`）

