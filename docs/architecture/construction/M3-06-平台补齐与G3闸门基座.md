## 1. FND-12 插件宿主（5 人天，BE-A，W25–W26）

ADR-026 规定九类 SPI 统一由插件宿主加载；M3 用到它的有领域包（ONT-05）、Flow 插件节点（FLW-05）、连接器（CON-SDK、CON-07a）、通知渠道（NTF-01 的非内置实现）。

### 1.1 改动清单

| 模块 | 组件 | 改动 |
| --- | --- | --- |
| infra-api | `PluginHost`、`PluginDescriptor`、`SpiType` | 新增。插件清单字段：插件键、版本、SPI 类型、SPI 版本、权限声明（`cpu`、`network`、`filesystem`）、入口类、签名 |
| infra-biz | 插件目录扫描 | 启动时与管理员触发时扫描配置的插件目录（默认 `/opt/tioka/plugins`），新文件不自动加载，需管理员在管理接口启用 |
| infra-biz | 签名校验 | 对 jar 计算 SHA-256，用配置的公钥校验签名；公钥可配置多把（约束 F34）；开发环境可关闭校验但启动日志告警 |
| infra-biz | 类加载器隔离 | 每个插件一个独立类加载器，父加载器只暴露该 SPI 类型声明的 `-api` 包；同一插件的新旧版本可并存，旧版本在没有引用后卸载 |
| infra-biz | 权限执行 | 按 SPI 类型规定允许的权限（领域包只允许 `cpu`，M3-03 第 10 节）；声明超出允许范围的插件拒绝加载；`network` 权限的插件出站仍经 EgressGuard |
| infra-biz | 适配器登记 | 插件启用后，各适配器实例的配置存登记表，密钥只存 `CredentialCipher` 密文的引用 |
| infra-biz | 管理接口 | 插件列表、详情（清单、签名、哈希、状态）、启用、停用、查看加载错误；权限点 `sys:plugin:admin` |
| framework | ArchUnit | `pluginsOnlyViaHost`：只有插件宿主可以创建加载外部 jar 的类加载器 |

### 1.2 加载顺序

读清单 → 校验签名与哈希 → 检查 SPI 版本兼容 → 检查权限声明 → 创建类加载器 → 实例化入口类 → 交给对应 SPI 的注册器（领域包交 ONT-05，节点交 FLW-05，连接器交 CON-SDK）→ 写审计。任一步失败，状态为 FAILED 并记录原因，不影响其他插件与启动。

### 1.3 测试

| 用例 | 断言 |
| --- | --- |
| `PluginHostIT#signatureRequired` | 未签名或签名不符的 jar 拒绝加载 |
| `PluginHostIT#permissionDenied` | 领域包声明 `network` → 拒绝加载 |
| `PluginHostIT#isolation` | 插件无法加载未暴露的 Tioka 内部类 |
| `PluginHostIT#versionsCoexist` | 新版本启用后，钉旧版本的使用方仍能调用旧版本 |
| `PluginHostIT#failureIsolated` | 一个插件加载失败，应用正常启动，其他插件可用 |

## 2. CON-SDK 通用连接器 SDK（3 人天，BE-A，W37–W38）

ADR-029 第 23 条把数据源改为「通用连接器 SDK + 三类通用连接器」；DAT-01（数据集，行列策略在连接器执行）与 KNW-06（知识数据源）都建在 SDK 上。SDK 只做两者共用的部分。

| 部分 | 内容 |
| --- | --- |
| 规格 | 每个连接器类型声明配置项的 JSON Schema，前端据此生成表单；声明能力：可列变更、可取文档、可查询数据集、是否提供源权限 |
| 凭证 | 只存 `CredentialCipher` 密文引用；代用户授权的走 FND-08 令牌保管 |
| 游标 | 同步游标按连接器实例保存，失败不前移 |
| 限流与重试 | 按连接器实例的令牌桶；可重试错误指数退避 3 次 |
| 健康 | 最近一次成功时间、最近错误、连续失败次数；连续失败 3 次标为 DEGRADED 并告警（GOV-13） |
| 出网 | 一律经 EgressGuard |
| 实现方式 | 内置连接器在 `connector-biz`；第三方连接器以插件形式经 FND-12 加载 |

- 测试：`ConnectorSdkContractTest`（一个桩连接器跑通规格、凭证、游标、限流、健康全部契约）；`ConnectorCursorIT#failureKeepsCursor`。
- DAT-01 的 JDBC 与通用 REST 数据集、KNW-06 的三类数据源连接器都按本节契约实现。

## 3. 知识增强（KNW-05、KNW-03、KNW-04，BE-C，W42–W44）

设计以 ADR-018 为准。施工补充：

### 3.1 KNW-05 ingest 异步化与事务（3 人天）

- 上传与数据源变更只写文档登记与入库任务，立即返回；任务创建与 outbox 消息在同一事务。
- 消费者按阶段（解析、切块、向量化、索引与切换）推进，每阶段完成写任务状态；失败按阶段重试最多 3 次，之后标 FAILED 并在知识库页可见。
- 版本切换：新版本全部分块写入后，在一个事务内切换文档的当前版本并删除旧版本分块；检索只看当前版本。
- 入库任务接受 `ChangeEvent` 作为来源（约束 F39），KNW-06 只需产生事件。
- LSE-07（修订案例与正反例同步）在 W43 直接用本节的入库任务。
- 测试：`IngestJobIT#asyncReturnsImmediately`；`IngestJobIT#retryPerStage`；`IngestJobIT#atomicSwitch`（切换过程中并发检索不会看到半个版本）。

### 3.2 KNW-03 结构感知切块与父子块（5 人天）

- 按标题切父块（一个小节，上限 2000 字），父块内切子块（约 400 token，重叠 50）；表格、代码块整块保留。策略存知识库配置，可改，改后触发重建。
- 检索返回子块用于引用定位，父块正文用于模型上下文，同一父块只返回一次。
- 测试：`StructuredChunkerTest`（Markdown、Word、PDF 各一份样本的切块结果与快照一致）；召回率在评测集上高于固定 200 字基线（KNW-07 判定）。

### 3.3 KNW-04 Rerank（2 人天）

- 召回前 50 条调 `ModelGateway.rerank`（purpose=rerank）取 topK；知识库未绑定 rerank 模型时跳过；用量计入空间配额。
- 测试：`RerankIT`（绑定 rerank 后排序变化且用量有记录；未绑定时结果与未开启一致）。

### 3.4 G3 用例 `G3KnowledgeRecallGateIT`

关闭 mock、双实例、开启鉴权。上传评测集对应的 20 份文档 → 全部 READY → 用评测集 50 个问题经 Agent 提问 → 回答带引用 → Recall@5 不低于 CI 基线、MRR 有记录 → 无权限用户提问检索不到受限文档。CI 中 embedding 与 rerank 用本地小模型（ENG-04d）。

### 3.5 KNW-06 数据源（方案 B 下在 M4 前段实现，10 人天）

- 飞书知识库与云空间：事件订阅拿增量（复用 M2 的 CON-02 入站），每日全量对账兜底；代用户授权文档走 FND-08。
- HTTP/REST、S3/MinIO/NAS、JDBC 三类通用连接器：按计划轮询列变更；有源权限时 `ChangeEvent` 带 `aclPrincipals`，检索取知识库与文档级权限的交集。
- 前端：数据源配置表单按规格生成、同步状态与错误（2 人天）。

## 4. 评测（EVO-01、EVO-02、KNW-07，BE-A，W45–W47）

设计以 ADR-031 为准。M3 只做 EVO-01、EVO-02 与知识评测；线上采样（EVO-03）在方案 B 下移到 M4 前段，实验对比、经验库、发布回归门禁在 M4。

### 4.1 EVO-01 轨迹导出与用户反馈（2 人天）

- 反馈：每条助手消息可点赞、点踩并写意见，写 `eval_feedback`；撤销（TRU-07）与合同场景的法务驳回（`lease.review.feedback`）同样写一条负向反馈。
- 轨迹导出：按 Turn 或时间范围导出 JSON，直接复用 HCI-07b 的轨迹查询（ADR-029 第 65 条）；导出受数据标签限制，CONFIDENTIAL 以上需要空间管理员权限。
- 测试：`FeedbackIT`（点踩写入、撤销自动写入负向反馈）；`TrajectoryExportIT#labelRestricted`。

### 4.2 EVO-02 数据集、评估器 SPI、批次评测（6 人天）

- 数据集与用例带版本；评估器以 SPI 注册（内置：精确匹配、包含、引用命中、模型打分），第三方评估器经插件宿主加载。
- 批次评测：选数据集版本、评估器组、被测对象（Agent 版本或 Flow 发布）；每条用例在隔离的 thread 运行（`origin = eval`），工具默认走桩或只读，用量计入空间的评测预算，不占用户配额。
- LSE-08 的四项门槛指标以评估器形式注册，结果写同一套表（约束 F32）。
- 测试：`BatchEvalIT`（一个 10 条用例的数据集跑完出报告；写工具在评测中只预演）；`EvaluatorSpiIT`。

### 4.3 KNW-07 知识评测进 CI（3 人天）

- 知识评测是 EVO-02 的特例：数据集是「问题 + 期望命中的文档或分块」，指标 Recall@5、MRR。不再单独建 `kb_eval_*` 表（ADR-018 的表并入 V212）。
- CI 用本地中文小模型（ENG-04d 的容器）保证可复现；Recall@5 比基线低 2 个百分点以上阻塞合并；基线随 PR 更新时要求评审确认。
- 测试：`KnowledgeRecallBaselineIT`。

## 5. RT-10 上下文组装与压缩（4 人天，BE-B，W48）

设计以 ADR-027「上下文组装与压缩」为准。

> **2026-11-06 修订（ADR-029 第 68 条）**：组装顺序、有效预算与削减规则改以 [ADR-048](../adr/ADR-048-context-engineering.md) 为准（四区组装：稳定前缀 → 会话快照 → 历史 → 本轮尾部；用户记忆、经验、知识检索移到本轮尾部；削减分卸载、清理、结构化摘要、溢出失败四级）。下面几条中与 ADR-048 冲突的以 ADR-048 为准。同期增加 CTX-01（后端 3）、CCH-01（后端 1，[ADR-049](../adr/ADR-049-prompt-caching.md)）、AST-11（后端 0.5），由 BE-B 在 W48 前与 RT-10 一起完成，在 M3 余量内吸收。

- 组装顺序固定：平台安全指令 → Agent 指令（含 AST-08 的 Prompt 模板）→ always Skill → auto Skill 索引 → 用户记忆 → 知识自动检索结果 → 压缩摘要 → 历史 item → 本轮输入。各模块只能向组装器登记自己的段，不能自行插入。方案 B 下 Skill 与记忆段在 M3 为空。
- 每个 item 入库记录 token 数；调模型前估算总量，超过所选模型上下文的 75% 就压缩：保留最近 3 个 Turn，更早内容经 `ModelGateway`（purpose=compaction）摘要为一个压缩 item，原始 item 保留供界面展示。
- 单个工具结果超过 8000 token：全文写入对象存储，提示里只放开头部分与引用。
- 压缩后允许重新选模（与 MH-06 衔接）；子 Agent（RT-12）的子 thread 各自压缩。
- 测试：`ContextCompactionIT`（超阈值时生成压缩 item，原始 item 仍可查询；压缩后可重新选模）；`ContextAssemblyOrderTest`。

## 6. MH-06 路由模式与决策器（6 人天，BE-B，W27–W28）

设计以 ADR-024「路由计划」「一次选模」为准；ADR-041 要求与 MH-08 一起做，路由计划数据只迁移一次。

- 路由计划内容（模式、组、类别映射、决策配置、升级策略）作为版本化快照，走 GOV-12 的发布与回滚；Agent 引用计划 ID，计划发布新版本立即生效，调用记录带计划版本。
- 四种模式：FIXED（不调决策器）、DIFFICULTY、BRANCH、FREE_FIRST；决策超时默认 1.5 秒，超时或失败走兜底组并在路由时间线记录原因。
- 决策器 SPI 与三个内置实现：启发式（现有难度路由搬入）、大模型决策（purpose=decision，固定提示词登记为 `sys.*` Prompt 模板）、外部 HTTP（经 EgressGuard）。
- 胜任度打分只记录，不参与决策（ADR-024）。
- DAT-03（按标签选模）在 W38 接在本节的候选过滤上。
- 测试：`RoutingModesIT`（四种模式各一例）；`DeciderTimeoutFallbackIT`；`RoutingPlanRollbackIT`（回滚后新 Turn 用旧计划版本）。

## 7. CON-05 MCP OAuth 与 Streamable HTTP（6 人天，BE-A，W36–W37）

设计以 ADR-021「MCP 管理」为准。

### 7.1 Tioka 作为 MCP 服务端

- 暴露知识检索与 MCP 形态的 Flow 发布（FLW-06）。
- Tioka 只做资源服务器：校验 Keycloak 签发的 OAuth 访问令牌（受众为 Tioka MCP），映射为 Principal；Tioka 不做授权服务器。令牌校验只经一个校验器（约束 F37）。
- 外部 MCP 客户端在管理接口登记（客户端 ID、允许的空间、允许暴露的工具），未登记的客户端拒绝。
- 每次调用写审计，用量计入调用用户与空间配额。

### 7.2 Tioka 作为 MCP 客户端

- 传输支持 Streamable HTTP（主）与旧 SSE（兼容）；stdio 只在私有化部署由管理员启用，进程跑在沙箱（沙箱在 M4，M3 不开放 stdio）。
- 需要代用户授权的 MCP Server，用户令牌存 FND-08 的令牌保管。

### 7.3 测试

| 用例 | 断言 |
| --- | --- |
| `McpServerOAuthIT#validToken` | Keycloak 令牌调用知识检索成功，审计有用户与客户端 |
| `McpServerOAuthIT#unregisteredClient` | 未登记客户端被拒 |
| `McpServerOAuthIT#flowPublication` | 外部客户端调用 MCP 形态的 Flow 发布，运行身份为该用户 |
| `StreamableHttpClientIT` | 连接 Streamable HTTP 的 MCP 桩，`tools/list` 与调用正常；断线重连 |

## 11. 完成标准
