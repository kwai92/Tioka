## 背景

负责人要求考虑「采购外部 OCR 产品的适配与对接」。调研 05 第 4 节比较了阿里云文档解析与读光 OCR、百炼 `qwen-vl-ocr`、百度文档解析（PaddleOCR-VL）、腾讯云文字识别、合合 TextIn：能力项相近，但调用模式（同步 / 异步轮询）、坐标形式、计费单位（页 / 次 / token / 并发）、结果链接有效期、限流、鉴权方式各不相同，且**公开页面都没有写清数据留存与是否用于训练**。

现有设计只有 M3-03 的 `BailianOcrAdapter`，作为 Model Hub 的 `ocr` 能力；按页计费的非模型产品、异步任务、自部署解析服务都没有位置（调研 05 G9）。

## 决定

1. **新增「文档解析引擎」SPI**，作为 ADR-026 插件宿主加载的第十类 SPI。所有解析引擎（进程内、自部署服务、云 API、模型）都实现同一个 SPI，由 ADR-060 的解析方案编排。
2. **适配器沿用通用连接器 SDK 的公共件**（M3-06 第 2 节）：配置规格（JSON Schema 生成表单）、凭证引用、按实例限流与重试、健康状态、出网经 EgressGuard。凭证管理复用 ADR-042（多 Key、有效期提醒、轮换、紧急吊销），供应商类型增加「解析服务」。
3. **VLM 类识别器仍是 Model Hub 的模型绑定**（purpose `ocr`），由内置的「模型引擎」适配器经 ModelGateway 调用，继续受模型配额、审计与路由约束；**非模型产品不进 Model Hub**（修订 ADR-024）。
4. **平台统一做**异步任务、结果转存、坐标换算、错误分类、按页计量与成本、去向过滤；适配器只负责「请求怎么发、结果怎么映射」。
5. **准入靠一致性测试与采购评估**：适配器通过一致性测试套件才能启用；采购前按第 7 节清单评估并取得书面数据处理条款。

## 1. 引擎分类

| 类别 | 例子 | 调用 | 去向属性 |
| --- | --- | --- | --- |
| `IN_PROCESS` | POI、PDFBox、LibreOffice 转换 | 进程内（LibreOffice 为本机子进程） | 私有 |
| `SIDECAR` | PaddleOCR 服务化部署（默认）、MinerU、`docling-serve` | 内网 HTTP | 私有（部署在客户环境） |
| `CLOUD_API` | 阿里云文档解析 / 读光 OCR、百度文档解析、腾讯云 OCR、TextIn | 公网 HTTPS | 云端，按实例声明 |
| `MODEL` | 百炼 `qwen-vl-ocr`、任何具备视觉能力的模型绑定 | ModelGateway | 继承模型绑定的去向 |

## 2. 适配器清单

每个适配器（插件）在清单中声明以下内容；引擎实例（一次具体配置）在登记表中保存配置值与凭证引用。

| 项 | 内容 |
| --- | --- |
| 标识 | 适配器键（如 `aliyun.docmind`）、版本、SPI 版本、类别 |
| 能力 | `LAYOUT`、`TEXT_OCR`、`TABLE`、`SEAL`、`HANDWRITING`、`CHECKBOX`、`FORMULA`、`DOC_PARSE`（整份文档级解析）；每项可声明支持的页类型 |
| 输入 | 接受的格式（页图、PDF、Office、OFD）；单文件大小、页数、像素上下限 |
| 调用模式 | `SYNC` / `ASYNC_POLL`；建议轮询间隔与最长等待；不支持回调模式（第 3 节） |
| 坐标 | 坐标形式（四点像素、`[x,y,w,h]`、旋转矩形、归一化）与参照（适配器收到的页图 / 供应商自行渲染的页）；是否有行级、字符级坐标；是否有置信度 |
| 计费 | 单位（页 / 次 / 千 token / 并发）、默认单价（实例可覆盖）、失败是否计费 |
| 限流 | 默认 QPS 与并发 |
| 配置规格 | JSON Schema：端点、地域、凭证类型（AK/SK、API Key、AppId + Secret、无）、功能开关（如印章擦除、跨页表合并） |
| 去向属性 | 部署（`PRIVATE` / `CLOUD`）、数据所在地域、供应商留存期（不留存 / N 天 / 未声明）、是否用于训练（否 / 是 / 未声明）、数据处理协议编号；**由引擎实例填写并由空间管理员确认**，不由插件作者决定 |
| 版本信息 | 供应商声明的模型或接口版本；能否在响应中取得 |

## 3. 调用与任务

| 项 | 定案 |
| --- | --- |
| 统一任务 | 每次引擎调用写一行 `dps_engine_job`：parseId、引擎实例、页范围、阶段、状态（`PENDING` / `SUBMITTED` / `POLLING` / `DONE` / `FAILED`）、供应商任务号、尝试次数、提交与完成时间、计量值、原始结果对象键 |
| 幂等 | 任务键为「文件哈希 + 页范围 + 引擎实例 + 阶段」；同步引擎重试前先查任务表；异步引擎提交成功后先落供应商任务号再轮询 |
| 轮询 | 按清单建议间隔起步，指数退避，上限 60 秒；超过最长等待（缺省 10 分钟）记超时，按降级链处理 |
| 回调 | 不支持。回调需要对公网开放入站地址，本部署规模（每天约 300 页）轮询足够 |
| 输入发送 | 优先发送平台自己渲染的页图（坐标参照确定）；只有 `DOC_PARSE` 类引擎发整份文件；大文件按页拆分（PDF 拆页、图片逐张）；不向外部发对象存储公网链接，必须用 URL 的引擎只用 5 分钟有效的签名链接并记审计 |
| 结果获取 | 结果到手即转存对象存储；供应商只给结果链接的（如百度 30 天有效）立即下载 |
| 坐标换算 | 适配器把供应商坐标换算为页内 0〜1 归一化；供应商自行渲染页面时，用其返回的页尺寸换算，无页尺寸的引擎只能用于 `TEXT_OCR` 第二意见，不能产出证据块的坐标 |
| 错误分类 | `RETRYABLE`（网络、5xx、限流）、`QUOTA`（额度或余额不足）、`INVALID_INPUT`（文件损坏、超限）、`AUTH`（凭证失效）、`UNSUPPORTED`；`RETRYABLE` 重试 3 次，`QUOTA` 与 `AUTH` 立即熔断该实例并告警，`INVALID_INPUT` 不换引擎重试 |
| 熔断与降级 | 实例连续失败 3 次标 `DEGRADED`（CON-SDK 健康规则）；路由跳过熔断实例，按方案降级链换下一个引擎；结果标 `DEGRADED_ENGINE` |
| 出网 | 一律经 EgressGuard；供应商域名进白名单；需要 IP 白名单的供应商，在部署手册中写出固定出口 IP |

## 4. 计量、成本与配额

- 每个任务记录计量值（页、次、token）与按实例单价算出的估算成本，写入 `dps_usage` 日汇总，按空间、引擎实例、用途（合同、知识库、附件）切片。
- `MODEL` 类引擎的 token 用量已由 ModelGateway 记入 `model_usage`，`dps_usage` 只记页数与关联，不重复计费。
- 空间预算（ADR-017 按成本扣减）同时计入解析成本；超预算时新解析任务排队并通知空间管理员，进行中的任务不打断。
- 统计页（ADR-041 第 6 节）增加「解析」分栏：页数、成本、各引擎失败率、平均时延、降级次数。
- 免费额度、资源包由供应商结算，平台不跟踪，只按标价估算。

## 5. 去向与数据治理

- 引擎实例按去向属性映射到 ADR-040 的去向许可：`PRIVATE` 实例等同私有化模型；`CLOUD` 实例等同云端模型供应商，只有空间批准过该供应商时才可处理 `CONFIDENTIAL` 文档。
- **留存或训练条款为「未声明」的云端实例不能处理 `CONFIDENTIAL` 及以上文档**；空间管理员可以在填写数据处理协议编号后放行，放行记入审计。
- `SECRET` 文档只能用 `PRIVATE` 实例。
- 每次外发记审计：引擎实例、文件哈希、页范围、数据标签、发送字节数。

## 7. 一致性测试与采购评估

### 7.1 一致性测试套件（PRS-05 交付）

| 项 | 要求 |
| --- | --- |
| 样本 | 平台自带 12 页样本：正文、无框表格、跨页表、合并单元格、印章盖字、手写日期、勾选框、旋转 90 度、倾斜拍照、低分辨率、空白填写位、页眉页脚 |
| 契约 | 输出通过 `tioka.parse/v1` 校验；所有 `regions` 在页内；`blockId` 稳定 |
| 坐标 | 与参考结果的行框 IoU ≥ 0.5 的比例 ≥ 90% |
| 能力声明 | 声明了 `SEAL` 的必须检出样本中的印章；声明了 `TABLE` 的单元格行列正确 |
| 错误 | 用桩模拟限流、5xx、鉴权失败、超时、结果链接过期，错误分类与重试行为符合第 3 节 |

| 结论 | 通过后才能在方案中启用；每次适配器升级重跑 |

## 修订：MinerU 4.x 与 TextIn（2026-11-07）

来由：[调研 06](../research/06-文档结构树图层与证照抽取补充调研.md)；ADR-029 第 72 条。

- **MinerU 4.x 提前到 M4 作为主引擎之一**：3.1.0 起许可由 AGPLv3 改为「Apache-2.0 + 附加条款」，附加条款对企业内部私有化部署影响很小，产品文档注明使用了 MinerU 即可；4.x 有原生 Office / OFD 解析、四档质量、CPU 可用、跨页表合并、印章文字识别、`/v1/tasks` 接口。适配器 `mineru.serving` 由 PRS-12 移入 PRS-03（PRS-03 由 4 人日增至 6 人日，同时交付 MinerU 4.x 与 PaddleOCR 两个服务化适配器及评测对比）。MinerU 4.1 的接口是破坏性变更（`/v1/tasks` 取代旧接口），适配器按 4.1 起的接口实现，清单中写明支持的版本范围。
- **外购参考适配器由阿里云文档解析改为 TextIn xParse**（PRS-05，人日不变）：标题树、元素层级、去水印、切边矫正、印章属性、手写行内对象、跨页表合并、字符级坐标与置信度、带引用的 Schema 抽取，与 ADR-063、ADR-064 需要的能力最贴合。TextIn 的私有化部署与数据处理条款公开文档未写明，按第 7.2 节采购清单书面确认；确认前其实例的留存与训练属性为「未声明」，按第 5 节不能处理 `CONFIDENTIAL` 文档。
- **没有必装的外部引擎**：本节与第 6 节列出的适配器都是可选的，客户按实际拥有的引擎登记实例，平台自动装配（ADR-063 第 5 节）；只有简单 OCR 接口的客户可用声明式适配器接入（PRS-19，M4 之后）。FE-36 由 3 人日增至 4 人日，增加能力覆盖矩阵与「生成推荐方案」。
- **能力声明增加**：`TREE`（引擎给结构树）、`DEWARP`、`WATERMARK_REMOVAL`、`SEAL_REMOVAL`、`SEAL_ATTRS`、`CHAR_DETAIL`、`KV_EXTRACT`（按 Schema 抽取），供 ADR-063 的元素级路由与 ADR-064 的抽取选择引擎。
- **一致性测试样本**增加：带水印页、证照页（营业执照、身份证）、有目录页的合同。
- **M4 之后**：PRS-10 改为百度、腾讯、阿里云文档解析适配器（仍约 6 人日）；PRS-12 只剩 Docling（约 1.5 人日）。
