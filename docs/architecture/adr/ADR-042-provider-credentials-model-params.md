# ADR-042 — 供应商凭证、连接配置与模型参数

- 状态：Accepted（设计定案，待实现）
- 日期：2026-11-06
- 覆盖工作项：MH-12〜MH-14、FE-11（新增）；FND-08 增补 1 人天
- 相关：[ADR-014](ADR-014-agentcore-alignment-package.md)、[ADR-017](ADR-017-model-gateway-quota-audit.md)、[ADR-024](ADR-024-model-hub-routing.md)、[ADR-026](ADR-026-foundation.md)、[ADR-041](ADR-041-config-versioning-observability.md)
- 约束：与 [ADR-029](ADR-029-design-rulings.md) 定案冲突时以定案为准（本 ADR 对应第 63 条）；修改本 ADR 走 [ADR-030](ADR-030-anti-drift-process.md) 的变更流程。
- 写法说明：只用文字和表格描述，不附代码片段。

## 背景

2026-11-06 负责人追问：供应商、模型、API Key 怎么管理，详细的自定义参数、API Key 有效期等。核对现有设计与代码，结果如下：

| 能力 | 现状 | 结论 |
| --- | --- | --- |
| Key 加密存储 | ADR-026 规定信封加密，生产缺主密钥启动失败。现有代码 `LocalSecretStore` 用 JDK 默认的 `AES` 变换（即 ECB 模式，没有完整性校验）；非 prod 环境会回退到内置开发密钥。M2 的 FND-08 设计了 AES-256-GCM 的 `CredentialCipher`，但只用于代用户令牌 | 部分覆盖，有安全缺口 |
| 每个供应商多个 Key | 一个供应商只有一个 `api_key_ref` | 未覆盖 |
| Key 有效期、到期提醒 | 没有 | 未覆盖 |
| Key 轮换、紧急吊销 | ADR-041 只写了"轮换记时间和操作人" | 未覆盖 |
| 按 Key 的用量、限流、预算 | 没有（ADR-041 的供给侧配额只到供应商一级） | 未覆盖 |
| 供应商连接细项（超时、代理、证书、协议专有字段、自定义头） | ADR-041 只列了"请求头模板、超时、出网策略" | 不够细 |
| 模型默认请求参数、厂商扩展参数、覆盖规则 | 没有；Agent 和 Flow 无法设置 temperature 等参数，也没有优先级 | 未覆盖 |
| 模型发现、连通性测试 | 只有 ADR-041 的健康探测 | 未覆盖 |

## 决定

1. **凭证从供应商配置里拆出来，单独管理**。一个供应商可以有多个凭证，每个凭证有有效期、状态、负责人和按 Key 的限额。凭证属于 ADR-041 的"即时型"对象：改了立即生效，每次改动写变更记录。密钥值不进入任何版本快照。
2. **密钥只写不读**。界面和接口只显示掩码和指纹。只有 Model Hub 的出站客户端能解密（ADR-014 白名单）。
3. **模型参数分层覆盖**：模型默认值 → 路由组 → Agent 或 Flow 节点 → 单次调用。模型上声明哪些参数可以覆盖、取值范围和锁定项。最终生效的参数记入路由事件。

## 1. 凭证（MH-12）

### 1.1 字段

| 字段 | 说明 |
| --- | --- |
| 名称 | 便于识别，如"百炼-生产-主" |
| 所属供应商 | 一个供应商可以有多个凭证 |
| 密钥来源 | 手工录入（加密存库）、外部密钥库引用（Vault 路径或客户 KMS，经 ADR-026 的 `SecretStoreAdapter`）、无需密钥（本地 vLLM、Ollama） |
| 密钥值 | 只写；显示前 4 位、后 4 位和 SHA-256 指纹前 8 位，用来和厂商控制台对照 |
| 附加身份 | 厂商的组织 ID、项目 ID、Azure 资源名等，随请求发送 |
| 角色 | 主用、备用 |
| 权重 | 轮询策略下使用 |
| 生效时间、到期时间 | 到期时间可以为空（长期有效） |
| 提醒提前量 | 默认到期前 30 天、7 天、1 天各提醒一次，可改 |
| 负责人 | 收到到期和失效提醒的人；系统管理员总会收到 |
| 按 Key 的限额 | RPM、TPM、月度 token、月度成本（厂商通常按 Key 限流和计费） |
| 状态 | 见 1.2 |
| 运行信息 | 最近使用时间、最近成功时间、最近失败的原因和时间、本月用量和成本 |

### 1.2 状态

| 状态 | 含义 | 能否被选用 |
| --- | --- | --- |
| PENDING | 新录入，尚未通过连通性测试 | 否 |
| ACTIVE | 正常 | 是 |
| COOLDOWN | 刚收到 429 或厂商额度错误，冷却中（默认 60 秒，与 MH-03 一致） | 否，冷却结束自动恢复 |
| DRAINING | 轮换中的旧 Key，只作备用，观察期结束后自动吊销 | 仅在没有其他可用 Key 时 |
| INVALID | 厂商返回 401、403，判定 Key 已失效 | 否，需要人工处理 |
| EXPIRED | 已过到期时间 | 否 |
| DISABLED | 人工停用 | 否 |
| REVOKED | 已吊销；保留期（默认 30 天）后删除密文 | 否 |

### 1.3 选用策略

供应商上配置一种策略：

- **主备**（默认）：用主 Key；主 Key 不可用时用备用 Key。
- **加权轮询**：按权重分摊，用来绕开单 Key 的限流。

选用发生在 `ModelGateway` 选定 binding 之后、发出请求之前。不随 Turn 冻结：同一 Turn 内换 Key 不影响结果。每次调用把凭证 ID 记入 `model_usage`，用来按 Key 统计用量与成本，并和厂商账单对账。

出错处理：

| 厂商返回 | 处理 |
| --- | --- |
| 401、403 | 这个 Key 立即标为 INVALID，不重试，换下一个 Key 重发一次；同时触发告警 |
| 429 或额度类错误 | 这个 Key 进入 COOLDOWN，换下一个 Key |
| 5xx、超时 | 不算 Key 的问题，按 MH-02、MH-03 的重试和故障接力处理 |
| 供应商下没有任何可用 Key | 供应商健康状态记为 `NO_CREDENTIAL`（ADR-041 第 5.1 节新增），路由跳过它的所有候选 |

### 1.4 有效期与提醒

- 每天检查一次到期时间。到达提醒提前量时，经 GOV-13 告警通知负责人和系统管理员；同一个提醒点只发一次。
- 到期时自动转为 EXPIRED，并发一条告警。如果这个供应商因此没有可用 Key，告警升级为"供应商不可用"。
- 管理页有"即将到期"清单，按剩余天数排序。
- 大多数厂商不提供查询 Key 有效期的接口，到期时间由录入人填写；厂商能查时可以在连通性测试里顺带更新。

### 1.5 轮换与吊销

**无中断轮换**分五步，每一步都写审计：

1. 录入新 Key，状态为 PENDING。
2. 连通性测试通过后，新 Key 自动转为 ACTIVE（备用）。
3. 新 Key 设为主用，旧 Key 转为 DRAINING。
4. 观察期默认 24 小时。这段时间旧 Key 只在新 Key 不可用时使用。
5. 观察期结束，旧 Key 自动吊销。

**紧急吊销**用于 Key 泄露：一步把 Key 转为 REVOKED，广播配置事件，各实例在几秒内停止使用。界面把这个操作和普通停用分开，并要求填写原因。

平台不负责到厂商处生成新 Key（大多数厂商没有这类接口），只管录入、切换和吊销。

### 1.6 加密存储（增补 FND-08，M2）

- 供应商 Key、MCP Server 的令牌、数据源凭证，与代用户令牌统一使用 FND-08 的 `CredentialCipher`：AES-256-GCM，随机 IV，带密钥版本号。附加认证数据（AAD）为"凭证 ID + 所属对象 ID"，防止密文被挪到别的行。主密钥轮换沿用 M2-03 的做法。
- 现有 `LocalSecretStore` 的 ECB 加密在 FND-08 中替换，已有密文由迁移任务重新加密。非 prod 环境回退到开发密钥的行为保留，但启动日志必须告警，健康检查接口也要标红。
- 以上增加 FND-08 约 1 人天。这是安全缺口，若希望早于 M2 修复，可以单独拿出来放进 M1 的修正时段。

### 1.7 权限

| 权限点 | 用途 |
| --- | --- |
| `model:credential:admin` | 录入、替换、轮换、停用、吊销凭证，修改有效期和限额 |
| `model:read` | 查看凭证的掩码、指纹、状态、有效期、用量，看不到密钥值 |

`model:credential:admin` 与 `model:admin`（ADR-041）分开：配模型的人不一定能接触 Key。没有任何权限可以读出密钥明文。

## 2. 供应商连接配置（MH-13）

这些字段补充进 ADR-041 第 1 节"供应商"对象的版本内容。

| 分组 | 字段 |
| --- | --- |
| 协议 | OpenAI 兼容、Azure OpenAI、Anthropic、阿里云百炼、DeepSeek、本地推理（vLLM、Ollama）。各协议有自己的专有字段，例如 Azure 的 api-version、Anthropic 的版本头 |
| 地址 | Base URL；可选的备用地址（同一厂商的其他地域） |
| 超时 | 连接超时、首 token 超时、流式空闲超时、总超时 |
| 并发 | 到该供应商的最大并发连接数 |
| 网络 | 出网代理；自定义 CA 证书（私有化常见）。生产环境禁止关闭证书校验 |
| 自定义请求头 | 静态值，或引用凭证的附加身份字段；不能填密钥明文（保存时按常见 Key 格式检测并拒绝） |
| 自定义查询参数 | 用于部分网关型供应商 |
| 凭证选用策略 | 主备、加权轮询（见 1.3） |
| 健康探测 | ADR-041 第 5.1 节的探测开关与周期 |

### 模型发现与连通性测试

- **模型发现**：对支持模型列表接口的协议，可以从供应商拉取模型清单，勾选后批量生成 binding 草稿。能力和价格要人工确认后才能发布。
- **连通性测试**：
  - 供应商 + 凭证：调用模型列表接口或发一次最小补全，返回耗时与错误分类。
  - binding：用该模型发一次最小请求，带工具时再测一次工具调用格式。
  - 测试用量计入操作人自己的配额，用途记为 `connectivity_test`。

## 3. 模型参数（MH-14）

### 3.1 binding 上的参数定义

这些字段补充进 ADR-041 第 1 节"模型"对象的版本内容。

| 分组 | 内容 |
| --- | --- |
| 能力声明 | 上下文长度、最大输出 token、是否支持工具调用、视觉、JSON 模式、流式、推理（思考）模式；嵌入维度 |
| 默认请求参数 | temperature、top_p、max_tokens、stop、presence_penalty、frequency_penalty、seed、response_format、推理强度或思考预算 |
| 参数约束 | 每个参数可以设置：允许覆盖与否、取值范围或枚举、是否锁定。锁定的参数忽略所有上层覆盖，常用于合规场景（如固定低 temperature） |
| 厂商扩展参数 | 原样并入请求体的 JSON，例如百炼的 `enable_search`、`enable_thinking`。只允许填该协议白名单里的键，防止误填后整个请求失败 |
| 价格 | 输入、输出、缓存命中 token 单价；按次、按图片计费项；可选阶梯价（按上下文长度分档）；币种。价格变更走版本（ADR-041），历史成本按调用当时的版本计算 |

### 3.2 覆盖顺序

优先级从低到高：

1. binding 默认参数
2. 路由计划中该组的参数覆盖（例如"创意组"统一调高 temperature）
3. Agent 的 `ModelPolicy.params`（AgentSpec，随 Agent 版本固定），或 Flow LLM 节点的参数
4. 单次调用的必要参数（例如结构化输出强制 `response_format`，工具调用强制相关字段）

规则：

- 每一层只能设置 binding 声明为"允许覆盖"的参数，超出范围的值截到边界，并在时间线记一条警告。
- 锁定参数不受任何上层影响。
- 第 3 层在 Agent 发布时校验（AST-02 增加一项检查）：参数名对候选 binding 都合法。
- **故障接力换模型时**：参数按 Tioka 统一的参数名翻译成目标协议的写法。目标模型不支持的参数会被丢弃，并在时间线记一条。厂商扩展参数只对声明它的 binding 生效，不会跟着带到其他 binding。
- 每次调用的最终生效参数，以"与 binding 默认值的差异"形式记入路由事件（ADR-024 的 `model_route_event`），排查时能看到这次到底用了什么参数。

## 4. 监控与统计的补充（并入 MH-10、MH-11）

- 运行状态页增加凭证一栏：每个 Key 的状态、最近失败原因、本月用量占按 Key 限额的比例、剩余有效天数。
- 统计增加"凭证"分组维度，可以按 Key 汇总用量与成本，用于和厂商账单对账。
- 告警内置规则增加：Key 即将到期（30、7、1 天）、Key 被判定为 INVALID、供应商没有可用 Key。

## 5. 界面（FE-11）

在 ADR-041"模型中枢"的供应商页下面增加以下内容：

- **凭证列表**：状态、掩码、指纹、角色、到期时间、用量。
- **凭证操作**：录入或替换（只写输入框）、连通性测试、按 1.5 的步骤轮换、停用、紧急吊销。
- **"即将到期"清单**。
- **供应商详细配置表单**：按协议显示专有字段。
- **模型发现**向导。
- **模型参数编辑**：默认值、约束、锁定、扩展参数（带白名单提示）、价格与阶梯价。
- **Agent 编辑器里的参数覆盖面板**：只列出允许覆盖的参数，并显示取值范围。

### G3 闸门增加的用例

`G3CredentialGateIT`：
1. 供应商配主备两个 Key，桩对主 Key 返回 401：主 Key 被标为 INVALID，请求改用备用 Key 成功，并触发告警。
2. 把备用 Key 的到期时间设为过去：它转为 EXPIRED，供应商状态变为 `NO_CREDENTIAL`，路由跳到另一个供应商。
3. Agent 覆盖 temperature 超出 binding 允许的范围：值被截到边界，时间线有警告。锁定参数不受 Agent 覆盖影响。
