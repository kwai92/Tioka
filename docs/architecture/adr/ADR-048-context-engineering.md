## 背景

ADR-027 的 RT-10 规定了一条固定组装顺序和一种压缩（超过模型上下文 75% 时摘要），ADR-031 又在其中插入了「经验」。调研发现三个问题（调研 03 第 9.2 节 G1〜G5）：

1. 用户记忆、经验、知识自动检索结果每一轮都会变，却排在历史之前，**每轮都让历史部分的提示缓存失效**；
2. 只有一种重型压缩，没有轻量的工具结果清理，也没有低于模型窗口的「有效预算」，上下文腐化在到达 75% 之前就开始了；
3. 子 Agent 委派与交接时传什么、回什么没有规定。

## 决定

1. **上下文是 Runtime item 的编译视图**。存储里永远是完整 item（ADR-016、ADR-022 不变）；发给模型的上下文由组装器按本 ADR 的分区与削减规则生成，每次生成都记录一份「上下文清单」。
2. **四区组装**：稳定前缀 → 会话快照 → 历史 → 本轮尾部。越靠前越稳定，每轮变化的内容只能放在本轮尾部。
3. **有效预算低于模型窗口**，削减分四级：卸载 → 清理 → 摘要 → 失败，先做可恢复的，再做不可恢复的。
4. **子 Agent 默认隔离**，只收任务简报与显式引用，回传有上限。
5. **各模块只能向组装器登记自己的段**，不能自行插入（沿用 ADR-027 原则），段属于哪一区由本 ADR 决定。

## 1. 四区组装

| 区 | 内容（按顺序） | 稳定范围 | 变化时机 |
| --- | --- | --- | --- |
| **A 稳定前缀** | 平台安全指令 → Agent 指令（含钉版本的 Prompt 模板，ADR-041）→ always Skill → auto Skill 索引 → 输出契约说明（ADR-037）→ 工具定义（见第 1.2 节） | Agent 版本级：同一 Agent 版本的所有会话、所有用户相同 | 发布新版本；平台指令升级 |
| **B 会话快照** | 用户画像记忆快照（ADR-050，≤ 500 token）→ 空间置顶记忆（ADR-050，≤ 300 token）→ 会话固定材料（会话级附件摘要、会话入口参数，如 ROUTER 交接带入的摘要） | thread 级：建 thread 时生成并冻结 | 只在第 3 级削减（摘要）时重新生成 |
| **C 历史** | 压缩摘要 item（若有）→ 之后的历史 item（经第 2 节削减） | 只追加 | 每轮追加；第 2、3 级削减时整体改写 |
| **D 本轮尾部** | 本轮检索到的记忆（ADR-050，≤ 500 token）→ 经验（ADR-031，≤ 3 条、≤ 800 token）→ 知识自动检索结果（ADR-018）→ 当前计划复述（ADR-046 `PLAN_EXECUTE` 时）→ 环境信息（当前日期到天、时区、本 Turn 剩余预算与步数）→ 本轮输入 | Turn 级：Turn 开始时生成并冻结，本 Turn 内的多步工具循环都复用同一份 | 每个 Turn |

本 Turn 内模型产生的工具调用、工具结果、思考与回答追加在 D 区之后。

**D 区不进入历史**。下一个 Turn 组装时，上一轮的 D 区内容（检索到的记忆、经验、知识片段、环境信息）不再出现，历史里只有本轮输入、工具往来与回答；知识片段若被回答采用，引用以 citation item 留在历史中（ADR-018 已定）。这样做的结果是：下一轮的前缀「A + B + 上一轮为止的历史」与上一轮请求的前缀一致，缓存命中（ADR-049）。

### 1.1 取代的顺序

本节取代 ADR-027 RT-10 与 ADR-031 第 3 条规定的顺序。原顺序中各段的新位置：

| 原顺序中的段 | 新位置 |
| --- | --- |
| 平台安全指令、Agent 指令、always Skill、auto Skill 索引 | A 区，不变 |
| 用户记忆 | 拆为两部分：画像快照进 B 区，按本轮检索的进 D 区（ADR-050） |
| 经验 | D 区 |
| 知识自动检索结果 | D 区 |
| 压缩摘要、历史 item | C 区 |
| 本轮输入 | D 区末尾 |

### 1.2 工具定义的稳定性

- 工具定义放在 A 区末尾，按工具名排序，定义内容按规范化后的 JSON（键序固定、去掉空值）序列化，规则见 ADR-049。
- 工具列表在 thread 开始时按授予计算一次，**同一 thread 内只在授予收窄或 Agent 版本切换时改变**。授予收窄属于安全事件，优先于缓存。
- ADR-016 RT-13 的「常用工具集合」改为在 thread 内不变（原为 Turn 内不变）；经 `tool.search` 加载的延迟工具定义作为工具结果出现在历史中，不改 A 区。
- 本 Turn 不可用但仍在列表中的工具（如审批策略暂停的类别），由 ToolGateway 在调用时拒绝，并在 D 区环境信息中写一句说明。不从列表中删除。

### 1.3 环境信息

时间、预算、步数等每轮都会变的信息只能写在 D 区。A 区与 B 区不得包含时间戳、请求 ID、随机数或无序集合（发布校验检查 Agent 指令中的时间类变量占位，命中则提示改到环境信息段）。

## 2. 有效预算与分级削减

### 2.1 有效预算

有效预算 E 取以下两者的较小值：所选模型上下文长度 × 75%；AgentSpec `context` 段的预算上限（默认 100K token）。所有阈值都按 E 计算。压缩后重新选模（设计 J）时，按新模型重算 E。

### 2.2 四级削减

| 级 | 名称 | 触发 | 做法 | 可恢复 |
| --- | --- | --- | --- | --- |
| 0 | 卸载 | 工具结果入库时 | 单条结果超过该工具声明的上限（默认 8000 token，工具元数据可声明更小或更大，平台上限 32000）时，全文写入工作盘或对象存储；上下文中放**结构化预览**与路径：JSON 保留顶层字段与数组前 5 项并注明总数；表格保留表头与前后各 10 行并注明总行数；文本保留开头与结尾；错误信息完整保留 | 是：模型可用 `workspace.read` 读回 |
| 1 | 清理 | 组装后总量超过 E 的 60% | 从最旧的开始，把**最近 3 个 Turn 之外**的工具结果替换为占位文本「已清理：工具名、调用时间、结果位置」；工具调用本身（名称与参数）保留；**失败结果保留错误摘要**；登记为「不清理」的工具（`plan.update`、`team.*`、`memory.*` 及 Agent 配置的列表）不清理；往轮的思考内容（reasoning item）不再回传。每次清理至少清掉 E 的 15%，不够就不清，避免为少量 token 打断缓存 | 是：结果仍在存储中，可重新调用或读文件 |
| 2 | 摘要 | 清理后总量仍超过 E | 保留最近 3 个 Turn 原样，更早的历史经 ModelGateway（purpose=compaction，系统 Prompt `sys.compaction`）生成**结构化摘要**，写一个 compaction item（第 2.3 节）；同时重新生成 B 区快照；之后允许重新选模 | 否（原始 item 仍保留供界面与审计） |
| 3 | 失败 | 摘要后仍超过 E（例如最近 3 个 Turn 本身就超长） | 先把保留的 Turn 数降到 1 再试一次；仍超则 Turn 以 `CONTEXT_OVERFLOW` 结束，提示用户新开会话或把材料作为附件索引。**不做静默截断** | — |

### 2.3 结构化摘要

- 摘要按固定栏目输出（Schema 登记在 ADR-037 登记表，名称「上下文摘要」）：目标与成功标准；用户明确的约束、偏好与禁止事项；已做的决定及理由；关键标识符（业务单号、文件路径、URL、产物 ID）；已完成的工作；未决问题与已知错误；当前进度与下一步。
- **原样保留不摘要**的内容，作为摘要的附表：最新版本的 `plan` item（ADR-046）；工作盘 `scratch/notes` 下的笔记路径（ADR-027 修订）；被摘要部分中出现的文件引用与产物引用清单；未决审批。
- 摘要调用不提供任何工具；摘要提示要求核对前后矛盾与时间顺序，对未经工具结果证实的说法标注「未证实」。
- 多模态内容：被摘要部分的图片与文档在摘要前已是 file_ref，摘要中保留引用，模型需要时重新读取。
- 摘要继承被摘要内容的最高数据标签（ADR-040 已定）。
- Agent 可在 `context` 段写一段「摘要补充说明」（例如合同审查 Agent 要求保留每条风险的条款号），追加在系统 Prompt 之后。`sys.compaction` 跟随最新版本（ADR-041 已定），补充说明随 Agent 版本冻结。

### 2.4 与分叉、计划、长任务的关系

| 场景 | 规则 |
| --- | --- |
| 分叉（ADR-022） | compaction item 属于其所在 thread。子 thread 拼接父 thread `seq ≤ fork_seq` 的 item 时，只采用位置在 `fork_seq` 之前的最后一个 compaction item；之后的不采用。分叉不复制 B 区快照，子 thread 重新生成 |
| `PLAN_EXECUTE`（ADR-046） | 当前计划在 D 区复述（每个 Turn 重新复述当前版本），对抗长任务跑偏；`plan.update` 的工具结果不清理 |
| `GOAL_LOOP`（ADR-046） | 每次 Run 是新 thread，进度靠工作盘清单与日志，不依赖压缩摘要 |
| 编排工单（ADR-020） | 工单上下文作为本轮输入的一部分进入 D 区 |

## 3. 子 Agent 与交接的上下文传递

### 3.1 委派（修订 ADR-027 RT-12、ADR-038）

| 项 | 规则 |
| --- | --- |
| 传入模式 | `ISOLATED`（默认）：子 Agent 的 C 区为空，D 区本轮输入是任务简报（MAS-08 的必填结构：目标、完成标准、输入产物、约束）与显式引用的产物、文件；`WITH_SUMMARY`：额外附父 thread 最近一次 compaction 摘要（只在摘要标签不超过子授予的 `maxDataLabel` 时允许，否则降为 `ISOLATED` 并记一条警告）。**不提供继承完整历史的模式** |
| 子 Agent 的 A、B 区 | 按子 Agent 自己的版本组装；B 区的用户画像快照取链根用户的（ADR-040 已定子 Agent 只读链根用户的记忆），仅当子 Agent 的 `memory` 段允许读个人记忆时才加入 |
| 回传 | 子 Agent 最终回答作为委派工具的结果回到父 Turn，上限默认 2000 token（AgentSpec `context` 段可调，平台上限 8000）；超出时平台要求子 Agent 先把完整结果发布为产物（团队内为黑板产物，单独委派时为工作盘文件），回传「摘要 + 产物引用」 |
| 团队（ADR-038） | 节点输入即任务简报；黑板是团队级的共享工作记忆，子 Agent 按 `consumes` 读取；共享决定日志（MAS-08）中与节点 `subjectKey` 前缀匹配的有效 `Decision` 附在任务简报中，这是对 Cognition 所说「隐含决定冲突」的补偿 |

### 3.2 交接（修订 ADR-044）

ROUTER 交接带入历史时：

- 前一 Agent 的回答改写为叙述形式「〔前序助手：X〕说：……」，作为目标 Agent 本轮输入的一部分，**不以 assistant 角色出现**，避免目标 Agent 把它当作自己说过的话；
- 前一 Agent 的工具调用与工具结果不带入；
- `SUMMARY` 模式的摘要由 `sys.compaction` 生成，栏目同第 2.3 节；
- 带入的内容进入目标 thread 的 B 区「会话固定材料」，交接后在该 thread 内保持不变。

## 4. 上下文清单（Context Manifest）

每次模型调用都记录一份上下文清单，与 `model_usage` 明细一一对应：

| 字段 | 内容 |
| --- | --- |
| 调用标识 | turnId、步序号、`model_usage` 明细 ID |
| 段列表 | 每段：所属区、段类型（平台指令、Agent 指令、Skill、工具定义、画像快照、空间记忆、历史、压缩摘要、检索记忆、经验、知识结果、计划、环境、输入）、来源引用（如 `memoryId`、`expId`、`chunkId@docVersion`、`promptTemplate@版本`、Agent 版本）、token 数、数据标签 |
| 削减事件 | 本次是否发生清理或摘要、清掉的 token 数 |
| 缓存 | 组装器给出的断点位置、供应商回报的缓存读与写 token（ADR-049） |
| 前缀指纹 | A 区、A+B 区、A+B+C 区各自的内容哈希，用于缓存诊断（ADR-049 第 5 节） |

保留期与 `model_usage` 明细相同（默认 180 天）。用途：

1. 轨迹视图的「上下文构成」面板（FE-31）；
2. ADR-031 评测可复现：评测运行记录用到的记忆、经验、知识片段与版本；
3. 回答「这条回答受了哪条记忆影响」，供用户在记忆管理页追溯（ADR-050）；
4. ADR-041 按版本统计时补上「哪个 Prompt 模板版本、哪个经验条目」维度。

清单只存引用与计数，不存正文；正文仍在 item、记忆、经验各自的表里，权限各自检查。

## 5. AgentSpec 的 `context` 段（修订 ADR-023）

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 预算上限 | 有效预算 E 的上限 | 100K token |
| 清理阈值 | 占 E 的比例 | 60% |
| 保留 Turn 数 | 清理与摘要时原样保留的最近 Turn 数 | 3 |
| 不清理的工具 | 追加在平台默认列表之后 | 空 |
| 摘要补充说明 | 第 2.3 节 | 空 |
| 子 Agent 传入模式 | `ISOLATED` / `WITH_SUMMARY` | `ISOLATED` |
| 子 Agent 回传上限 | token | 2000 |

M3（AST-11）只预留本段并固定为默认值，M4（CTX-02）开放配置。随 Agent 版本冻结。

## 6. 不做的事

- 不使用供应商的加密压缩条目：轨迹必须可读、可审计、可换供应商续接。返回可读摘要的供应商原生压缩可在 M4 之后作为 `sys.compaction` 的一种实现接入（CTX-03），规则不变。
- 不在组装器里按相似度删除历史消息（语义裁剪）：效果难以预测，且破坏缓存。
- 不允许 Agent 在运行时修改 A 区（自身指令）：程序记忆只经发布与人审改变（ADR-050）。
