# ADR-068 — 评测方法规范：评测集分层、标注、评分器与裁判校准、统计口径

## 背景

ADR-031 给出了评测的对象模型（数据集、评估器、批次评测、实验、线上采样），ADR-056、ADR-062、ADR-066、ADR-067 各自定义了专项评测集与闸门。缺的是**共同的方法口径**：

1. 评测集没有分层，没有只用于准入的密封集，切分单位没有规定，团队容易对开发集过拟合；
2. 用例没有标注规范版本与生效日期，业务规范（如合同要点库）改版后旧标签悄悄变错；
3. 模型打分评估器没有和人工标注校准，也没有偏差检查；
4. 每条用例只跑一次，看不出不稳定；
5. 报告只有点估计，样本小时差异是噪声还是真实无从判断。

本 ADR 是所有评测（Agent、Flow、Prompt、模型选型、专项评测）共用的方法规范；ADR-069（上线与发布）、ADR-070（模型选型）、ADR-071（反馈回流）都以它为准。

## 决定

1. 评测集分五层：冒烟、开发、密封、回归、专项（第 1 节）。
2. 切分与统计以**材料单元**为单位（合同场景为合同链），不以单条判定为单位（第 1.2 节）。
3. 用例卡增加来源、标注、规范版本与生效日期、分层标签、数据标签等字段（第 2 节）。
4. 评分器按「结果检查 → 规则 → 模型分类 → 模型打分 → 人工」的优先级选用，能用前者不用后者（第 3 节）。
5. 模型裁判先校准后使用：校准集、κ 门槛、偏差检查、钉快照版本、与被测模型不同族（第 4 节）。
6. 准入与对比类评测每条用例默认运行 3 次，报单次成功率与 pass^k（第 5 节）。
7. 报告一律给区间：按材料单元聚类的标准误、配对差异、比例用 Wilson 区间；门禁按非劣效判定（第 6 节）。
8. 标注采用「开发预标 + 业务专家只看争议」，双人标注只用于校准集与密封集争议项（第 7 节）。

## 1. 评测集分层

| 层 | 用途 | 谁能看用例内容 | 是否可据其调参 | 运行时机 |
| --- | --- | --- | --- | --- |
| 冒烟集 `SMOKE` | 快速发现「跑不通」 | 全员 | 可以 | 每次提交，CI 录制回放（ADR-030） |
| 开发集 `DEV` | 日常迭代、模型初筛 | 全员 | 可以 | 随时 |
| 密封集 `SEALED` | 准入评测、模型选型终选、双跑对照的离线部分 | 评测负责人与业务专家 | **不可以** | 只在 ADR-069 的 E2 准入、ADR-070 第 3 轮终选、哨兵评测时运行 |
| 回归集 `REGRESSION` | 出过错、修好后不能再错 | 全员 | 可以 | 每次准入与 C1 以上变更；**逐条必须通过** |
| 专项集 `SPECIAL` | 解析、检索、结构化、护栏等 | 按各 ADR | 按各 ADR | 按各 ADR |

- 层是数据集版本上的属性（`eval_dataset` 增加 `tier`），同一用例只能属于一层；回归集与开发集可以引用同一原始材料，但**密封集的材料不得出现在任何其他层**。
- **密封集保护**：密封集的用例内容与逐条结果只有评测负责人（新权限点 `eval:sealed:read`）与该 Agent 的业务专家能看；其他人只能看汇总指标。批次评测运行密封集时，轨迹与上下文清单按密封权限隔离，不进入经验提取（EVO-05）和候选题生成（KNW-15）。
- **轮换**：每季度把密封集的约 1/3 移入开发集，补入同等数量的新线上样本（来自影子期或分诊后的线上用例）；轮换记入数据集版本说明。被移出的用例在移出后可以调参。
- **饱和与毕业**：能力评测（开发集中的难例）连续两个版本通过率 ≥ 95% 时，转入回归集，开发集补充新的难例。

### 1.1 起步规模

| 场景风险等级（ADR-069） | 开发集起步 | 密封集起步 | 说明 |
| --- | --- | --- | --- |
| R1 只读问答 | 30 条 | 30 条 | 可用 KNW-15 候选题生成，人工审核后入集 |
| R2 产出建议、由人决定 | 20〜50 个材料单元 | 20 个材料单元 | 从真实工单与失败中取 |
| R3 产出结论或触发写操作 | 30 个材料单元 | 30 个材料单元 | 合同审查属于 R3 |

规模的最终依据是第 6.3 节的功效估算：要分辨的差异越小，集合越大。

### 1.2 切分单位

- 每个数据集声明**材料单元键**（合同场景为合同链的 `contract_key` 根，问答场景为文档或会话）。一个材料单元派生的所有用例必须在同一层。
- 统计时以材料单元为聚类单位计算标准误（第 6 节）。
- 合同场景：主合同、补充协议、续约协议属于同一材料单元；同一门店的不同合同链可以分到不同层。

## 2. 用例卡

在 ADR-031 `eval_case` 的输入与期望之外增加：

| 字段 | 含义 |
| --- | --- |
| `unit_key` | 材料单元键 |
| `source` | `MANUAL` / `IMPORT` / `ONLINE` / `SHADOW` / `FEEDBACK` / `GENERATED`（生成后须人工审核） |
| `source_ref` | 来源 Turn、合同、反馈 ID |
| `polarity` | `POSITIVE`（期望 Agent 做出某判断）/ `NEGATIVE`（期望 Agent 不做某判断或识别出问题）；用于检查正反例平衡 |
| `labels` | 分层统计标签：扫描件、补充协议、多门店、注入样本等 |
| `annotator`、`reviewer`、`adjudicator` | 标注人、复核人、仲裁人 |
| `guideline_version` | 标注规范版本 |
| `spec_ref`、`effective_from` | 期望答案所依据的业务规范版本（合同场景为要点库版本）与生效日期 |
| `label_status` | `VALID` / `STALE`（规范已变，待重标）/ `DISPUTED`（标注争议未仲裁） |
| `data_label` | 用例数据标签（ADR-040）；评测运行的模型去向受其约束 |
| `must_pass` | 是否逐条必须通过（回归集缺省为是） |

- `label_status ≠ VALID` 的用例不参与门禁统计，只在报告中列出数量。
- 业务规范发布新版本时（例如要点库），按 `spec_ref` 找出受影响的用例，批量标为 `STALE` 并生成重标任务（ADR-071 第 5 节）。
- 期望答案可以是结构化（字段与取值、四态结论）、引用（期望命中的块或条款）、或评分细则（给模型裁判用）。

## 3. 评分器的选用

| 优先级 | 类型 | 适用 | 合同场景例子 |
| --- | --- | --- | --- |
| 1 | 结果检查 | 检查环境的最终状态，而不是 Agent 自己说了什么 | 业务系统里是否真的写入了草稿；变更单内容 |
| 2 | 规则 | 结构化字段比对、四态比对、引用命中、Schema 校验 | 必备要点四态与金标准逐项比对；证据是否回指到正确条款 |
| 3 | 模型分类 | 输出 Pass / Fail / Unknown，标签互斥且穷尽 | 「建议修改文字是否消除了风险」 |
| 4 | 模型打分 | 0〜5 等级，只用于趋势，不单独用于门禁 | 理由的可读性 |
| 5 | 人工 | 校准、争议、密封集抽样 | 法务复核 |

- **评结果，不评路径**：Agent 调用工具的顺序不作为通过条件；需要约束路径时（例如「不得调用写工具」）用安全类断言单独表达。
- 一个评测运行可绑定多个评分器；每个评分器只评一个维度。
- 评分器本身有版本（`eval_evaluator` 增加 `version` 与 `config_hash`）；评分器改版视为评测定义变化，新旧结果不直接对比，需在同一运行中同时跑新旧评分器。

## 4. 模型裁判校准（EVO-09）

### 4.1 使用条件

模型类评分器（优先级 3、4）用于**门禁**之前必须满足：

| 条件 | 规则 |
| --- | --- |
| 校准集 | 绑定一个人工标注的校准集，起步 100 条，按真实分布并对难例与少见失败过采样；其中 30% 作为留出，不参与细则调整 |
| 一致性 | 先测人与人一致性（两名标注者在 30 条上的 κ）；裁判与人工多数结论的 Cohen's κ ≥ 0.6，且 κ 不低于人与人 κ 的 80%；未达标时只能出报告，不能用于门禁 |
| 误放率 | 在留出集上，裁判判 Pass 而人工判 Fail 的比例 ≤ 10%（误放比误杀更危险） |
| 偏差检查 | 两两比较类裁判：交换顺序，结论翻转率 ≤ 10%；单点评分类：等内容不同长度、等内容不同格式（纯文本与 Markdown）的成对样本，分数差异不显著 |
| 不同族 | 裁判模型不得与被测对象使用同一模型族；被测对象换模型族时检查冲突 |
| 钉版本 | 裁判绑定具体模型快照（不得引用跟随型别名）、提示版本与参数；任一变化视为裁判新版本，需重测第 2、3 条 |
| 未知选项 | 分类型裁判必须提供 Unknown；Unknown 计入报告，不计入通过 |

- 校准结果写在评分器版本上（κ、误放率、翻转率、校准集版本、日期），报告引用它。
- 校准每季度复核一次；复核时用当季分诊确认过的线上样本补充校准集。

### 4.2 裁判模型的来源

- 默认用 Model Hub 中登记的模型，`purpose = EVALUATION`，用量计入空间的评测预算（ADR-031 已定）。
- 外部裁判产品（如阿里云 PAI 裁判员模型）按评估器 SPI 的插件接入，同样必须过第 4.1 节校准。
- 数据标签：裁判看到的内容与被测对象相同，去向许可按 ADR-040 判定；`SECRET` 用例只能用私有部署的裁判。

## 5. 多次运行与一致性

- 准入评测（ADR-069 E2）、模型选型第 2〜3 轮（ADR-070）、双跑对照的离线部分：每条用例默认运行 **3 次**（`trials`，可配 1〜10）；冒烟集与日常开发 1 次。
- 每次运行在干净的隔离 thread 中进行（ADR-031 `origin = eval`），不共享记忆、经验命中统计和缓存外的状态；运行记录上下文清单（ADR-048），保证可复现。
- 报告同时给出：
  - **单次成功率**：各次运行成功率的均值（作为该用例的分数参与统计，降低题内方差）；
  - **pass^k**：k 次全部成功的用例比例；
  - **结论一致率**：k 次运行的关键输出（合同场景为必备要点四态）完全一致的用例比例。
- R3 场景的准入门槛必须包含 pass^k 或结论一致率（具体值在场景评测规格中定，合同场景见 ADR-069 第 5 节）。

## 6. 统计口径

### 6.1 报告格式

每个指标报：点估计、95% 区间、样本数（材料单元数与判定数）、`STALE` / `DISPUTED` 排除数。

| 指标类型 | 区间方法 |
| --- | --- |
| 均值类（分数、一致率） | 按材料单元聚类的标准误，均值 ± 1.96 × 聚类标准误 |
| 比例类且分母小（召回率、误放率） | Wilson 区间；分母为材料单元内聚类时，先按材料单元计算有效样本量再算 |
| 两版本对比 | 同一批用例上的**配对差异**：逐用例差值的均值与聚类标准误；同时报两者的相关系数 |
| 实验多臂 | 每臂与基线臂两两配对；超过 3 臂时报告注明多重比较，不自动判定「最优」 |

样本少于 10 个材料单元时，报告标注「样本不足」，不做显著性判定。

### 6.2 门禁判定：非劣效

用于 EVO-06 发布回归门禁、AST-09 Prompt 发布评测、ADR-069 的 C1 / C2 变更与 ADR-070 的模型替换：

| 情形 | 判定 |
| --- | --- |
| 配对差异的 95% 区间下界 ≥ −容差 | 通过（非劣效） |
| 区间上界 < −容差 | 阻止（确实变差） |
| 区间跨过 −容差 | **无法判定**：不自动放行，转人工审批（ADR-025 发布审批），审批卡片附报告与最差的 5 条用例 |
| 回归集或 `must_pass` 用例有任一失败 | 阻止，不论平均分 |

- 容差缺省 3 个百分点，场景评测规格可收紧到 1〜5 个百分点；不同指标可设不同容差（例如召回率 2、精确率 5）。
- 这一判定取代 ADR-031「低于稳定版本超过 2 个百分点阻止」的写法。

### 6.3 功效估算

数据集管理页提供功效估算：给定材料单元数、每单元判定数、预期基线、配对不一致比例与设计效应，估算可分辨的最小差异；也可反向给出要分辨某差异所需的材料单元数。估算公式采用配对比例差的正态近似并乘设计效应，结果只作为规划参考。合同场景的估算见调研 08 第 4 节：30 份合同约可分辨 4〜5 个百分点。

## 7. 标注

### 7.1 分工

| 角色 | 职责 |
| --- | --- |
| 开发（Agent 负责人团队） | 预标：用当前 Agent 或更强模型生成初稿，逐条核对可客观判断的部分（字段取值、条款位置） |
| 业务专家（合同场景为法务） | 只看需要专业判断的部分：「不满足」、有争议的结论、开发标为不确定的项 |
| 评测负责人 | 维护标注规范、分配任务、仲裁、密封集管理 |

### 7.2 双人标注与仲裁

- 只用于校准集（第 4 节）与密封集中的争议项：两人独立标注，不一致的进入仲裁；仲裁结果为最终标签，三者都记录在用例卡上。
- 人与人 κ 低于 0.6 时，说明标注规范不清楚，先修订规范再继续标注。

### 7.3 标注台（EVO-15，M4）

- 任务队列：来源包括 EVO-03 的「待标注」、ADR-071 的分诊结果、重标任务（`STALE`）、校准集与密封集建设。
- 支持：预标展示与逐项确认、快速标注模式（只选 Pass / Fail / Unknown）、双人盲标、仲裁视图、标注耗时统计。
- 合同场景在业务系统里已有处置与确认界面，影子期的法务结论直接作为标签导入，不重复标注。

## 8. 评测预算

- 评测用量（被测对象与裁判）计入空间评测预算（ADR-031 已定），预算在 ADR-041 配额中配置。
- 运行前估算：用例数 × 运行次数 × 最近一次同数据集运行的单条平均成本，超出剩余预算时提示。
- 合同场景量级（规划参考）：密封集 30 份 × 3 次 = 90 次审查运行，按一次审查数十次模型调用估算，单次准入评测的成本是日常一天线上用量的数倍，属可接受范围；具体以 MH-11 实测为准。

## 10. 测试与验收

| 用例 | 断言 |
| --- | --- |
| `SealedSetIsolationIT` | 无 `eval:sealed:read` 的用户看不到密封集用例与逐条结果；密封集运行的轨迹不进入经验提取 |
| `UnitSplitIT` | 同一合同链的主合同与补充协议被放入不同层时导入被拒 |
| `StaleLabelIT` | 要点库发布新版本后受影响用例变为 `STALE`，不参与门禁统计 |
| `ClusteredCiTest` | 构造的聚类数据上，聚类标准误大于朴素标准误 |
| `NonInferiorityGateIT` | 区间跨过容差时发布转人工审批；回归集有一条失败时阻止 |
| `JudgeCalibrationIT` | κ 未达标的裁判不能被选为门禁评分器；裁判模型快照变化后校准状态失效 |
