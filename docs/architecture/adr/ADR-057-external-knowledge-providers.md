## 背景

企业可能已经采购或将要采购知识库产品（Dify、RAGFlow、FastGPT、阿里云百炼知识库、扣子、WeKnora、MaxKB 等），内容由业务部门在那边维护。Tioka 的 Agent、Flow、Chat 需要用到这些知识，同时权限、数据标签、审计、引用仍要按 Tioka 的规则执行。

调研结论（调研 04 第 7.2 节）：

- 各产品都有「知识库 ID + 查询 + 条数 + 阈值 → 片段 + 分数 + 文档标识 + 元数据」的检索接口；Dify 还定义了外部知识库接入协议（External Knowledge API），事实上成了通用检索协议；
- 分数不可互比；
- 检索接口都不接受最终用户身份，权限只到 Key 或知识库级，文档级只能靠元数据过滤模拟；
- 接口稳定性不一（FastGPT 已声明知识库接口不再维护；百炼有两套接口）。

## 决定

1. 定义 **`KnowledgeProvider` SPI**。外部知识库登记后在 Tioka 中是一种知识库，调用方（Agent 绑定、`kb.*` 工具、Flow 知识节点）不感知差别。
2. **检索联邦为默认方式**：内容留在外部，检索时实时调用；结果与自有知识库一起按名次融合、统一 Rerank、统一引用（ADR-056 第 2 节第 5〜9 步）。
3. 内置七种适配器，**第一批为飞书与腾讯乐享**（负责人 2026-11-06 指定，M3），第二批为 Dify、RAGFlow、百炼、**通用检索协议**（Dify External Knowledge API 形态）、MCP（M4 前段）。其他产品（FastGPT、Amazon Bedrock、扣子、MaxKB 等）按需以插件提供（FND-12 插件宿主）。
4. 权限、数据标签、出网、凭证、审计、限流、熔断全部在 Tioka 侧执行，规则与自有知识库相同。
5. 补充两种方式：**内容同步**（外部产品有文档导出接口时，作为 KNW-06 的一种数据源连接器）与**反向暴露**（Tioka 实现同一通用检索协议，让采购的产品使用 Tioka 知识库；MCP 方式 ADR-021 已定）。

## 1. 概念

| 概念 | 含义 | 管理者 |
| --- | --- | --- |
| 提供方类型 | 一种外部产品的适配器，如 `dify`、`ragflow`、`bailian`、`generic_retrieval`、`mcp` | 平台（内置或插件） |
| 提供方实例 | 一个具体的外部系统连接：地址、凭证引用、版本、允许接收的最高数据标签、超时与限流 | 系统管理员 |
| 外部知识库 | 挂在某个实例下的一个外部知识库（外部 ID），在 Tioka 中登记为知识库：名称、说明、所属空间、数据标签、ACL、检索参数、文档级权限方式 | 空间管理员 |

外部知识库与自有知识库共用知识库表与 ACL；用一个字段区分「自有 / 外部」，外部的另记实例与外部知识库 ID。外部知识库不能上传文档、不能切块，知识库页只读展示外部信息。

## 2. SPI 能力

适配器声明自己支持的能力，平台按能力决定功能是否可用。

| 能力 | 必需 | 用途 |
| --- | --- | --- |
| 检索 | 是 | 输入：外部知识库 ID、查询、条数、分数阈值、元数据过滤（可选）；输出：片段列表 |
| 列出知识库 | 否 | 管理员登记外部知识库时从列表选择，而不是手填 ID |
| 元数据过滤 | 否 | 支持时才可配置文档级权限（第 4.2 节）与调用方传入的过滤条件 |
| 读取原文 | 否 | 引用展示时取片段所在文档的更多上下文；不支持时只显示片段 |
| 原生 Rerank | 否 | 外部产品自带 Rerank 时可在外部先重排；Tioka 侧的统一 Rerank 照做 |
| 健康检查 | 是 | 连接器 SDK 的健康规则（连续失败 3 次标为 DEGRADED 并告警） |
| 文档导出 | 否 | 支持时可作为内容同步的数据源（第 7 节） |

**统一返回字段**：片段文本、外部分数（只用于外部阈值，不参与跨来源比较）、外部文档 ID、文档标题、来源 URL（可选）、页码或位置（可选）、元数据、片段内容哈希（由 Tioka 计算）。

**配置**：每个提供方类型声明配置项的 JSON Schema，前端据此生成表单（连接器 SDK 规格，M3-06 第 2 节）。

## 3. 内置适配器

### 3.1 第一批：飞书与腾讯乐享（M3，KNW-17a）

两家都不是「按知识库 ID 返回片段」的标准形态，适配器要多做一些工作。

| 项 | 飞书知识库与云文档 | 腾讯乐享 |
| --- | --- | --- |
| 检索方式 | **两段式**：先用飞书的搜索接口找文档（知识库节点搜索 `wiki.v1.node.search`、云文档搜索），只返回文档列表、不返回片段；再取前 N 篇（缺省 5）的纯文本（`docx` 的 `raw_content`），由适配器在内存里按 ADR-055 的子块规则切块，取与查询最相关的块返回 | **一段式**：乐享 AI 检索接口（`/cgi-bin/v1/ai/search`）按查询返回片段：标题、Markdown 正文、链接，`top_n` 最多 50，可选返回分数；`targets` 可限定到企业、团队、知识库或单篇 |
| 外部知识库 ID 对应 | 一个飞书知识空间（`space_id`），或一组云文档文件夹 | 一个乐享团队或知识库（`team_id` / `space_id`） |
| 身份 | **用户身份模式（推荐）**：用 FND-08 保管的该用户 `user_access_token` 调用，搜索结果天然只含该用户在飞书里有权限的文档，即文档级权限准确；用户未授权时该来源本次跳过，并在回答里给出「去授权飞书」的卡片。**应用身份模式**：用应用的 `tenant_access_token`，只能看到管理员共享给应用的空间，权限只到知识库级 | 应用凭证（AppKey / AppSecret 换 `access_token`，有效期 7200 秒，缓存复用）。部分接口要求请求头带员工身份 `x-staff-id`：**用户身份模式**按实例配置的映射规则（员工号、企业微信账号或邮箱前缀）把 Tioka 用户映射为乐享员工 ID，M4 起改用 FND-09 的外部身份映射；**应用身份模式**用一个固定的服务账号，权限只到知识库级。乐享是否按 `x-staff-id` 过滤检索结果，官方文档未写明，接入时须实测，未证实前一律按「仅知识库级」标注 |
| 文档级权限 | 用户身份模式下由飞书保证 | 见上；实测证实前不承诺 |
| 限流与延迟 | 取正文接口每秒 5 次（官方说明）；两段式一次检索最多 1 次搜索 + 5 次取正文，适配器内并发 3、总超时 5 秒；正文按「文档 token + 修订版本」缓存 10 分钟，以减少重复拉取（缓存只在同一用户内复用） | 换令牌接口每 10 分钟 20 次，其他接口每分钟 3000 次；令牌集中缓存，多实例共享 |
| 引用 | 文档标题、飞书链接、文档 token 与修订版本、命中块文本 | 标题、乐享链接、条目 ID、片段文本 |
| 与内容同步的关系 | 飞书知识空间也可以走 KNW-06 的飞书数据源同步进 Tioka；同一空间二选一（第 7 节）。建议：内容常改、权限复杂的空间用联邦（用户身份）；稳定的制度库用同步，检索质量更好 | 乐享有知识库条目列表与正文接口，同样可以写成数据源连接器；第一批只做联邦 |
| 已知风险 | 飞书搜索按标题与正文关键词匹配，语义召回弱，适配器只能在前 N 篇文档里做块级重排；建议对高频问答空间改用同步 | 是否支持私有化部署版本、是否提供 MCP 未在官方文档中确认；AI 检索接口的计费方式需向厂商确认 |

官方也有飞书 MCP Server（`lark-openapi-mcp`，含文档读取、知识库节点搜索等工具，支持用户身份），可作为飞书适配器之外的备选，经 MCP 适配器接入；但它在本地运行、处于 Beta，不作为默认。

## 4. 权限与数据安全

### 4.1 知识库级（必有）

外部知识库与自有知识库同一公式：知识库 ACL ∩ 授予资源 ∩ `maxDataLabel`（ADR-040）。外部知识库的数据标签由空间管理员登记，缺省 `INTERNAL`。

### 4.2 文档级（可选）

| 方式 | 条件 | 做法 |
| --- | --- | --- |
| 元数据过滤 | 适配器支持元数据过滤，且外部文档带权限元数据（如 `acl` 字段存部门或组编码） | 检索时由 Tioka 按当前用户的身份映射（FND-09 外部身份）拼过滤条件，交给外部产品执行 |
| 文档 ID 过滤 | 适配器只支持按文档 ID 过滤 | 定期同步「文档 ID → 权限主体」映射，检索时传可见文档 ID 列表；文档多于 1000 时退回知识库级并告警 |
| 无 | 以上都不满足 | 只做知识库级；登记页与知识库详情明确标注「仅知识库级权限：能用这个知识库的人能看到其中全部内容」 |

### 4.3 出网与数据标签

- 查询文本会发到外部产品。每个实例登记「允许接收的最高数据标签」（缺省 `INTERNAL`）；当前会话或调用的数据标签高于它时，跳过该来源并在轨迹里记录，与 DAT-04 按标签选模同一规则。
- 调用一律经 EgressGuard；实例地址要在出网白名单里。
- 外部返回的片段带上外部知识库的数据标签进入上下文，参与 ADR-040 的标签传播。

### 4.4 凭证

凭证按 ADR-042 加密保存（`CredentialCipher`），只存引用，支持多 Key 与到期提醒；日志与轨迹不出现明文。

### 4.5 外部内容不可信

外部片段与工具结果同等对待：放入上下文时标为「检索资料」，不得作为指令执行（ADR-048 对工具结果的规则）；外部片段不进入长期记忆的抽取来源（ADR-050 已定只从用户消息抽取）。

## 5. 检索、融合与可靠性

| 项 | 规定 |
| --- | --- |
| 并行 | 同一次检索里的各外部知识库与自有知识库并行；总超时取调用方预算与 5 秒的较小值 |
| 单来源超时 | 缺省 3 秒（百炼 5 秒），按实例可配 |
| 限流 | 按实例的令牌桶（连接器 SDK）；超限时该来源本次跳过，不排队 |
| 熔断 | 连续 5 次失败或 1 分钟内失败率超 50%，熔断 60 秒；熔断期间跳过并在回答中注明 |
| 部分失败 | 一个来源失败不影响其他来源；轨迹记录失败来源与原因；全部来源失败时按「无答案」处理并说明原因 |
| 融合 | 外部片段与自有子块一起按名次 RRF，再统一 Rerank（ADR-056 第 6、7 步）；外部分数只用于该来源自己的阈值 |
| 缓存 | 不缓存外部检索结果（内容与权限都可能变化） |

## 6. 引用

- 引用号格式：`ext:{实例}:{外部知识库}:{外部文档ID}:{片段哈希前 12 位}`。
- 回答采用外部片段时，citation item 保存片段全文、标题、来源 URL、外部文档 ID、内容哈希与检索时间。外部原文之后变化或删除，界面仍展示当时的片段，并提示「来源可能已更新」（与第 12 条同一表现）。
- 来源 URL 是否可点击按实例配置（外部产品要求登录时，用户点击后由外部产品自己鉴权）。

## 7. 内容同步（与 KNW-06 衔接）

外部产品提供文档列表与导出接口时，可以把它当作一种数据源：用连接器 SDK 写一个数据源连接器，增量拉取文档进入 Tioka 的入库流水线（ADR-055）。适合：外部产品只是内容仓库、需要严格的文档级权限、或评测显示外部检索质量明显不如 Tioka。同一个外部知识库不同时以「联邦」与「同步」两种方式登记，避免重复命中。

## 8. 评测与选型

- KNW-07 / KNW-15 的评测可以选外部知识库作为被测对象；同一评测集可以分别跑外部知识库与内容相同的 Tioka 知识库，比较 Recall@5、MRR、忠实度、引用正确率与 P95 延迟。
- 评测调用计入实例限流，在评测预算内执行，不占用户配额。
- 报告用于采购选型与「联邦还是同步」的决定。

## 9. 反向暴露（KNW-18，M4 之后）

- Tioka 实现通用检索协议的服务端：外部系统按 `knowledge_id`（对应 Tioka 知识库 ID）调用 `/retrieval`，返回 `records`。
- 鉴权用 Tioka 签发的 API Key，每个 Key 绑定一个服务身份与授予（ADR-039 的授予规则：可用知识库、`maxDataLabel`、有效期）；不支持代最终用户检索，因此只能授予知识库级权限的知识库。
- 限流、审计、出网标签与入站一致；返回内容的标签不得高于 Key 的 `maxDataLabel`。
- MCP 方式的知识检索暴露 ADR-021 已定（Tioka 作为 MCP Server），本 ADR 不重复。
