# ADR-062 — 解析质量评测、合同特殊元素与解析安全

- 状态：Accepted（设计定案，待实现）
- 日期：2026-11-06
- 覆盖工作项：PRS-06、PRS-07、PRS-08（新增）；M4 之后 PRS-11、FE-38

- 相关：[ADR-025](ADR-025-governance.md)、[ADR-031](ADR-031-agent-eval-experience.md)、[ADR-036](ADR-036-business-ontology-domain-pack.md)、[ADR-037](ADR-037-structured-outputs.md)、[ADR-041](ADR-041-config-versioning-observability.md)、[ADR-060](ADR-060-document-parsing-service.md)、[ADR-061](ADR-061-parse-engine-spi-external-ocr.md)；M3-03 第 2〜3 节、M3-04 LSE-08
- 约束：与 [ADR-029](ADR-029-design-rulings.md) 定案冲突时以定案为准；修改本 ADR 走 [ADR-030](ADR-030-anti-drift-process.md) 的变更流程。
- 写法说明：只用文字和表格，不附代码。

## 背景

合同审查的取值必须能定位到原文并通过引文校验（DOC-03、ADR-037 证据绑定）。解析出错会直接变成审查结论出错，而且是「看起来有证据」的错。公开评测以论文、报告为主（调研 05 第 2.2 节），不能代表中文合同；VLM 会给出「稳定但错误、且置信度高」的结果 [调研 05 参考 8]。M3 只有「条款路径识别率 ≥ 95%」一个指标，换引擎或引擎升级时无法判断好坏。印章、手写、勾选框、文字层可信性、恶意文件都没有设计。

## 决定

1. **建合同解析评测集，作为引擎选型、方案发布与引擎升级的闸门**（第 1 节）。
2. **印章、手写、签名、勾选框、空白填写位是一等元素**，各有输出规则与下游处理规则（第 2 节）。
3. **文字层不默认可信**：抽检文字层与页图是否一致，检测隐藏文字（第 3 节）。
4. **解析不可信文件有资源上限与进程隔离**（第 4 节）。
5. **低置信、来源冲突、手写的金额与日期一律进人工复核**，复用 ONT-08 确认页（第 5 节）。

## 1. 评测

### 1.1 评测集

| 子集 | 内容 | 数量 |
| --- | --- | --- |
| 合同-Word | 自动编号、修订稿、表格合并单元格 | 8 份 |
| 合同-文字型 PDF | 多栏、页眉页脚、跨页表 | 6 份 |
| 合同-扫描件 | 印章盖字、骑缝章、手写日期与金额、勾选框、倾斜 | 10 份 |
| 合同-拍照件 | 手机拍摄、阴影、曲面、多张拼成一份 | 4 份 |
| 参考资料 | 制度、案例（知识库用） | 2 份 |

合计 30 份，标注由开发团队预标、业务方抽检（沿用合同场景「开发预标、法务只看不合规结论」的分工），标注工作量约 3 人日，不计入开发人日。M3 的 10 组样本是它的子集。

### 1.2 指标

| 指标 | 定义 | 闸门 |
| --- | --- | --- |
| 字符错误率 | 正文块文字与标注的编辑距离 ÷ 标注长度，按子集分别统计 | 扫描件 ≤ 2%，拍照件 ≤ 5% |
| 关键字段准确率 | 金额、日期、面积、当事方名称、合同号等由标注指定的字段完全一致的比例 | ≥ 99%（不含已标「待复核」的字段） |
| 条款路径识别率 | 条款树与标注一致的比例（M3 已有） | ≥ 95% |
| 表格结构 | 单元格行列与合并关系正确的比例 | ≥ 95% |
| 印章召回 | 检出的印章 ÷ 标注印章 | ≥ 98% |
| 手写检出 | 标为手写的块 ÷ 标注手写块 | ≥ 95% |
| 「错而不报」率 | 字段错误且未标低置信、冲突或手写的比例 | ≤ 0.5%（这是最关键的指标：错了但没人看会直接进结论） |
| 时延 | 30 页合同 P95 | ≤ 5 分钟（与 M3-04 时延预算一致） |

关键字段准确率不含「待复核」字段，是因为待复核的字段会被人看到；「错而不报」率才衡量风险。

### 1.3 闸门与回归

- 解析方案发布新版本前必须跑评测集，任一闸门不达标不能发布（ADR-041 发布校验增加一项）。
- 夜间任务用当前方案跑评测集；云端引擎悄悄升级导致指标下降时告警（GOV-13 规则模板）。
- 评测结果按方案版本保存，可对比；M4 之后由 FE-38 提供报告页，M4 内用 EVO-02 的评测报告格式输出。
- 合同模型层的评测（ONT-09）与本评测分开：本评测只看「原文读对没有」。

## 2. 合同特殊元素

| 元素 | 解析输出 | 下游规则 |
| --- | --- | --- |
| 印章 | `SEAL` 块：印章文字（环形文字与中心文字）、形状、颜色、坐标；`occludes` 列出被遮挡的正文块，被遮挡块打 `OCCLUDED_BY_SEAL` | 审查要点「是否盖章」「印章名称与当事方是否一致」以 `SEAL` 块为证据；被遮挡块上的取值置「待复核」 |
| 骑缝章 | 多个页边缘的 `SEAL` 块，`attrs` 标「骑缝」 | 只作存在性证据，不做文字比对 |
| 被遮挡正文 | 支持印章擦除的引擎先擦除再识别，结果标来源与 `OCCLUDED_BY_SEAL`；不支持的保留原识别 | 同上 |
| 手写 | 文字块 `handwritten = true`，打 `HANDWRITTEN` | 手写的金额、日期、期限一律「待复核」，原因「手写」；手写的其他内容置信度上限 0.8 |
| 签名 | `SIGNATURE` 块，只有位置不承诺文字 | 只作「已签署」存在性证据 |
| 勾选框 | `CHECKBOX` 块，`checked` 为是 / 否 / 无法判断；与右侧选项文字同属一个父块 | 「无法判断」视同空白填写位 |
| 空白填写位 | `BLANK_FIELD` 块（沿用 M3-03 五种写法）；填写位内有手写内容时为手写文字块，父块为该填写位 | 未填 → 取值状态「空白」（ADR-036）；手写填写 → 按手写规则 |
| 跨页续表 | 组装阶段按「上一页末尾是表格、下一页开头是表格、列数一致或表头重复」合并，`continuedFrom` 记录 | 合并后单元格保留各页坐标 |
| 金额大小写 | 解析不判断；契约保证大写金额与小写金额各自成块 | 由领域包校验器（LSE-02）比对，不一致置「待复核」 |

## 3. 文字层可信性与隐藏内容

| 检查 | 做法 | 结果 |
| --- | --- | --- |
| 文字层与图像一致性 | 对 `TEXT_PDF` 页抽样（每份文档至少 2 页，含首尾页；含金额的表格页必抽），用 OCR 识别页图后与文字层比较，字符差异率超过 5% 判为不一致 | 页降为 `SCANNED` 重新识别；文档标 `TEXT_LAYER_MISMATCH`，在确认页提示「PDF 文字层与页面内容不符」 |
| PDF 不可见文字 | 文字渲染模式为不可见，且该页不是扫描页加 OCR 文字层的常见形态（整页图像覆盖） | 不进正文，打 `HIDDEN_TEXT` |
| 极小字号与白色文字 | 字号小于 2 磅、颜色与背景接近 | 同上 |
| Word 隐藏文字 | 隐藏属性的文字 | 同上 |

被识别为隐藏的内容不进入任何 Agent 上下文与知识库（防止文档内的提示注入），只在查看器中可见并标出。即使不是隐藏内容，解析结果也一律是参考数据、不是指令：进入上下文时明确标注来源为文档，不能覆盖平台与 Agent 指令（与 ADR-050 对记忆的处理一致），也不能作为记忆抽取的来源（ADR-050 写入来源限制）。

## 4. 解析安全

| 项 | 规则 |
| --- | --- |
| 类型识别 | 只按文件头字节判断；扩展名与内容不符时以内容为准并记警告 |
| 大小与页数 | 单文件 ≤ 100 MB、≤ 500 页（可按空间调整）；图片长边 ≤ 10000 像素 |
| 压缩包类格式 | docx、xlsx 等解压后总大小 ≤ 原文件 100 倍且 ≤ 1 GB；条目数 ≤ 10000 |
| XML | 禁用外部实体与 DTD 加载 |
| 加密文档 | 不尝试破解；状态 `FAILED`，原因「文档已加密」，提示上传方提供未加密版本 |
| 进程隔离 | LibreOffice 与页面渲染在独立子进程中运行，有超时（单文件 120 秒）与内存上限；`SIDECAR` 引擎独立容器，不挂载业务数据卷 |
| 超时 | 单页识别 60 秒，整份文档 30 分钟；超时页按降级链处理，整体超时为 `PARTIAL` |
| 审计 | 拒绝、加密、隐藏内容、文字层不一致均写审计事件 |

## 5. 人工复核衔接

- 文档层把块的 `flags` 与 `confidence` 带入证据单元；@model.build 抽到这些单元上的取值时，按下表置状态（扩充 M3-03 第 3 节的「OCR 低置信」规则）：

| 条件 | 取值状态 | 原因 |
| --- | --- | --- |
| `confidence` < 0.8 | 待复核 | OCR 低置信 |
| `SOURCE_CONFLICT` | 待复核 | 两个识别来源不一致 |
| `HANDWRITTEN` 且字段为金额、日期、期限 | 待复核 | 手写 |
| `OCCLUDED_BY_SEAL` | 待复核 | 印章遮挡 |
| 文档 `TEXT_LAYER_MISMATCH` | 全部取值附提示，不改状态 | 文字层不一致 |

- ONT-08 确认页用 FE-37 的查看器展示原文位置；人工更正的结果回流为评测集候选（经标注人确认后加入）。

## 修订：结构树、图层与证照（2026-11-07）

来由：[调研 06](../research/06-文档结构树图层与证照抽取补充调研.md)；ADR-029 第 72 条。

- **PRS-06 由 ADR-063 的 PRS-14（跨页合并）与 PRS-16（印章、手写、签名、勾选框）取代**；第 2 节的元素规则不变，但手写、印章遮挡的「待复核」改为按行内对象的字符区间判断（ADR-063 第 1.2 节），印章增加类型属性（公章、合同专用章、财务专用章等）。
- **评测指标增加**：章节树节点层级正确率 ≥ 98%、条款路径正确率 ≥ 98%（取代 ≥ 95%）、跨页表合并正确率 ≥ 95%、印章类型分类正确率 ≥ 90%、证照字段完全一致率 ≥ 98%（证照子集每类 5 份，ADR-064 第 4 节）。PRS-08 由 3 人日增至 4 人日。
- **PRS-11** 只剩 HEIC 与无引擎能力时的拍照曲面矫正（约 2 人日）；OFD 由 MinerU 4.x 原生支持。
