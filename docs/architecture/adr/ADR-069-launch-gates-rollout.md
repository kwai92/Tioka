## 背景

负责人问：上一个新的场景 Agent 时，如何做评测？现有设计里，评测与闸门分散在 ADR-031（发布回归门禁）、ADR-034（影子上岗）、ADR-056（检索）、ADR-062（解析）、ADR-066（结构化）、ADR-067（护栏）与 M3-04（合同场景四项门槛）中，没有一份文件说清楚「一个新场景从立项到在岗要过哪几关、每关谁签字、上线后怎么改」。另外两个缺口：

1. ADR-041 规定别名与路由计划「跟随」，发布即对全平台生效；系统管理员换一个模型，等于对所有引用它的 Agent 做了一次没有评测的全局变更；
2. 合同审查每天约 10 份，业界常用的按比例金丝雀与 A/B 在这个量级没有统计意义。

## 决定

1. 新场景 Agent 按 **E0〜E5 六个阶段**上线，每个阶段有出口条件与签字人（第 1 节）。
2. 立项时写**场景评测规格**，按风险等级 R1〜R3 决定门槛的严格程度（第 2 节）。
3. 准入时生成**上线准入单**，把质量、一致性、专项（解析、检索、结构化、护栏）、成本、时延、人工签字汇总在一页（第 3 节）。
4. 已上线 Agent 的每次变更按 **C0〜C3 分级**走不同的关；平台配置（别名、路由计划、解析方案、知识库）变更要找到受影响的 Agent 并评测（第 4 节）。
5. 低流量的结论类 Agent 用**双跑灰度**，高流量的对话类用按比例灰度（第 5 节）。
6. 上线后用生产配置每晚跑**哨兵评测**，统一各 ADR 的夜间回归（第 6 节）。
7. 以合同审查为样例给出完整的规格与准入单（第 7 节）。

## 1. 上线阶段

| 阶段 | 内容 | 出口条件 | 签字 |
| --- | --- | --- | --- |
| E0 立项 | 写场景评测规格（第 2 节）；确认标注人与人日；确认影子期的人工对照来源 | 规格评审通过 | 业务负责人、Agent 负责人 |
| E1 开发 | 冒烟集 + 开发集迭代；按角色选模型（ADR-070 第 1〜2 轮） | 开发集达到规格门槛 | Agent 负责人 |
| E2 准入 | 密封集 × 3 次运行 + 回归集 + 专项评测 + 成本时延；生成上线准入单（第 3 节） | 硬门槛全部通过；软门槛未达标的有书面说明 | Agent 负责人、业务负责人；R3 加空间管理员 |
| E3 影子 | 真实输入、结果不展示，与人工结论比对（ADR-034 TRU-11） | 影子一致率 Wilson 下界达到规格；上岗报告 | 业务负责人确认初始自治等级 |
| E4 灰度 | 仅用于已在岗 Agent 的新版本（第 5 节） | 非劣效、无告警 | Agent 负责人 |
| E5 在岗 | 线上采样评测（EVO-03）、哨兵评测（第 6 节）、反馈分诊（ADR-071）、抽检（ADR-034） | — | — |

- 新场景走 E0→E1→E2→E3→E5；已在岗 Agent 的 C2 变更走 E2→E4→E5；C3 变更等同新场景。
- 阶段状态记录在 Agent 上（`agent_launch_stage`），档案页（ADR-032）显示当前阶段与距下一阶段还差什么。
- 未完成 E2 的 Agent 版本不能被设为 `accept_mode = auto` 的编排规则引用（ADR-020），也不能对非开发成员可见，除非空间管理员显式豁免并写审计。

## 2. 场景评测规格

E0 时由 Agent 负责人与业务负责人共同填写，作为 Agent 的一份带版本的附属文档（随 AgentSpec 发布，ADR-023）。

| 项 | 内容 |
| --- | --- |
| 业务目标 | 替代或辅助的人工工作、成功的业务定义 |
| 风险等级 | 见下表 |
| 输出类型 | 回答、建议、结论、写操作；结论的形态（四态、分级、自由文字） |
| 主指标与门槛 | 每个指标：定义、门槛（点估计与区间下界）、是否硬门槛、容差（ADR-068 第 6.2 节） |
| 一致性门槛 | pass^k 或结论一致率（R3 必填） |
| 专项 | 适用的专项评测（解析、检索、结构化、护栏）及其门槛（缺省引用各 ADR） |
| 成本与时延 | 每单位业务（一份合同、一张工单）的成本上限、P90 / P95 时延上限 |
| 评测集计划 | 各层规模、材料单元键、来源、标注人与人日、密封集负责人 |
| 影子期计划 | 人工对照来源、时长或用例数、比对方式（结构化或裁判） |
| 回滚条件 | 在岗期间哪些指标触发降级或回滚 |

### 2.1 风险等级

| 等级 | 定义 | 例子 | 最低要求 |
| --- | --- | --- | --- |
| R1 | 只读、给个人参考 | 制度问答、知识检索 | 开发集 + 密封集；检索专项；无影子期；可直接按比例灰度 |
| R2 | 产出建议，由人决定是否采纳 | 邮件草稿、工单分类建议 | R1 + 回归集；影子期 ≥ 2 周或 30 个用例 |
| R3 | 产出业务结论，或触发写操作 | 合同审查、改价、退款 | R2 + 3 次运行一致性门槛；护栏专项；影子期 ≥ 50 个有对照用例；双跑灰度；空间管理员签字 |

## 3. 上线准入单（EVO-10）

E2 准入时系统自动生成，是一页汇总报告，存档在 Agent 版本上：

| 区块 | 内容 | 来源 |
| --- | --- | --- |
| 版本 | Agent 版本、Prompt 版本、别名及其当时解析到的模型快照、路由计划版本、知识库快照、解析方案版本、输出 Schema 版本、要点库等业务规范版本 | ADR-023、ADR-041 |
| 质量 | 规格中的每个主指标：点估计、区间、门槛、是否通过；与上一在岗版本的配对差异 | ADR-068 |
| 一致性 | 单次成功率、pass^k、结论一致率 | ADR-068 第 5 节 |
| 回归集 | 通过数 / 总数，失败条目列表 | ADR-068 |
| 专项 | 解析、检索、结构化、护栏各项指标与门槛 | ADR-062、ADR-056、ADR-066、ADR-067 |
| 成本与时延 | 每单位成本、P50 / P95 时延、修复与降级的额外调用占比 | MH-11 |
| 裁判 | 使用的模型裁判及其校准状态 | ADR-068 第 4 节 |
| 已知问题 | 软门槛未达标项与说明；最差的 10 条用例 | — |
| 签字 | 按第 1 节 | 通用审批（ADR-025） |

- 硬门槛任一不通过时，准入单状态为「不通过」，不能进入 E3 / E4。
- 准入单本身不可修改；重跑生成新的准入单。
- 数据来源都是已有的评测运行，准入单只汇总不重算；专项评测的运行时间距准入不超过 7 天，否则自动重跑。

## 4. 变更分级

### 4.1 Agent 自身的变更

| 级别 | 例子 | 必须 |
| --- | --- | --- |
| C0 不影响行为 | 展示文案、图标、说明 | 冒烟集 |
| C1 局部 | 单个要点表达式或阈值、Prompt 中一个片段、经验条目生效、知识库增补文档 | 开发集 + 回归集逐条通过 + 受影响要点在密封集上非劣效 |
| C2 全局 | 换模型或路由计划、换解析方案、改输出 Schema（ADR-066 兼容组内）、改检索配置、改执行策略 | 完整 E2 准入 + E4 灰度 |
| C3 新场景或新动作 | 新 Agent、新增写操作类别、Schema 不兼容变更 | E0〜E5 |

- Agent 发布时，系统按变更内容自动判定最低级别（对比新旧 AgentSpec 快照与引用的配置版本），发布者可以上调不能下调。
- 经验条目（EVO-05）自动生效的空间开关只适用于 R1、R2；R3 的经验必须人审并按 C1 评测。

### 4.2 平台配置的变更（MH-15）

别名、路由计划、binding、解析方案、知识库的嵌入与 Rerank 绑定、系统 Prompt（`sys.*`）发布时：

1. ADR-041 的「发布前影响分析」递归列出引用方后，筛出其中**处于 E5 且绑定了密封集的 Agent**；
2. 对这些 Agent 以「新配置」自动跑密封集准入评测（每条 1 次，节省成本），与当前配置配对比较；
3. 发布对话框展示每个受影响 Agent 的结论（非劣效、无法判定、变差）；有「变差」时发布需要填写原因并二次确认，写审计；
4. 支持**分批切换**：别名可以带一个灰度规则「对以下 Agent 先指向新版本」或「按调用哈希 x% 指向新版本」，其余仍指向旧版本；灰度期间 MH-11 版本对比按两组统计；确认后全量，或一键撤回；
5. **紧急发布**（供应商故障、密钥泄露等）可跳过第 2〜4 步，必须填写原因，系统在 24 小时内补跑评测并把结果发给受影响 Agent 的负责人。

快照钉住：

- binding 必须指向供应商的**固定快照**模型名；指向供应商「最新版」类名称（如不带日期的滚动名称）的 binding 在管理页显示警告，R3 Agent 引用的路由计划中不得出现这类 binding（发布校验拒绝）。
- 供应商下线快照的公告由管理员登记到 binding（`retireAt`），到期前 30 / 7 天提醒，并自动创建 ADR-070 的复评任务。

## 5. 灰度

### 5.1 双跑（低流量结论类，R3 缺省）

- 新版本发布后进入 `CANDIDATE` 状态：对在岗版本处理的每一个真实输入，在后台以 `origin = shadow` 再跑一次新版本（复用 ADR-034 的影子硬约束：只预演不提交、不外发、计入评测预算）。
- 比对三方：新版本、在岗版本、人工最终结论（合同场景为法务处置后的结论）。主判定是新旧两版本对人工结论的**配对差异**（ADR-068 第 6.2 节非劣效）；次要输出是新旧版本不一致的条目清单，供 Agent 负责人逐条查看。
- 时长：缺省 10 个工作日或 50 个有人工对照的材料单元，以后到为准；可在规格中调整。
- 双跑期间若新版本触发任一硬性安全条件（护栏「有后果攻击」、结构化异常逃逸、证据绑定错误），立即终止并通知。
- 通过后由 Agent 负责人确认切换；切换后进入 ADR-034 的观察期。

### 5.2 按比例（高流量对话类，R1 / R2 可选）

- 按用户 ID 哈希分流，档位 5% → 25% → 100%，每档至少 24 小时且至少 200 个 Turn。
- 每档观察：点踩率、重新生成率、结构化失败率、护栏拦截率、P95 时延、单次成本，与在岗版本同期对比；任一项超过规格中的回滚条件即自动回到 0%。
- 同一用户在灰度期间固定在一个版本（避免同一会话来回切换，也符合 ADR-049 的缓存规则）。

### 5.3 回滚

回滚是一次配置写入：Agent 版本指针（ADR-023）或别名指针（ADR-041）移回旧版本，进行中的 Turn 不受影响（MH-01 冻结）。所有灰度与回滚写审计并通知负责人。

## 6. 哨兵评测（EVO-12）

- 每晚对每个处于 E5 的 R2 / R3 Agent，用**生产配置**（别名当时解析到的实际模型）跑密封集中固定的一个子集（缺省 5 个材料单元，每条 1 次）。
- 与该 Agent 最近一次准入单的同一子集结果比较；关键指标下降超过容差，或结构化失败、证据绑定错误出现，即告警（GOV-13 规则模板 `eval.sentinel.drift`）。
- 用途：发现供应商悄悄更新模型、价格调整后路由变化、知识库内容变化、解析引擎升级带来的漂移。
- 合并已有夜间任务：ADR-062 第 1.3 节的解析夜间回归、ADR-066 第 10.2 节的结构化夜间回归改为哨兵评测的专项子任务，共用调度、预算与告警。
- 子集固定且不轮换（与密封集轮换分开管理），以保证夜间结果可比；子集用例随密封集轮换移出时同步替换并重置基线。

## 7. 样例：合同审查

### 7.1 规格要点

| 项 | 内容 |
| --- | --- |
| 风险等级 | R3（产出法务结论；`lease.review.draft` 为写操作） |
| 材料单元 | 合同链 |
| 评测集 | 冒烟 5 份；开发集为 M3-04 的 10 组样本租约，逐步扩到 30 份；密封集取影子期 50 份中的 20 份（按合同链随机留出），M4 扩到 30 份；回归集来自 ADR-071 分诊 |
| 影子期对照 | 法务在业务系统录入的结论（M3 用业务系统可见性开关，M4 起用 TRU-11） |
| 回滚条件 | 按要点驳回率周环比翻倍且绝对值 > 20%；哨兵告警；任一硬性安全条件 |

### 7.2 上线准入单门槛

| 指标 | 门槛 | 类型 | 来源 |
| --- | --- | --- | --- |
| 必备要点四态一致率 | ≥ 85%，区间下界 ≥ 80% | 硬 | M3-04 LSE-08（加区间下界） |
| 必备「不满足」召回率 | ≥ 90%，Wilson 下界 ≥ 80% | 硬 | 同上 |
| 「不满足」精确率 | ≥ 70% | 软 | 同上 |
| 三次运行必备要点结论一致率 | ≥ 90% | 硬 | 本 ADR 新增 |
| 证据绑定率 | 100% | 硬 | M3-04、ADR-066 |
| 结构化最终失败率；异常逃逸 | ≤ 0.5%；0 | 硬 | ADR-066 |
| 解析「错而不报」率 | ≤ 0.5% | 硬 | ADR-062 |
| 注入样本：有后果攻击成功率；结论篡改漏检率 | 0；0 | 硬 | ADR-067 |
| 模型层属性 F1 | ≥ 0.9 | 软 | M3-04 |
| 提交到草稿时延 | P90 ≤ 30 分钟 | 硬 | M3-04 |
| 每份合同模型成本 | 规格中定（M3 选型时按实测设定） | 软 | ADR-070 |
| 回归集 | 全部通过 | 硬 | ADR-068 |

- M3 的 G3 时点：密封集尚未建立（影子期才产生），G3 以开发集（10 组）判定，报告带区间与「样本不足」标注；影子期结束时（W50 前后）以影子期留出的 20 份作为首个密封集，生成第一份正式准入单，作为 `lease.review.draft` 设为 L2 的依据之一。
- 三次运行一致率门槛在 M3 只出报告，M4 起作为硬门槛（M3 的 EVO-07 已支持多次运行，但影子期前样本不足以设阈）。

## 8. 对现有设计的修订

| 设计 | 修订 |
| --- | --- |
| ADR-031 EVO-06 | 发布回归门禁按第 4.1 节变更分级决定跑哪些集合，判定按 ADR-068 第 6.2 节 |

## 9. 测试与验收

| 用例 | 断言 |
| --- | --- |
| `LaunchReadinessIT` | 硬门槛任一不通过时准入单为「不通过」，Agent 不能进入影子阶段 |
| `ChangeClassIT` | 换路由计划的 Agent 发布被判为 C2，发布者不能下调为 C1 |
| `AliasImpactEvalIT` | 别名改指向时，绑定了密封集的在岗 Agent 自动跑评测，结果出现在发布对话框 |
| `AliasCanaryIT` | 别名按 Agent 白名单灰度时，名单内 Agent 用新模型、其余用旧模型，MH-11 分组统计正确 |
| `DualRunIT` | 双跑期间新版本不产生任何提交；10 个用例后生成三方配对报告 |
| `SentinelDriftIT` | 录制桩模拟供应商输出变化后，哨兵评测告警 |
| `LatestAliasRejectIT` | R3 Agent 的路由计划含「最新版」类 binding 时发布被拒 |
