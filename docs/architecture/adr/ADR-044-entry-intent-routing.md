## 背景

Tioka 已有三种路由：事件路由（ADR-020，CEL 只看可信属性）、模型路由（ADR-024）、团队内分派（ADR-038）。缺的是**入口路由**：用户在企业门户或飞书「一个助手入口」说一句话，应交给哪个 Agent、Flow 或知识库问答，还是先追问。业界成熟做法是分层级联：显式指令 → 向量语义匹配 → LLM 分类 → 低置信度澄清，并对每次决定留痕评测（调研 01 第 4.2 节）。

## 决定

1. **入口路由是一种 Agent**：`AgentSpec.profile.type = ROUTER`。与普通 Agent 一样有草稿、版本、ACL、发布校验、授权书。用户和 IM 机器人看到的是一个 Agent。
2. **先按权限过滤候选，再分类**。路由只能在调用人本来就有 USE 权限的目标里选，路由结果不改变任何权限。这延续 ADR-020 的硬边界：正文可以决定「交给谁」，但只能在调用人本来能用的范围内选，不能决定权限。
3. **分层级联**，每层命中即结束：显式指令 → 向量匹配 → LLM 分类 → 澄清或兜底。
4. **决策器与模型路由共用**：ADR-024 的 `RoutingDecider` SPI 增加内置「向量匹配」决策器，模型路由的 BRANCH 模式与入口路由都能用；LLM 分类决策器同样共用。
5. **受控交接**：路由选中后在同一会话里切换当前 Agent，只在 Turn 边界发生，链根身份不变，写一条路由事件。不做 Agent 之间自由来回交接。
6. **路由可评测**：每次决定落库，ADR-031 数据集可标注期望目标，批次评测出准确率与混淆矩阵。

## 1. RouterSpec

ROUTER 型 Agent 的 AgentSpec 增加 `router` 段：

| 字段 | 说明 |
| --- | --- |
| 候选目标 | 列表，每项为目标类型（AGENT / FLOW / KB_QA）、目标引用（Agent 版本或「跟随最新发布」、Flow 发布 ID、知识库 ID）、显示名、能力描述、示例话术（3〜20 条）、显式指令别名（如「合同审查」「/contract」） |
| 向量匹配 | 是否启用、高置信阈值（默认 0.82）、中置信下限（默认 0.70）；向量模型取知识层统一向量维度的嵌入别名 |
| LLM 分类 | 模型别名（经 ModelGateway，purpose=decision）、超时（默认 2 秒）、最低置信度（默认 0.6） |
| 低置信处理 | `CLARIFY`（发澄清卡片，列出最多 3 个候选让用户点选）或 `FALLBACK`（交兜底目标） |
| 兜底目标 | 可选，一个 Agent；为空时只能澄清 |
| 交接时带入的历史 | `NONE`、`LAST_USER_MESSAGE`（默认）、`SUMMARY`（由路由 Agent 压缩为一段摘要）、`FULL` |
| 粘滞 | 会话已交接到某目标后，后续消息默认继续交给它；用户发显式指令或说「换一个」时重新路由。粘滞时长默认 30 分钟无消息后失效 |

发布校验：候选目标都存在且已发布；发布者对每个候选有 USE（ADR-023 发布校验第 2 条）；每个候选至少 3 条示例话术；阈值合法；兜底目标若有则必须是 AGENT。

## 2. 一次路由

1. **候选过滤**：取 RouterSpec 的候选，剔除调用人无 USE 权限、已停用、熔断中的目标。剩 0 个时直接答复「没有可用的助手」；剩 1 个时直接交接。
2. **显式指令**：消息以别名或 @ 目标开头时命中，置信度记 1.0。
3. **向量匹配**：本消息与各候选的示例话术和描述的最大相似度。最高分 ≥ 高置信阈值且领先第二名 ≥ 0.05 时命中。示例话术的向量在路由 Agent 发布时生成并随版本存储。
4. **LLM 分类**：把过滤后的候选（显示名、描述、各 3 条示例）与本消息、粘滞目标交给分类模型，要求结构化输出：目标编码、置信度、理由、需要澄清时的问题。输出 Schema 登记在 ADR-037 登记表。超时或失败按「低置信」处理。
5. **低置信**：`CLARIFY` 发澄清卡片（与审批卡片同一渲染通道，但不进审批表，答复作为下一条用户消息）；`FALLBACK` 交兜底目标。
6. **交接**：在当前会话上把「当前 Agent」切到目标；按「交接时带入的历史」组装目标 Agent 的输入；目标为 FLOW 时以调用人身份调用该 Flow 发布（origin=chat），结果作为答复；目标为 KB_QA 时调用内置的知识问答 Agent 并限定该知识库。
7. 每一步写一条 `route_decision`，字段：会话、Turn、路由 Agent 版本、层（EXPLICIT / VECTOR / LLM / CLARIFY / FALLBACK / STICKY）、候选数、选中目标、置信度、理由、耗时。

路由本身不调用任何业务工具，路由 Agent 的授权书只有「路由」一个只读动作类别。

## 3. 入口

| 入口 | 用法 |
| --- | --- |
| Chat（ADR-022） | 新建会话时可选择 ROUTER 型 Agent；会话头部显示当前交接到的目标，用户可手动改选（记为负反馈） |
| IM（ADR-021 CON-02） | 飞书机器人可绑定 ROUTER 型 Agent；话题内粘滞 |
| OpenAI 兼容接口（ADR-022） | `model = agent:{routerId}` 照常可用，只是无状态调用不粘滞 |
| 编排 | 不使用。事件路由仍由规则决定（ADR-020 硬边界不变） |

## 4. 与其他设计的关系

- **ADR-038 团队**：路由是一次性分派，团队是主管持续调度；路由的目标可以是团队型 Agent。
- **ADR-024 模型路由**：共用决策器 SPI 与向量匹配实现；两者的决定分别写 `route_decision` 与 `model_route_event`。
- **ADR-043 Flow**：Flow 内的分类用 StructuredExtract + Switch，节点模板库提供「意图分类」模板（ADR-043 修订），不依赖本 ADR。
- **安全**：分类模型看到的是候选描述与用户消息；候选描述来自已发布资产，不来自外部。用户消息中的注入最多导致选错目标，而目标都是调用人本来就能用的。

## 5. 评测（与 ADR-031）

- 数据集用例增加可选字段「期望目标」。批次评测对 ROUTER 型 Agent 只跑路由不跑目标，报告准确率、各层命中比例、混淆矩阵、P95 延迟。
- 线上信号：用户手动改选、澄清卡片被选中的选项，都作为标注回流到「待标注」队列。
- 发布门禁（EVO-06）：路由 Agent 新版本准确率低于稳定版本 2 个百分点时阻止发布。
