## 背景

负责人问：某个 Agent 做模型选型时，如何评测？现状：

1. ADR-031 的实验（EVO-04）可以对比「模型绑定」这个变量，但在 M4，且没有规定候选从哪来、比几轮、看哪些维度；
2. ADR-066 的能力记录与一致性测试只回答「能不能产出合法结构」，不回答「哪个模型结论更准」；
3. 合同场景 M3 就要选定模型（影子期在 W49 起），而 EVO-04 在 M4；
4. 国产模型的快照、价格变化频繁：DeepSeek 2026 年内先降价 75%、后部分上调最多 1100%（调研 08 第 6.4 节），选型结论若不能复跑，变化后就无从判断要不要换。

## 决定

1. 选型按**五轮漏斗**进行：准入过滤 → 冒烟 → 开发集 → 密封集终选 → 双跑（第 1 节）。
2. 选型**按角色**进行，一个 Agent 的抽取、判断、复核、路由、压缩等角色分别选（第 2 节）。
3. 比较维度固定为**质量、一致性、成本、时延、稳定性、合规**六项，产出帕累托表与推荐，不产出单一总分（第 3 节）。
4. 选型实验是可复跑的定义：数据集版本、评分器版本、角色、候选臂、参数；复评只换候选臂（第 4 节）。
5. 发生新快照、调价、下线、漂移等情况时**自动触发复评**（第 5 节）。
6. 选型结果落成路由计划或别名的新版本，按 ADR-069 第 4.2 节发布（第 6 节）。

## 1. 选型漏斗

| 轮 | 输入 | 做法 | 淘汰条件 | 成本量级 |
| --- | --- | --- | --- | --- |
| 0 准入过滤 | Model Hub 中全部已登记 binding | 按角色需求自动过滤：数据标签与去向（ADR-040，`SECRET` 只能私有）、供应商留存与训练条款（ADR-061 已有登记）、上下文长度、工具调用、视觉、结构化能力记录且一致性测试通过（ADR-066 第 4 节）、`BETA` 能力是否允许、是否固定快照（ADR-069 第 4.2 节） | 任一硬条件不满足 | 无模型调用 |
| 1 冒烟 | 通过第 0 轮的候选，建议不超过 6 个 | 冒烟集（合同场景 5 份），每条 1 次 | 结构化最终失败、证据绑定错误、超时 | 很低 |
| 2 开发集 | 冒烟通过者 | 开发集全量，每条 3 次，与基线臂（在岗模型，或新场景时选定的参照模型）配对 | 主指标配对差异区间上界 < 0（确定更差）且成本不更低；或任一硬性指标不达标 | 中 |
| 3 终选 | 第 2 轮保留的 2〜3 个 | 密封集，每条 3 次，与基线臂配对；生成帕累托表 | — | 中 |
| 4 双跑 | 推荐者 | 新场景：随 E3 影子期；在岗替换：ADR-069 第 5.1 节双跑 | 非劣效不成立或触发安全条件 | 线上一倍推理 |

- 第 1、2 轮可以由开发自行发起；第 3 轮需要评测负责人发起（使用密封集，ADR-068 第 1 节）。
- 外部公开基准（如中文法律基准 LexEval、LawBench）与厂商排行榜只可用于决定第 0 轮后**先测哪几个**，不作为淘汰依据。

## 2. 按角色选型

一个 Agent 内的模型调用按角色登记（AgentSpec 中已有的路由组、ADR-046 规划与执行分组、ADR-038 团队成员都视为角色）。每个角色有自己的主指标：

| 角色 | 主指标 | 次要指标 | 约束 |
| --- | --- | --- | --- |
| 抽取 | 关键字段准确率、证据绑定正确率 | 结构化首次通过率（ADR-066）、每份成本 | 需要 `STRICT_SCHEMA` 或 `STRICT_TOOL` 时以能力记录为准 |
| 判断 | 必备「不满足」召回率、四态一致率 | 三次运行结论一致率、精确率 | 需要思考模式时检查 `thinkingCompat`，不兼容则用「先推理后成形」（ADR-066 第 4.2 节），并把额外一次调用计入成本 |
| 复核 | 对判断员错误的检出率（在判断员出错的用例上复核员给出分歧的比例） | 误报率 | 与判断员**不同模型族**（ADR-024 模型多样性约束） |
| 路由与决策 | 类别准确率、混淆矩阵 | P95 时延 ≤ 1.5 秒（ADR-024 决策超时） | 优先小模型或向量匹配 |
| 上下文压缩、查询改写 | 压缩质量评估器、改写后检索 Recall@5 | 成本 | — |
| 裁判（评测用） | 与人工的 κ（ADR-068 第 4 节） | 成本 | 与被测角色不同族、钉快照 |

- 角色之间有依赖（判断员吃抽取员的结果），按「上游先选、下游在上游选定后再选」的顺序进行；上游替换时，下游角色的终选结果失效，需要在新上游下复跑第 3 轮。
- 端到端指标（例如合同四态一致率）在每个角色终选时都要报告，防止角色指标提升但整体下降。

## 3. 比较维度

| 维度 | 指标 | 测法 |
| --- | --- | --- |
| 质量 | 角色主指标与端到端主指标；与基线臂的配对差异及区间 | ADR-068 第 6 节 |
| 一致性 | 单次成功率、pass^3、结论一致率 | ADR-068 第 5 节 |
| 成本 | **每业务单位成本**（每份合同、每张工单）：实测输入、输出、思考、缓存读写 token × 评测时单价，含修复、降级、先推理后成形的额外调用 | 用 MH-11 明细，按评测运行汇总；单价取评测时 binding 版本上的价格（含阶梯价，ADR-042） |
| 时延 | 每业务单位端到端 P50 / P95，含排队与限流等待；首 token 时延 | 评测运行在接近生产的并发下进行（缺省 4 并发），并记录供应商当时的限流事件 |
| 稳定性 | 评测期间错误率、限流次数、故障接力次数、超时率 | 路由事件（ADR-024） |
| 合规 | 允许处理的最高数据标签、部署形态、留存条款、是否 `BETA` 能力 | 第 0 轮结果 |

### 3.1 选型报告

报告是一页表格加推荐：

- 每个候选一行：六个维度的值与区间；
- **帕累托标注**：在质量与成本两维上没有被任何其他候选同时超过的候选标为「前沿」；
- **推荐规则**：在满足全部硬门槛（场景评测规格，ADR-069 第 2 节）的前沿候选中，选质量与基线非劣效、且每单位成本最低的；若有质量显著更好（配对差异区间下界 > 0）且成本增加不超过规格中的「质量溢价上限」（缺省 30%）的，改推荐该候选；
- 推荐只是建议，最终由 Agent 负责人选择并写理由；
- 报告记录：模型快照名、评测时单价、能力记录版本、数据集与评分器版本、运行次数、评测成本。

### 3.2 私有化部署的选型

- 用客户实际部署的量化版本与推理后端测（量化与是否开思考都会影响质量，调研 08 第 6.4 节）；
- 时延在客户的实际 GPU 规格上测；成本以「每业务单位 GPU 秒」代替 token 单价，按客户提供的折算价换算；
- 私有化客户的选型实验定义可从交付模板导入，在客户环境复跑。

## 4. 选型实验

- 选型实验是 EVO-04 实验的一种（`kind = MODEL_SELECTION`），定义包括：Agent 与版本、角色、数据集与版本（按轮次）、评分器与版本、候选臂（每臂是一个 binding 或路由组配置及模型参数覆盖，ADR-042）、运行次数、基线臂、硬门槛（引用场景评测规格）。
- 定义有版本；复评时复制定义、替换或增加候选臂，其余不变，保证与上次结果可比。
- 运行时每个候选臂以「临时别名覆盖」的方式注入被测 Agent（只在 `origin = eval` 的 thread 内生效），不修改线上别名与路由计划。
- 同一角色同一时间只允许一个进行中的选型实验，避免预算浪费与结果混淆。

## 5. 复评触发（EVO-13）

| 触发 | 动作 |
| --- | --- |
| 管理员登记了新的模型快照（新 binding 或 binding 新版本） | 对引用同一用途、同一供应商族的 R2 / R3 角色，建议发起复评（不自动跑） |
| binding 单价变化 ≥ 20% | 自动用最近一次选型的 token 实测量重算每单位成本，更新报告；变化 ≥ 50% 或使推荐改变时，通知 Agent 负责人发起复评 |
| binding `retireAt` 登记 | 自动创建复评任务，截止日为下线前 14 天 |
| 哨兵评测漂移告警（ADR-069 第 6 节） | 自动创建复评任务 |
| 线上按角色主指标相关的驳回率连续两周上升（ADR-071） | 通知 Agent 负责人，由其决定是否复评 |
| 季度例行 | R3 Agent 每季度一次，只跑第 3 轮（在岗 + 新候选） |

复评结果若推荐替换，按 ADR-069 第 4.1 节作为 C2 变更处理（准入 + 双跑）。

## 6. 落地为路由配置

- 选定后生成路由计划或别名的**草稿**：角色对应的路由组，按推荐顺序排列候选（第一候选为主，第二为接力备选）；接力备选也必须在第 3 轮中达到硬门槛，否则不能列入。
- 发布走 ADR-041 发布流程与 ADR-069 第 4.2 节的受影响 Agent 评测。
- 选型报告链接写进路由计划版本的说明，审计可追溯「为什么用这个模型」。

## 7. 样例：合同审查的首次选型（M3，EVO-13a）

| 项 | 内容 |
| --- | --- |
| 时间 | W47，影子期（W49 起）之前 |
| 角色 | 抽取（证照与合同字段）、判断（必备要点）、复核；解析的 VLM 识别器沿用第 71 条 Q6 结论，不在本次选型 |
| 候选（示例，以选型时 Model Hub 实际登记为准） | 百炼 Qwen 系列旗舰与中档各一个快照；DeepSeek 正式版通用与推理各一个；若客户允许，一个其他国产供应商；私有化参照为 Qwen 开源权重中档量化版 |
| 数据 | 冒烟 5 份；开发集 10 组样本租约（M3 尚无密封集，第 3 轮以开发集代替并在报告中注明） |
| 运行 | 第 2 轮每份 3 次 |
| 产出 | 每角色一份选型报告；路由计划草稿；场景评测规格中的「每份合同成本上限」按选定组合实测值的 1.5 倍设定 |
| 影子期后 | 以留出的 20 份密封集对选定组合补跑第 3 轮，结果写进第一份正式准入单 |

M3 的最小版只要求：同一数据集多臂运行、每臂多次、配对差异与区间、成本与时延汇总、报告模板；帕累托标注、复评触发、私有化折算、临时别名覆盖以外的界面在 M4。
