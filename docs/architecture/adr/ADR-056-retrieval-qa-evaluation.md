## 背景

ADR-018 定了「权限过滤 → 混合召回 → Rerank → 父块扩展」四段，但：

1. 现有代码的关键词一路只在向量近邻上打分，不是独立召回；ADR-050 的记忆检索又复用这个组件；
2. 嵌入与 Rerank 模型一直是负责人待定项，KNW-07 的基线和 G3 闸门没有依据；
3. 多轮对话的追问直接拿去检索，没有改写；出错时没有检索轨迹可查；
4. 知识「自动注入」还是「作为工具」没有定义，ADR-048 只规定了自动注入结果的位置；
5. 评测只测召回，回答编造或引用错误测不出来。

## 决定

1. 部署统一 **1024 维**；公有云默认 `text-embedding-v4`，私有化默认 `Qwen3-Embedding-0.6B`；Rerank 对应 `qwen3-rerank` 与 `Qwen3-Reranker-0.6B`（第 1 节）。
2. 检索链路固定为九步（第 2 节），向量与全文**两路独立召回**，一次可查多个知识库（含 ADR-057 的外部知识库）。
3. Agent 的知识使用模式取 `AUTO`、`TOOL`、`BOTH` 之一（第 3 节）。
4. 每次检索写检索轨迹，提供命中测试（第 4 节）。
5. 评测加生成侧三个评估器与候选题生成（第 5 节）。
6. GraphRAG 移到 M4 之后，按评测证据触发（第 6 节）。

## 1. 模型与维度

| 用途 | 公有云部署 | 私有化部署 | CI |
| --- | --- | --- | --- |
| 嵌入 | 百炼 `text-embedding-v4`，指定 1024 维（支持 64〜2048，默认 1024；单条 8192 token，每批 10 条） | `Qwen3-Embedding-0.6B`（原生 1024 维，Apache-2.0）；有 GPU 且要更高精度时用 `Qwen3-Embedding-4B` 以 MRL 截到 1024 维 | `Qwen3-Embedding-0.6B` CPU 推理（ENG-04d 容器）；资源不够时退回 `bge-small-zh`，CI 部署单独配置 512 维 |
| Rerank | `qwen3-rerank` | `Qwen3-Reranker-0.6B` | `Qwen3-Reranker-0.6B` |
| 查询改写 | 部署登记的小模型（purpose=`kb_rewrite`） | 同左 | 录制回放桩 |

- 维度由 `tioka.knowledge.embedding-dim` 决定（M1-03、V119 已定），本 ADR 只给推荐值 1024；1024 低于 pgvector HNSW 对 `vector` 类型 2000 维的上限，不需要 `halfvec`。
- 两种部署的嵌入模型维度相同，但向量空间不同；换模型仍要整库重嵌入（ADR-018 已定），只是不改表结构。
- 负责人可改选；改选时只改第 70 条与本表，不影响其他设计。

## 2. 检索链路

| 步 | 做法 | 说明 |
| --- | --- | --- |
| 1 查询改写 | 有历史时，用最近 3 轮把本轮问题改写为独立问题；无历史或问题已独立时跳过 | KNW-13（M4）；M3 先不改写，直接检索 |
| 2 范围解析 | 把调用方给的知识库列表拆成自有知识库与外部知识库；对每个知识库判定 知识库 ACL ∩ 授予资源 ∩ `maxDataLabel`（ADR-040） | 无权的知识库静默剔除并记入轨迹 |
| 3 向量召回 | 自有知识库合并为一次查询，ACL 与文档级权限作为 SQL 条件下推，取 50 条子块；开启 pgvector 的迭代索引扫描，避免过滤后结果不足 | KNW-12 |
| 4 全文召回 | 独立的一路：中文分词（`pg_jieba` 或 `zhparser`，装不了扩展时按 ADR-018 退回应用层分词），同样的权限条件，取 50 条 | KNW-12；**不得**只在向量结果上打分 |
| 5 外部召回 | 外部知识库按 ADR-057 并行调用适配器 | M4 |
| 6 融合 | 各路按名次做 RRF（k=60），不比较原始分数 | — |
| 7 Rerank | 融合后前 50 条调 `ModelGateway.rerank`，取 topK；低于阈值（缺省 0.3，按知识库可配）的丢弃 | 未绑定 Rerank 时跳过并不设阈值 |
| 8 父块扩展 | 子块用于引用定位，父块正文送给模型；同一父块只返回一次；外部片段没有父块，原样返回 | — |
| 9 预算裁剪 | 按调用方给的 token 预算从高分到低分取，超出的截断 | 自动注入的预算见第 3 节 |

**接口**：ADR-018 的 `KnowledgeSearchApi.search` 保持，请求增加：知识库列表（可混合外部）、元数据过滤、token 预算、是否改写、调用场景（自动注入、工具、评测、命中测试）。返回每条命中带来源类型（自有 / 外部）、文档与版本、块、标题路径、页码、父块正文、融合名次与 Rerank 分、引用号。记忆检索（ADR-050）用同一组件的第 3、4、6、7 步。

**元数据过滤**：只接受调用方显式传入的条件（工具参数、Flow 节点配置、Agent 配置），支持等于、包含、范围、存在；不从问题里自动抽取。

**无答案**：第 7 步之后为空时，返回「无命中」并附原因（无权限、无结果、低于阈值）；自动注入时在本轮尾部写一句「知识库中没有找到与问题相关的内容」，让模型如实说明而不是凭空作答。

## 3. 知识使用模式（KNW-14）

AgentSpec 的 `knowledge` 段增加模式字段：

| 模式 | 行为 | 默认用于 |
| --- | --- | --- |
| `AUTO` | 每个 Turn 开始时检索一次，结果放在本轮尾部（ADR-048 D 区） | 问答型 Agent、IM 机器人 |
| `TOOL` | 不自动检索；开放 `kb.*` 工具，模型自己决定何时检索、是否再读全文 | 多步任务、研究型问题 |
| `BOTH` | 自动注入，同时开放工具 | 通用助手（缺省） |

- **自动注入预算**：缺省 3000 token、最多 5 个父块，Agent 可在 1000〜8000 之间配置；与记忆、经验等 D 区段一起受 ADR-048 有效预算约束。
- **工具**：`kb.search`（多知识库、元数据过滤、topK）、`kb.read`（按块、父块或文档的页范围读取，替代 `kb.read_chunk` 与 `kb.read_document`）、`kb.list`（列出本 Agent 可用的知识库及其说明，帮助模型选库）。工具结果按 ADR-048 的工具结果规则裁剪。
- **引用**：自动注入与工具返回的片段都带引用号；回答采用时由 Runtime 写 citation item（ADR-018 已定，KNW-08）。
- Agentic RAG（检索 → 判断 → 再检索、多跳）就是 `TOOL` 或 `BOTH` 模式下的 ReAct 循环，配合 ADR-046 的执行策略，不另建框架。

## 4. 检索轨迹与命中测试（KNW-13）

- 每次检索写一条轨迹：调用场景、原始问题、改写后问题、范围（含被剔除的知识库与原因）、各路召回条数与耗时、融合与 Rerank 后的前 20 条（块 ID、名次、分数）、最终返回条数与 token 数、来源 Turn。
- 轨迹的数据标签取涉及知识库的最高标签；保留 30 天；只有知识库管理员与 Turn 所属用户可查。
- 命中测试：知识库页输入问题、选择是否改写与 Rerank，展示各步结果与分数，用于调参与排障（前端 FE-32）。
- ADR-048 的上下文清单记录本轮注入了哪些块（`chunkId@docVersion`），轨迹与清单通过 Turn 关联。

## 5. 评测（KNW-15，修订 KNW-07）

| 层 | 指标 | 实现 |
| --- | --- | --- |
| 检索 | Recall@5、MRR（KNW-07 已定）、nDCG@10、无答案题的空召回率 | KNW-07 的知识评测 |
| 生成 | 忠实度（回答中每个论断是否被检索内容支持）、引用正确率（引用的块是否支持对应论断）、回答相关性、无答案拒答率 | 以 EVO-02 评估器 SPI 注册三个模型打分评估器；评分模型与被测模型不同 |
| 线上 | 无命中率、低分率、点踩与轨迹关联、引用点击率 | GOV-13 统计；EVO-01 反馈 |

- **候选题生成**：从选定文档抽样，用模型生成问题与期望命中块，进入「待审」状态，人工审核通过后才入评测集。
- **外部知识库**：同一评测集可对外部知识库运行（ADR-057 第 8 节），用于采购选型与「要不要同步到 Tioka」的判断。
- **门禁**：KNW-07 的 CI 门禁不变（Recall@5 低于基线 2 个百分点阻塞合并）；生成侧指标在 M4 只出报告，不阻塞，待积累基线后再定门槛。

## 6. GraphRAG（修订 KNW-10）

- KNW-10 移到 M4 之后，P2。
- 触发条件：评测集中「全局性问题」（跨多篇文档的归纳）一类的忠实度或相关性比局部问题低 15 个百分点以上。
- 届时采用 LightRAG 式的实体与关系索引，存在 PostgreSQL，增量更新；或 LazyGraphRAG 式查询时构图。不引入独立图数据库。
- 业务对象之间的关系（合同、租户、物业）由业务本体（ADR-036）表达，不进 GraphRAG。

## 7. 测试与验收

| 用例 | 断言 |
| --- | --- |
| `HybridRecallIT#keywordIndependent` | 一条只有字面命中、向量排名在 200 名之外的条款能被召回 |
| `HybridRecallIT#multiKb` | 三个知识库一次查询，结果按 RRF 融合，无权知识库被剔除并记入轨迹 |
| `HybridRecallIT#aclWithIterativeScan` | 用户只能看到 1% 的文档时仍返回足量结果 |
| `KnowledgeModeIT` | `AUTO` 不开放工具；`TOOL` 不自动注入；`BOTH` 两者都有且注入不超过预算 |
| `NoAnswerIT` | 低于阈值时回答说明未找到，不编造 |
| `QueryRewriteIT` | 「那违约金呢」在有上文时改写为包含主语的完整问题，轨迹里两者都有 |
| `GroundednessEvaluatorTest` | 人工构造的 10 条编造回答全部被判为不忠实 |
