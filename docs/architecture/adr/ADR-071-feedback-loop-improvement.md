# ADR-071 — 反馈回流与持续改进：原因码、分诊、正反例入集、标签版本与改进闭环

## 背景

M3-04 已经让法务处置（接受、修改、驳回）发 `lease.review.feedback`，写入 EVO-01 的反馈记录，并按要点出驳回率周报；M4 起修改与驳回的原因进入经验库。问题在于：

1. 原因是自由文字，无法判断错在哪一层（解析、抽取、规则、判断），也就不知道该改什么；
2. 法务改判不一定是 Agent 错了：业务决定接受某个风险、或要点口径已经调整，这两种改判如果被当成反例进入回归集和经验库，会把 Agent 教坏；
3. 法务自己发现、Agent 没有报出的问题（漏报）没有入口，而漏报恰恰是召回率门槛要防的；
4. 反馈变成评测用例没有规则：谁确认、进哪一层、正例要不要、标签随规范变化怎么办；
5. 改进动作（改 Prompt、改要点表达式、加经验、换模型）没有统一的再评测要求。

## 决定

1. 所有负向信号统一为**反馈项**，带结构化**原因码**；合同场景在业务系统处置时选择（第 1、2 节）。
2. 业务系统增加**漏报入口**（第 2.2 节）。
3. 反馈项经**每周分诊**确认归属与是否为 Agent 错误（第 3 节）。
4. 确认的 Agent 错误自动生成**回归用例（反例）**；被原样接受且稳定的结论按比例抽成**正例**（第 4 节）。
5. 业务规范改版时，旧用例按规范版本标为待重标，「规范已变化」类反馈不算错误（第 5 节）。
6. 每个改进动作关联到反馈项，并按 ADR-069 变更分级再评测；闭环指标进入看板（第 6 节）。
7. 偏好数据导出与私有模型微调在 M4 之后（第 7 节）。

## 1. 反馈项

| 来源 | 触发 | 缺省原因码 |
| --- | --- | --- |
| 法务处置 `MODIFY` / `REJECT` | `lease.review.feedback` | 法务选择（第 2 节） |
| 法务新增问题（漏报） | `lease.review.missed`（新增事件） | `MISSED` |
| 撤销（ADR-033） | `action_undone` | 待分诊 |
| 抽检「应撤销」「有错但保留」（ADR-034） | 复核审批 | 待分诊 |
| 审批驳回（含带参数修改的批准） | `runtime_approval` | 待分诊 |
| 用户点踩与意见（EVO-01） | `eval_feedback` | 待分诊 |
| 线上低分（EVO-03） | 采样评估低于阈值 | 待分诊 |
| 哨兵告警（ADR-069 第 6 节） | 漂移 | `DRIFT` |

反馈项（`eval_feedback_item`）的内容：来源与来源 ID、Agent 版本、Turn、材料单元（合同链）、涉及对象（要点、字段、动作类别）、Agent 原输出、人工最终结果、原因码（主因与次因）、备注、数据标签、分诊状态（`NEW` / `TRIAGED` / `LINKED` / `CLOSED`）、是否为 Agent 错误、关联的改进项。

- 反馈项的数据标签取来源数据的最高标签（ADR-040）；查看与分诊受同样的约束。
- 一次处置可以产生多个反馈项（一个要点一个）。

## 2. 原因码

### 2.1 码表

| 原因码 | 名称 | 归属层 | 算 Agent 错误 | 去向 |
| --- | --- | --- | --- | --- |
| `PARSE` | 原文读错 | 解析 | 是 | ADR-062 解析评测集候选、回归集 |
| `EXTRACT` | 取值或证据错 | 抽取 | 是 | 模型层评测（ONT-09）、回归集 |
| `RULE` | 要点规则或阈值不当 | 规则（业务规范资产） | 是（规范资产的错误，不是模型的） | 要点库修订；受影响用例重标 |
| `JUDGE` | 判断错误 | 判断 | 是 | 回归集（反例）、经验候选 |
| `MISSED` | 漏报 | 判断或规则 | 是 | 回归集（反例）；分诊时细分为判断或规则 |
| `RETRIEVE` | 没找到应参考的条款、案例或制度 | 检索 | 是 | 检索评测集（ADR-056）候选 |
| `ACCEPT_RISK` | 业务接受该风险 | — | **否** | 不进反例；可作为经验「什么情况下可接受」的说明，需法务负责人确认 |
| `SPEC_CHANGED` | 口径已调整 | 标签 | **否** | 触发要点库新版本；旧用例 `STALE`（第 5 节） |
| `WORDING` | 表述或建议文字优化 | 文字 | 轻微 | 只统计；累计多次时作为 Prompt 改进候选 |
| `OTHER` | 其他 | — | 待分诊 | 分诊时必须改为上述之一 |

- 法务在 `MODIFY` / `REJECT` 时必须选一个主因，可选多个次因；文字原因保留但不再必填（保留 M3-04「驳回必填原因」的规则：驳回时主因或文字至少有一）。
- 码表是空间级配置（ADR-041 发布型对象），可以按场景增加细分码，但不能删除上述码；细分码必须映射到上述码之一。
- 非合同场景（撤销、点踩等）由分诊人选择原因码。

### 2.2 漏报入口（业务系统）

- 结论页增加「补充问题」：法务选择要点（或「要点库之外」）、填写结论、选择原文位置（可选），提交后发 `lease.review.missed`。
- 「要点库之外」的问题进入要点库候选（BIZ-04 的案例与正反例），由法务负责人决定是否新增要点。
- 补充问题计入召回率的分母（法务判不满足的总数），保证召回率不被漏报低估。

## 3. 分诊

### 3.1 节奏与参与者

- 每周一次，Agent 负责人（开发）与业务负责人（合同场景为法务负责人）共同进行，缺省 1 小时。
- 分诊视图（FE-44）按原因码与要点分组，显示数量、周环比、典型样例；可批量确认。
- 系统预分诊：用固定规则给出建议，例如 Agent 的取值与人工取值不同且证据位置相同 → 建议 `EXTRACT`；解析层标了低置信 → 建议 `PARSE`；同一要点本周 `REJECT` 集中出现且要点库最近改过版 → 建议 `SPEC_CHANGED`。建议只供参考，以人确认的为准。

### 3.2 分诊结论

| 结论 | 动作 |
| --- | --- |
| Agent 错误（`PARSE`、`EXTRACT`、`JUDGE`、`MISSED`、`RETRIEVE`） | 生成回归用例（第 4 节）；关联或新建改进项（第 6 节） |
| 规范资产错误（`RULE`） | 新建要点库修订改进项；受影响用例在修订发布后重标 |
| 非错误（`ACCEPT_RISK`、`SPEC_CHANGED`） | 不生成反例；`SPEC_CHANGED` 触发第 5 节 |
| 重复 | 合并到已有反馈项 |
| 证据不足 | 留待下周或请业务方补充 |

分诊确认后，`ADR-034` 自治指标中的批准率、复核不通过率按「是否 Agent 错误」重新归类展示（不影响已发生的降级，降级仍立即生效）。

## 4. 正反例入集

### 4.1 反例

- 来源：分诊确认的 Agent 错误。
- 内容：材料单元（整份合同链，不只是出错的要点）、期望答案为人工最终结果、`polarity = NEGATIVE`、`source = FEEDBACK`、`spec_ref` 为处置时的要点库版本、`must_pass = true`。
- 去向：**回归集**；同一材料单元的其他要点作为开发集用例（因为整份合同进入了可调参的层）。
- **不进密封集**：若该合同已在密封集中，分诊确认后把它移出密封集（密封集按 ADR-068 第 1 节补充新的样本），避免密封集中出现团队已经针对性修过的用例。

### 4.2 正例

- 来源：法务 `ACCEPT` 且未修改、并在之后 30 天内没有被撤销或改判的结论。
- 抽样：按要点分层，每周每个要点最多抽 2 份，总体约 10%；优先抽 Agent 置信度低但被接受的（这些最能防止「改了反例后把正例改坏」）。
- 内容：`polarity = POSITIVE`，其他同反例；进入回归集时 `must_pass = false`（正例只要求在非劣效判定中不退化，不逐条必过），进入开发集无限制。
- 回归集中正例与反例的比例在报告中显示；反例占比超过 80% 时提示补正例，防止 Agent 越改越保守。

### 4.3 去重与隐私

- 同一材料单元不重复入集；同一要点的高度相似反例（同一条款模板）只保留 3 份，其余计数。
- 用例保持原数据标签；数据标签为 `CONFIDENTIAL` 以上的用例只能在允许该标签的模型上评测（ADR-068 第 2 节），选型时第 0 轮据此过滤。
- 客户合同的留存期限按客户合同管理制度；评测用例随原合同的删除请求一起删除（`source_ref` 关联）。

## 5. 标签版本

- 业务规范（合同场景为要点库与阈值，ADR-036 领域包）每次发布新版本时，记录变更的要点。
- 回归集、开发集、密封集中 `spec_ref` 指向旧版本且涉及变更要点的用例，标为 `STALE`，不参与门禁统计；生成重标任务进入标注台（ADR-068 第 7.3 节），业务专家只需逐条确认「新规范下结论是什么」。
- 未涉及变更要点的用例自动把 `spec_ref` 前移到新版本。
- `SPEC_CHANGED` 类反馈集中出现（同一要点一周 ≥ 3 条）而要点库没有发布新版本时，分诊视图提示「口径可能已变但规范未更新」，提醒业务负责人发布。

## 6. 改进闭环

### 6.1 改进项

| 字段 | 内容 |
| --- | --- |
| 关联反馈项 | 一个或多个 |
| 层与手段 | 解析方案、检索配置、抽取 Prompt、判断 Prompt、要点表达式或阈值、经验条目（EVO-05）、换模型（ADR-070）、Schema |
| 变更级别 | 按 ADR-069 第 4.1 节自动判定 |
| 状态 | `OPEN` / `IN_PROGRESS` / `EVALUATING` / `RELEASED` / `WONT_FIX` |
| 验证 | 关联的回归用例全部通过；按变更级别要求的评测结果 |

- 改进项可以链接到外部缺陷单（文本字段），不接外部系统。
- `RELEASED` 时，系统检查关联的回归用例都在本次准入或回归运行中通过，否则不允许置为 `RELEASED`。

### 6.2 经验库的接入（修订 EVO-05）

- 经验提取（ADR-031）的失败组只取**分诊确认为 Agent 错误**的反馈，`ACCEPT_RISK` 与 `SPEC_CHANGED` 不进失败组。
- `ACCEPT_RISK` 可以生成一类特殊经验「可接受条件」（例如「门店为旗舰店时，装修期 90 天以内可接受」），只能由业务负责人确认后生效，并且 R3 Agent 的经验生效按 C1 变更评测（ADR-069 第 4.1 节）。

### 6.3 闭环指标

进入 Agent 看板（ADR-041 统计）：

| 指标 | 定义 |
| --- | --- |
| 按原因码的反馈率 | 每周每百个结论的反馈项数，按原因码 |
| Agent 错误率 | 分诊确认的 Agent 错误 / 结论数 |
| 漏报率 | `MISSED` / 法务判不满足总数 |
| 分诊及时率 | 一周内完成分诊的反馈项比例 |
| 修复周期 | 反馈项创建到关联改进项 `RELEASED` 的中位天数 |
| 复发率 | 已 `RELEASED` 的改进项关联的问题再次出现的比例 |

### 6.4 合同场景的周例会产出

替代 M3-04「驳回率最高的 10 个要点」周报：按原因码分组的反馈量与环比、Agent 错误率趋势、本周新增回归用例数、待重标数、改进项进展、下周计划。

## 7. 偏好数据（EVO-16，M4 之后）

- 分诊确认的「Agent 输出 → 人工结果」对，可以导出为偏好数据集，供客户私有模型的偏好优化（DPO 一类）使用。
- 只在客户书面授权、且数据标签允许时导出；导出写审计。
- 微调后的模型作为新 binding 进入 ADR-070 选型漏斗，与其他候选同等对待。
