# ADR-077 — Dashboard 卡片注册与个人工作台

- 状态：Accepted（设计定案，待实现；放入 F 阶段之后的 **F2 增强批次**，见 ADR-029 第 81 条）
- 日期：2026-11-13
- 覆盖工作项：BAS-31、BAS-FE-14、BAS-FE-16
- 详细设计：[S15](../systems/S15-Foundation基础平台系统.md) 第 23 节
- 相关：[ADR-051](ADR-051-foundation-platform.md)、[ADR-052](ADR-052-org-account-authz-center.md)、[ADR-054](ADR-054-engineering-base-subsystem-microfrontend.md)、[ADR-076](ADR-076-app-to-app-authorization.md)、ADR-029 第 57 条
- 约束：与 ADR-029 定案冲突时以定案为准；修改本 ADR 走 [ADR-030](ADR-030-anti-drift-process.md) 的变更流程。

## 背景

门户到 ADR-054 为止只有「应用启动台、个人中心、消息与待办」（S15 第 3.1 节、BAS-FE-08）。负责人 2026-11-13 要求 Foundation 提供**类似 Apple 桌面小组件的 Dashboard 卡片组件注册能力**：各业务应用把「我这个应用里用户关心的一小块信息」注册成卡片，用户在统一入口（门户）的个人工作台上像摆小组件一样编排自己的看板。

现状里没有这个概念：ADR-028 / 45-FE 的 Embed Widget 是「把对话嵌到别的站点」，不是「把业务应用的一块信息注册到门户」。因此需要一个新的卡片注册与工作台能力。

## 决定

1. **门户即全公司统一入口**，由四部分组成：**应用启动台**（按权限展示可进入的应用与模块）、**个人工作台**（本 ADR 的多套 Dashboard）、**个人中心**、**消息与待办**，外加全局导航。工作台是门户内的一个分区，不是独立系统。

2. **卡片注册中心是 Foundation 的主数据**。新增卡片目录 `fdn_widget`：应用、编码、名称、图标、尺寸档（如 1×1 / 2×1 / 2×2 等栅格单位）、渲染方式（`SCHEMA` / `REMOTE`）、数据源、所需权限码、参数 schema、数据标签、状态、排序。卡片清单随应用版本声明并导入，沿用 S15 第 11.1 节的清单规则（同哈希不重复导入、消失的编码标「已下线」保留 90 天后清理、导入幂等）。

3. **双轨渲染**（负责人选定「两类都支持」）：
   - **SCHEMA 型（配置化）**：应用只提供只读数据接口 `dataEndpoint`，返回统一 JSON；门户内置通用渲染器渲染指标卡、图表（折线/柱/饼，用 ECharts）、列表、待办、进度等标准形态。适合绝大多数「展示一块数据」的需求，应用不需要写前端。
   - **REMOTE 型（远程组件）**：应用发布 Vue 卡片组件（npm 包 / 微前端远程组件），门户按 ADR-054 同一加载机制加载，交互与视觉完全由应用控制；数据可自取，但必须经前端包提供的通信接口取得令牌与用户上下文，不得直接访问基座全局对象（沿用 ADR-054 第 4 条的通信约束）。

4. **数据契约**（SCHEMA 型）：`GET {dataEndpoint}` 返回卡片数据 JSON，至少含 `dataUpdatedAt`；可选 `drillDown`（点击后跳转的深链，只带业务对象 ID，鉴权沿 ADR-029 第 57 条）。卡片数据一律按「当前用户」身份在被调应用内鉴权；OBO 场景按 ADR-076 走用户委派。

5. **布局与编排**：新增 `fdn_dashboard`（所有者：用户 / 角色 / 组织）与 `fdn_dashboard_widget`（看板、卡片引用、尺寸档、栅格坐标、排序、参数）。用户可自建个人看板；管理员或角色可下发默认看板（新用户首次进入看到默认板）。栅格支持拖拽与尺寸切换。

6. **权限与披露**：
   - 卡片按其「所需权限码」过滤：无权限的卡片不出现（既不下发也不占位）。
   - 卡片数据标签作为「可发送到前端的披露上限」：`SECRET` 不进卡片，`CONFIDENTIAL` 是否允许由空间配置（沿用 ADR-040 数据标签与 ADR-025 的去向许可）。
   - 新增权限码 `fdn:widget:admin`（卡片目录与默认看板管理）。

7. **性能与降级**：卡片数据由门户基座统一代理请求（带用户令牌）并发拉取，短 TTL 缓存 + 手动刷新；单卡请求失败或超时只显示错误态与重试，不拖垮整个看板；REMOTE 卡片加载失败降级为「在新窗口打开」深链（与 ADR-054 第 4 条的子应用降级一致）。

8. **不做**：不做拖拽式低代码图表设计器（卡片形态由应用声明或门户内置渲染器覆盖）；不做卡片之间的联动钻取编排（先用深链跳转，跨卡片联动留待需要时再议）。

9. 卡片目录变更发事件 `fdn.widget.changed`；看板布局属个人数据，变更不广播。

## 备选

| 备选 | 不选原因 |
| --- | --- |
| 纯前端：只支持远程组件卡片 | 灵活，但无法做统一的权限过滤、服务端数据代理与降级，运维与安全口径难统一 |
| 纯配置化：只支持 schema 驱动卡片 | 简单可控，但复杂交互（联动、富操作）做不了，应用仍会各写各的 |
| 把卡片做成独立门户/独立前端 | 另起一套入口，失去「统一入口」的意义，与 ADR-054 微前端重复 |
| 卡片数据由前端直接请求各应用接口 | 绕过统一鉴权与披露控制，令牌与跨域管理分散，无法统一降级 |

## 后果

- Foundation 新增 `fdn_widget` / `fdn_dashboard` / `fdn_dashboard_widget` 与事件 `fdn.widget.changed`；新增权限码 `fdn:widget:admin`。
- 前端包新增卡片注册与渲染接口（`registerWidget` 等）与工作台页面（栅格编排、双轨渲染、降级）。
- 门户由「启动台 + 个人中心 + 消息待办」扩展为「统一入口」；工作台与 ADR-054 微前端共享同一加载与通信机制。
- 排期：F2 增强批次，后端 BAS-31（5），前端 BAS-FE-14（6）、BAS-FE-16（3）；闸门 `GfWidgetGateIT`。
