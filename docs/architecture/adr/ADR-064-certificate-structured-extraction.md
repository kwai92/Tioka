# ADR-064 — 证照与票据结构化抽取 `@doc.extract`

- 状态：Accepted（设计定案，待实现）
- 日期：2026-11-07
- 覆盖工作项：PRS-18、FE-40（新增）
- 来由：[调研 06](../research/06-文档结构树图层与证照抽取补充调研.md) 第 3 节，选项 V2；ADR-029 第 72 条
- 相关：[ADR-036](ADR-036-business-ontology-domain-pack.md)、[ADR-037](ADR-037-structured-outputs.md)、[ADR-040](ADR-040-dataset-policy-data-label.md)、[ADR-060](ADR-060-document-parsing-service.md)、[ADR-061](ADR-061-parse-engine-spi-external-ocr.md)、[ADR-062](ADR-062-parse-quality-special-elements-security.md)、[ADR-063](ADR-063-docast-layers-element-processing.md)
- 约束：与 [ADR-029](ADR-029-design-rulings.md) 定案冲突时以定案为准；修改本 ADR 走 [ADR-030](ADR-030-anti-drift-process.md) 的变更流程。
- 写法说明：只用文字和表格，不附代码。

## 背景

负责人指出：证照类文件用现有方案也产不出结构化数据。合同通常附带承租方营业执照、法定代表人或经办人身份证、不动产权证书、授权委托书、发票等，现在只被当成普通页解析成文字。调研 06 第 3 节：TextIn 抽取有字段引用但没有置信度；百炼 `qwen-vl-ocr` 覆盖约 50 种证照票据但没有位置；没有一家能同时给出「结构化字段 + 原文位置 + 可校验」。Tioka 已有 Schema 登记表与证据绑定（ADR-037）、引文校验（DOC-03），缺的是把它们用在证照上的编排。

## 决定

1. **先分类，再抽取**：解析完成后对每页做文档类别判定，合同页走文档层，证照与票据页走 `@doc.extract`。
2. **抽取以 Schema 为准**：每类证照对应 Schema 登记表（ADR-037）中的一个 Schema；平台预置 5 类，新类别只加 Schema、不改代码。
3. **每个抽取值必须回指 DocAST**（块或字符区间），并通过归一化比对；比对不上或引擎不给位置的值置「待复核」。
4. **抽取引擎可替换**：默认 `qwen-vl-ocr` 信息抽取，可选 TextIn 文档抽取、通用视觉模型；按 ADR-061 去向规则过滤。

## 1. 文档与页的分类

| 项 | 定案 |
| --- | --- |
| 类别 | `CONTRACT`（合同正文、补充协议）、`CERTIFICATE`（证照）、`INVOICE`（发票与票据）、`FORM`（表单）、`OTHER` |
| 证照子类 | 首批：营业执照、居民身份证、不动产权证书（含旧版房屋所有权证）、授权委托书、增值税发票（含全电票） |
| 判定 | 先用版面与文字规则（标题关键词、版式特征，如「营业执照」「统一社会信用代码」「中华人民共和国居民身份证」）；规则不能判定的页交给视觉模型做一次分类 |
| 粒度 | 按页判定，相邻同类页合并为一个「文档段」（如身份证正反面、多页委托书） |
| 输出 | 契约文档级增加 `segments`：段 ID、类别、子类、页范围、判定依据与置信度 |
| 上传场景 | 一份 PDF 里合同正文后附证照扫描页是常态，按段处理，不要求分开上传 |

## 2. 抽取

### 2.1 流程

1. 取文档段的 DocAST（块、行内对象、字符、键值关系）与页图。
2. 选 Schema：按子类取已发布的 `schemaKey@version`（ADR-037 Schema 登记表），`owner_pack = platform` 为平台预置。
3. 调抽取引擎：输入 Schema 与页图（视觉模型类）或 DocAST 文字（文本模型类）；要求每个字段同时返回原文片段。
4. 回指与校验（第 2.3 节）。
5. 结果写成 `data` item（ADR-037），负载引用 Schema；字段附 `Source`（块 ID 与字符区间）。

### 2.2 抽取引擎

| 引擎 | 类别 | 说明 |
| --- | --- | --- |
| `qwen-vl-ocr` 信息抽取（默认） | `MODEL` | 自定义 `result_schema`（最多 3 层）；不返回位置，位置由第 2.3 节回指得到 |
| TextIn 文档抽取 v3（可选） | `CLOUD_API` | JSON Schema 字段模式，返回字段引用（页码、位置、原文）与印章列表；无字段置信度；价格为解析的 2 倍；坐标单位文档前后不一致，适配时实测 |
| 通用视觉模型（备选） | `MODEL` | 用于预置 Schema 之外的类别 |
| 键值规则（兜底） | `IN_PROCESS` | 对版式稳定的证照（营业执照、身份证），用 DocAST 中的 `KEY_VALUE` 关系直接取值，不调模型 |

Schema 超过引擎限制（层级或字段数）时自动拆成多次调用，结果合并。

### 2.3 回指与校验

| 情况 | 处理 |
| --- | --- |
| 引擎给了原文片段 | 在文档段的 DocAST 文字中按 DOC-03 的归一化规则查找，找到则记 `Source`；找不到置「待复核」，原因「原文不符」 |
| 引擎给了位置 | 位置与 DocAST 块按 IoU 配对后取块文字比对；位置与文字不一致置「待复核」 |
| 引擎什么都没给 | 用值本身在 DocAST 中查找；唯一命中记 `Source`，多处命中取与字段标签距离最近者并降低置信度，无命中置「待复核」 |
| 格式校验 | Schema 中的格式约束：统一社会信用代码 18 位与校验位、身份证号 18 位与校验位及出生日期一致、日期合法、金额大小写一致 |
| 跨字段校验 | 证照有效期是否覆盖合同签订日；营业执照名称与合同当事方名称一致（由领域包校验器 LSE-02 做，平台只提供字段） |
| 行内对象 | 落在手写或印章遮挡行内对象内的值置「待复核」（ADR-063 第 1.2 节） |

### 2.4 预置 Schema 字段（首批）

| 子类 | 字段 |
| --- | --- |
| 营业执照 | 名称、统一社会信用代码、类型、法定代表人或负责人、注册资本、成立日期、营业期限、住所、登记机关、发照日期 |
| 居民身份证 | 姓名、性别、民族、出生日期、住址、公民身份号码、签发机关、有效期限（正反面合并） |
| 不动产权证书 | 证号、权利人、共有情况、坐落、不动产单元号、权利类型、权利性质、用途、面积、使用期限 |
| 授权委托书 | 委托人、受托人、受托人身份证号、委托事项、委托权限、委托期限、签署日期、是否盖章 |
| 增值税发票 | 发票代码、发票号码、开票日期、购买方名称与税号、销售方名称与税号、金额、税额、价税合计（大写与小写）、备注 |

身份证号等个人敏感信息按 ADR-040 的数据标签处理：抽取结果默认 `CONFIDENTIAL`，在 IM 与通知中按 ContentSafetyHook 脱敏（ADR-025）。

## 3. 使用方式

- **工具** `@doc.extract`：参数为文档段 ID 与可选的 `schemaKey`（不给则按子类自动选）；返回 `data` item。权限与 `@doc.unit` 相同（能读该文档的人才能抽取）。
- **@model.build**：租赁合同建模在第 0 步解析之后，对证照段自动调用 `@doc.extract`，结果作为对象属性的来源（如承租方名称、统一社会信用代码以营业执照为证据），`method = E`、证据绑定照常校验。
- **知识库**：证照与票据段默认不入知识库（含个人信息），知识库配置可显式开启。

## 4. 评测

ADR-062 评测集增加证照子集：每类 5 份（含拍照件、复印件、加盖「仅供某用途」水印），指标为字段完全一致率（≥ 98%）与「错而不报」率（≤ 0.5%），后者的定义同 ADR-062。
