## 背景

Agent 的成本主要在反复读取上下文：Manus 报告输入与输出 token 之比约 100:1，并把 KV 缓存命中率当作生产 Agent 最重要的单一指标（调研 03 第 1、2.4 节）。Tioka 计划使用的供应商都支持前缀缓存，但规则各不相同：

| 供应商 | 模式 | 命中价格 | 要点 |
| --- | --- | --- | --- |
| 阿里云百炼 | 显式（`cache_control` 标记）或隐式（自动），二选一 | 显式多数模型 10%（创建 125%）；隐式多数模型 20%（无创建费） | 工具定义必须逐字节一致；最多 4 个标记，回看 20 个块 |
| DeepSeek | 硬盘缓存，默认开启 | 见价格页 | 尽力而为，按前缀单元完整匹配 |
| Anthropic 协议 | 自动或显式断点 | 0.1 倍（写 1.25 倍或 2 倍） | 改工具定义使全部缓存失效 |
| OpenAI 协议 | 默认自动，新模型可显式 | 最多便宜 95% | 按前缀哈希与缓存键路由 |
| 自部署 vLLM / SGLang | 前缀缓存 | 省 GPU 计算 | 多副本时要按会话亲和路由 |

所有供应商的共同点是**只认前缀**：前缀里有一个字节不同，后面全部不命中。因此缓存命中率首先由上下文组装决定（ADR-048），其次才是网关怎么打标记。现有设计只有两处涉及缓存：ADR-024 要求不得默认关闭 `preferPreviousInGroup`，ADR-041 在用量明细里记录缓存命中 token。

## 决定

1. **缓存友好是组装器的硬约束**，写成五条规则（第 1 节），由测试和运行时指标共同守住。
2. **组装器只给出与供应商无关的「断点提示」**，由 ModelGateway 按 binding 声明的缓存能力落地（第 2 节）。
3. **缓存写入与读取分开计量计价**，进入配额与成本统计（第 3 节）。
4. **命中率是一等指标**，有告警和断点诊断（第 4、5 节）。
5. 不做语义缓存（相似问题返回旧答案）。

## 1. 缓存友好规则

| # | 规则 | 守护方式 |
| --- | --- | --- |
| C1 | **前缀稳定**：ADR-048 的 A 区、B 区不得包含时间戳、请求 ID、随机数、无序集合；当前日期只出现在 D 区环境信息，精确到天 | Agent 发布校验检查指令中的时间类占位；`ContextAssemblyOrderTest` 断言同一 Turn 内各步 A+B+C 前缀哈希不变 |
| C2 | **确定性序列化**：工具按名称排序；工具定义与 JSON Schema 规范化（键按字典序、去掉空值与默认值、描述文本不做运行时拼接）；消息内容的结构化部分同样规范化；同一份输入在任何实例上序列化结果逐字节相同 | 序列化器单元测试；双实例闸门用例比较两实例的前缀哈希 |
| C3 | **只追加**：历史只在 ADR-048 的第 1、2 级削减时被改写；第 1 级每次至少清掉 E 的 15% | ADR-048 规则 |
| C4 | **工具列表 thread 内稳定**：见 ADR-048 第 1.2 节；不可用的工具在调用时拒绝，不从列表删除（授予收窄除外） | ToolGateway 测试 |
| C5 | **换模型只在边界发生**：同一 thread 内只在 ADR-048 第 2 级摘要之后、用户显式切换、或当前模型不可用（熔断、配额、标签限制）时换模型；路由计划的 `preferPreviousInGroup` 在 thread 内强制生效 | ADR-024 路由测试；换模型写入上下文清单 |

## 2. 供应商适配（CCH-02）

### 2.1 binding 声明缓存能力（修订 ADR-041 模型对象、ADR-042 模型参数）

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| 缓存模式 | `NONE` / `IMPLICIT` / `EXPLICIT` | 百炼可按 binding 选显式或隐式；DeepSeek、OpenAI 协议为隐式；Anthropic 协议为显式 |
| 最小缓存长度 | token | 低于此长度的断点不打 |
| 有效期选项 | 短（默认，通常 5 分钟）/ 长（如 1 小时，供应商支持时） | — |
| 价格 | 缓存写入单价、缓存读取单价 | 与普通输入、输出单价一起进 binding 版本（ADR-041） |
| 亲和键 | 是否支持（如 OpenAI 协议的缓存键、自部署推理服务的会话亲和头） | — |

这些字段进 binding 的发布版本，变更走 ADR-041 版本框架。

### 2.2 断点提示

组装器在上下文清单中给出至多三个断点提示，网关按缓存模式处理：

| 断点 | 位置 | 意义 |
| --- | --- | --- |
| P1 | A 区末尾（工具定义之后） | 同一 Agent 版本所有用户共享 |
| P2 | B 区末尾 | 同一 thread 内共享 |
| P3 | C 区末尾（历史末尾） | 本 Turn 多步之间、下一 Turn 复用 |

| 缓存模式 | 网关动作 |
| --- | --- |
| `EXPLICIT` | 在 P1、P2、P3 处打标记（第四个标记位留给供应商的自动断点或以后使用）；段长度低于最小缓存长度时合并到下一个断点；P1 在 Agent 配置为「高频共享」时可用长有效期，其余用短有效期 |
| `IMPLICIT` | 不打标记；支持亲和键时传 thread ID 的哈希 |
| `NONE` | 不处理 |

### 2.3 有效期选择

默认全部用短有效期。长有效期写入更贵（Anthropic 为 2 倍），只在 Agent 配置「高频共享」时用于 P1（同一 Agent 版本被大量用户并发使用，A 区在 1 小时内会被反复读取）。审批挂起、`WAITING_CHILD` 等长等待恢复后缓存大概率已过期，不为它们使用长有效期。

### 2.4 私有化部署

部署指南（ops 文档）增加两条：自部署推理服务开启前缀缓存；网关到推理服务的多副本负载均衡按亲和键做一致性哈希路由。没有亲和路由时，命中率随副本数近似线性下降。

### 2.5 数据标签与隔离

缓存存在供应商侧，与请求本身的数据去向相同，ADR-040 的去向许可已经覆盖（读到 `SECRET` 的 Turn 只能用私有化模型）。P1 段由 Agent 版本决定，不含任何用户数据；B、C、D 区含用户数据，不同用户的内容不同，不会互相命中。

## 3. 计量与成本（修订 ADR-017、ADR-041 第 6 节）

- 用量明细（`model_usage`）把输入 token 拆为三项：普通输入、缓存写入、缓存读取（ADR-041 已有「缓存命中 token 数」，本 ADR 增加「缓存写入 token 数」）。
- 成本按 binding 版本中的三种单价分别计算；配额与预算按成本扣减时用实际成本（ADR-017 配额不变，只是成本算法变）。
- 日汇总（MH-11）增加缓存写入 token 与「缓存节省金额」（按普通输入单价重算的差额），在模型中枢统计页展示。

## 4. 指标与告警

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `tioka_model_cache_hit_ratio` | 缓存读取 token ÷ 全部输入 token，按 Agent、binding、用途切片 | 主指标 |
| `tioka_model_tokens_total{direction="cache_write"}` | 缓存写入 token | 写多读少说明前缀不稳定或有效期过短 |
| 多步 Turn 命中率 | 只统计 Turn 内第 2 步及之后的调用 | 这部分理论上应接近全部命中，最能暴露组装问题 |

告警（GOV-13 规则模板）：某 Agent 的多步 Turn 命中率连续 1 小时低于 50%（缓存模式非 `NONE` 时）；某 binding 的缓存写入 token 超过读取 token 的 2 倍。

## 5. 断点诊断

上下文清单记录了 A 区、A+B 区、A+B+C 区的前缀哈希（ADR-048 第 4 节）。诊断视图（FE-31）对同一 thread 内相邻两次调用比较哈希，指出**第一个发生变化的区和段**，例如「A 区工具定义在第 3 步发生变化：授予收窄」或「B 区画像快照变化：发生了摘要」。这把「为什么没命中」从猜测变成可查。
