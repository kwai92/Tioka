# DA — Tioka 数据架构

> 回答：有哪些数据、谁拥有、存在哪、如何流动、如何分级与留存。  
> 字段级细节仍以各 S 第 8 章演进；本文给**全局**约束与概念/逻辑模型。

---

## 1. 目标与原则

1. **分 schema / 禁跨库 join**；跨域只存对方业务 ID。  
2. **主数据与操作数据分离**（BA §7）。  
3. **发布快照不可变**（AgentVersion、RoutingPlan 发布、FlowVersion）。  
4. **密钥不进业务表明文**（只存 secretRef）。  
5. **租户/空间隔离字段强制**。  
6. **可重建优先**：向量/缓存可重建；真相在关系库 + 对象存储。

---

## 2. 数据分层

| 层 | 内容 | 存储 |
| --- | --- | --- |
| 主数据 MD | 用户组织、空间角色、Provider/Model、Adapter 登记 | PG `sys_*` / `md_*` |
| 资产配置 CD | Agent/MCP/Skill/Flow 草稿与版本、RoutingPlan | PG 各域 schema |
| 操作数据 OD | Session/Turn、Conversation、Run、Attention、FlowRun | PG；热点可归档 |
| 内容数据 CT | Document 原文、Chunk、Wiki、Skill 包、**已发布产物** | OSS + PG 元数据 |
| **会话工作盘 WD** | Session 过程文件、物化附件、已安装 Skill 只读树、scratch | **POSIX Workdisk**（本地/PVC/NFS）；**不**用 OSS 当工作目录（ADR-014 D1） |
| 向量 VX | Embedding | pgvector → 可迁 Milvus |
| 事件 EV | MQ 消息、审计日志 | MQ / 审计表 / SIEM |
| 缓存 CA | 权限、工具目录、路由快照 | Redis |

> 上传原稿可先落 OSS（交换层），再 `materialize` 到 WD `uploads/`；`publish_artifact` 后回写 CT。

## 6. 数据流

### 6.1 对话写路径

User Message → `ch_*` → Runtime Turn → Part 追加（chat + runtime 事件）→ 用量 `mdl_usage_ledger`。

### 6.2 知识入库

Upload/Sync → OSS 原文 → 解析 → `kb_chunk` → embedding 写 VX → 状态回文档。

### 6.3 配置发布

Draft → Validate → Version 行（不可变 JSON 快照）→ MQ `*.published` → 各执行侧缓存失效。

### 6.4 审计

管理 API → `sys_audit_log` → AuditSink（文件/SIEM）。

## 7. 数据分级与留存

| 级别 | 示例 | 控制 |
| --- | --- | --- |
| L0 机密 | API Key、OAuth token | SecretStore；禁日志 |
| L1 敏感 | 会话内容、文档原文、审批意见 | 空间 ACL；可配置留存/脱敏导出 |
| L2 内部 | Agent 指令、Flow 图、路由计划 | RBAC |
| L3 运营 | 用量指标、健康状态 | 可聚合外送 |

留存：会话/Run 默认策略可配（如 180 天）；审计更长；向量随文档删。

## 8. 一致性与幂等

| 场景 | 策略 |
| --- | --- |
| MQ 消费 | 业务幂等键（eventId/runId） |
| 发布快照 | 版本号 + content hash |
| 同步任务 | SyncJob 状态机；contentHash 跳过 |
| 用量 | 追加账本，不对热行做强一致扣减以外的复杂事务 |
