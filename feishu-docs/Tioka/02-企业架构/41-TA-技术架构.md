# TA — Tioka 技术架构

> 回答：系统如何分层、如何部署、横切能力如何落地；技术选型与约束。  
> 模块依赖细节见 **EA**；数据落库见 **DA**；集成拓扑见 **AA**。

---

## 1. 架构原则

1. **自研运行时**：不把外部 Agent Runtime 当执行依赖（ADR-001）。  
2. **api/biz 分离**：跨模块只依赖 `-api`；biz 互斥（ADR-002）。  
3. **出网收敛**：IM/MCP SDK/业务 HTTP 只在 connector（或经 Tool SPI）。  
4. **控制面 / 执行面分离**：S10–S14 管配置与发布；S1/S2/S5 执行已发布快照。  
5. **契约优先**：Part Schema + api 合同测试；变更带版本。  
6. **私有化默认**：客户外置中间件与 IdP 为一等公民（ADR-010）。

```
┌─────────────────────────────────────┐
│ 体验层 FE：Chat / Studio / 配置台 / 审批 │

├─────────────────────────────────────┤

├─────────────────────────────────────┤
```

## 4. 关键技术路径（运行时）

```
UI SSE ← Chat ← Runtime Turn Loop
                ↕ ModelRouter(S10) → LlmClient（凭证白名单/Broker）
                ↕ ToolGateway ← ToolProvider(MCP/KB/Flow/Builtin)
                ↕ WorkspaceFs ← Session Workdisk；SkillLoader → skills/
                ↕ Attention(S2) 当 suspend
```

选模只在「可切换边界」发生；同轮工具续跑冻结 Binding。  
文件/Skill/工具/凭证硬约束见 **ADR-014**（工作盘方案 A、ToolGateway 方案 C）。

## 6. 横切架构

### 6.1 安全

- 认证：OIDC/SAML/CAS/LDAP + 本地可关  
- 鉴权：RBAC + DataScope + 资源 ACL  
- 密钥：SecretStore → 客户 KMS Adapter  
- 出站：白名单；空气间隙开关  
- 内容安全钩子（可 Noop）

### 6.2 多租户

- 行级 `tenant_id` / `workspace_id`  
- 禁止跨库 join；跨域用 ID 引用  
- 配额按空间

### 6.3 韧性

- MQ 至少一次 + 业务幂等键  
- Run 租约/心跳  
- MCP/模型组内熔断与故障接力  
- DLQ + 重放工具

### 6.4 可观测

- Trace：`traceId` 贯穿 session/run/tool  
- Metrics：Token、延迟、队列、工具成功率  
- 审计：管理操作 → AuditSink

### 6.5 HA（W5）

- 无状态应用扩缩  
- DB/MQ/Redis 客户侧 HA  
- 会话粘性可选（SSE）；优先无状态 + 票证续传

## 8. 性能与容量假设（初始）

| 指标 | 起步目标 |
| --- | --- |
| 单会话首 Token | 视模型；平台开销 < 200ms（不含模型） |
| 同步 API P99 | < 300ms（简单读） |
| 并发 Run | 配额可配；默认谨慎 |
| 向量检索 | 十万级 chunk 单库起步；超规模换 Milvus |

**重要**：上表仅为工程容量**设计假设**，**不是**对客户的 SLA/合同指标；对外承诺须单独签约并以压测报告为准。

## 9. 技术债与演进

- 单体→按域拆分：保持 api 稳定  
- pgvector→专用向量：Knowledge 检索 Adapter  
- 本地 Bean→Feign：仅加注解与注册，不改用例接口
