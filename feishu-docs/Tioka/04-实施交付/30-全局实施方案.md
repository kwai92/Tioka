> 权威能力范围：S0–S14 + ADR-009/010/011/012 + **ADR-014（M-Gap 补强包）**  
> 切片任务清单：[31-W0至W5实施计划](31-W0至W5实施计划.md)（历史 W0–W5；`[x]`=slice）  
> **后续推进执行权威**：[33-差距收口与后续推进计划](33-差距收口与后续推进计划.md)（路径 A：R0–R6）

## 1. 一句话目标与成功定义

建设**自研**企业级 Agent 套件（Runtime + Orch + Chat/KB/Flow + Connector + HCI + Foundation + Model Hub + 资产控制面），私有化可交付，外部只接 MCP / IM / 业务系统。

**成功** = 累计通过 S0 门禁 **G1–G7**，且每波退出时回归已过门禁；文档与实现波次标签一致。

| 门禁 | 含义（摘要） |
| --- | --- |
| G1 | 执行面：工具、MCP、流式、Steer、Cancel（经 S10 选模） |
| G1b | 模型面：目录、固定/智能路由、发布、同轮冻结、故障接力、成本时间线 |
| G2 | 人机面：双卡片、审批台、IM、轨迹、分叉 |
| G3 | 知识面：多格式入库、混合检索、引用、≥3 数据源、评测骨架 |
| G4 | 编排面：事件规则、挂起续跑、why、定时、并行 |
| G5 | Flow：节点库约定清单、发布 API+Tool+MCP、Playground |
| G6 | 治理：资产目录、配额、审计、多环境 |
| G7 | 企业接入：SSO/组织/RBAC、客户 IM/业务 Adapter、外置中间件、断公网可用（**部分@W1–W2，完备@W5**） |

## 2. 架构执行视图

### 2.1 控制面 vs 执行面

| 面 | 系统 | 职责 |
| --- | --- | --- |
| 执行 | S1 Runtime | Turn/Step、工具循环、沙箱 |
| 执行 | S2 Orch | 事件、Run、Attention |
| 产品 | S3/S4/S5 | Chat / Knowledge / Flow 引擎 |
| 通道 | S6 Connector | 出网 IM/MCP/业务/数据源实现 |
| 交互 | S7 HCI | 工作台与 Part 渲染 |
| 工程 | S8 | 构建、部署、观测工程落地 |
| 基座 | S9 | SSO、RBAC、Adapter SPI、SecretStore |
| 模型控制面 | S10 | Provider / LogicalModel / RoutingPlan |
| 资产控制面 | S11–S14 | Agent / MCP / Skill / Flow 管理 |

```
刺激 → Chat | Orch | Flow
     → Runtime Session（经 ModelRouter 取模）
     → Tools：KB / Flow / MCP / 沙箱 / 业务
     → 人机：Part 卡片 | Attention
     → 写回 Chat / IM / 业务 / 知识
```

### 2.2 资产挂载（管理态）

```
Agent(S11)
  ├── RoutingPlan(S10)
  ├── McpGrant(S12)
  ├── SkillBinding(S13)
  └── FlowPublication(S14) → Tool
Runtime 只读已发布快照
```

### 2.3 模块树（落地名）

```
tioka-modules/
  tioka-module-system          # 含 Foundation 起步 / 可拆 foundation
  tioka-module-infra
  tioka-module-runtime
  tioka-module-orchestration
  tioka-module-chat
  tioka-module-knowledge
  tioka-module-flow            # 执行 + S14 管理包可同模块分 package
  tioka-module-connector
  tioka-module-model           # S10
  tioka-module-agent           # S11
  tioka-module-mcp             # S12 管理面（Client 执行可在 runtime/connector）
  tioka-module-skill           # S13
tioka-ui / tioka-server / tioka-framework / tioka-dependencies
```

**硬规则**：`*-biz` 互不依赖；跨域只引 `-api`；出网只在 connector（或经 Tool SPI）。

## 3. 关键路径与并行轨

### 3.1 关键路径（最短可卖演示）

1. W0：可编译单体 + Part 契约 + 本地登录  
2. W1：**对话 → Agent → 固定路由模型 → MCP 工具 → 流式回复**（私有化 SSO 可开关）  
3. W2：同一路径叠加 **人审卡片 + IM 续办 + 智能路由可观测**  
4. W3/W4：知识引用问答 / Flow 发布为 Tool 挂回 Agent  
5. W5：密度与 HA，不挡前序售前 PoC

**价值叙事优先于工程炫技**：W1 结束必须能对客户演示「企业登录 + 自有 Key 模型 + MCP 工具 Agent」。

**商业 PoC Gate（W1 Exit 别名）**：通过后方可对外 PoC；未过 Gate 不得用 W3/W4 预研占用主链 >30% 人力。

**G7 分期**：W1–W2 交付 **G7 部分**（SSO 可开关、RBAC/空间、SecretStore、外置 PG/Redis）；W5 交付 **G7 完备**（SCIM、多 IM、空气间隙、客户 Biz Adapter 示例、HA 手册）。禁止把「私有化可卖」拖到仅 W5 才第一次可讲。

### 3.2 并行轨（契约冻结后）

| 轨 | 起始 | 条件 |
| --- | --- | --- |
| Chat 密度 | W1 后 | Part Schema + Runtime API 冻结 |
| Knowledge | W2 末可预研，W3 主交付 | Retrieval/Citation Part 契约 |
| Flow | W2 末可预研，W4 主交付 | Tool Mode / Publication 契约 |
| 企业 Adapter | W0 SPI，W1 SSO，W2+ IM/业务 | 不阻塞 Runtime 主链 |

## 5. 默认技术冻结（W0 末 ADR 可修订，不挡 W1）

| 项 | 默认 | 替换点 |
| --- | --- | --- |
| 语言 | Java 17+ | — |
| 框架 | Spring Boot 3.2.x | 小版本可升 |
| 工程形态 | RuoYi 式 `*-api`/`*-biz`，先**单体** `tioka-server` | 按域拆 server |

| DB | PostgreSQL | 客户外置 |
| 缓存 | Redis | 客户外置 |
| MQ | RocketMQ（或 Kafka，W0 选型会二选一） | 客户外置；Topic 常量在 api |

| 向量库 | pgvector 起步 | Milvus 等可替换 Adapter |

| 认证 | Sa-Token（见 **41/44**） | Security 适配后补 |
| 密钥 | S9 SecretStore（本地加密起步） | 客户 KMS Adapter |

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Part/API 契约漂移 | 三轨并行崩 | W0 契约包+合同测试；变更走版本字段 |
| Agent 快照与运行时不一致 | 工具幽灵/权限扩大 | 发布快照哈希；会话钉版本；MQ 刷新缓存 |
| 模型供应商差异 | 工具调用失败 | S10 Binding 能力标签；组内故障接力 |
| MCP HTTP 协议碎片 | 接入成本高 | S12 向导+健康探测；优先 Streamable HTTP |
| 私有化 Adapter 延期 | G7 推迟 | SPI 空实现+官方飞书先通；客户 Adapter 并行包 |
| Flow/KB 过早上量 | 拖垮 W1 演示 | 严格波次；预研不占主链人力 >30%；PoC Gate 前禁开 Studio/知识大页 |
| W3∥W4 抢人力 | 两轨皆半成品 | W2 后设容量预算：KB 与 Flow 主 R 各 1，共享契约/Runtime 支持 |
| 文档与代码双源 | 实现偏离 | S 篇权威；31 任务勾选；飞书 push 纪律 |
| 模块依赖表过期 | 新人引错包 | W0 同步更新 `docs/architecture/module-dependencies.md`（含 model/agent/mcp/skill） |

## 8. 度量与每波 Exit

每波退出必须同时满足：

1. **门禁**：见 §1 与 [31](31-W0至W5实施计划.md) 各章 Exit  
2. **契约**：相关 `-api` 合同测试绿  
3. **黄金路径 E2E**：该波定义的冒烟脚本通过  
4. **回归**：此前已过 G 的冒烟不全红  
5. **文档**：能力地图波次标签无「永久不做」；本波任务勾选可审计  
6. **HCI 走查**（W1+）：该波「可感知」任务（选择器/双卡片/引用/Studio 空态等）走查通过  

**W0→W1 硬门**：未完成 W0-17 契约冻结，不得合并 Runtime 业务实现 PR。
