## ADR-014：AgentCore 对齐补强包（工作盘 / Skill / ToolGateway / 多模态 / 凭证）

- **状态**：已采纳（2026-11-05）  
- **背景**：对照 AgentCore+Codex 生产硬模式，Tioka 在会话工作盘、Skill 执行链、工具面收敛、文件多模态、凭证边界上存在系统性缺口。  
- **决策**：  
  1. **D1 方案 A**：POSIX Session Workdisk + OSS/MinIO 仅作交换与产物；新增 `WorkspaceFs` SPI；  
  2. **D2**：Skill 经 AgentVersion 快照绑定 → 工作区只读安装 → always/auto 注入；**禁止**当 MCP Tool；  
  3. **D3 方案 C**：统一 **ToolGateway**（list/call + grant + HITL + 审计）；MCP Aggregator 协议出口可后置；  
  4. **D4**：文件驱动多模态为主路径；禁止默认 Base64 入模；  
  5. **D5**：密钥不进 prompt/工作盘/日志；`SecretStore.get` ArchUnit 白名单 → 演进 CredentialBroker。  
- **依赖序**：D1 → D2/D4 → D3 深化；D5 白名单可并行。  
- **详见**：仓库 `docs/architecture/adr/ADR-014-agentcore-alignment-package.md`；spec `docs/superpowers/specs/2026-11-05-agentcore-alignment-gap-design.md`；里程碑 M-Gap。

## ADR-007：文档体系 — 分系统独立详设

- **状态**：已采纳（2026-11-05）  
- **背景**：单篇技术方案过松散，无法支撑并行评审与实现。  
- **决策**：  
  1. 管理面保留 6 篇（主页/需求/总览/接口总表/ADR/运维）；  
  2. 增加 S0–S8 分系统详设，**统一 14 章大纲**；  
  3. 飞书节点与本地 `feishu-docs/Tioka/` 一一对应；仓库 `docs/architecture/systems/` 同步镜像；  
  4. 旧长文架构稿降级为参考，**以 S 篇为权威**。  
- **后果**：文档量增加；变更需改对应 S 篇再 push；`feishu.mjs ensure` 用于补节点。

## ADR-013：企业架构六册成体系（BA/TA/DA/AA/EA/FE）

- **状态**：已采纳（2026-11-05）  
- **背景**：仅有 S 域能力详设与实施波次时，业务/技术/数据/Java/前端缺少成体系设计，W0 编码缺基线。  
- **决策**：  
  1. 新增 **40 BA / 41 TA / 42 DA / 43 AA / 44 EA / 45 FE**，并以 **46** 做 CEO→Eng→Design 三轮评审回写；  
  2. 认证默认 **Sa-Token**；Studio 画布默认 **Vue Flow**（经 studio-kit 抽象）；  
  3. foundation 在 W0–W1 合入 system，W2+ 可拆独立模块；  
  4. 与 S 篇冲突时：范围以 S0/ADR-009 为准，工程硬规则以 TA/EA 为准。  
- **后果**：技术方案总览改为导航；编码前须对照 40–45。

## ADR-012：资产控制面独立成册（S11–S14）

- **状态**：已采纳（2026-11-05）  
- **背景**：Agent / MCP-HTTP / Skill / 工作流 若只散落在 Chat/Flow/Connector，无法支撑企业级「创建—挂载—发布—授权—运维」。  
- **决策**：  
  1. **S11** Agent 资产管理；**S12** MCP 管理（含 HTTP/SSE）；**S13** Skill 资产管理；**S14** 工作流编排管理（相对 **S5** 执行引擎的控制面）；  
  2. **S10** 继续专管模型/供应商/路由；Agent **只绑定 RoutingPlan**，禁止散落互斥主模型字段；  
  3. 运行时只装载**已发布快照**；管理面变更经 MQ 刷新缓存；  
  4. Flow 发布为 Tool / MCP 出口 / Webhook 的登记归属 S14，执行仍归 S5。  
- **后果**：控制面与执行面评审可并行；HCI 配置台按 S11–S14 导航。

## ADR-011：模型中台对齐 HiRoute — 独立 S10

- **状态**：已采纳（2026-11-05）  
- **背景**：需要企业级模型管理与智能切换（成本/质量平衡），对标 HiRoute。  
- **决策**：  
  1. 新增 **S10 模型管理与智能路由**；  
  2. 通用模型与决策模型分离；路由类型含固定/难度/分支/免费优先；  
  3. **发布后生效**；同轮工具续跑冻结模型；组内故障接力；  
  4. Runtime/Chat/Flow/Orch **统一经 ModelRouter 取模**，自研实现对齐 HiRoute，不嵌入 HiRoute。  
- **后果**：模型凭证与路由治理集中；会话可展示实际模型与成本。

## ADR-010：私有化 Foundation — 客户体系可插拔接入

- **状态**：已采纳（2026-11-05）  
- **背景**：私有化客户自有用户体系、IM、业务中台；仅内置飞书/本地账号无法交付。  
- **决策**：  
  1. 新增 **S9 平台基座与企业接入**；  
  2. 身份联邦（OIDC/SAML/CAS/LDAP）+ 组织同步（SCIM/Adapter）+ RBAC/数据权限为一等能力；  
  3. **ImChannelAdapter / BizSystemAdapter / AuditSink / SecretStore** 等 SPI，官方飞书等只是实现；  
  4. 默认联邦优先，本地账号可关；中间件支持客户外置。  
- **后果**：集成交付以 Adapter 包+绑定配置为主；内核不写客户 if-else。

## ADR-009：能力范围按对标并集写全，分期不阉割

- **状态**：已采纳（2026-11-05）  
- **背景**：初稿用「MVP 非目标」删除 LibreChat/Langflow/WeKnora/harness 级能力，导致设计偏残缺。  
- **决策**：  
  1. 产品范围 = 对标产品能力并集（见 S0 §2）；  
  2. 各 S 篇第 2 章必须是**完整能力地图**（含波次标签）；  
  3. W0–W5 只表示交付顺序；未排期项进 backlog，**不得**从需求删除；  
  4. 唯一 Out：不自研基模训练、不以外部云 Agent 替换 Runtime、不复制第三方商标资产。  
- **后果**：文档与排期变长；评审按能力地图勾选，而不是按「砍需求」压缩。
